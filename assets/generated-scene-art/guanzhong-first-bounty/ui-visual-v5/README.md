## 本轮完成

1. 两角固定 HUD 沿用 v4 的形态与位置；战斗中左上始终为玩家，底部为当前可操作角色，右侧为查看目标。
2. 左侧行动轴：固定“当前行动”，下方按预计先后等距排列；编号/阵营形状辅助识别，CT 单独显示。12 人模式可以滚动查看末端，无实时倒计时。自身下次位置使用独立标记；施行后的固定顺序快照与预览一致。
3. 右侧目标详情：身份、生命/灵力、状态、攻防与抗性、未知值、可展开的已知能力。状态可点击查看效果与剩余持续次数。
4. 底部操作栏：招式、物品、其他行为分组；快捷键、灵力/行动/移动余量、禁用理由、取消/施行/等待/结束分别呈现。可操作取消、确认、移动、状态与物品数量变化、行动交接。
5. 玩家行动＋选中敌人＋招式范围＋预计结果＋自身下次位置同时显示的组合状态。
6. 8 / 12 人场景展示夹具。新增角色仍由原有三维代理复用，不是新增正式角色资产。37 六角地块、0/1/2 高度与两组石阶仍是真实 WebGL 几何。

## 浏览器实际验证

使用 Codex 内置 Chromium，1920 与 1280 宽。验证以当前版本为准，范围限原型。

- 御气术无目标、选中范围外敌人均不能施行；点选范围内敌人可施行。轴与世界标签同步目标详情，操作栏仍属于无名修士。
- 取消前后玩家灵力均为 126；确认后为 108，目标生命固定投影为 713；预览关闭，行动权变为 0，不能重复施行。
- 施术后仍可完成一次固定石阶移动样例；剩余移动显示 2，灵力仍为 108。结束前有独立确认，行动交给敌1。
- 查看敌2后结束行动，右侧与场景选中仍为敌2；当前行动标识单独指向敌1。玩家在剩余队列第4，与施术前第5位预览扣除正在行动的敌1一致。
- 等待显示其独立语义并投影玩家 CT 50；未将其当作普通关闭按钮。
- 回灵丹确认后灵力 168、数量 2；禁用原因优先显示行动权耗尽，不出现“168 小于 140”的矛盾提示。
- 破甲与守势确认后分别显示对应敌方/自身状态；己方属性可读，敌方未知属性不通过伤害/命中预览泄漏。
- 12 人轴可滚动选择敌8，场景存在对应第12个代理；未知目标不因选择而变成可施行。返回默认/他人行动/重置没有操作栏归属残留。
- 默认、选中、键盘焦点、禁用及其解释、预览确认/取消均有入口；浏览器控制台未发现 error / warning。
- 1280 宽无横向溢出；最大组合面板互不遮挡，中央仍能看到玩家、敌人、两组台阶及三层地面。侧看按钮可直接检查真实高差。

## 明确边界与当前事实

- **固定样例，不是战斗实现。** `review-fixtures.json` 提供数值、合法目标、范围、状态结果、物品数量和行动后顺序快照；页面不运行 CTB、伤害、命中、神识或通行算法。范围、行动后剩余移动均不是当前 Unity 功能完成的证据。
- 神识不足、术法名称/效果、同行者、额外敌人都是 UI 容量样例，不建立设定或数值合同。未探明数据只显示 `??`；伤害与命中未知时不预测数值。已施行后的生命变化属于观察结果。
- 移动只演示一条固定石阶通路，不能任意寻路；侧视仅作高差检查，个别世界标签会投影重叠，可通过行动轴选择。本轮不解决地形接口、净空或正式可通行性。地形视觉方向已接受不等于本版 UI 通过。
- 用户尚需判断：左侧纵轴宽度与排列是否顺手、底部图标与信息密度、右侧详情阅读节奏、仙侠视觉强度。12 人仅为布局压力样例，不是已支持12单位的正式战斗。
- 正式接入前必须重新核对 `CombatHudSnapshot`：本轮主线仍缺多单位行动顺序/CT、可见性、状态、范围与预计结果的完整投影。`CombatantHudSnapshot` 仅有身份与生命/灵力等基础字段。不能复制原型公式或在 UI 实现战斗规则。
- 战斗设计有移动/行动权流程，当前正式 `CombatCommandService` 的成功 Move 消耗行动，与本版演示的剩余移动流程存在差异；需正式任务裁决和实现。
- 正式 UI 资源切分、Unity 接入、背景、角色表现、音画反馈和全流程实机验收均未在本轮完成。
