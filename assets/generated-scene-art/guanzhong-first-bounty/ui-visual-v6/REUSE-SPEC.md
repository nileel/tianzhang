# 《天章》UI 统一复用规格 v6

2026-09-20 · 用户已确认本版可操作设计原型与统一复用规格定稿，并授权合并、推送。v5 战斗接受基线保留；不构成最终美术或正式 Unity 验收。

## 1. 复用结论与职责

普通全屏、大弹窗、小弹窗使用同一 `windowTemplate()`，只改变尺寸变体与内容。它们共用 header / body / footer 骨架，目录使用 `listTemplate()`，普通按钮使用 `buttonTemplate()`。页面不得复制一份窗口底图、按钮底图或为不同页面另画同用途资源。

| 层 | 唯一出处 | 可以改变 | 不负责 |
|---|---|---|---|
| 内容与状态 | 消费页的数据与事件；样板为 components.js | 名称、说明、条目 key、数量、选中、禁用原因、确认结果 | 绘制皮肤、战斗规则 |
| 结构 | ui-kit/templates.js | 插槽内容、size、variant | 页面导航、窗口管理器、持久化 |
| 尺寸和状态规则 | ui-kit/components.css | 窗口尺寸、内边距、正文滚动、状态优先级 | 决定禁用原因、扣除资源 |
| 美术与皮肤 | ui-kit/skin.css + ui-kit/art/ | 稳定槽位对应的图、颜色、字体、状态亮度 | 文字内容、尺寸、玩法数据 |
| 专用布局 | style.css / components.css | 战斗布局、行囊双列布局 | 复制共用资源 |

`.ui-root` 是共享样式宿主，不依赖战斗的 `#game-frame`。样板页只依赖三个 ui-kit 文件与资源，不导入 v3/v4/v5。战斗页仍继承历史原型布局；该继承链不是正式架构决策。

## 2. 窗口骨架与尺寸

`windowTemplate({ size, key, title, subtitle, body, footer })` 生成同一种窗口：
- header：标题、副题、关闭按钮；始终可见。
- body：自由内容插槽；唯一垂直滚动区。
- footer：状态说明与操作按钮；超长时自然换行，始终可达。
- size 仅取 fullscreen / large / small；窗口不自带业务事件。

| 变体 | 本样板实际尺寸（CSS 逻辑像素） | 适用内容 |
|---|---|---|
| fullscreen | 占满宿主；1920×1080 审阅视口下为 1728×878，1280×860 下为 1216×666 | 普通角色资料、行囊、功法目录等。页面可改变 body 的列数 |
| large | 880×660，受视口安全边距限制 | 详细说明、较长列表、筛选或分组操作 |
| small | 宽 520，高随正文；受同一视口上限限制 | 确认、简短说明、少量操作 |
| 弹窗外边距 | 每边至少 32；最高为视口高减 64 | 窗口外层使用浏览器原生 dialog 负责模态和焦点 |

1920 下 header 为 22×28 内边距，body 26×28，footer 18×28；宽度 ≤1400 时分别为 18×22、20×22、14×22。标题 32→28；正文 16–18；普通按钮 22→20、最小高 48；关闭 40×40；列表行最小高 68。样板使用流式像素布局，1280 下不整体缩小文字。

战斗沿用 v5 的 1920×1080 固定画布，在 1280 宽下整体缩放至 2/3；它与普通模板页的适配方式不同。本轮验证桌面 1920 和 1280 宽；更小尺寸不构成验收范围。

关闭／取消不会自动确认。浏览器 dialog 使用原生模态、Tab 焦点约束、Esc 返回与焦点恢复；小弹窗打开时，大弹窗仍保留滚动位置。原型没有新增窗口栈管理器。

## 3. 列表与按钮数据

列表：`listTemplate(items, emptyText)`，每项含 `key / title / subtitle / trailing / selected / disabled / hint`。key 稳定且唯一。disabled=true 时 hint 必须提供原因，行内直接显示；不只依赖悬停。空数组走相同入口输出空态。

按钮：`buttonTemplate({ label, key, variant, disabled, selected, hint })`。
- variant：normal 普通操作、primary 关键确认、quiet 返回或取消。
- selected 独立于用途，通过 aria-pressed 与选中底图／左侧标记表达。
- 普通模板使用原生 disabled；战斗既有动作使用 aria-disabled 并由事件检查可用原因，仍允许查看解释。
- 事件只消费 key，展示文字不充当业务标识。

| 状态 | 共用表现 | 规则 |
|---|---|---|
| 普通 | normal 底图 | 可点击 |
| 悬停 | hover 底图 | 仅普通可用按钮；quiet 用下划线 |
| 选中 | selected 底图、左侧强调 | 悬停保持选中底，仅提亮 |
| 按下 | 当前底图乘 pressed brightness | 不改变尺寸或文字 |
| 键盘焦点 | 3px focus 外框，外偏移 3px | 不依赖鼠标悬停 |
| 禁用 | normal 底图、disabled 色、0.65 不透明度 | 禁用优先，不能执行，保留原因 |
| 确认 | primary 使用 selected 底图 | 只是用途样式；业务仍显式处理确认 |

本轮修正了草稿中“选中悬停被普通 hover 底覆盖”的优先级，并排除了禁用与悬停叠加。

标题和列表主列自然换行，`min-width:0`；长词可断行。尾列不收缩、最大 7em，可换行；不能挤掉正文。长正文只滚 body，不能靠缩字、截断动作名称或拉高整个窗口解决。

## 4. 资源包合同

资源索引：[ui-kit/RESOURCE-MANIFEST.json](ui-kit/RESOURCE-MANIFEST.json)。皮肤的实际加载入口仅 `ui-kit/skin.css`；清单用于交接，不另建运行时加载器。

| 语义槽 | 青玉包 | 绛紫校验包 |
|---|---|---|
| panel.dark | art/panel-dark.svg | art/panel-check.svg |
| panel.paper | art/panel-paper.svg | art/panel-check-paper.svg |
| button.normal | art/button-normal.svg | art/button-check.svg |
| button.hover | art/button-hover.svg | art/button-check-hover.svg |
| button.selected / primary | art/button-selected.svg | art/button-check-selected.svg |

两套共 10 张 SVG。全部为代码绘制的 64×64 示范资源，透明外缘、sRGB 色值、无烘焙文字。没有商业字体文件或最终美术切图。标题默认系统楷体、替换包为系统宋体；正文为微软雅黑系统回退。未来字体包需附字符覆盖、授权及回退说明，不能将当前系统字体截图当作商用授权证据。

九宫格固定合同：
- 源切片四边各 16（中心 32×32）；网页面板显示边框 8，按钮 5；切片值与显示宽度分别记录，不能混淆。
- 四角保持比例；边缘沿长轴延展；中心可伸展。装饰只放角区或延展安全区，不依赖整幅纵横比，不画文字、图标或进度数值。
- 更换 64×64 SVG 时保持切片合同；若交付双倍 PNG，则资源 128×128、源切片四边 32，展示仍采用同一逻辑尺寸。
- 不按全屏／大窗／小窗分别出图，不把列表行重新画成独立按钮包。
- primary 与 selected 可共享底图；pressed、focus、disabled 由颜色与状态配置合成，无需为了数量齐全另产重复图片。

除 5 个图像槽外，每个包需配置：text/muted、paper-text/paper-muted、accent、disabled、line/paper-line、font-title/font-body、focus、pressed/hover brightness、header-fill、stage、scrim、shadow。稳定变量名即接口，页面 CSS 不写具体美术路径。

替换流程：备份当前包 → 在 art/ 放入同合同资源 → 只更新 skin.css 槽位与配置 → 打开同一模板页核对五类控件、全部状态及长文 → 留存前后同构截图。需要长期重命名槽或改变切片尺寸时，应修订本合同，不能在每页加覆盖补丁。

## 5. 可操作样板与换肤证据

打开 [components.html](components.html)：
1. 列表选中不同物品；长题签自然换行；封存卷册显示禁用原因。
2. “任务物品”显示空列表；返回“全部物品”保留选择。
3. “查看详录”打开大窗，滚动长文；“整理确认”打开小窗。
4. 取消／Esc 回到原处；确认将展示标签改为“已整理”，数量不变。
5. “换肤：绛紫校验”或 K 原位切换两包。弹窗打开时用 K，模态外的工具栏保持不可点击。
6. “控件状态”查看普通、选中、确认、禁用、弱操作和键盘焦点；“收起行囊”与“打开全屏”验证关闭／重开。

实际证明：全屏 `innerHTML` 在换肤前后完全相同；全屏、大窗、小窗同时存在时，三者 HTML、dialog open 列表及长文 scrollTop=268 均保持相同。变化来自根节点皮肤属性；没有重新生成页面或切换另一份静态截图。对应图 04/05 与 07/08。

绛紫只是资源可替换的验收包，未宣称这是新的正式美术方向。当前样板没有搜索、批量管理、路由、资源热更新服务或全游戏页面系统。

## 6. 战斗 v6 收尾

| 元素 | 1920×1080 画布位置／尺寸 | 行为 |
|---|---|---|
| 悬赏追踪 | 右 52、顶 171、宽 360、高 100 | 从地图标题下移至右上通用入口下方 |
| 目标详情 | 右 52、顶 294、宽 360、最大高 700 | 固定头部，超长正文内部滚动 |
| 更多菜单 | 通用入口下方，悬赏左侧；宽 154 | 展开时与悬赏横向留 24 像素间隔 |
| 行动轴 | 左 52、顶 279、宽 76（v5 为 255） | 常驻仅头像／阵营图形、编号、当前、选中、自身下次标记 |
| 轴按钮 | 52×46，当前 66×66；间隔 5 | 悬停或键盘焦点显示姓名与 CT；点击与世界选中联动 |
| 轴列表 | 最大高 605，超长可滚 | 12 人 + 自身未来位置可完整到达 |
| 战场工具 | 右 52、底 32 | 不挤占悬赏和详情 |

当前行动者、被查看目标、自身预计下次位置是三个独立语义。去掉的是常驻姓名与 CT，不是删除身份和顺序信息。预计位置来自 v5 固定 fixtures，不在 UI 计算 CTB。

悬赏、目标详情、行动预览、操作栏、战报及普通战斗按钮已消费共享面板／按钮资源；目标详情复用 panelContent。行动轴、世界标记、固定两角 HUD、资源条、头像与战斗图标保留专用布局与既有样式，未宣称全部战斗表面已完成换肤。

## 7. 专门界面的例外

| 对象 | 专用理由 | 仍应复用 |
|---|---|---|
| 战斗行动轴、世界标签、招式栏 | 顺序投影、三维锚点、操作密度 | 通用按钮状态、基础面板、文字配置 |
| 城镇建筑服务入口、城市标题／出城 | 场景位置与服务含义 | 弹出的普通窗口、列表、确认按钮 |
| 角色展示、全图地图、对话演出 | 肖像构图、地图交互、演出节奏 | 标题、关闭、普通操作与确认窗 |

本轮没有重做这些专门界面，也没有把所有历史原型迁移到 ui-kit。新增例外需说明普通骨架不能满足的具体原因；不能因“是另一个页面”就新建皮肤资源。

## 8. 未来 Unity 映射与未完成项

这是一份未来接入建议，未编辑 src、Prefab、场景或 Builder：
- 窗口骨架映射一个公共窗口 Prefab 的尺寸变体；header/body/footer 保留固定槽位。基础控件不各自建立 Canvas。
- 图像语义槽映射统一皮肤资源引用；面板和按钮按九宫格使用。源 Border 与最终 Canvas 缩放需实机验证，不能直接把网页 border-image 显示宽度当源切片。
- 标题／正文／数量独立文本控件，字体资产独立；图标、头像、状态符号也独立于背景。
- 表现数据需要稳定 ID、文本、数量、选中、可用性与原因、确认意图／结果。战斗另需当前行动、顺序、自身预测位置和可透露的目标／范围／状态投影。
- 正式任务启动时按当时 src 重新查明真实运行时所有者与 CombatHudSnapshot 等合同；本轮未复核这些正式字段，不把 v5 展示夹具当现成功能。

本轮设计已确认：76 宽行动轴、右侧悬赏与详情排布、普通窗口比例及统一复用方向作为当前基线。待正式任务：最终切图与字体批准、Unity 数据／事件／资源接入、实际场景和分辨率验收。验收记录见 [VALIDATION.md](VALIDATION.md)。
