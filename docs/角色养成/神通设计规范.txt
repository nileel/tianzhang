# 神通设计规范

✅ 已审核（2026-06-21 Codex / gpt-5.5；神通体系迁移为紫府神通、丹相主枢与源化界丹枢接口；依据：f3ebf04）

## 文件位置
- 神通原文：`docs/角色养成/神通/[门派]/神通名.txt`
- 通用模板参考：`docs/角色养成/神通/神通设计.txt`
- 神通按门派分文件夹存放，一个门派的所有神通可放在一个文件或拆分多个文件。

## 模板字段（设计新神通时全部必填）

- 名称 — 格式与功法命名规则一致，需有古典出处或人物典故为原型。
- 来源 — 镇府神通 | 丹相主枢表现 | 血脉 | NPC领域。太一道庭内容形式可写：本命符箓 | 本命法坛。
- 类型 — 主动（战斗中释放） | 被动（持续生效） | 触发（满足条件自动结算）。
- 伤害类型 — 物理 | 神魂 | 混合 | —（非攻击类神通填“—”）。
- 五行属性 — 神通自身的五行属性。镇府神通和丹相主枢表现继承来源术法；血脉神通由血脉来源决定；NPC领域继承功法或位格属性；无属性关联的被动神通标注“—”。
- 物理倍率 / 神魂倍率 — 主动攻击类填写，非攻击类可省略。
- 冷却惩罚 — 由具体实现声明；不得假定丹相主枢全局无消耗或无冷却。
- 射程/范围 — 主动类填写，格式同术法。
- 效果绑定 — 平铺填写触发、条件、目标、效果类型和参数；涉及金丹位格时必须区分矩阵通用效果与丹枢战斗表现，不得递归调用效果包。
- 数值 — 具体数值或公式；未由 TQ-015C 锁定的成丹、主枢或槽位数值不得填写为正式规则。
- 获取条件 — 镇府神通写源术法升格方案与来源紫府；丹相主枢表现写目标位格、占据状态、丹名、丹性和来源镇府神通；血脉写创建或觉醒条件；NPC领域写 NPC 专属条件。
- 强化节点 — 镇府神通按需填写行为、修持、资源、府间或特殊节点，不建立统一等级或统一经验条。
- 目标源化界席位 — 金丹相关神通必填。引用《元婴锚点与金丹位格效果矩阵》的分支与源/化/界席位，不得自行命名或新增席位。
- 丹枢接口 — 金丹相关神通必填。只能填写媒介、偏向对象、代价分配、丹域景象、战斗表现和宗门叙事，不能改写矩阵变量、边界或不可替代项。
- 丹器显化 — 可选。填写实体或非实体外显形态，不能独立提供超出席位边界的效果。
- 说明 — 一段话解释神通的来源、在游戏世界中的意义。

## 四种神通类型

### 镇府神通
- 来源：筑基期将兼容源术法按升格方案转化后，由一座完整紫府唯一承载。
- 核心特征：每座紫府恰有一项镇府神通，是成丹与唯一丹相的个人输入。
- 设计规则：必须记录来源紫府、固定神通本体、源术法处置、主动／被动／触发形态、平铺效果绑定和可选强化节点。
- 金丹去向：可主承载一个稳定位格、辅助多个明确兼容位格，或只保留原有效果；不得默认全部成为主枢。

### 丹相主枢表现
- 来源：某项镇府神通作为目标稳定位格主承载后，在占据状态、丹名、丹性与丹枢接口约束下形成。
- 核心特征：必须继承来源镇府神通的核心定位，并服从目标位格矩阵边界；它是唯一丹相内部的职责，不是新神通实例。
- 暂寄：不生成丹相主枢，只保留不完整丹相与辅枢残影。
- 数量与资源规则：稳定真实位格数为一至三，因此主枢表现为一至三；所有引用共享来源 `abilityInstanceId` 的唯一账本。

太一道庭专属例外：
- 金丹期通过升箓形成太一道庭丹相表达。
- 本命符箓或本命法坛可作为丹相主枢或丹器显化，但仍须填写目标席位与丹枢接口。
- 血脉神通仍保留，用于表示王、谢、庾、桓四大道脉的血脉特性和家箓亲和。

### 血脉神通
- 来源：角色创建时选择血脉背景，或在特定条件下觉醒。
- 数量：固定 1 个，不可更换。
- 核心特征：与角色绑定，有独特机制（变身、召唤、被动守护等）。
- 设计规则：体现门派/家族的历史特征，强度随境界自然增长；不能只是纯数值加成。

### NPC领域
- 来源：元婴/化神级 NPC 的专属能力或世界背景事件。
- 当前用途：传说级 NPC 威慑、世界事件与资料片预留，不作为当前玩家神通类型。
- 设计规则：必须声明启动成本、持续时间、打断条件、失败代价与 AI 使用条件；不得以领域替代源/化/界矩阵的世界效果。

## 核心设计原则

### 1. 神通总量严格控制

| 类型 | 数量规则 | 获取时机 |
|------|----------|----------|
| 镇府神通 | 等于已建紫府数（1～5） | 筑基期逐府升格 |
| 丹相主枢/辅枢表现 | 主枢等于稳定位格数；辅助按兼容配置 | 金丹期进入同一丹相 |
| 血脉神通 | 1 | 角色创建或觉醒 |
| NPC领域 | NPC 专属 | 世界背景或高阶 NPC |

### 2. 全部镇府神通进入唯一丹相
- 全部已建紫府及其镇府神通都是丹相输入，保留核心定位但不保证担任主承载。
- 每个稳定位格使用不同主承载形成主枢表现；辅枢承担明确兼容的被动、触发、资源循环与抗性支撑。
- 第四、第五府不会因只有三个稳定位格而失效，也不会自动增加位格或效果槽。
- 丹枢只允许个性化表现，不能重写席位的世界变量、对象、边界和代价。

### 3. 血脉神通是身份标签
- 必须在机制层面有独特性，不能是简单的数值加成。
- 优先设计变身、召唤、特殊状态、被动守护等机制类效果。
- 血脉神通不消耗任何资源（灵力/行动权），是天生能力。

### 4. NPC领域不替代位格规则
- 必须声明高消耗、高回报与明确边界。
- 不能仅做属性加成，也不能用领域名替代矩阵定义的源/化/界效果。
- 多个 NPC领域的碰撞规则应在对应世界事件或后续高阶战斗规范中单独定义。

## 通用约束（与功法、术法共用）

1. **命名不出典不立**：神通名必须有历史典故、典籍出处或人物原型支撑。
2. **设计围绕原型人物**：血脉神通应体现归属门派/家族的历史特征。
3. **文件按门派归档**：放入 `docs/角色养成/神通/[门派]/`。
4. **强化节点必须具体**：需要强化时，逐项写明可记录行为、固定修炼周期、资源、府间条件或特殊事件；不使用统一经验条。
5. **效果绑定必须平铺**：每条只保存触发、条件、目标、效果类型和参数；不得递归调用任意效果包。

## 新增神通前置检查清单

- [ ] 来源类型明确（镇府神通/丹相主枢表现/血脉/NPC领域）。
- [ ] 一座紫府只承载一项镇府神通，来源紫府实例明确。
- [ ] 源术法处置、主动／被动／触发形态和可选强化节点明确。
- [ ] 效果绑定平铺填写，未递归调用效果包。
- [ ] 丹相主枢有来源镇府神通、目标源化界位格、占据状态和丹相适配依据。
- [ ] 丹枢接口只使用矩阵允许的六项个性化字段，未改写世界变量或边界。
- [ ] 暂寄内容未生成丹相主枢。
- [ ] 太一道庭本命符箓/本命法坛注明升箓条件、目标席位与丹枢接口。
- [ ] 血脉神通具有独特机制，非纯数值加成。
- [ ] NPC领域声明启动成本、持续时间、打断条件、失败代价与 AI 使用条件。
- [ ] 强化节点均为具体可执行条件，没有统一等级或经验条。
- [ ] 名称有典故出处，且体现归属门派/人物特征。
- [ ] 五行属性已标注，获取条件具体可执行。
- [ ] 文件放入正确门派文件夹并附带说明文字。
