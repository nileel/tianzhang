【术法槽位系统设计】

✅ 已审核（2026-06-21 Codex / gpt-5.5；金丹槽位迁移为源/化/界席位、占据状态与丹相接口；依据：f3ebf04）

═══════════════════════════════════════════════════════════════

第一章：设计目的
═══════════════════════════════════════════════════════════════

现存术法无装备数量上限，导致 Build 选择无意义——玩家
可以携带全部可学术法进入战斗，消解了战术准备的策略深度。

术法槽位系统为修士设定术法与神通的携带上限，
强制玩家在有限槽位中做出取舍，构建差异化 Build。

当前重构口径：紫府本身不自动生成通用术法槽或神通槽；每座完整紫府固定承载的
镇府神通也不因紫府数量自动占用或生成普通神通槽。具体槽位预算必须由独立数值设计锁定。


═══════════════════════════════════════════════════════════════
第二章：槽位数量
═══════════════════════════════════════════════════════════════

当前只确认槽位用于限制战斗携带量。练气 4/1、筑基 5/2 及其衍生区间均是旧实现基线，
不能作为四阶段道基、五座独立紫府和唯一丹相的新数值事实。新槽位预算须经 BattleSim
与 Unity 数据链路共同验证后另行锁定；本轮不重分配这些数值。


────────────────────────────────────
二.1 紫府与镇府神通边界
────────────────────────────────────

规则：
  - 命、魂、识、悟、运是五座独立紫府，每类最多一座，不再使用“主修府位”槽位表。
  - 每座完整紫府恰有一项镇府神通；已建紫府总数可以是 1～5。
  - 紫府数量、府属或第四、第五府都不会自动生成额外术法槽、神通槽、位格或丹相。
  - 若具体府体效果、镇府神通或金丹接口需要修改槽位，必须以平铺效果绑定明示，并接受独立数值验证。


────────────────────────────────────
二.2 金丹席位与丹相槽位接口
────────────────────────────────────

金丹不再使用通用层级槽位表。槽位修正必须由以下输入共同决定：

1. 目标源/化/界席位在矩阵中允许的丹枢接口。
2. 占据状态带来的稳定度、使用边界和代价。
3. 唯一丹相中主承载与辅助输入的已实现表现。
4. 具体内容明示且已验证的槽位效果绑定。

规则：
  - 不同席位不得仅因名称获得固定高低槽位；所有修正必须能回指矩阵边界与代价。
  - 暂寄状态不生成稳定位格主承载表现，只保留不完整丹相与合法辅助表现；是否获得槽位修正由具体实现声明。
  - 自辟不是通用加成标签，必须先形成可验证的完整源化界结构。
  - 具体槽位数、替换规则与数值上限由 TQ-015C/TQ-013C 以 BattleSim 和 Unity 实现共同锁定。

═══════════════════════════════════════════════════════════════
第三章：非战斗替换规则
═══════════════════════════════════════════════════════════════

一、安全区域（道观/洞府/城镇/营地）
  - 可随时自由替换术法和神通，无任何代价
  - 替换即时生效

二、野外/副本（非战斗状态）
  - 可自由替换，但需消耗时间（每次替换 = 1 刻游戏时间）
  - 替换期间有概率遭遇随机事件（敌人巡逻/天象变化）
  - 概率 = 5% × 替换次数（第 3 次起 15%，鼓励一次性配好）

三、战斗前准备阶段
  - 看到敌方阵容后、开战前，有一次免费调整槽位的机会
  - 调整次数不限，但仅限战斗触发前的准备窗口
  - 开战后槽位锁定


═══════════════════════════════════════════════════════════════
第四章：战斗中切换规则
═══════════════════════════════════════════════════════════════

一、基本原则
  - 战斗中不可自由切换术法，槽位在开战时锁定
  - 但提供"临阵换法"特殊行动作为紧急出口

二、临阵换法（战斗中特殊行动）
  消耗：1 次完整行动权（不可移动、不可同时攻击）
  效果：将一个已装备术法替换为术法库中另一个术法
  代价：
    - 新术法获得双倍冷却惩罚（CD × 2）
    - 被替换的术法本场战斗不可再装备
    - 每次战斗最多执行 2 次临阵换法
    - 神通不可临阵更换（神通为"根本大法"，战斗中不可变更）

三、解除锁定
  - 战斗结束后所有槽位自动解锁
  - 被"本场不可再装备"标记的术法在战后恢复可用


═══════════════════════════════════════════════════════════════
第五章：槽位与神通的关系
═══════════════════════════════════════════════════════════════

一、神通槽独立
  - 神通槽和术法槽完全独立，不共享数量
  - 神通不可放入术法槽，术法不可放入神通槽

二、镇府神通与唯一丹相规则
  - 每座完整紫府恰有一项镇府神通，全部已建紫府共同进入一个丹枢核心和一个丹相。
  - 每个稳定位格仍需不同镇府神通担任主承载；其他镇府神通可作为完整辅助输入。
  - 主承载或辅助表现是否占据普通神通槽，必须由具体实现声明；当前不预设全局数量或槽位表。
  - 主承载关系绑定角色与目标席位，战斗中不可更换；丹成后的安全重铸只能在结丹时已固化的镇府神通集合内进行。

三、太一道庭法箓例外
  - 本命符箓和本命法坛是太一道庭丹相的门派表达；是否占据神通槽由具体实现声明，不新增独立法箓槽
  - 本命符箓不占术法槽；来源术法仍保留在术法库中
  - 本命法坛的召唤、阵地或法司效果由具体丹相、神通/功法声明，且不得越过目标席位边界


═══════════════════════════════════════════════════════════════
第六章：Unity 实现接口（历史草案，暂停采用）
═══════════════════════════════════════════════════════════════

本章原字段清单建立在“已开发府位直接重算槽位”和旧多丹相接口上，与当前事实源冲突，
不得作为实现依据。新的 Unity 数据字段、运行时重算入口和 UI 动态数量须等待槽位预算、
统一效果绑定与丹枢数据结构分别锁定后再设计。本轮不创建兼容读取字段或临时运行时接口。


═══════════════════════════════════════════════════════════════
第七章：现有实现迁移状态
═══════════════════════════════════════════════════════════════

既有装备数组、CSV 行数、BattleSim Build 与旧槽位数之间的兼容结论尚未按新结构复验。
在新槽位预算锁定前，不得继续引用“现有数据全部兼容”或假定导入时可直接截断。
本轮不修改代码、CSV 或模拟器。


═══════════════════════════════════════════════════════════════
第八章：边界情况
═══════════════════════════════════════════════════════════════

一、槽位不足
  - 新槽位预算未锁定前，不按紫府是否建成自动增减槽位
  - 学会新术法但槽位已满 → 提示替换或放弃学习
  - 暂寄修士没有稳定位格主承载表现，具体可用能力由其不完整丹相与合法辅助接口声明

二、多门派术法
  - 术法库不区分门派来源，玩家可混搭装备
  - 但部分术法有门派前置要求（见术法设计规范），
    未满足则无法学习，与槽位无关

三、二周目/传承
  - 重生后的术法库与槽位重算规则待传承系统和新槽位预算共同锁定
  - 传承角色可保留部分术法（具体规则见传承系统，TBD）
