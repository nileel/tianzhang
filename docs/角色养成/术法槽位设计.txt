【术法槽位系统设计】

⚠️ 已修改/未审核（2026-06-21：金丹槽位迁移为源/化/界席位、占据状态与丹相接口）

═══════════════════════════════════════════════════════════════

第一章：设计目的
═══════════════════════════════════════════════════════════════

现存术法无装备数量上限，导致 Build 选择无意义——玩家
可以携带全部可学术法进入战斗，消解了战术准备的策略深度。

术法槽位系统为修士设定术法与神通的携带上限，
强制玩家在有限槽位中做出取舍，构建差异化 Build。

v3.5 重构：槽位不再随境界线性增长到高阶，改为受紫府府位开发
与金丹目标席位、占据状态和丹相接口影响，将槽位成长融入筑基深度经营与金丹 Build。

设计说明：
- 筑基 5/2 为紫府开启前的基准槽位。
- 紫府府位开发提供额外槽位，反映修士的深度经营成果。
- 金丹目标席位、占据状态和丹相接口在结丹后决定是否产生槽位修正；具体修正由 TQ-015C/TQ-013C 锁定。
- 高阶境界（元婴/化神）在当前版本为 NPC/世界背景，不再提供玩家槽位增长。
- 旧线性槽位表已废止。

│ 识府     │ —        │ +1       │ 神识扩张，神通槽+1            │
│ 气府     │ +1       │ —        │ 灵力循环增强，术法槽+1        │

└──────────┴──────────┴──────────┴──────────────────────────────┘

规则：
  - 紫府初开后，每主修一府获得对应加成。主修府位由功法和 Build 决定。
  - 术法槽加成上限 +3（即最多三个府位提供术法槽），神通槽加成上限 +2。
  - 同府多段开发可提升槽位质量（减少特定术法的冷却/消耗），但槽位数量仅加一次。
  - 紫府成长来自事件、试炼、地脉、灵眼等目标，非经验条。


────────────────────────────────────
二.2 金丹席位与丹相槽位接口
────────────────────────────────────

金丹不再使用通用层级槽位表。槽位修正必须由以下输入共同决定：

1. 目标源/化/界席位在矩阵中允许的丹枢接口。
2. 占据状态带来的稳定度、使用边界和代价。
3. 丹相主枢与辅枢的已实现表现。
4. 已开发紫府府位的既有槽位加成。

规则：
  - 不同席位不得仅因名称获得固定高低槽位；所有修正必须能回指矩阵边界与代价。
  - 暂寄状态不生成丹相主枢，只保留不完整丹相与辅枢残影；是否获得辅枢相关槽位修正由具体实现声明。
  - 自辟不是通用加成标签，必须先形成可验证的完整源化界结构。
  - 具体槽位数、替换规则与数值上限由 TQ-015C/TQ-013C 以 BattleSim 和 Unity 实现共同锁定。

═══════════════════════════════════════════════════════════════
第三章：非战斗替换规则
═══════════════════════════════════════════════════════════════

一、安全区域（道观/洞府/城镇/营地）
  - 可随时自由替换术法和神通，无任何代价
  - 替换即时生效

二、野外/副本（非战斗状态）
  - 可自由替换，但需消耗时间（每次替换 = 1 刻游戏时间）
  - 替换期间有概率遭遇随机事件（敌人巡逻/天象变化）
  - 概率 = 5% × 替换次数（第 3 次起 15%，鼓励一次性配好）

三、战斗前准备阶段
  - 看到敌方阵容后、开战前，有一次免费调整槽位的机会
  - 调整次数不限，但仅限战斗触发前的准备窗口
  - 开战后槽位锁定


═══════════════════════════════════════════════════════════════
第四章：战斗中切换规则
═══════════════════════════════════════════════════════════════

一、基本原则
  - 战斗中不可自由切换术法，槽位在开战时锁定
  - 但提供"临阵换法"特殊行动作为紧急出口

二、临阵换法（战斗中特殊行动）
  消耗：1 次完整行动权（不可移动、不可同时攻击）
  效果：将一个已装备术法替换为术法库中另一个术法
  代价：
    - 新术法获得双倍冷却惩罚（CD × 2）
    - 被替换的术法本场战斗不可再装备
    - 每次战斗最多执行 2 次临阵换法
    - 神通不可临阵更换（神通为"根本大法"，战斗中不可变更）

三、解除锁定
  - 战斗结束后所有槽位自动解锁
  - 被"本场不可再装备"标记的术法在战后恢复可用


═══════════════════════════════════════════════════════════════
第五章：槽位与神通的关系
═══════════════════════════════════════════════════════════════

一、神通槽独立
  - 神通槽和术法槽完全独立，不共享数量
  - 神通不可放入术法槽，术法不可放入神通槽

二、丹相主枢规则（v3.5 重构）
  - 金丹期由兼容紫府神通形成丹相主枢或辅枢，不再从术法直接跳变为独立系统。
  - 暂寄状态不生成丹相主枢，只保留不完整丹相与辅枢残影。
  - 丹相主枢是否占据神通槽，必须由其具体实现声明；当前不预设全局数量或槽位表。
  - 丹相主枢的资源消耗、冷却和成长性由 TQ-015C/TQ-013C 锁定。
  - 丹相主枢绑定角色与目标席位，不可在战斗中替换。

三、太一道庭法箓例外
  - 本命符箓和本命法坛是太一道庭丹相的门派表达；是否占据神通槽由具体实现声明，不新增独立法箓槽
  - 本命符箓不占术法槽；来源术法仍保留在术法库中
  - 本命法坛的召唤、阵地或法司效果由具体丹相、神通/功法声明，且不得越过目标席位边界


═══════════════════════════════════════════════════════════════
第六章：Unity 实现接口
═══════════════════════════════════════════════════════════════

一、数据层
  - CharacterData 已有 equippedSpells / equippedSkills 数组
  - 新增字段：
    * maxSpellSlots: int（由境界、紫府府位与已实现丹相接口决定，战斗中不变）
    * maxSkillSlots: int
    * availableSpells: string[]（术法库，玩家已学会的全部术法）
    * developedMansions: string[]（已主修府位列表）
    * targetPosition: string（目标源/化/界席位 ID）
    * positionOccupationState: string（夺取/继承/敕封/暂寄/自辟）
    * danXiangId: string（丹相 ID）
    * danPivotRole: string（none/main/auxiliary）
    * mansionBindings: string[]（紫府神通绑定府位）
    * danArtifactForm: string（可选丹器显化形态）
    * legacyDanJiType: string（旧 danJiType 兼容读取字段；TQ-015C 完成迁移后删除）

二、运行时
  - Character 类新增：
    * SpellSlots: List<SpellSlot>（含当前装备术法引用 + CD 状态）
    * SwapSpellInCombat(int slotIndex, string newSpellId): bool
    * GetAvailableSpells(): List<string>
    * RecalculateSlots()（根据当前府位、目标席位、占据状态和已实现丹相接口重算槽位数）

三、UI 层
  - 战斗 UI 术法按钮区域按 maxSpellSlots 动态生成
  - 空槽位显示为灰色"+"图标（仅在非战斗时可用）
  - 临阵换法按钮（战斗中，位于术法栏旁）→ 点击打开术法库弹窗
  - 灰化规则：MP 不足/冷却中/已消耗次数的术法按钮灰化


═══════════════════════════════════════════════════════════════
第七章：与现有体系兼容性
═══════════════════════════════════════════════════════════════

一、现有数据兼容
  - 太一修士当前装备 3 术法 + 2 神通，练气 4/1 槽位可容纳
  - 散修强盗当前装备 2 术法 + 0 神通，练气 4/1 槽位有余量
  - 血影魔修（筑基）装备 1 术法，筑基 5/2 槽位有余量
  → 现有数据全部兼容，无需修改

二、BattleSim 兼容
  - 模拟器 BuildDef 中 spells/skills 数组即为"已装备"
  - 当前 Build 术法数为 3-6 个，均在槽位范围内
  - 模拟器暂不实现槽位硬限制（不影响矩阵验证）
  - Unity 端实现槽位限制后，模拟器输出可保持现状

三、CSV 导入兼容
  - Enemies.csv 的 equippedSpells 列保持不变
  - Characters.csv 同
  - 若装备术法数 > 该阶段槽位数 → 导入时警告并截断


═══════════════════════════════════════════════════════════════
第八章：边界情况
═══════════════════════════════════════════════════════════════

一、槽位不足
  - 府位未开发时槽位停留在筑基基准值
  - 学会新术法但槽位已满 → 提示替换或放弃学习
  - 暂寄修士没有丹相主枢，需围绕紫府府位与辅枢残影进行更精细的 Build 规划

二、多门派术法
  - 术法库不区分门派来源，玩家可混搭装备
  - 但部分术法有门派前置要求（见术法设计规范），
    未满足则无法学习，与槽位无关

三、二周目/传承
  - 重生后术法库清空，槽位按当前境界+府位重新计算
  - 传承角色可保留部分术法（具体规则见传承系统，TBD）
