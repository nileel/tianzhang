# 金丹位格索引

内容状态：已审核；2026-10-02 按用户确认同步名称与位格附性。通用声明与道路履历见同目录 `金丹位格共用说明.txt`。

> 本文是金丹具体位置正式登记与数量汇总的唯一索引事实源。结构与数量规则以 `docs/基础设定/元婴锚点与金丹位格设定.txt` 为准；单文档生产以同目录 `金丹位格设计规范.txt` 为准；道路与基础效果以 `docs/基础设定/元婴锚点与金丹位格矩阵.txt` 为准；证位档案以 `docs/基础设定/金丹位格证位与争位规则.txt` 及独立位置文档为准。索引只提供登记、计数与定位，不能替代具体位置文档。

## 一、登记对象与边界

1. 索引登记的是世界中可被证取和唯一占据的具体位置，不登记位格类型、基础效果或组合产物为独立位置。
2. 源位、化位、界位是三种位格类型。每条道路必须且只能有一个源位，可以有多个理念不同的化位和界位；每个具体位置同一时间只能由一人稳定占据。
3. 当前十七条道路各有一个初始源位、一个初始化位和一个初始界位，共五十一个具体位置。当前另有五十一个基础效果及一百五十三个位别版本；三组数量不得互相替代。
4. 未逐项生产并登记的初始位置不得编造名称、理念、`positionId`、证位档案标识或占位文档；已按批次完成独立文档的位置按第三节登记为待审核条目。
5. 没有完成独立文档的位置只能保留在“结构数量”中；已生产独立文档但未审核的位置登记为「待审核」条目，不能伪装成已经审核的具体内容。

## 二、正式登记字段

每个具体位置完成逐项生产后，必须登记以下字段：

| 字段 | 必填内容 | 唯一职责 |
|---|---|---|
| `positionId` | 稳定且全局唯一的具体位置标识 | 供文档、证位、占据、存档与引用定位 |
| 具体位置名称 / `seatNameKey` | 经审核的正式名称与显示键 | 表达被证取和争夺的真实席位，不随装配变化 |
| `road_id` | 十七道路之一 | 指向所属道路、变量边界与基础效果库 |
| `positionType` / `positionNameKey` | `SOURCE`、`TRANSFORM` 或 `DOMAIN` 及类型显示键 | 只表达源位、化位或界位 |
| 理念与附性摘要 | 位别分工与已确认附性的一句摘要 | 用于比较与定位，完整触发和边界仍读独立文档 |
| 效果白名单摘要 | 允许的 `effect_id` 集合 | 指向独立文档中的逐项适配理由 |
| 证位档案标识与版本 | 该位置独立档案的稳定引用 | 指向道路共享履历、位格类型通用要求与位置专属成就 |
| 位置档案版本 | 当前有效文档版本 | 支持证位、存档、兼容与实例重验 |
| 内容状态 | 草拟、待审核、已审核、迁移中或退役 | 表达内容生命周期，不表达世界占据状态 |
| 正式文档路径 | 一份独立位置文档 | 唯一内容入口 |

运行时占据者、候选进度、临时权限和空缺情报属于世界存档，不写成索引静态内容。索引可以说明位置的设定初始状态，但不得拿索引替代占据事务。

## 三、登记与变更规则

1. 新位置先按 `金丹位格设计规范.txt` 完成独立文档和检查清单，再新增索引条目；不得先造空条目、占位名称或空文档锁号。
2. 新增源位前必须核验所属道路没有既有源位；由于当前十七道路均已有一个源位，现行规则下不得再新增源位。
3. 新增化位或界位必须证明与同道路既有同类位置理念不同，声明效果白名单，并建立独立证位档案；不得复制既有位置改名。
4. 初始五十一个位置的白名单当前均为所属道路现有三项效果。以后新增位置可以只开放其中一部分；白名单变化必须同时更新独立文档、索引摘要、位置版本与兼容档案。
5. `positionId` 一经正式引用不得因改名而变化。确需迁移时，条目必须记录旧标识、迁移版本、存档与引用处理；不得静默复用旧 ID 表示另一个位置。 显示名称以本索引对应的 `positionId` 为准；既有审核与迁移记录保留当时用名，后续复用同名不恢复旧机制，也不改变原兼容性结论。
6. 位置退役不删除历史引用。索引保留退役状态、最后版本、替代关系或关闭原因；退役不得制造第二源位或让旧占据继续生效。
7. 索引条目、独立文档和审核结论必须同轮保持一致。任何一项未完成时不得标记为“已审核”。
