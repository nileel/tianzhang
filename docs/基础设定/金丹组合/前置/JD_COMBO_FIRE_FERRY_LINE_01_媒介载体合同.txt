# JD_COMBO_FIRE_FERRY_LINE_01 · 渡火引线媒介与载体输入合同

> 状态：设计前置已冻结。本文只证明赫曦炉心显化的燃烧地格能够作为燃犀渡预装火种档案的合法战场火源；它不是正式 `comboProfileId`、`compatibilityProfileId`、火种数据、数值配置或运行时实现。正式组合仍只能由 `C-JD-COMBO-01` 在全部前置完成后独立生产。
>
> 判定：在本文逐字段限定下，源位 `FIRE_MANIFEST` 的燃烧地格与化位 `FIRE_ESCALATE` 的预装“走火”存在唯一、非越界的**合法设计输入交集**。该判定不表示当前仓库已有火种／费用／容量／结果原型数据，也不表示战棋运行时已支持组合。

## 一、身份、范围与唯一输入

| 字段 | 冻结值 | 依据与边界 |
|---|---|---|
| 候选工作名 | 渡火引线 | 仅继承 `docs/superpowers/specs/2026-09-20-jindan-combo-scope-design.md#二` 的审批定位，不登记正式组合。 |
| 源位 | `JD_FiveElements_Fire_SOURCE`／`ROAD_FIRE`／`SOURCE`／赫曦炉心／位置档案 `1.1` | 索引 §六与赫曦炉心 §六；只装配 `FIRE_MANIFEST` 源版。 |
| 化位 | `JD_FiveElements_Fire_TRANSFORM01`／`ROAD_FIRE`／`TRANSFORM`／燃犀渡／位置档案 `1.1` | 索引 §六与燃犀渡 §六；只装配 `FIRE_ESCALATE` 化版。 |
| 源对象 | 一处由赫曦炉心手动显化、已支付且仍存在的燃烧地格 `sourceRef` | `FIRE_MANIFEST` 源版允许燃烧地格；它是真实火焰／热压的一种受控形态，而非叙事“火势”。 |
| 化位接受对象 | 同一 `sourceRef`，且其地格位于已启用的燃犀渡渡域、满足预装档案 `validCarriers` | 化位只筛选源对象，不补造火源、不改写源位操作。 |
| 固定操作 | `走火`，一次沿预装的相邻、连续、可燃渡口地格路线逐节点传播 | 不得改选聚焰、自由点选远格或逐对象改用其他火种。 |
| 既有结果载体 | `地表状态` | 五行显化 §二列为既有运行载体；持续地表占显化容量且战斗结束清除。 |
| 候选结果原型 | `JD_FIRE_FERRY_BURNING_LINE_01` | 仅为未来档案的 `resultPrototypeId` 输入；未登记，不新建单位、CT、山河状态、战利品或第二载体。 |

本文只覆盖“先有源位燃烧地格，再由化位预装走火使用它”的局部战棋顺序。普通通用火种、自身其他特殊火种、主场景火渠、区域工程和第三位置均不在输入集合内。

## 二、两份位置兼容合同

下表以 `金丹基础效果装配与冲突规则.txt#三.2` 的字段为准。`costSchemaId` 与 `capacitySchemaId` 仅冻结共同记账的接口责任；其真实配置 ID、数值和 BattleSim 结论由 `N-JD-COMBO-FIRE-BUDGET-01` 另行提供，本文不得填零值或伪造档案。

| 字段 | 源位合同：赫曦炉心显化燃烧地格 | 化位合同：燃犀渡预装走火 |
|---|---|---|
| `contractId` | `PC_JD_FIRE_SOURCE_MANIFEST_01` | `PC_JD_FIRE_TRANSFORM01_ESCALATE_01` |
| `contractVersion` | `1.0` | `1.0` |
| `positionId`／`positionProfileVersion` | `JD_FiveElements_Fire_SOURCE`／`1.1` | `JD_FiveElements_Fire_TRANSFORM01`／`1.1` |
| `roadId`／`positionType`／`effectId` | `ROAD_FIRE`／`SOURCE`／`FIRE_MANIFEST` | `ROAD_FIRE`／`TRANSFORM`／`FIRE_ESCALATE` |
| `objectSchema` | 普通距离内、目标层级与地表载体空位均合法的一处地格。 | 位于渡域的同一 `sourceRef`，以及从该起点开始、相邻且连续的可燃渡口地格链。 |
| `operationSchema` | 手动选择“燃烧地格”一种火象，形成真实火焰／热压并结算燃料、热量和延烧对象。 | 只按预装档案执行一次“走火”；每进入一节点消耗公开火势预算。 |
| `mediumSchema` | 炉心直连、合法灵力、实际燃料、热量与延烧对象。 | 已启用燃犀渡阵眼、渡口地形、预装火种档案与其声明的地表载体；不借无来源媒介。 |
| `filterSchema` | 受控火象选择；不适用化位式固定筛选。 | `sourceRef` 必须满足 `FIRE_SEED_JD_FIRE_FERRY_MANIFEST_TERRAIN_01`，起点在渡域内，路线逐格满足相邻、连续、可燃与载体空位。 |
| `scopeSchema` | 普通距离内的一处地格；不扩大为广域。 | 预装的单条渡口路线；路线之外、断链之后和渡域外均不在范围。 |
| `resultCarrierSchema` | 既有 `地表状态`，以 `sourceRef` 连接显化容量来源。 | 同一既有 `地表状态` 分类，候选 `resultPrototypeId=JD_FIRE_FERRY_BURNING_LINE_01`；不新增结果类型。 |
| `costSchemaId` | `PENDING:N-JD-COMBO-FIRE-BUDGET-01:manifest-source`；账本类别为行动、灵力、实际燃料、热量与显化。 | `PENDING:N-JD-COMBO-FIRE-BUDGET-01:ferry-escalate`；账本类别为行动、展开、逐节点火势预算与必要维持。 |
| `capacitySchemaId` | `PENDING:N-JD-COMBO-FIRE-BUDGET-01:manifest-surface`；持续地表显化容量。 | `PENDING:N-JD-COMBO-FIRE-BUDGET-01:ferry-surface-environment`；同一结果的地表／环境容量，不另造第二份容量。 |
| `forbiddenContractIds` | 未登记横向组合、递归以组合结果作未付费输入、免费供能或多火种混合均拒绝。 | 通用火种兜底、临场改聚焰、跨断链跳格、逐对象换火种、无阵眼传播与重复计费均拒绝。 |

`PENDING:` 是本前置到数值前置的字面量闸门，不能被当作可解析配置 ID、默认值或兼容 fallback。它只证明两侧成本与容量的账本位置唯一且可共同记账；真正 ID 未交付前，不能创建正式配方、运行实例或 `compatibilityProfileId`。

## 三、预装火种档案与合法战场火源映射

燃犀渡化版必须预装一个档案、一个起点条件和一种操作，且没有通用火种兜底。为避免把“有火”误作合法输入，预装档案固定为以下**未来登记引用**；它只映射战场火源，不宣称赫曦炉心额外提供特殊火种。

| 火种档案字段 | 冻结输入 | 说明 |
|---|---|---|
| `fireSeedProfileId` | `FIRE_SEED_JD_FIRE_FERRY_MANIFEST_TERRAIN_01` | 仅在未来档案实际登记后可解析；当前不是仓库数据。 |
| 具体显示属性 | 赫曦炉心 `FIRE_MANIFEST` 源版留下的可见燃烧地格。 | 显示的是已存在的真实战场火源，不是凭名称推定的新火种。 |
| `baseBudgetRef` | 指向该 `sourceRef` 的已支付显化／火势账本，不填数值。 | 化位借用战场火源时只能消耗其持续、充能或公开火势预算。 |
| `signatureEffectId` | `FIRE_MANIFEST` | 只保留源位产生燃烧地格这一项签名来源；不复制完整源位动作、额外目标、触发链或资源循环。 |
| `validCarriers` | 既有 `地表状态`，且该状态的 `sourceRef` 是本合同定义的源位 `FIRE_MANIFEST` 燃烧地格。 | 载体类别已经存在；候选结果原型未登记前不产生任何组合实例。 |
| `invokeCostRef` | 受控空值：本路线不直接调用自身特殊火种。 | 起点只借已显化的战场火源；因此不得免除源位显化费用，也不得把空值解释为免费调用。 |
| `spreadRule` | 单一预装“走火”路线：从起点开始逐格核验相邻、连续、可燃和预算。 | 每次只执行一次固定操作；水、隔绝、拆除燃料、扑灭或路线断裂立即阻止后续节点。 |
| 起点条件 | `sourceRef` 存在、仍燃烧、位于燃犀渡渡域、阵眼有效、与首个路线节点相邻且地表载体未失效。 | 任一条件不满足即不触发；不得退回通用火种。 |

因此，源位燃烧地格落入规则已明确允许的“棋盘既有火焰、燃烧地表、蓄热或持续火行效果”中的燃烧地表入口；化位的预装档案再将它唯一收窄为渡域内的该类地表状态。此映射没有新增道路、效果、位置、媒介类别或源位操作。

## 四、行动、路线、结果与账本顺序

1. 赫曦炉心先以自身正常行动手动选择合法地格与“燃烧地格”形态。预览并一次性核对源位行动、灵力、实际燃料、热量、延烧对象、地表载体空位和显化容量；通过后建立 `sourceRef`。
2. 只有 `sourceRef` 仍合法时，燃犀渡才可开始自身的正常行动预览。阵眼、预装档案、起点条件与固定路线必须先同时通过；化位不从源位取得第二次行动。
3. 预装路线由同一份档案给出唯一的渡口地格序列：首格与 `sourceRef` 相邻，后续每格与前格相邻、连续、可燃且位于渡域。每进入一格先扣该格公开火势预算，再生成或延续同一地表状态链；不能跳过、重排或临场增选节点。
4. 化位建立前再原子预览并支付其行动、展开、逐节点与必要维持责任。任一费用、容量、燃料、阵眼或路线检查失败时，化位不建立半状态；已独立建立的 `sourceRef` 按自己的原账本继续或熄灭，不被伪装为组合结果。
5. 未来正式产物只能以一个可见、可切断的地表状态链承载 `resultPrototypeId=JD_FIRE_FERRY_BURNING_LINE_01`。它占用两个位置的持续承载和已声明的地表／环境容量；不额外增加效果槽、火种、行动、单位或跨战斗产物。

### 不可双算账本

| 账本项 | 唯一支付／消耗位置 | 禁止解释 |
|---|---|---|
| 源位显化 | 源位建立 `sourceRef` 时：行动、灵力、实际燃料、热量、延烧对象与显化容量。 | 不因后续走火再收一次同一笔显化费用，也不因已付款让走火免费。 |
| 借用火源 | 化位读取并消耗 `sourceRef` 的持续、充能或公开火势预算，并记下 `sourceRef` 与消耗量。 | 不复制火源、倒回已消耗预算或把来源能力完整动作带入化位。 |
| 化位走火 | 化位自身行动、展开、逐节点火势预算和必要维持。 | 不借“组合”名称免除行动、节点、燃料或容量。 |
| 容量与结果 | 一个地表状态链的显化／环境占用，以 `sourceRef` 和未来结果原型引用同一条账本。 | 不对同一地表链重复占用两份容量，也不将容量空位当作生成第二条链。 |

## 五、退出、解除与失败关闭

- 未来正式档案只能采用 `breakPolicy=END`，`fallbackProfileId` 为受控空值。任一参与位置切换／退出、阵眼失效、起点熄灭、路线断裂、燃料或容量失效、行动或费用不足、预装档案缺失，均结束未来作用或在支付前拒绝建立。
- 水、隔绝、拆除燃料、扑灭和拆毁阵眼是可见反制；它们不生成半路线、不改用聚焰，也不从通用火种补救。
- 已合法完成的源位显化、已消耗的火势节点与已支付费用均按原账本保留，不返还、不倒流；结束只停止未来作用。战斗结束清除全部战斗显化地表，不进入战后存档、战利品、制作、拾取或山河状态。
- 下列反例一律失败关闭：没有 `sourceRef` 却以通用火种代替；`sourceRef` 不在渡域或不匹配 `validCarriers`；路线不相邻／不连续／不可燃；阵眼被拆；未交付火种、费用、容量或结果原型档案；试图把已生成路线重新作为未付费起点。

## 六、按静态编译顺序的结论

| 编译步骤 | 核验结果 | 精确原因 |
|---|---|---|
| 位置白名单 | 通过 | 两位置的 §六均允许对应效果与位别版本。 |
| 位置理念与效果权限交集 | 通过 | 源位只手动显化燃烧地格；化位只固定筛选该地格并走火，没有互换位别职责。 |
| 对象交集 | 通过 | 源输出是规则明确允许的燃烧地表；化位 `validCarriers` 唯一收窄为该既有地表状态。 |
| 化位输出与界位承载 | 不适用 | 本输入只含源位和化位，没有界位；化位仍使用源位已允许的地表状态，不扩张载体。 |
| 保持源操作和结果边界 | 通过 | 走火是 `FIRE_ESCALATE` 自身允许的固定操作；不改写源位显化，也不造新结果类型。 |
| 成本与容量共同记账 | 通过（结构） | 支付顺序、唯一账本与一条地表状态链已冻结；真实配置 ID 和数值留给 `N-JD-COMBO-FIRE-BUDGET-01`。 |
| 自供能、循环、重复计费与禁止项 | 通过 | 必须先有已支付 `sourceRef`；逐节点消耗、无通用兜底、无递归输入、无免费行动或供能。 |

结论为**合法（LEGAL）设计输入**，而非当前运行时的已登记组合。没有对象空交集、多个可选操作或必须用新权限消歧的情形，因此不是 `INCOMPATIBLE` 或 `AMBIGUOUS`；火种、费用、容量与结果原型尚未登记属于后续前置的交付闸门，不能被提前解释为已实施。
