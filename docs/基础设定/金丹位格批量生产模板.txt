# 金丹位格批量生产模板

✅ 已审核（2026-07-18 Codex；同步十七道路、三真实位格、五十一个效果与三字段口径）

> 本文约束后续角色、丹枢、功法、术法、神通、洞府与事件生产。结构与生命周期以 `元婴锚点与金丹位格设定.txt` 为准；道路与效果以 `元婴锚点与金丹位格矩阵.txt` 为准；装配、兼容与冲突以 `金丹基础效果装配与冲突规则.txt` 为准。

## 一、通用硬约束

### 1.1 三字段与稳定 ID

每份涉及金丹位格的内容必须分别填写：

| 字段 | 唯一职责 | 合法来源 |
|---|---|---|
| 金丹名称 | 表示所属世界规则 | `road_id` 对应的 `jindanNameKey` |
| 位格名称 | 表示源位、化位或界位 | 位格类型对应的 `positionNameKey` |
| 效果名称 | 表示当前装配的基础效果 | `effect_id` 对应的 `effectNameKey` |

1. 三字段不得互相吸收，不保存强制拼接标题；位格名称不得使用效果名，效果名称不得加入道路名或源／化／界后缀。
2. 五十一个正式效果名称由 `DS-JINDAN-NAMES-20260718-01` 起草，须经 Codex 审查和用户确认。完成前只引用矩阵的 `effect_id` 与功能性临时代号，批量生产不得自行发明正式名称。
3. 每份内容必须回指稳定 `road_id`、`positionType`、`effect_id` 和矩阵节号，不能从显示文本反推规则对象。

### 1.2 结构硬约束

1. 现行只有十七道路和源位、化位、界位三种真实位格；未经用户批准不得创建第十八道路或第四位格。
2. 金丹初期、中期、圆满共享 `JINDAN` 规则位阶，依次具有一、二、三个真实位格，取得位格类型的顺序自由；阶段不提供自动压制。
3. 每个真实位格同一时间只装配本道路三项候选中的一项效果。取得位格不表示三项同时生效。
4. 同一 `effect_id` 可跨位格纵向嵌套；不同 `effect_id` 默认独立，只有命中已登记 `comboProfileId` 才能组合。不得按名称、母属性或自由标签临场合成。
5. 每个 `STABLE` 位格必须由一个互不重复的 `primaryCarrierAbilityInstanceId` 主承载；同一紫府神通可辅助其他位格，但效果、支点、资源、充能和冷却只按唯一实例账本计算一次。
6. 成丹时必须建立唯一、不可变的 `JindanCoreBinding`。丹枢核心不可更换、移植、顶替、复制或通过洞府重铸重选；安全洞府只可原子重铸主承载或府位绑定。
7. 稳定金丹任一真实位格丧失或丹枢核心永久毁坏，必须原子触发丹毁死亡；不存在回退阶段、缺位存活或事后补绑。
8. 宗门只能掌握传承、资源、解释、占据方式或局部地域，不能垄断整条道路。夺取、继承、敕封、暂寄、自辟是占据方式或状态，不是新位格。

### 1.3 禁止事项

- 不得改写道路变量、效果权限、源／化／界版本、不可越界项或现实支点。
- 不得让丹枢、组合、辅助神通或表现档案创造额外效果槽、额外位格或新道路权限。
- 不得把兼容编译通过、异效组合成功或普通战斗胜利直接写成自辟元婴成立。
- 不得在未运行 BattleSim 时自定倍率、阈值、目标数、概率、CT、资源费或本命神通数量。
- 不得把元婴写成常规模板、低配版本或可批量复制的位格。
- 不得使用炼虚作为现行可用境界。
- 不得把太一道庭写成全部敕封或位格的垄断者，不得把司马承景写成常规可击杀单位。

### 1.5 提交前自检

- [ ] `road_id` 是否属于十七道路，`effect_id` 是否属于该道路三个候选？
- [ ] 是否将金丹、位格、效果三个字段分开？
- [ ] 每个真实位格是否只装配一项效果？
- [ ] 不同效果组合是否引用明确 `comboProfileId`，而非自由标签？
- [ ] 每个稳定位格是否使用互不重复的主承载实例？
- [ ] 辅助神通是否只贡献一次并共享唯一账本？
- [ ] 是否保持原 `JindanCoreBinding` 不可换绑？
- [ ] 是否明确真实位格／核心丧失触发丹毁死亡？
- [ ] 是否突破对象、操作、媒介、结果或不可越界项？
- [ ] 是否误将兼容、组合或普通胜利写成自辟元婴？
- [ ] 数值是否标为待 BattleSim 验证并进入配置？
- [ ] 正式效果名称是否仍留给既定命名任务？

## 三、丹枢模板

丹枢是不可变核心绑定下的个人表达接口。它只能在道路与效果已经提供权限时调整媒介、偏向对象、代价分配、丹域景象、战斗表现与宗门叙事，不能修改道路变量、对象、操作、结果或不可越界项。

```text
丹枢名称：临时代号
金丹名称字段：
road_id：
boundDanshuCoreId：
JindanCoreBinding：不可换绑声明
媒介：
偏向对象：
代价分配：
丹域景象：
战斗表现：
宗门叙事：
不可越界：
提供的 fireSeedProfileId 或其他接口：没有合法来源则填无
```

丹枢不得直接充当紫府神通主承载，不得凭空提供特殊火种，也不得为位格增加装配槽。

## 四、功法／术法／神通模板

新增或修改内容必须先读取对应设计规范，并在原模板外补充：

| 字段 | 说明 |
|---|---|
| `road_id` | 适配道路 |
| `positionType` | 源位、化位或界位 |
| `effect_id` | 当前适配效果 |
| 矩阵回指 | 具体章节和效果行 |
| 主承载资格 | 是否可作为某位格独立主承载及兼容理由 |
| 辅助接口 | 显式开放的媒介、触发、代价改道或组合接口 |
| 丹枢接口 | 六种允许个性化维度 |
| 不可越界 | 对象、操作、媒介、结果和道路边界 |

功法必读 `docs/角色养成/功法设计规范.txt` 与 `docs/角色养成/功法/功法设计.txt`；术法必读 `docs/角色养成/术法设计规范.txt` 与 `docs/角色养成/术法/术法设计.txt`；神通必读 `docs/角色养成/神通设计规范.txt` 与 `docs/角色养成/神通/神通设计.txt`。

## 七、自辟元婴模板边界

自辟方向必须引用 `自辟元婴方向设定.txt`，并额外证明新高位变量不被十七道路完整解释、能长期存在且可承接。普通 `compatibilityProfileId`、`comboProfileId`、金丹争位或同阶 QTE 都不能替代该证明。成功晋升只在新 `YuanyingRoadAnchor` 原子建立后退出输入三位；新元婴不得处分旧道路位格。

2. 五十一个正式效果名称只由 `DS-JINDAN-NAMES-20260718-01` 处理；该任务不得修改效果功能、位格版本、装配、兼容、冲突或矩阵结构。
