═══════════════════════════════════════
一、职责与规则层
═══════════════════════════════════════

《册界天章》调用已登记的治理条目，调整地区长期环境基础态。它不是金丹位格、元婴道路、自由脚本、任意变量编辑器或第二套冲突引擎。

规则层的观察顺序是：

自然基础态 → 天章登记基础态 → 金丹战斗／山河介入态 → 元婴道路锚点

这条顺序只表示“长期底色与主动介入如何叠放”，不是把四层写成固定数值优先级：

1. 自然基础态记录没有持续人工规则时的地理、气候、灵气与资源条件。
2. 天章登记基础态在完整条目、授权、节点、现实供给和世界代价成立后，成为地区新的长期基础态。
3. 金丹战斗或山河规则是有来源、有支点、有承载的介入态。它停止后，天章基础态重新显现；已经结束的介入不得被天章倒写成自然法则。
4. 元婴道路锚点锁定同一变量时，天章标记为“受锚”。单件天章不能直接覆盖锚点。

═══════════════════════════════════════
二、完整规则条目
═══════════════════════════════════════

每条可调用规则必须以一个完整条目记录以下字段：

```text
ruleEntryId
displayName
ruleFamily
relationElement
compatiblePhenomena
positiveCommit
negativeCommit
requiredAuthority
requiredNodeTypes
scopeType
scopeTierCap
anchorNodeIds
propagationBoundaryProfileId
currentCoverageSet
affectedWorldVariables
conflictProfileId
failurePolicy
worldEventOutputs
```

字段边界：

- `ruleEntryId`：稳定且唯一；同一条目版本升级不创建可并行刷取的复制品。
- `ruleFamily`：受控类别，首批只允许灵机聚散、劫威缓厉、五行地纪及后续明确批准的同层类别。
- `relationElement`：五行母属性；风、毒归木，雷归金，冰归水，暗归土，星归火。派生属性保留显示身份，不增加第二个母属性。
- `compatiblePhenomena`：世界中必须已经存在、或能由列明现实支点合法支持的现象。空列表不能解释为“任意现象”。
- `positiveCommit` 与 `negativeCommit`：同一次调用原子提交的收益和世界代价。任何一方不能单独启用、拆出、交易或丢弃。
- `requiredAuthority`：版本化权限表达，可要求太玄界印、一个或多个合法组织授权，或明确的组合关系；不能由“身处此地”“关系友好”或战力代替。
- `requiredNodeTypes`、`anchorNodeIds`：节点种类与实际锚点。缺失、损坏、断开或未接入的节点不提供范围。
- `scopeType`、`scopeTierCap`：范围类型与条目允许的最大规模，不是玩家可拖动的半径。
- `propagationBoundaryProfileId`：灵脉、水系、地火、气候／地理单元或登记渡劫场等真实传播边界。
- `currentCoverageSet`：本次预览与提交时的准确稳定区域／节点集合；必须可列举、可复核，不能写“全地图”。
- `affectedWorldVariables`：条目唯一允许提交的世界变量集合。未列变量失败关闭。
- `conflictProfileId`：命中同变量介入时使用的既有冲突、挑战资格和受锚处理档案。
- `failurePolicy`：只能选择拒绝提交、暂停或已登记安全降级；降级必须缩小范围或效果，并仍提交匹配的负面结果。
- `worldEventOutputs`：带来源的地区事件信号，不得递归把信号当作新规则调用。

玩家合法取得一条规则后，条目永久登记在《册界天章》中。调用时只能选择完整条目；条目不是消耗性“规则碎片”，其正负提交也不是可拆装词条。

═══════════════════════════════════════
三、规则类别
═══════════════════════════════════════

### 1. 灵机聚散

只调整灵气总量、纯度和流通，不调整金、木、水、火、土比例，也不借派生属性改写五行比例。聚集必须说明从何处汇入，疏散必须说明流向何处；它不能凭空创造灵气。

### 2. 劫威缓厉

只作用于已登记渡劫地及其设施化缓冲范围。普通雷电、雷暴、雷法和雷属性战场现象不等于天劫。条目可以调节已发生渡劫过程对场地的外溢方式，但不能降低证位、境界、个人准备或天劫本身的成立条件。

### 3. 五行地纪

每条五行地纪必须以一个不可拆分的原子生态包，同时提交：天气、地形演化、灵气结构和资源产出。四项内容可以各有受控参数，但不能变成四个自由滑杆，也不能只启用其中有利项。

五行地纪使用 `relationElement` 参加五行母属性关系；风、毒、雷、冰、暗、星等派生身份仍按既有母属性读取。战场如何表现地表、区域现象与五行交互，继续由两份战场环境事实源决定；地区长期状态只输出明确档案引用，不复制战场结算规则。

═══════════════════════════════════════
四、范围、节点与传播
═══════════════════════════════════════

每次调用必须公开范围类型、规模上限、现实锚点、传播边界和当前准确覆盖：

1. 单一节点：一座洞府、宝库、渡劫台、旧公共设施或一个据点。覆盖不得越出目标节点的登记边界。
2. 连通节点：同一灵脉、水系、气候单元或地质结构中已经接通的片区。断裂、封堵或未授权接入会从 `currentCoverageSet` 中移除对应部分。
3. 地区总枢：只有完整节点网络、地区总枢设施和所需行政授权同时成立时，才能覆盖一域；“持有天章”不构成整域前置。

传播边界按条目读取：

- 灵机沿灵脉及明确的导流设施传播。
- 水府类沿同一流域和已接通水工节点传播。
- 火脉类沿连通地火与导热地质结构传播。
- 天气生态类沿登记气候／地理单元传播。
- 劫威只覆盖登记渡劫场及其明确缓冲构件。

宗门、城镇或行政边界不能只凭文字改变自然传播范围，但可以拒绝组织授权、节点接入、岗位、维护或现实供给。自然可达与政治合法必须分别通过。

═══════════════════════════════════════
五、调用事务与失败关闭
═══════════════════════════════════════

每次调用按固定顺序预览并原子提交：

1. 验证天章有效实例、持有／认主状态和完整登记条目。
2. 验证 `requiredAuthority`：太玄界印、合法组织授权或条目声明的组合。
3. 验证节点类型、实际锚点、连通状态、岗位和承载容量。
4. 计算 `scopeType`、`scopeTierCap`、传播边界与 `currentCoverageSet`。
5. 验证 `compatiblePhenomena`、现实供给和 `positiveCommit`／`negativeCommit` 都能落地。
6. 扫描 `affectedWorldVariables` 上的金丹介入与元婴道路锚点，决定正常提交、进入一次冲突、受锚、暂停或拒绝。
7. 全部通过后，一次性占用条目和节点承载，提交正负世界状态，发布地区事件信号并写入唯一记录。

任一步失败都不留下半覆盖、只得收益、未付代价、幽灵授权或隐藏节点占用。失败不自动改用更小范围；只有 `failurePolicy` 已登记安全降级时，才可让玩家预览后提交完整的降级正负结果。

═══════════════════════════════════════
六、金丹冲突与元婴受锚
═══════════════════════════════════════

天章基础态与金丹介入命中同一对象、同一时点、同一世界变量且结果不能并存时，建立现有 `RuleConflictInstance`，严格使用冲突五要素：

变量权限与目标合法性 → 源／化／界位别 → 现实支点 → 已实际支付代价 → 当前有效持续承载

天章没有金丹位别，不能凭“剧情遗物”直接参加比较。只有条目引用版本化 `CrossTierChallengeGrant`，且 `sourceKind = CHARTER_RELIC`，才可对档案列明的变量、对象、范围和一次冲突取得挑战层级。挑战资格不保证获胜，不改变持有者境界，也不扩展到其他变量。

天章调用命中元婴道路锚点锁定的同一变量时，状态固定为“受锚”：

- 单件天章不得建立直接覆盖结果，也不得把锚点降格为金丹冲突。
- 可行路线只有协商取得锚点许可、等待锚点撤回、合法破坏其现实支点，或取得另一个明确高位帮助。
- 任何路线仍须重新验证条目、授权、节点、范围、现实供给和世界代价。

没有直接变量冲突时，金丹与天章可以同时存在。金丹介入停止后，天章长期基础态重新显现；系统不把已结束介入的表现永久写回自然基础态。

═══════════════════════════════════════
七、承载、维护与世界代价
═══════════════════════════════════════

`sourceKind = CHARTER_RELIC` 是现有山河运行中的单一明确例外：

1. 复用 `MountainRiverNode`、组织授权、统一周期、`WorldStateCommit`、`RegionEventSignal`、失败策略和唯一结算记录，不建立第二套节点、授权、提交或事件引擎。
2. 不收山河规则的通用每日灵石物业费。调用改为支付条目引用的 `CharterTradeoffProfile`，其中必须包含可落地的 `negativeCommit`、现实供给、节点／条目占用、承载释放条件和事件风险。
3. 世界代价不是通用货币，不能用灵石自动买断或折算；若代价无法在当前世界状态落地，本次调用失败。
4. 条目永久登记不等于可无限并行维持。当前调用仍占用天章条目、节点承载、界印／组织认可和现实供给；条件变化由合法 `WorldStateCommit` 触发重检。
5. 天章本体不靠随意掉耐久维持。其受限承载账本由条目占用、节点承载、授权认可、现实供给和正负提交共同构成。

═══════════════════════════════════════
八、三类规则走查
═══════════════════════════════════════

以下只验证规则结构，不是 M7 的可收集条目成品，也不锁定数值、地区分配或资源倍率。

### 1. 灵机聚散走查

- 影响什么：一段已登记灵脉中的灵气总量、纯度和流通；五行比例不变。
- 范围到哪：连通节点；只覆盖实际接通的灵脉支线和导流设施。
- 谁授权：目标设施的太玄界印授权或沿线合法组织共同授权，按条目档案判断。
- 支点是什么：灵脉、导流设施、册界节点与可接收／释放灵气的现实端点。
- 收益是什么：让目标据点获得更稳定或更纯净的灵气流。
- 代价是什么：灵气必须从登记来源转移，来源片区出现对应减薄、流向变化或节点承载压力；不得凭空增量。
- 遇金丹／元婴怎么办：灵识灵气调御等金丹介入命中同变量时，只有取得列明挑战资格才进入既有冲突；命中元婴锚点则受锚。

### 2. 劫威缓厉走查

- 影响什么：登记渡劫场内天劫外溢的时间分布、缓冲路径和场地余波；不改证位或境界条件。
- 范围到哪：单一节点，只到渡劫台与登记缓冲构件；普通雷雨和场外雷法不受影响。
- 谁授权：渡劫场管理组织及条目要求的设施权限。
- 支点是什么：完好渡劫台、泄威构件、册界节点和能承受余波的缓冲区。
- 收益是什么：减少一次渡劫对无关居民和关键设施的突发外溢。
- 代价是什么：余威被导入登记缓冲区，形成雷痕、节点占用或后续场地风险；不能让余威凭空消失。
- 遇金丹／元婴怎么办：只有直接改写同一渡劫外溢变量的金丹介入才冲突；普通雷法不是同变量。对应元婴锚点成立时受锚。

### 3. 水府地纪结构走查

- 影响什么：以水母属性的原子生态包同时提交季节降水、湿地／水线演化、水行灵气结构和水生资源产出。
- 范围到哪：连通节点，只沿同一流域和已接通水工节点；不越过分水岭或关闭水闸。
- 谁授权：流域内合法组织授权；古代公共水工设施要求界印时，必须同时满足界印接口。
- 支点是什么：现有水源、河道／湿地、水工节点、册界节点及可承载变化的土地。
- 收益是什么：在完整包内改善蓄水、湿地稳定、水行灵气环境与相应资源恢复。
- 代价是什么：水量从登记来源重新分配，旱地通行、火行资源或既有农地可能退让，并产生对应地区事件；四项不能拆开选择。
- 遇金丹／元婴怎么办：水道路金丹介入若直接命中同一水线或灵气变量，按一次列明挑战资格进入既有冲突；水道路元婴锚点锁定同变量时受锚。

三个走查都必须先通过条目、授权、节点、范围、现实供给和世界代价，再讨论高阶冲突。任何一项都不能据此创建新大道、授予境界、修改资质或自由填写世界变量。
