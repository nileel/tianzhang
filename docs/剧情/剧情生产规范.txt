# 剧情生产规范

✅ 已审核（2026-07-22 Codex；宇宙观事实源与揭露边界迁移）

> 适用范围：世界主线、章节主线、地区主线、势力线、NPC 个人分支、固定支线、随机事件、据点对话、副本叙事、CG/演出脚本等全部剧情内容。
> 目标：让后续 AI 拿到本规范后，能按统一粒度拆写剧情文件，并能为后续 Unity 任务系统、对话系统、事件系统和演出资源估算提供输入。
> 必读事实源：`docs/基础设定/太玄界天意与绝地天通设定.txt`、`docs/剧情/背景与重要NPC设计规范.txt`、`docs/剧情/世界背景故事.txt`、涉及地区的 `docs/地图/*.txt`、涉及势力的 `docs/门派/**/*.txt`、涉及重要 NPC 的 `docs/剧情/重要NPC/*.txt`。涉及金丹、高阶境界、册界规则或战斗环境时，继续按下列职责路由读取，不得让单一文件代替全部规则。

## 一、剧情内容分层

剧情文件按“叙事层级”和“开发粒度”分开，不要求所有类型都写到同样细。

| 层级 | 类型 | 用途 | 粒度要求 | 是否直接可开发 |
|------|------|------|----------|----------------|
| L0 | 世界背景/规则规范 | 锁定世界观、术语、禁止项、信息边界 | 原因、时代、势力、核心悬念 | 否，作为事实源 |
| L1 | 世界主线/章节主线/地区主线骨架 | 定义章节目标、节拍、出场限制、后续钩子 | 章节或地区级节拍 | 否，需要拆成 L2/L3 |
| L2 | 任务链/副本线/势力线 | 可交给任务设计继续拆分 | 任务链目标、触发、阶段、分支、奖励 | 部分可开发 |
| L3 | 单个任务/事件/NPC 分支节点 | 直接进入任务、对话、事件配置 | 一任务一文件、一事件一文件 | 是 |
| L4 | 对话全文/CG/复杂演出脚本 | 直接交给文本、镜头或实现人员 | 台词、镜头、入出场、音画资源 | 是 |

硬规则：
- 非规则描述类完成品必须单独文件：一个任务、一个随机事件、一个 NPC 分支节点、一个 CG 脚本都不要合并进大总表。
- L1 骨架只负责方向和边界；不能假装已经具备实现所需的任务 ID、状态变量和演出脚本。
- L3/L4 文件必须包含触发条件、状态变化、失败/回退方式和玩法接口。

世界主线 L1 追加规则：
- 若世界主线跨越多个大境界，必须先定义寿元上限、章节跳年方式、低阶 NPC 换代方式和重要 NPC 活动期，不能把修仙长线压缩成数年连续冒险。
- 若玩家可自选出生地，L1/L2 不得默认唯一出生区域；每章至少说明“本地入口、跨域线索、核心证据”三层接入，并明确哪些地区不开放为出生地。
- 世界主线总纲通过或修订后，必须同步产出或更新后续拆分工作清单，列出 L0、L1、L2、L3、L4 的优先级、前置条件和交付文件。
- L1 世界总纲不得直接写成单一 NPC 的个人史。重要 NPC 可以是失败样本、成功样本、局部见证者或终局变量，但玩家必须是比较、选择和定界的人。
- L1 世界总纲不得提前给出完整真相；每章只允许解锁与玩家境界、证据来源和 NPC 知识边界相匹配的信息。
- 涉及古代历史时必须标明叙述层级：作者事实、档案记录、公共史观、角色判断或传闻。后四类可以保留“天门崩塌”等不完整说法，但不得伪装成作者结论。
- 第一章只处理龙脊余震、近代旧承接网络和局部异常，不揭露绝地天通、天庭直属化计划或三项遗产全貌；现有 L2/L3 任务原则上保持不变。

## 二、剧情类型与最低字段

### 1. 世界主线

用途：定义从游戏开始到终局的核心矛盾、阶段推进和最终回收。

最低字段：
- 主线 ID：如 `story_world_main`
- 核心问题：玩家最终要回答或解决什么
- 阶段划分：按章节或大事件列出
- 时间尺度：寿元、跳年、闭关、世代更替和重要 NPC 活动期
- 出生地接入：可选出生地、本地入口、跨域线索和不开放出生地
- 关键悬念：引入、误导、反转、回收时机
- 关键 NPC/势力：谁推动、谁阻止、谁只提供局部信息
- 重要 NPC 知识边界：每人知道什么、误判什么、不能知道什么
- 玩家成长边界：每阶段允许的境界、资源、系统解锁
- 终局形态：最终决战、最终选择、世界状态变化
- 演出预算：哪些节点需要 CG、哪些只需对话/史实演出
- 后续拆分：每章对应哪些 L1/L2/L3/L4 文件，以及拆分工作清单位置

### 2. 章节主线

用途：定义某一章的可玩节拍，不写完整对白。

最低字段：
- 章节 ID 与标题
- 时间锚点、地理范围、玩家境界范围
- 章节目标、章末状态、不得越界内容
- 入口路线：不同出身/势力/地区如何接入
- 任务节拍：3-7 个，每个节拍说明触发、目标、冲突、产出
- 参与角色：重要 NPC、普通 NPC 类型、敌对/协作势力
- 信息分层：玩家何时知道什么、谁不知道什么
- 演出等级规划：每个节拍使用哪类演出
- 玩法接口：涉及 Settlement/World/Adventure/Combat/修炼/交易/声望的哪一类
- 失败代价与回退：失败后如何恢复，不得软锁
- 后续章节钩子

### 3. 地区主线

用途：定义一个地区自己的长期矛盾，让地区不是主线路过点。

最低字段：
- 地区 ID、对应地图事实源
- 地区核心矛盾：资源、宗门、环境、历史遗留、外部入侵
- 参与势力和当地普通 NPC 类型
- 地区阶段：初到、立足、卷入、选择、收束
- 地区机制：独有环境、资源、声望、探索、副本或世界事件
- 与世界主线关系：提供线索、反证、支援、阻碍或终局条件
- 可重复内容：随机事件池、委托池、环境叙事
- 不可越界项：不能提前揭露的世界真相或高阶机制

### 4. NPC 个人分支

用途：写角色自己的目标、困境、玩家介入点和关系变化。

重要 NPC 分支最低字段：
- NPC 文件引用
- 本分支解决的个人问题
- 当前目标、失败代价、行动时限
- 知识边界复核：已知、误判、不可知不能越过 NPC 正文
- 玩家关系阶段：陌生、交易、信任、冲突、决裂等
- 关键选择：玩家能改变什么，不能改变什么
- 战斗/非战斗表达
- 结局状态：NPC 生死、立场、世界状态、资源或路线变化

普通 NPC 分支最低字段：
- NPC 文件引用或模板类型
- 可交互职责
- 一句话动机
- 任务钩子和可替换性
- 不得掌握核心悬念，不得与重要 NPC 建立直接强关系

### 5. 固定支线/任务链

用途：可直接拆成任务系统配置。

最低字段：
- 任务 ID、标题、类型、所属章节/地区/势力
- 触发条件
- 接取 NPC、提交 NPC、可替代 NPC
- 任务目标：收集、探索、战斗、护送、修复、对话、选择等
- 阶段列表：每阶段的目标、地点、参与角色、状态变化
- 分支选择：选项、条件、短期结果、长期结果
- 玩法接口：场景、战斗、道具、声望、修炼、商店、副本入口
- 奖励与代价：只写类别和强度档，不写未验证数值
- 失败/放弃/超时处理
- 演出等级
- 数据字段建议

### 6. 随机事件

用途：世界移动、地区探索、副本探索或据点停留时触发的小型内容。

最低字段：
- 事件 ID、事件池 ID、地区/场景范围
- 触发权重、冷却、是否唯一
- 前置条件：境界、时间、地点、声望、道具、天气/世界事件
- 事件文本概要：不超过 3 个节拍
- 玩家选项：通常 2-4 个
- 结果：资源、状态、关系、战斗、后续事件标记
- 失败/负面结果
- 可重复性：重复时文本是否变化
- 演出等级：默认 D/C，不得随意要求 CG

### 7. 据点对话与氛围文本

用途：支持 SettlementScene 的 NPC 闲聊、服务入口、传闻和称谓。

最低字段：
- 对话组 ID、NPC/据点/势力
- 解锁条件
- 文本用途：寒暄、任务入口、传闻、世界状态反馈、服务说明
- 玩家称谓规则：境界、势力、关系变化
- 轮换规则：首次、重复、事件后、章节后
- 禁止项：不能承担主线唯一信息，不能越过 NPC 知识边界

### 8. 副本叙事

用途：让 AdventureScene 的探索、战斗和奖励有叙事结构。

最低字段：
- 副本 ID、来源节点、地区、入口条件
- 副本叙事目标：玩家进去要发现什么或改变什么
- 探索层级：入口、表层、中层、深层、终点
- 环境叙事点：遗留物、碑文、尸骸、阵法、异象
- 敌人与 Boss 的叙事定位
- 关键事件：触发、选择、失败、奖励
- 退出规则：完成、撤退、失败、重复进入变化
- 演出等级：Boss 出场、终点揭示、重要回忆是否需要特殊演出

## 三、演出等级

演出等级用于控制制作成本，不能随意把普通内容写成大演出。

| 等级 | 名称 | 适用内容 | 交付要求 |
|------|------|----------|----------|
| D | 文本/日志 | 随机事件、环境描述、普通传闻 | 简短文本、选项、结果 |
| C | 对话场景 | 普通任务、NPC 闲聊、支线节点 | 说话人、台词摘要或全文、表情/立绘需求 |
| B | 轻量场景演出 | 章节关键节点、重要 NPC 首次接触、副本终点 | 角色入出场、镜头/位置、音效、特效、战斗衔接 |
| A | 重点演出 | 章末抉择、重要 NPC 转折、地区主线收束 | 分镜级流程、资源清单、失败/跳过处理 |
| S | CG/终局演出 | 世界主线开场、重大反转、最终决战、结局 | 独立 CG 或高规格 Timeline，需单独 L4 文件 |

默认规则：
- 世界主线可有少量 S/A；章节主线通常每章 0-1 个 A，少数章可有 S。
- 地区主线收束可用 A/B；普通地区任务多为 C/D。
- NPC 分支结局可用 B/A；普通 NPC 不使用 A/S。
- 随机事件默认 D，特殊稀有事件最高 C，除非被明确升格为固定支线。

## 四、触发条件与状态变量

所有 L2/L3/L4 文件必须写触发条件和状态变化。即使当前 Unity 尚未实现任务系统，也要为后续数据化保留字段。

推荐字段：

```
storyId:
contentType:
chapterId:
regionId:
factionId:
npcId:
locationId:
adventureId:
triggerCondition:
unlockCondition:
failCondition:
completionCondition:
stateFlagsAdded:
stateFlagsRemoved:
worldStateChanges:
relationshipChanges:
repeatRule:
cooldown:
exclusiveWith:
performanceTier:
gameplayHooks:
rewardTier:
```

触发条件可使用以下类型组合：
- 章节进度：`chapter >= ch01_beat03`
- 地点：当前 WorldNode、Settlement、Adventure
- 境界：凡人、练气、筑基、金丹等；不得超出章节边界
- 势力/声望：所属势力、敌对关系、地区声望
- NPC 关系：陌生、相识、信任、敌对
- 物品/线索：持有道具、情报、残篇、报告
- 世界状态：灵潮、灵脉风暴、节点归属、封锁状态
- 时间：章节内天数、季节、倒计时
- 随机权重：事件池权重、冷却、唯一性

状态变量命名建议：
- 世界主线：`story_world_<name>`
- 章节：`story_ch01_<beat>`
- 地区：`region_guanzhong_<state>`
- NPC：`npc_xieguanwei_<state>`
- 任务：`quest_ch01_taiyi_trial_<state>`
- 随机事件：`event_guanzhong_storm_<state>`

## 五、玩法接口字段

剧情不能只写“发生了什么”，必须说明它接入哪些玩法。

| 接口 | 需要写清 |
|------|----------|
| WorldScene | 世界节点、移动消耗、区域解锁、事件池 |
| SettlementScene | 据点 ID、服务入口、NPC 面板、任务入口、商店/修炼/情报 |
| AdventureScene | 副本 ID、地图主题、探索事件、敌人池、出口 |
| Combat | 是否战斗、战斗类型、敌人类型、胜负结果；具体数值另入数据文件 |
| 修炼/境界 | 是否解锁修炼节点、功法、术法、突破条件；涉及平衡必须跑 BattleSim |
| 经济/奖励 | 奖励类型、强度档、是否唯一；不在剧情文件写未经验证的具体倍率 |
| 关系/声望 | 哪个势力或 NPC 关系变化，变化方向和用途 |
| 道具/线索 | 关键物品、情报、可交易物、是否可丢弃 |
| 世界状态 | 节点归属、封锁、天气/灵灾、地区事件是否改变 |

## 六、分支、失败与回退

剧情设计必须避免“玩家选错就断主线”。

最低要求：
- 主线必要信息不能只由一个可错过普通 NPC 提供。
- 关键线索被截获、丢失或误读时，必须有后续补线方式。
- 失败结果要区分：可重试、延迟、路线变化、关系恶化、永久后果。
- 永久后果只能影响资源、立场、结局变体或路线难度，不得让游戏无法继续。
- 随机事件不能持有唯一主线钥匙。

## 七、信息边界与禁止项

全局禁止：
1. 不得出现全知 NPC。任何 NPC 都必须受自身文件的知识边界限制。
2. 不得提前揭露绝地天通、天庭直属化计划、上界现状、苻渊闭关、司马承景状态或三项遗产全貌；第一至第四章只能给出与章节证据相称的局部解释。
3. 不得把完整金丹道路、基础效果、三实位装配与生命周期规则写成单一宗门私产。
4. 不得使用旧口径作为现行规则：正籍、辅籍、敕籍、寄丹、妖血敕等只能在历史说明或禁止条款中出现。
5. 不得让玩家在章节边界外提前突破或使用未解锁高阶系统。
6. 不得让普通 NPC 占据金丹实位、持有金丹基础效果、成为重要 NPC 亲传，或独占主线推进信息。
7. 不得在剧情文件中写未经验证的战斗倍率、伤害数值或掉落概率。
8. 不得照抄真实历史事件、人物结局或台词；只能借用结构张力。
9. 不得在作者视角重建统一“上古仙朝”，不得把太一道庭写成上古太玄道庭本体，也不得把司马承景写成仙朝末代道主。
10. 不得让天庭、本界天意、法箓或三项遗产授予金丹／元婴、创建大道、改变先天资质或绕过现行高阶冲突。
11. “仙朝、天命、天道、天劫”等词必须逐处判断语义；具体地方政权、角色信仰和修行现象可保留，不做机械全局替换。

## 十、AI 生产流程

1. 先确认内容类型和层级，不要把 L1 骨架写成 L3 任务，也不要把随机事件写成主线唯一钥匙。
2. 读取本规范和对应事实源。
3. 新建内容前检查是否已有同主题文件。
4. 生产世界主线或章节/地区 L1 前，先锁定五类边界：寿元与时间尺度、出生地接入、玩家境界上限、重要 NPC 知识边界、不得提前揭露的悬念。
5. 生产世界主线总纲时，先提出 2-3 种结构方案和优缺点，等待用户确认；若用户已明确指定方向或要求继续推进，可按已确认方向落稿。
6. L1 世界总纲完成后，必须同步列出后续 L0/L1/L2/L3/L4 拆分清单；若拆分规模较大，应单独建清单文件。
7. 生产 L2 前，确认对应章节/地区 L1 已稳定；生产 L3/L4 前，确认 L2 的触发条件、状态变量、失败回退和演出等级已稳定。
8. 具体完成品一文件一个；总纲、规范、候选清单和拆分清单可以是总表。
9. 涉及设计内容时不写具体战斗数值；涉及平衡结论时必须运行 BattleSim。
10. DeepSeek 或外部 AI 产出必须标 `⚠️ 已修改/未审核` 并写交接；Codex / ChatGPT5.5 自产内容完成文本验证后可闭环。
11. 完成后至少运行：
   - `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths docs/剧情,开发管理`
   - `git diff --check`

## 十一、审核清单

剧情文件审核时按以下问题判断：

1. 类型和层级是否明确？
2. 是否读取并引用了必要事实源？
3. 是否有触发条件和状态变化？
4. 是否说明参与角色、势力和知识边界？
5. 是否说明演出等级，且演出成本与内容重要性匹配？
6. 是否说明玩法接口，而不是只写故事梗概？
7. 是否有失败、回退或替代路径？
8. 是否避免普通 NPC 独占主线信息？
9. 是否存在旧口径污染或高阶越界？
10. 是否把具体任务、事件、NPC 分支拆为单独文件？
11. 是否留下可供 Unity/CSV/任务系统接入的 ID 或字段？
12. 是否避免未经验证的数值和掉落概率？
13. 若为世界主线或章节/地区 L1，是否说明寿元与时间尺度、出生地接入和玩家境界边界？
14. 若为世界主线总纲，是否同步产出或更新后续拆分工作清单？
