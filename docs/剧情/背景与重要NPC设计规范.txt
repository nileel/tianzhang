# 背景与重要 NPC 设计规范

✅ 已审核（2026-06-21 Codex / gpt-5.5）

## 一、世界背景方向

1. 时代骨架采用“强结构映射”：保留东晋十六国/南北朝式乱世格局、人物关系张力与淝水之战式的成败因果；不复写真实历史事件、人物结局或台词。
2. 龙脊之变的因果必须是北方霸权在王玄略死后，苻渊强行提前发动大阵，内部体系原有裂缝被放大；谢氏水系反制只能成为放大局部反流的关键条件，不得写成全知全能、单独摧毁北方体系的万能法术。
3. 时间锚点固定为：371 年秋王玄略身死；372 年秋龙脊之变；387 年秋游戏开始。
4. 关键信息必须分层：谢观微知风险但不知全盘崩坏；钟离幽知裂缝而不知起因；吕星枢掌握数据而不知总因；司马承景可知更深，但必须有边界与不确定性。不得让多个 NPC 同时“唯一知晓全部真相”。

## 二、重要 NPC 写作字段

每名重要 NPC 必须单独文件，至少包含：

1. 历史锚点：借用的结构与明确不照抄的部分。
2. 叙事层级：本章功能、当前目标、失败代价、行动时限。
3. 知识边界：已知、误判、不可知的事实分别列明。
4. 位格状态：具体元婴分支、源/化/界席位、占据方式（夺取/继承/敕封/暂寄/自辟）与是否存在空位。
5. 关系限制：最多三条强关系；其余关系写为阵营或弱联系，避免关系网失控。
6. 战斗表达：人物志只写战法标签、战略威胁和克制关系；命中率、伤害倍率等具体数值移入术法、神通或数据文件。

## 三、位格与势力约束

1. 不得把完整丹系写成单一门派私产；宗门拥有的是传承、资源、叙事解释权或敕封能力。
2. 既有 NPC 若出现同一源/化/界席位被重复占据，或“已满”与“仍有空位”并存，必须在迁移时修正为唯一状态。
3. 慕容朔类“妖血注入但不产生独立金丹位格”的设定，不得称妖血敕籍，应称妖血契、血脉注入或同类关系。

## 四、太一道庭与司马承景

1. 太一道庭是司马氏南渡后凭残存道印、四大道脉与沧海灵脉维系的“东晋式续统”；继承西晋仙朝的法统与正统名义，不拥有对全域灵脉的实际统治力。
2. 司马承景保留为真实存在的元婴 NPC，用于展示元婴层、承接西晋—东晋法统与扩展太一道庭法箓体系；可通过外封祭坛、道印回响或高代价投影出现，不应作为常规可击杀战斗单位。
3. 太一道庭金丹可占据自然源/化/界席位，也可通过有限递减的道印敕封、法箓暂寄或自凝方式取得使用权；不得写成“所有太一金丹均由司马承景敕封”。
