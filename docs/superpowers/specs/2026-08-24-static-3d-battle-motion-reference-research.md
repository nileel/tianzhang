# 静态 3D 战斗动态表现参考游戏调研

日期：2026-08-24
任务：`D-CHAR-STATIC3D-MOTION-REFERENCE-01`
状态：已完成调研；本文不决定《天章》的静态 3D 动态表现技术、Pose／动作数量、导出方式或资产生产流程

## 一、范围、证据分级与结论边界

本调研只核查数字棋盘、微缩模型与低动画战棋如何在 3D 中让角色表达方向、移动、攻击、受击、施法和死亡，并逐项区分“已披露的生产事实”“画面或产品定位邻近”与“项目既有样例”。苻渊、固定斜俯视六角镜头和既有 `VisualBaselineBoard` 只用于判断约束；它们不证明外部游戏的生产管线，也不构成新的《天章》方案。

| 等级 | 含义 | 可支持的结论 |
|------|------|--------------|
| E1 | 开发者／发行方正式材料、开发团队具名且可核实的公开答复，或 Unity 官方文档 | 明确披露的游戏设计取舍，或明确的引擎能力与其组件前提 |
| E2 | 可确认主讲人、公司与主办方的演讲／复盘 | 讲者明确说明的动画制作经验；不能外推成另一游戏的资产成本 |
| E3 | 官方产品页面或开发者未披露生产细节的画面／功能说明 | 微缩视觉、是否有动画等邻近事实；不能反推骨骼、换模、渲染或资产结构 |
| P1 | 《天章》已归档的静态样例合同和验证记录 | 现有模型与 Unity 样例的既有约束；不是外部游戏先例，也不授权沿用或扩展旧路线 |

“等价”在本文中严格指：同一公开来源能够确认以**多套独立、无骨骼的静态 3D Pose 模型替换**来覆盖战斗角色的动态语义，并至少说明其资产或运行时处理。只显示数字微缩模型、只称“fully animated”、或只说明不做传统角色动画，均不满足此定义。调研没有来源提供《天章》的角色量、服饰／武器组合、动作覆盖、返工次数、工时或 credits，故本文不估算成本，也不选择技术路线。

## 三、是否存在等价 Pose 换模先例

**没有找到。**本卡检查的 Wartile、Moonbreaker 与公开的 Unity／GDC 材料中，没有一项可确认“多套独立静态 3D Pose 模型换模覆盖战斗动态表现”的已上线生产流程。Wartile 的作者材料反而只证实其存在动画挑战和完整动态画面，未披露内部动画形态；Moonbreaker 的开发团队说明的是为桌面感和规模而避免逐单位绑定／手工关节动画，并没有说明其以多个 Pose 模型替换作为替代。

因此，若后续有人提出独立 Pose 换模，它只能被记录为**待验证的项目自研假设**：尚未有本调研范围内的等价生产先例支持其身份一致性、宽袖、武器、六向、接地、遮挡、批量生产或 Unity 维护成本。不得把 S1～S9 的画面、产品定位或引擎能力改写成此方法已成熟。

## 五、六类战斗语义的证据覆盖

| 语义 | 可确认的外部参考事实 | 与《天章》既有静态样例的关系 | 仍未由调研证明的事项 |
|------|----------------------|----------------------------------|--------------------------|
| 方向 | S5 只说明 Wartile 是位置决策的动态微缩棋子游戏；不披露方向资产。 | P1 有既有六向根节点映射，且人物网格保持静态。 | 方向是否需要模型替换、骨骼、根节点转向或其他表达；任一做法的批量成本。 |
| 移动 | S3、S5 证明动态微缩战棋画面存在；不披露移动的资产与运行时所有权。 | P1 已记录“抬起—移动—落下”仅作用于表现根节点。 | 这种表现是否足以作为后续完整样例的可读性合同，以及复杂服饰／武器下的接地与遮挡。 |
| 攻击 | S5 的“fully animated”不说明攻击的实现。 | P1 的旧样例可作根节点短促前倾／位移的历史范围。 | 角色姿态、武器、命中效果与命中时点的分工；不得把根节点历史样例当作最终方案。 |
| 受击 | S2 说明团队没有为每个模型手工制作高质量关节动画；未说明受击替代。 | P1 有根节点震动／后仰的已验证静态样例行为。 | 受击视觉是否足够、如何处理宽袖轮廓和击退边界、以及是否需要更改模型。 |
| 施法 | S3 提到选择性特效，但语境未限定为角色施法。 | P1 只允许一次性施法特效，角色网格不变。 | 法术特效能否独立承担可读性、角色／特效遮挡和批量维护成本。 |
| 死亡 | 没有来源披露与静态 3D 微缩棋子等价的死亡生产步骤。 | P1 记录过根节点倾倒／降低与淡出是旧隔离样例允许的表现。 | 死亡状态、占格、残留物、复位、网格变化及规则隔离的最终可见合同。 |

P1 的结论只说明现有苻渊静态样例曾在隔离测试台证明六向和根节点表现不写回规则；它不填补外部生产资料的缺口，也不允许把旧灰白材质画面或旧合同作为新动态路线能力证据。当前 BaseColor 修正仍由独立的 `U-CHAR-STATIC3D-MATERIAL-CORRECT-01` 处理。

## 六、对详细方案前的风险边界

1. 已找到的可信近邻分成两类：Wartile 证明“动态微缩棋子”画面可以存在，但不公开其资产机制；Moonbreaker 证明开发团队会因单位规模与桌面模型感主动不做逐单位高质量关节动画，但也不披露一个可替换的动态生产机制。二者不能合成为 Pose 换模的先例。
2. S6～S8 只回答 Unity 能否承载骨骼、动画曲线和 Root Motion 这类机制；它们没有回答苻渊宽袖、接地、六向遮挡和身份一致性能否通过，也不提供项目成本。
3. 当前 P1 静态样例的根节点表现是一个既有项目约束，不是外部可迁移的“完成路线”。特别是它明确没有 Animator、AnimationClip、SkinnedMeshRenderer 或运行时骨骼动画，不能被改写成任一其他方法已经通过。
4. 若负责人允许进入详细方案，首先仍需把“没有等价 Pose 换模先例”作为公开自研风险，并以可运行样例验证身份、宽袖／武器、六向、脚底／底座接地、前后遮挡、事件时点、根节点复位和规则隔离。该许可之前，不生成、下载、编辑模型，不消费 credits，也不改 Unity。
