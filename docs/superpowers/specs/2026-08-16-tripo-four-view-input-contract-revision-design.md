# Tripo 四视图输入合同修订设计

日期：2026-08-16
状态：负责人已复核确认并授权实施

## 一、背景与根因

现有平台评估设计 §5.1 把角色四视图定义为正面 A／T Pose、左或右正侧面、背面、前三分之四面。当前 Tripo Studio 的多视图入口则把一次请求的四个输入槽固定为“前／左／右／后”，没有“前三分之四”槽位。

这不是 Tripo 缺少四图输入能力，而是项目输入合同与平台的角色语义不一致。继续把前三分之四图塞入左或右槽位会制造错误的视图声明；因这一差异关闭整条 Tripo 路线也会把合同问题误判为平台能力问题。

负责人于 2026-08-16 选择修改全局四视图合同，使所有正式平台槽位统一使用前、角色左侧、角色右侧和背面四图。前三分之四角度仅保留为模型生成后的比较渲染，不再属于平台输入。

## 二、已确认的合同

### 2.1 四张正式输入

固定集合与顺序为：

1. 正面 A／T Pose；
2. 角色左侧严格正侧面；
3. 角色右侧严格正侧面；
4. 背面。

“左／右”一律以角色自身方向为准。两张侧面均采用近似正交的严格 90° 观察，不得用前三分之四角度代替。角色存在非对称发型、服装、系结、饰物或纹样时，不得通过简单镜像另一侧伪造缺失结构。

四图必须保持同一身份、比例、发型、服装结构、配色与标志物，使用近似正交观察、简单同色背景、均匀中性照明、全身完整入镜和安静姿势。动态立绘、宣传图、模型效果演示和旧模型补渲染均不能替代四张原始输入。

四张字面量路径及 SHA-256 共同构成唯一获批输入集。任一图片内容变化都会使整组批准失效。所有被正式比较的平台必须消费同一组图片；平台槽位存在语义标签时，按前／角色左／角色右／后逐一映射，不允许为单个平台替换更有利的图片。

### 2.2 输入与结果展示分离

平台输入合同不再包含前三分之四图。平台生成模型完成后，Blender 评估仍按既有流程输出前左、前右和背后三分之四三个正交斜俯视中性比较图。后者是结果展示与验收视角，不得回填或冒充平台原始输入。

## 三、Tripo 当前入口事实

负责人提供的当前 Tripo Studio 高精度模型页面截图证明：

- 多视图模式在同一生成面板内提供四个固定槽位，字面量为“前／左／右／后”；
- 四个槽位由同一个“生成模型”操作提交，因此能够对应修订后的同次四图输入合同；
- 页面显示上传格式为 JPG、PNG、WEBP，单图大小不超过 20MB；截图未显示可证明的分辨率限制；
- 当前 AI 模型为 `v3.1 – 最高质量`，目标面数显示为 12000、三角面、纹理生成开启、4K、PBR 开启、超清几何精度关闭、分部件生成关闭、8K 贴图关闭；
- 当前私密性字面量为 `仅分享`，基础按钮显示 `生成模型 40`；
- 检查期间没有选择或上传图片，没有提交生成，也没有扣除 credits。

因此预检对修订后合同的唯一结论为“支持”。该结论只覆盖截图中可见的当前入口事实，不外推隐藏参数、历史扣费或未来页面状态。

## 五、实施边界

本次合同修订实施只允许修改设计、当前合同／预检记录、相关未完成任务卡、父任务、任务列表和当前队列。它不生成四张图片，不上传 Tripo，不生成 3D，不扣 credits，不操作 Blender，不修改任何 `raw/`，也不向 `src/Assets/` 写入内容。

隔离 worktree 中此前形成但未提交的“Tripo 不支持合同、关闭严格轮并清空下游”结论必须被替换，不得进入最终差异或提交。

## 七、停止条件

实施合同修订时，只要发现新定义不能唯一映射当前 Tripo 四槽、需要修改已归档历史、任务投影无法保持单一 ready 叶子，或预期修改超出第五节边界，就停止并请求负责人裁决。

后续四图制作或付费生成阶段，任一图片身份／比例／结构不一致、哈希变化、四图尚未获负责人明确批准，或 Tripo 的槽位语义、模型、私密性、关键设置与显示价格发生变化时，都必须停止；不得上传、生成或扣除 credits。
