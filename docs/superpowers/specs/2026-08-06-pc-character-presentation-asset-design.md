# 《天章》PC 宽屏角色展示资产设计

> 日期：2026-08-06
>
> 状态：设计对话已批准；本文只锁定人物介绍、角色资料与对话界面的 2D 立绘承载、拆层和轻量动效边界，不代表资源已经重新导出或 Unity 已经接入。
>
> 关联设计：`docs/superpowers/specs/2026-08-05-character-art-and-modular-appearance-design.md`

## 一、决策摘要

1. PC 人物介绍与角色资料界面以 `1920×1080` 的 16:9 宽屏构图为设计基准。
2. 16:9 描述的是最终 UI 展示容器，不要求透明人物母版本身也是 16:9；人物继续使用高分辨率竖向 RGBA 全身立绘。
3. 运行时不把背景、人物、姓名、道号、印章和动效烘焙成唯一图片，而是按稳定层级组合。
4. 人物介绍、角色资料、对话半身和头像默认复用同一张透明全身人物母版，通过锚点、遮罩或裁切区域得到不同构图。
5. 只有特殊表情、伤势、换装、剧情姿势或母版裁切后清晰度确实不足时，才允许配置显式的对话覆盖图；覆盖图不是每个角色的必做资源。
6. 首版采用轻量动效：整个人物作为单层做淡入、轻微位移、呼吸缩放、视差和轮廓光，不拆五官、头发、衣袖、手臂或其他身体部件。
7. 当前合成完成的 16:9 图片保留为构图样张、宣传图或静态回退图，不作为运行时可变内容的唯一事实源。

## 二、当前事实与适用范围

- 项目现有主要 Unity UI 使用 `1920×1080` 参考分辨率，适合建立统一的 PC 宽屏角色展示构图。
- `assets/generated-character-art/` 当前保存无字版、题字版和透明对话版生成结果；现有苻渊、谢观微资源大多是竖向图片。
- 正式 `src/Assets/Art/` 尚未建立，角色展示资源仍处于美术样张与生成工作流阶段。
- 既有角色美术设计已经规定：角色详情显示全身，对话和行动轴裁切同一全身立绘结果。本设计补足宽屏背景、姓名、道号、印章与轻量动效的组合边界。

本设计适用于：

- 重要 NPC 人物介绍页；
- 角色资料或图鉴界面；
- 对话界面的全身或半身人物显示；
- 需要同一身份视觉的头像或行动轴裁切。

本设计不决定战棋场景中的 3D 角色表现，也不改变运行时模型、换装或战斗规则。

## 三、运行时分层

从后到前使用以下逻辑层级：

1. `profileBackground16x9`：无人物、无姓名、无道号、无印章的宽屏背景。
2. `profileFx`：法相圆环、承诺线、云雾、墨流等可选轻量动效层。
3. `characterFullBody`：唯一必需的透明全身人物母版。
4. `foregroundFx`：少量前景墨迹、光点或粒子，可选。
5. `name` 与 `daoTitle`：来自角色数据的正确繁体文本。
6. `nameArt` 与 `daoTitleArt`：可选的透明书法美术字；存在时替代普通字体表现，但不替代文字数据。
7. `seal`：独立透明朱砂印章；没有道号或不适合使用印章的角色可以不配置。
8. UI 按钮、资料字段和交互反馈。

`staticPreview16x9` 保存全部批准层的静态合成效果，只用于审批、宣传、加载占位或明确的静态回退，不参与拆层内容的反向解析。

## 四、人物母版复用规则

### 4.1 默认路径

- 人物介绍界面直接显示 `characterFullBody` 的完整构图。
- 对话界面继续引用同一资源，通过 `RectMask2D`、UV 裁切或等价的 UI 裁切方式显示半身。
- 头像与行动轴继续从同一资源裁切头肩区域。
- 不为上述三个用途复制内容相同的 PNG，也不分别生成容易产生身份漂移的同姿势图片。

### 4.2 显式覆盖

允许可选字段 `dialogueOverride`。只有下列情况之一成立时才使用：

- 剧情要求不同表情、伤势、服装或姿势；
- 全身母版裁成半身后，面部清晰度在目标 UI 尺寸下不合格；
- 人物轮廓或手势在对话框安全区域内无法形成可读构图。

覆盖图缺失表示继续使用全身母版，不属于错误。覆盖图存在时必须与母版保持同一角色的脸型、发型、主配色、服装结构和标志物。

## 五、文字与印章

- `name` 和 `daoTitle` 必须作为正确的繁体文本数据保存，不能只存在于 AI 生成图片中。
- 首版可使用已确认授权且字形正确的字体在 Unity 中显示，并用透明度或矩形遮罩完成淡入、纵向揭示等轻量动画。
- 若角色需要独特书法笔触，可另行提供 `nameArt` 和 `daoTitleArt` 透明图；其内容必须逐字对照文本数据验收。
- 印章使用独立透明 PNG，以便执行落印、缩放、晕染或淡入动画。印章文字仍须人工验字。
- 普通 NPC 若没有道号或印章，界面直接隐藏对应层，不生成伪道号或通用印章填空。

## 六、轻量动效边界

首版允许：

- 人物整层淡入、轻微上下漂移和约 1% 的缓慢呼吸缩放；
- 背景、法相和人物之间的低幅度视差；
- 法相圆环、承诺线、墨流或光点的低速循环；
- 姓名、道号的遮罩揭示；
- 印章的短促落印与朱砂晕染；
- 人物轮廓的克制柔光或材质参数动画。

首版禁止：

- 为呼吸效果拆分胸腔、头部或四肢；
- 拆分眼、眉、嘴并制作口型或眨眼；
- 为头发和衣袖建立骨骼、网格变形或物理模拟；
- 从完整合成图中运行时抠图或推导缺失图层。

若以后批准中量衣发摆动或 Live2D 级表现，必须另立资源拆层与动画设计，不能在当前轻量方案上临时叠加身体部件。

## 七、宽屏与适配规则

- `1920×1080` 是构图参考，不要求资源只支持这一种窗口尺寸。
- 背景必须允许在 16:10 与超宽屏上向左右延展或适度裁边，不拉伸人物。
- 姓名、道号、印章、人物头顶、双手和脚部必须位于中央安全区域；背景远山、云雾和边缘墨迹可以进入裁切余量。
- 人物介绍界面默认使用“左侧名号、右侧全身人物”的宽屏构图；个别角色可镜像布局，但同一界面内的文字安全区和人物锚点规则保持一致。
- 对话界面只消费人物母版与自己的对话布局，不强行复用人物介绍背景、名号或印章。

## 八、逻辑资源合同

每个需要宽屏展示的重要角色最多配置以下引用：

```text
characterFullBody       必需：透明全身人物母版
dialogueOverride        可选：特殊对话覆盖图
profileBackground16x9   必需：宽屏人物介绍背景
profileFx               可选：法相或背景动效层
foregroundFx            可选：前景墨迹或粒子层
name                    必需：繁体显示名数据
daoTitle                可选：繁体道号数据
nameArt                 可选：透明书法姓名图
daoTitleArt             可选：透明书法道号图
seal                    可选：透明朱砂印章
staticPreview16x9       可选：静态合成预览或回退图
```

这只是资源职责合同，不在本设计中批准具体 Unity 数据类、序列化字段或加载系统。

## 九、资源生产与验收

### 9.1 建议的单角色源资产

```text
<character-id>/
├─ background_16x9.png
├─ character_full_rgba.png
├─ profile_fx.png
├─ foreground_fx.png
├─ name.png
├─ dao_title.png
├─ seal.png
└─ preview_16x9.png
```

仅创建该角色实际需要的可选文件，不生产空白占位图。源工程保存在 `assets/source/characters/`，正式 Unity 导出在资源批次获批后进入 `src/Assets/Art/Characters/`，并遵守现有美术资源登记与版本管理规范。

### 9.2 验收条件

- 人物介绍在 16:9 下形成明确的左侧名号、右侧人物层级，人物与文字互不遮挡。
- 透明人物四角 alpha 为零，没有背景、地面、投影或残留色边。
- 同一人物母版能够在全身、对话半身和头肩裁切中保持可读；不合格时才启用覆盖图。
- 姓名、道号和印章文字逐字正确，繁简体符合角色数据。
- 隐藏任一可选动效层后，人物、背景和文字仍能形成完整静态界面。
- 动效不改变人物身份、人体结构或 UI 可读性，不依赖身体部件拆分。
- 16:10 与超宽屏适配不拉伸人物，不裁掉关键文字和角色主体。

## 十、实施边界

本轮设计批准后仍不自动执行以下工作：

- 不立即重做全部现有角色图片；
- 不立即替换 `assets/generated-character-art/` 的现有目录或提示词；
- 不创建 `src/Assets/Art/`、Unity Prefab、数据类、动画或 Shader；
- 不把苻渊样张直接声明为所有角色的最终风格母版；
- 不批量生产姓名、道号、印章或背景。

后续实施应先以苻渊一个角色制作完整分层技术样例，验证人物介绍、对话复用、文字准确性、轻量动效和窗口适配，再决定是否推广到其他重要角色。
