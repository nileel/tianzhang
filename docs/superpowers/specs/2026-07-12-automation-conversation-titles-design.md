# 天章自动化对话命名设计

> 日期：2026-07-12
> 状态：修订待用户复核（基于 12:25 成功改名运行）

## 目标

让定时控制器和手动快捷工作流都以中文任务摘要命名，避免用难以辨认的 TQ 或 HANDOFF 编号作为标题主体；单次改名超时不得阻断任务。

## 方案

定时控制器与用户发送纯 `1`、纯 `2` 后的快捷工作流，都在动态路由完成、任务事实源已确认后调用 `tools.codex_app__set_thread_title`。执行、维护或恢复标题为 `TZG｜<中文简述>`，复审标题为 `TZG｜复审：<中文简述>`。

- 执行任务：使用任务卡中面向人的中文标题或目标摘要，例如 `TZG｜接通冒险场景战斗流程`。
- 复审任务：使用被复审对象的中文主题，例如 `TZG｜复审：地图战斗接入`。
- 队列维护：使用维护对象的中文主题，例如 `TZG｜维护当前任务队列`。
- 恢复任务：沿用恢复任务事实源中的同一简述，不以“恢复中”覆盖原主题。

TQ、HANDOFF 等标识仍保留在本机控制器状态、自动化 memory、提交信息和任务文件中，作为可追溯的机器标识；它们不进入对话标题。

## 时机与边界

标题仅在本轮已选定真实工作对象后更新一次。无候选任务、有效租约占用、身份无法确认或人工脏工作区时不改名，避免制造空泛或误导性的对话记录；定时控制器与手动纯 `1` / `2` 都在完成任务选择后、读取实施细则前更新。

改名是可观察性增强，不得改变任务路由、租约、恢复、验证、提交或失败关闭逻辑。改名调用失败或超时时，在 automation memory 或当前对话记录原因并继续既有流程；不得因一次超时整体禁用定时控制器改名。

## 实施范围

1. 在 `开发管理/自动工作流规则.txt` 明确定时控制器和手动入口的改名时机、格式及失败不阻断边界。
2. 在 `开发管理/审核入口.txt`、`开发管理/AI协作规则.txt` 与短入口 `AGENTS.md` / `CLAUDE.md` 明确手动纯 `1`、纯 `2` 使用 `tools.codex_app__set_thread_title`。
3. 在 `tzg-wf2-codex-execute-1` 的控制器提示中恢复标题工具调用和超时记录要求。
4. 调整 `tools/check-automation-workflow.ps1`：要求控制器调用标题工具、使用中文简述，并明确失败不阻断；项目文本检查手动入口的真实工具名。

## 验证

- 运行自动化配置静态检查，确认唯一写入控制器仍启用，其他旧写入工作流仍暂停。
- 运行项目文本检查与 `git diff --check`。
- 检索控制器配置，确认包含 `set_thread_title`、中文简述和失败不阻断语义，且未硬编码任何具体任务编号。
- 在下一次真实定时控制器与手动纯 `1` 或纯 `2` 选中任务时，人工检查其对话标题是否符合相应格式；两项运行验收不在本次配置提交前宣称已完成。
