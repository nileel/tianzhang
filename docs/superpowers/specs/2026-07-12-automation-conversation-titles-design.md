# 天章自动化对话命名设计

> 日期：2026-07-12
> 状态：用户已确认，待实施计划

## 目标

让所有自动选题工作流的对话标题反映本轮实际工作，便于用户在自动化历史中按内容定位；不以难以辨认的 TQ 或 HANDOFF 编号作为标题主体。

## 方案

每小时控制器与用户发送纯 `1`、纯 `2` 后的快捷工作流，都在动态路由完成、任务事实源已确认后调用 Codex 的对话标题更新能力。标题格式为 `TZG｜<中文简述>`；复审标题使用 `TZG｜复审：<中文简述>`，清楚区分工作性质。

- 执行任务：使用任务卡中面向人的中文标题或目标摘要，例如 `TZG｜接通冒险场景战斗流程`。
- 复审任务：使用被复审对象的中文主题，例如 `TZG｜复审：地图战斗接入`。
- 队列维护：使用维护对象的中文主题，例如 `TZG｜维护当前任务队列`。
- 恢复任务：沿用恢复任务事实源中的同一简述，不以“恢复中”覆盖原主题。

TQ、HANDOFF 等标识仍保留在本机控制器状态、自动化 memory、提交信息和任务文件中，作为可追溯的机器标识；它们不进入对话标题。

## 时机与边界

标题仅在本轮已选定真实工作对象后更新一次。无候选任务、有效租约占用、身份无法确认或人工脏工作区时不改名，避免制造空泛或误导性的对话记录。每小时控制器在其 `task_selected` 检查点后执行；手动纯 `1` 或纯 `2` 在完成相同的任务选择后、读取实施细则前执行。

改名是可观察性增强，不得改变任务路由、租约、恢复、验证、提交或失败关闭逻辑。改名调用失败时，控制器在自动化 memory 中记录原因并继续执行既有流程，不得因此修改项目文件、阻止验证或伪造完成状态。

## 实施范围

1. 在 `开发管理/自动工作流规则.txt` 增加每小时控制器的对话命名时机、格式、事实源与失败边界。
2. 在 `开发管理/审核入口.txt`、`开发管理/AI协作规则.txt` 与短入口 `AGENTS.md` / `CLAUDE.md` 加入手动纯 `1`、纯 `2` 的同一命名要求。
3. 在 `tzg-wf2-codex-execute-1` 的控制器提示中加入实际调用标题更新能力的步骤，并明确在 `task_selected` 后执行。
4. 扩展 `tools/check-automation-workflow.ps1`，静态检查控制器提示和规则都包含命名约束，防止未来回归。

## 验证

- 运行自动化配置静态检查，确认唯一写入控制器仍启用，其他旧写入工作流仍暂停。
- 运行项目文本检查与 `git diff --check`。
- 检索控制器配置，确认命名格式使用中文简述，且未硬编码任何具体任务编号。
- 在下一次真实控制器选中任务时，人工检查其对话标题是否符合 `TZG｜<中文简述>`；在下一次手动纯 `1` 或纯 `2` 选中任务时，人工检查其对话标题是否符合相应格式。两项运行验收不在本次配置提交前宣称已完成。
