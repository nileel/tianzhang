# 金丹丹相与源化界丹枢设计规格

状态：✅ 核心边界保留；紫府输入与多位格丹相关系已按 2026-07-20 集成规格迁移
日期：2026-06-19
来源：用户确认“B + 丹相命名”方向成立；2026-06-21 源/化/界位格体系已锁定
用途：作为 `docs/基础设定/修行境界.txt`、`docs/基础设定/境界特性.txt`、角色养成规范与 TQ-015C 数据迁移的设计输入。本文件不替代《元婴锚点与金丹位格效果矩阵》对世界变量、边界和代价的定义。

## 一、设计目标

新版金丹不再以“本命神通 + 本命法宝”作为主要能力表达。金丹期的自身能力由角色占据的具体源/化/界席位及其占据状态、丹名、丹性，以及筑基期全部已建紫府与镇府神通统合生成。

本设计采用“丹相”作为金丹自身能力总称。每个金丹只有一个丹相；第一至第三个稳定位格只向同一丹相追加规则权限。丹相必须服从源/化/界位格矩阵：矩阵决定能作用的世界变量、对象、边界和代价；角色只能通过丹枢表现个人差异，不能借丹相改写席位事实。

目标如下：

1. 让金丹能力承接筑基期的紫府与镇府神通经营，而不是金丹后突然挑选技能升格。
2. 让席位、占据状态、丹名与丹性都参与能力生成，避免它们停留在叙事标签。
3. 保留旧本命神通的战斗招牌价值，但迁为丹相内部的主枢。
4. 保留旧本命法宝的修仙味道，但迁为部分丹相的外显形态，不再作为所有金丹的必备系统。

## 二、核心名词

### 丹相

丹相是金丹成就后显化出的金丹能力形态，不是单个技能，也不是一件法宝。

丹相由“全部已建紫府 + 一至三个稳定源/化/界位格及装配效果 + 占据状态 + 丹名道途 + 丹性回响 + 主／辅承载”统合形成。其通用效果必须回指《元婴锚点与金丹位格矩阵》；角色差异只写入合法丹枢接口。

示例命名：

- 九霄雷劫丹相
- 南华梦魂丹相
- 混元铁军丹相
- 太一玄箓丹相
- 秋水游心丹相

### 镇府神通

镇府神通是源术法按升格方案转化后，由一座完整紫府唯一承载的核心能力。每座已建紫府恰有一项镇府神通；全部已建紫府都是丹相输入，不在成丹时被丢弃。

镇府神通数量等于已建紫府数量，范围为一至五。结丹只要求至少一座完整紫府，不强制用满容量；结丹后不能新增或替换紫府。

### 丹枢

丹枢不是镇府神通的同义词，也不是脱离位格的额外能力节点。

每个金丹只有一个成丹时永久绑定的丹枢核心；各稳定位格在该核心上开放自己的个性化接口。丹枢将镇府神通、丹名与丹性组织为位格允许的表现，只能改变以下六项：

1. 媒介
2. 偏向对象
3. 代价分配
4. 丹域景象
5. 战斗表现
6. 宗门叙事

丹枢不得改变矩阵已定义的世界变量、作用边界和不可替代项。

### 丹相主枢

丹相主枢是某个稳定位格的主承载神通在该位格和丹枢接口约束下形成的主要表现。每个 `STABLE` 位格必须有一项不同且兼容的主承载；同一神通实例不能主承载两个稳定位格。

暂寄状态不生成丹相主枢，只保留不完整丹相与辅枢残影。主枢数量随稳定真实位格数为一至三，不从紫府数量额外增加。

### 辅枢

辅枢是未担任目标位格主承载、但与该位格明确兼容的镇府神通支撑表现。辅枢可提供被动、触发、资源循环、抗性、范围、代价减免或丹域回响，但不能越过目标位格边界，也不复制神通实例。

### 丹器显化

丹器显化是部分丹相的外在表现，用于替代旧“本命法宝”的通用地位。它不是所有金丹的必备系统：

- 剑修可显化丹剑或雷印。
- 符修可显化本命法箓或法坛。
- 丹修可显化丹炉或丹火法坛。
- 军阵修士可显化令旗、兵符、战鼓或阵图。
- 魂修、梦修、因果修可以显化梦界、魂灯、因果线等非实体形态。

## 三、生成规则

丹相由五层输入共同生成：

| 输入 | 决定内容 |
| --- | --- |
| 一至三个稳定源/化/界位格 | 各自的世界变量、对象、边界、代价和允许的丹枢接口 |
| 占据状态 | 夺取、继承、敕封、暂寄或自辟带来的稳定度与使用边界 |
| 丹名 | 丹相主题、道途标签和可兼容主枢方向 |
| 丹性 | 五行/变异/特殊属性、环境回响和属性匹配 |
| 全部已建紫府 | 府体效果、镇府神通、府间节点、触发链与资源循环 |

生成流程：

1. 检查道基第四阶段、至少一座完整紫府及其镇府神通、丹材和第一个目标位格条件。
2. 确认当前一至三个稳定源/化/界位格及占据状态，并从矩阵读取各自变量、边界与代价。
3. 将全部已建紫府共同接入唯一丹枢核心，根据丹名、丹性和镇府神通确定唯一丹相的主题与可用表现。
4. 以丹枢将个人表现限制在矩阵允许的六项个性化字段内。
5. 每个 `STABLE` 位格从兼容镇府神通中指定不同主承载并形成主枢；其余明确兼容输入形成辅枢。
6. 若适合外显器物或景象，则生成丹器显化；否则保持为丹域、魂景、法箓、军阵等非器物形态。

## 四、与旧系统的关系

### 旧本命神通

旧本命神通不再作为金丹能力总称。其来源必须写为：源术法按升格方案成为镇府神通，再作为某个稳定位格的主承载或辅助输入进入同一个丹相。

“本命神通”可保留为 UI、民间称呼或旧内容兼容别名，但不能作为系统字段或独立数量规则。

### 旧本命法宝

旧本命法宝不再作为金丹通用系统，迁为丹器显化。太一道庭的本命符箓和本命法坛是法箓道基的门派表现，仍须受目标席位、占据状态、唯一丹相和丹枢约束，不另建生命周期或第二核心。

### 旧丹籍层级

正籍、辅籍、敕籍、寄丹不再是金丹层级。旧文本中的寄丹语义迁为“暂寄占据状态”：暂寄保留不完整丹相和辅枢残影，但不生成丹相主枢。其余旧层级差异必须迁为具体源/化/界席位及占据状态，不能以名称直接保留。

## 五、门派示例

下表只展示五类紫府与门派主题的兼容方向，不表示角色必然建成五府。实际丹相只读取结丹时已建成的 1～5 座紫府及其镇府神通。

### 玉清崖：九霄雷劫丹相

| 紫府类别 | 镇府神通方向 | 丹枢表现 |
| --- | --- | --- |
| 命府 | 苦行/雷体 | 承伤、代价转化、濒危强化 |
| 悟府 | 雷法参悟 | 雷法推演、雷劫印记理解 |
| 识府 | 剑心 | 命中、预判、暴击 |
| 魂府 | 劫意 | 神魂压迫、心魔抗性 |
| 运府 | 应劫 | 劫数触发、反击、爆发窗口 |

主枢可由“雷剑”或“剑心”方向形成；辅枢提供雷劫印记、承伤转化和应劫触发。丹器显化可表现为丹剑或雷印，但不得把雷剑表现扩展为目标席位以外的世界变量。

### 太虚观：南华梦魂丹相

| 紫府类别 | 镇府神通方向 | 丹枢表现 |
| --- | --- | --- |
| 魂府 | 梦界 | 控场、入梦、恐惧 |
| 识府 | 观照 | 命中、识破、控制判定 |
| 运府 | 因果 | 反制、转嫁、触发 |
| 悟府 | 虚实参悟 | 虚实推演、术法折返理解 |
| 命府 | 替劫 | 保命、复原、代价吸收 |

主枢可由“梦界”或“因果”方向形成；辅枢提供虚化、替劫和识破能力。丹器显化不必是实体器物，可表现为梦界、魂灯或因果线。

### 混元山：混元铁军丹相

| 紫府类别 | 镇府神通方向 | 丹枢表现 |
| --- | --- | --- |
| 命府 | 铁骨 | 减伤、再生、格挡 |
| 悟府 | 军势参悟 | 阵势推演、号令理解 |
| 识府 | 号令 | 阵型、协同、目标锁定 |
| 运府 | 胜机 | 追击、暴击、战机触发 |
| 魂府 | 军魂 | 士气、恐惧抗性、队友支援 |

主枢可由“铁骨”或“征旗”方向形成；辅枢提供阵型压制、协同攻击和士气循环。丹器显化可表现为令旗、兵符、战鼓或阵图。

## 六、数据与文档落点

1. `docs/基础设定/修行境界.txt` 与 `docs/基础设定/境界特性.txt`
   - 以“位格 + 占据状态 + 丹名 + 丹性 + 丹相”描述金丹。
   - 以“全部已建紫府 -> 唯一丹枢核心 -> 各稳定位格主／辅承载 -> 唯一丹相”描述能力承接。

2. 角色养成功法、术法、神通规范与模板
   - 使用“一至三个稳定源化界位格、占据状态、丹相适配、丹枢接口、全部已建紫府与镇府神通绑定”字段。
   - 不再要求每个术法直接变成主枢。

3. TQ-015C/TQ-013C 数据迁移
   - 先建立字段差异表，再改 BattleSim、Unity 或 CSV。
   - 旧稿列出的字段名只作为差异分析输入，不是现行 schema；先锁定一核心、一丹相、全部紫府输入、不同主承载和唯一实例账本语义，再设计字段。
   - 数量阈值、槽位加成与成丹判定必须由 BattleSim 验证后锁定。

## 七、平衡原则

1. 丹相替代旧本命神通/本命法宝总称，不额外叠加一套无来源能力。
2. 矩阵的通用效果不能由丹枢或丹相覆盖；战斗表现只是个性化出口。
3. 每个稳定位格的主枢承担该位格的主要稳定表现；辅枢承担明确兼容的支撑，全部仍属于同一个丹相。
4. 暂寄不是坏档，但必须有稳定度、代价或功能缺口，且不生成主枢。
5. 丹器显化不强迫所有路线拥有实体法宝。
6. 丹相必须反映筑基期选择；已建紫府集合不同，即使丹名相同，丹相表现也应不同。

## 八、已锁定与待迁移项

已锁定：

1. 系统名使用丹相、丹枢、镇府神通和丹相主枢。
2. 暂寄不生成丹相主枢。
3. 丹枢仅为源化界席位允许的个性化接口。
4. 丹器显化为可选外显形态。
5. 每个金丹角色只有一个不可变丹枢核心和一个丹相；全部已建紫府共同进入其中。

待 TQ-015C/TQ-013C 锁定：

1. 全部紫府输入、府体效果与主／辅连接的数值预算。
2. 丹相主枢／辅枢的具体表现、槽位占用和数值成长。
3. BattleSim、Unity 与 CSV 的字段落地与兼容迁移。
