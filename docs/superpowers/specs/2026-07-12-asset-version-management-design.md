# 单人 AI 开发资产版本管理设计

## 目标

在不迁移 SVN 或 Unity Version Control 的前提下，为天章游戏建立可复现、可审查、可备份的美术资产管理流程：GitHub 管理工程事实，Git LFS 管理正式运行时二进制资源，本地 `assets/source/` 保存原始素材工程文件。

## 决策与边界

- 版本控制主系统为 Git + GitHub；不迁移 SVN，也不在当前阶段引入 Unity Version Control（UVCS）。
- `assets/source/` 是本地原始素材工作区，必须由 `.gitignore` 排除；它不是 GitHub 内容，也不是唯一备份。
- 百度网盘可作为 `assets/source/` 的异地备份目的地。它只保存加密或可校验的备份副本，不承担提交历史、分支、差异审查或构建复现职责。
- 游戏构建所需的导出资源属于 `src/Assets/Art/`，必须进入 Git；可执行的大二进制格式由 Git LFS 存储。
- Unity 的 `.meta`、`.unity`、`.prefab`、`.asset`、`.mat` 保持普通 Git 追踪，不进入 LFS。这样保留文本序列化、GUID 引用和可审查差异。
- 不为尚未存在的美术资源创建占位资源或空 `Art` 目录；目录在首批真实资源导入时建立。

## 资源流

```text
assets/source/（本地原始文件，Git 忽略）
    -> 导出、压缩、导入
src/Assets/Art/（正式游戏资源，Git LFS）
    -> Unity 构建
Git tag（代码、配置与正式资源的可复现游戏版本）

assets/source/（关键里程碑副本）
    -> 百度网盘备份
```

## LFS 规则

根目录 `.gitattributes` 将跟踪正式游戏资源中常见且不可文本合并的二进制格式，包括：`.psd`、`.psb`、`.png`、`.jpg`、`.jpeg`、`.tga`、`.exr`、`.hdr`、`.wav`、`.mp3`、`.ogg`、`.flac`、`.aiff`、`.fbx`、`.blend`、`.mp4`、`.mov`、`.webm`、`.ttf` 与 `.otf`。

规则仅覆盖 `src/Assets/Art/` 下的匹配文件，避免把文档、参考图和本地原始素材误推入 LFS。首批资源导入前必须用 `git check-attr filter -- <path>` 验证目标文件具有 `filter=lfs` 属性。

## 资源登记与备份

仓库将保存一份资源登记册模板。每个正式资源批次至少记录：原始文件的 `assets/source/` 相对路径、导出文件的 `src/Assets/Art/` 相对路径、用途、导出日期、导出者、对应 Git tag 或提交。

原始素材的备份规则：完成一个可用素材批次或达到每周一次的最低频率后，将 `assets/source/` 的变更备份至百度网盘；备份包使用日期和 Git tag 命名，并在上传后通过文件大小或校验和确认。百度网盘中的副本不得取代本地工作副本与 GitHub 中的正式资源版本。

## 工作流

1. 在 `assets/source/` 创建或编辑原始素材。
2. 导出适合 Unity 的正式资源，并放入 `src/Assets/Art/`。
3. 更新资源登记册，建立原始文件与导出文件之间的可追溯映射。
4. 检查新资源的 LFS 属性并运行 `git lfs fsck`。
5. 运行与改动范围相关的 Unity、数据链路或构建验证；随后提交普通 Git 元数据和 LFS 指针。
6. 在可运行里程碑创建 Git tag；备份当前 `assets/source/` 到百度网盘。

## 自动化与失败处理

- 自动控制器仅在本轮变更涉及 `.gitattributes`、`src/Assets/Art/` 或资源登记册时追加 LFS 完整性检查；其他任务不增加无关耗时。
- 若二进制资源未被 LFS 规则覆盖，或 `git lfs fsck` 失败，任务必须失败关闭，不得提交为可复现版本。
- 若原始文件缺失、登记册映射缺失或百度网盘备份未验证，正式资源仍可作为代码改动提交，但该素材批次不得标为“可恢复原始工程”。

## 任务拆分与优先级

资产版本管理任务登记为 P1 工程治理 backlog，不进入当前 `1` 队列抢占 G2/G3 P0 可信度闸门任务。

1. **AVM-01：资产版本管理基线** — 创建 `.gitattributes`、更新 `.gitignore`、新增资源规范及登记册模板；验证 LFS 跟踪边界。
2. **AVM-02：正式资源入库检查** — 增加对 `src/Assets/Art/` 的 LFS 覆盖与文本资产排除检查，并接入条件化自动工作流。
3. **AVM-03：首批真实资源试运行** — 在第一批美术资源出现时验证原始文件、导出资源、LFS、干净工作区恢复和 Unity 构建闭环。
4. **AVM-04：规模复盘** — 按季度或当 LFS 存储、下载耗时、备份可靠性触及阈值时评估；只有多人并发不可合并资源冲突或 LFS 形成实证瓶颈时，重新评估 UVCS。

## 验收标准

- 新的正式二进制资源不会以普通 Git blob 提交。
- Unity 文本资产与 `.meta` 不会被误转入 LFS。
- 任一发布 tag 都能从 GitHub 获取代码、配置和正式资源，并完成 Unity 构建。
- 资源登记册能从任一正式资源定位其本地原始文件路径。
- 每个原始素材关键批次至少有一份经确认的百度网盘备份。
