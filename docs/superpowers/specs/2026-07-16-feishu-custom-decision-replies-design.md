# 飞书决策卡短按钮与自定义回复设计

**日期：** 2026-07-16
**状态：** 已获用户批准，待实施计划
**依赖：** `2026-07-15-feishu-decision-channel-design.md`、飞书长连接桥接服务、控制器 schema v7

## 目标

修复飞书移动端决策卡按钮文字被截断的问题，并在 A/B/C 都不符合用户意图时，同时提供两条自定义回复路径：

1. 直接在卡片内输入并提交自定义方案。
2. 向机器人发送带决策编号和固定前缀的普通文字消息。

两条路径必须进入同一套身份校验、决定绑定、去重和落库流程。普通聊天不得被误识别为决定。

## 已批准的产品决策

- 卡片正文继续完整展示问题、A/B/C 说明、推荐项和影响。
- A/B/C 按钮只显示 `选择 A`、`选择 B`、`选择 C`，不得重复放入完整选项说明。
- 卡片增加自定义方案输入框和 `提交自定义方案` 按钮。
- 卡片明确展示可复制的文字回复格式：`DEC-编号：自定义 <你的方案>`。
- 同时支持卡片输入和普通文字消息，两者直接登记，不增加二次确认。
- 成功登记后必须回显决定编号和已登记内容；首个有效回复胜出。

## 非目标

- 不搜索飞书聊天历史，也不让模型读取自然语言会话来猜测决定。
- 不接受缺少决定编号或 `自定义` 前缀的普通消息。
- 不允许自定义回复创建新决定、修改其他决定或覆盖已解决决定。
- 不在按钮、日志、公开项目状态或发送意图中复制完整自定义内容。
- 不改变 A/B/C 现有语义和推荐项样式。

## 卡片交互

### A/B/C 区域

正文中的选项保持以下形式：

```text
A：完整选项说明
B：完整选项说明
C：完整选项说明
```

下方三个按钮固定为：

```text
选择 A
选择 B
选择 C
```

推荐项仍使用主按钮样式，但按钮文案不附带说明。这样移动端无需依靠按钮宽度理解选项，完整语义只在正文维护一份。

### 自定义输入区域

卡片使用飞书官方表单容器，包含：

- 一个多行文本输入组件，名称固定为 `customDecision`。
- 占位提示：`输入你希望采用的方案（最多 1000 字）`。
- 一个提交按钮，文案固定为 `提交自定义方案`。
- 提交动作携带既有 `decisionId` 和 `cardNonce`，自定义内容由回调的表单值提供，不写入按钮 value。

空白内容、超过 1000 个 Unicode 字符的内容或含不安全控制字符的内容不得提交到收件箱。内容在校验前统一 CRLF/CR 为 LF，并只去除首尾空白；正文内部换行予以保留。

### 可复制文字格式

卡片在自定义输入区域下方显示：

```text
也可直接发消息（长按复制格式）：
DEC-20260715-75D7BA2AF210：自定义 <你的方案>
```

决定编号使用当前卡片的真实编号。该格式必须作为独立文本显示，不嵌在按钮文案中。

## 普通文字消息协议

桥接服务新增飞书新消息事件处理，但只接受文本消息。规范格式为：

```text
DEC-YYYYMMDD-ID：自定义 <自定义内容>
```

解析规则：

- 允许中文全角冒号或 ASCII 冒号。
- 决策编号必须完整且与当前有效绑定逐字一致。
- `自定义` 为必需固定前缀，前后只允许常规空白。
- 前缀后的内容不能为空，规范化后最长 1000 个 Unicode 字符。
- 不匹配格式的普通消息不登记为决定。
- 只有已配对操作人、预期租户、当前有效会话和未过期决定可以提交。
- 非文本消息、机器人消息、未配对账号和错误会话一律静默拒绝，且不得暴露待决策信息。

已配对操作人在正确会话中发送近似但不合法的格式时，机器人可回复一次简短用法提示，并带上当前决定的可复制格式。提示发送必须按 provider event ID 去重，避免飞书重投造成刷屏。

业务卡发送成功时，发送器从飞书响应中取得会话标识，只把其 SHA-256 摘要写入当前私有决定绑定。普通文字事件的会话标识必须与该摘要匹配；项目状态、控制器状态和发送意图都不保存原始会话标识。

## 统一回执模型

### 回执类型

现有 A/B/C 回执保持 `decision_reply`。自定义回复使用独立类型 `decision_custom_reply`，避免一个对象中出现互斥的 `optionKey` 和 `customText`。

卡片输入形成的自定义回执至少包含：

```json
{
  "kind": "decision_custom_reply",
  "decisionId": "DEC-20260715-75D7BA2AF210",
  "customText": "采用明确的双通道字段，但只迁移攻击术法",
  "cardNonceHash": "64-lowercase-hex",
  "providerMessageIdHash": "64-lowercase-hex",
  "providerEventIdHash": "64-lowercase-hex",
  "operatorOpenIdHash": "64-lowercase-hex",
  "tenantKeyHash": "64-lowercase-hex",
  "receivedAt": "2026-07-16T00:00:00.000Z",
  "source": "feishu_card_input"
}
```

普通文字形成相同类型的回执，`source` 为 `feishu_text`。文字消息没有卡片 nonce，因此由当前有效决定绑定、决定编号、已配对身份、租户、会话和消息事件 ID 共同约束；其 HMAC 信封不伪造空 nonce 字段。

### 持久化

控制器状态升级为 schema v8。v8 的 resolution 必须恰好是以下两种形态之一：

```json
{ "optionKey": "A", "source": "feishu_card", "resolvedAt": "...", "evidenceHash": "..." }
```

```json
{ "customText": "...", "source": "feishu_card_input", "resolvedAt": "...", "evidenceHash": "..." }
```

自定义来源只允许 `feishu_card_input`、`feishu_text` 和显式人工兜底 `manual_custom`。v7 状态原地、单向迁移到 v8；既有 A/B/C resolution 和 Gmail legacy 证据保持不变。不得把自定义内容塞入 `optionKey` 或伪造一个 D 选项。

本机 HMAC 收件箱可以保存自定义原文，因为目录已受私有 ACL 保护。公开日志、健康文件、发送意图和项目状态只记录类型、长度、时间和摘要，不记录原文。

## 处理顺序与冲突

1. 桥接层先做结构快照、身份、租户、会话、决定绑定、有效期和内容校验。
2. 合格事件写入原子 HMAC 信封；provider event ID 用于重投去重。
3. 消费器同时识别 A/B/C 与自定义回执，并按 `receivedAt` 选择首个有效回复。
4. 同一决定的相同回复重投视为幂等；不同回复同时到达时，最早有效回复胜出，其余移入 quarantine。
5. 控制器落库后返回原始 TaskId 和 `InspectCandidate`，与现有 A/B/C 闭环一致。
6. 已解决决定的后续卡片点击或文字消息不得覆盖 resolution。

## 用户反馈

- A/B/C 卡片点击成功：沿用只读卡片和成功 toast。
- 卡片自定义提交成功：卡片替换为只读状态，显示 `已登记自定义方案`、决定编号和规范化后的内容。
- 普通文字登记成功：机器人在同一会话回复一条确认消息，显示决定编号和规范化后的内容。
- 自定义内容无效：卡片回调返回可操作的错误提示；正确会话中的文字消息返回一次格式提示。
- 决定已解决、绑定过期或身份不符：不修改状态；对未配对身份保持静默。

所有确认发送都必须以决定编号和事件摘要为幂等键，飞书重投不得产生多条确认消息。

## 安全与权限

- 新增普通文字路径只订阅飞书官方的新消息事件，不查询历史消息。
- 部署时仅申请接收机器人会话文本消息所必需的最小权限，并在开发者后台启用对应长连接事件。
- 回调解析继续使用字段白名单、数据属性快照、长度限制和 HMAC 信封；不记录原始事件。
- 卡片 value 只携带类型、决定编号、选项键或 nonce，不携带自定义原文。
- 文本事件只允许当前私有配置中的已配对操作人和预期会话。
- 自定义原文属于决定业务数据，只允许进入私有收件箱和控制器私有状态；发布到项目状态时只写摘要结论。

## 组件边界

- `card.mjs`：渲染完整正文、短按钮、表单输入和可复制格式。
- 卡片回调解析器：识别 A/B/C 按钮与表单提交，输出规范化的内部回执。
- 新消息解析器：只解析严格格式的文本事件，不负责状态落库。
- HMAC 信封与 inbox：保存、校验、去重并选择首个有效回执。
- PowerShell 控制器与状态工具：升级 schema v8，持久化 option 或 custom resolution，并恢复原任务。
- setup/canary：分别验证 A/B/C、卡片自定义输入和严格格式文字消息三条真实链路。

## 错误处理

- 飞书未授权新消息事件时，卡片 A/B/C 和卡片输入仍可工作；健康状态应明确报告 `TEXT_REPLY_UNAVAILABLE`，不得把整个卡片通道误报为离线。
- 卡片表单字段缺失或形状不符时拒绝回调并记录净化分类，不记录字段值。
- 文字事件格式错误时不得写 inbox；用法提示失败不影响决定通道，也不自动重试为新的 provider 消息。
- 控制器无法持久化 v8 resolution 时保留已签名信封供后续重试，不提前移动到 processed。
- 自定义回复与 A/B/C 冲突时不得让模型选择赢家，完全按首个有效 `receivedAt` 和现有去重规则处理。

## 测试与验收

### 离线测试

- 卡片快照证明按钮只有 `选择 A/B/C`，完整说明只出现在正文。
- 卡片包含输入框、提交按钮和带真实决定编号的可复制格式。
- 卡片回调测试覆盖空白、超长、控制字符、合法多行、错误 nonce、错误身份和重投。
- 文字解析测试覆盖全角/半角冒号、错误决定编号、缺少前缀、非文本消息、错误会话和未配对身份。
- HMAC/inbox 测试覆盖两类 payload、首个有效回复、同值幂等、冲突 quarantine 和原文不出日志。
- 状态与控制器测试覆盖 v7→v8 迁移、custom resolution、恢复 TaskId、重复消费和人工自定义兜底。
- setup 测试证明文字事件权限缺失只降级文字路径，不影响卡片路径。

### 真实飞书验收

1. 发送一张测试决定卡，确认移动端三个按钮均完整显示 `选择 A/B/C`。
2. 在卡片输入自定义内容并提交，确认卡片变为只读且控制器只登记一次。
3. 发送卡片中展示的严格格式文字，确认机器人回复已登记且控制器只登记一次。
4. 发送不带前缀的普通聊天，确认不会解决决定。
5. 用未配对账号、错误决定编号和过期卡片测试，确认均不会落库。
6. 对同一事件触发重投，确认 inbox、resolution 和确认消息均保持幂等。

## 发布顺序

1. 先完成当前飞书桥接回调兼容、发送器静默输出和私有 ACL 修复，恢复稳定 v7 基线。
2. 在离线测试中实现卡片短按钮和两条自定义回复路径，并迁移状态到 v8。
3. 在飞书开发者后台启用新消息长连接事件和最小权限。
4. 运行三路 canary：A/B/C、卡片输入、严格格式文字。
5. 发布控制器状态与提示词，最后恢复唯一自动化写入器。

## 验收标准

- 移动端按钮不再包含会被截断的选项说明。
- 卡片输入与严格格式文字消息都能登记同一类自定义 resolution。
- 卡片明确展示可复制的真实决策编号回复格式。
- 普通聊天、错误账号、错误会话、错误决定和过期事件都不会被登记。
- 首个有效回复胜出，重复和冲突事件不会覆盖决定。
- 自定义原文不进入日志、发送意图、健康文件或公开项目状态。
- v7 历史无损迁移到 v8，现有 A/B/C 工作流继续通过。
