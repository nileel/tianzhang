# 战场角色静态 3D 棋子／2D 战术精灵并行评估设计

状态：2026-08-21 用户批准；2026-08-23 固定比较完成，2D 战术精灵胜出，父项待汇总。

## 一、决策背景

- 项目继续使用固定正交斜俯视的 2.5D 六角战斗场景；规则、朝向判定和战斗结果不因视觉路线改变。
- 既有 Tripo 绑定人形在脸部身份、宽袖结构、蒙皮动作和烘焙贴图上连续失败，继续修补已超出最简单可控路线。
- 既有角色立绘的姿势为头像／剧情 UI 服务，不适合直接放入战斗场景。无论静态 3D 或 2D 路线，都必须重新生产适配固定战术镜头的战斗姿态美术；旧立绘只提供身份、服饰、配色和气质参考。
- 本轮只比较战场角色表现路线，不晋升正式 Adventure 资产，不修改战斗、空间、装备或存档规则。

## 二、共同评估合同

- 固定样例角色为苻渊；两条路线使用相同身份、服饰、主色、战术占格、世界尺度、六向定义和固定相机。
- 固定表现语义为待机、移动、基础攻击、受击、施法和死亡。表现可以不同，但不得改变触发时机或规则结果。
- 对比证据使用相同分辨率、相同场景光照、相同地块、相同六向和相同动作时点。
- 共同硬门为：身份可辨、六向可读、占格与遮挡稳定、无明显生成污染、运行时结果不变、可形成可重复生产合同。
- 现有立绘不得缩小、裁切或简单透视变形后冒充战场角色素材。

## 三、静态 3D 棋子路线

1. 先冻结自然战斗定姿、轮廓、持物、宽袖收束、六向可读和独立修炼底座接口，再重新生成苻渊战斗姿态四视图。四图必须是同一自然定姿和一致服饰结构，不复用现有站立立绘姿势。
2. Tripo 只生成无运行时骨骼动画的静态人物候选；不要求 Quad，不自动绑定，不消费平台动作。发起任何会消费 credits 的操作前必须取得用户对该次消费的单独授权。
3. Blender 只对同一原包做静态检查、最小清理、材质／法线验证、尺度／朝向冻结和候选导出；不得恢复换头、袖根蒙皮或统一骨架修补路线。
4. Unity 中以角色根节点和表现特效完成移动、攻击、受击、施法和死亡：允许抬起—移动—落下、倾斜、震动、短促位移、倒伏和一次性特效，不允许运行时骨骼动画。
5. 修炼底座是独立可替换 3D 组件，不与人物网格合并；本轮只证明接口和最小占位，不生产完整境界批次。

## 四、2D 战术精灵路线

1. 重新绘制适配斜俯视战场的苻渊六向战术精灵；姿态、透视、脚底锚点、武器与宽袖轮廓以战场可读性为准，不复用现有立绘姿势。
2. 六向战术精灵是独立战场资产，不是 UI 立绘的缩略图。可使用有限帧或切换图，但本轮不要求完整逐帧动画集。
3. Unity 中使用同一角色根节点、六向选择和表现事件；移动、攻击、受击、施法、死亡必须与静态 3D 路线在相同时点取证。
4. UI 头像、剧情半身像和战术精灵可以共享身份与配色事实，但不得共享不适合目标用途的姿态成品。

## 六、比较与唯一收口

- 比较维度固定为：身份保持、固定镜头六向辨识、动作语义可读、遮挡与占格、资产稳定性、单角色生产成本、批量扩展成本、外观变化承载能力、Unity 复杂度和后续维护风险。
- 任一路线未通过共同硬门即记为失败，不用降低分辨率、减少方向、隐藏污染、追加平台生成或改变战斗规则换取通过。
- 两条路线都完成后必须给出“静态 3D 胜出”“2D 胜出”或“两者均失败”之一。两者均失败时父项保持 blocked 并请求用户决定，不自动建立混合第三路线。
- 父项关闭时才允许重写正式角色生产设计和后续 Adventure／外观任务依赖；本轮不提前晋升项目资产。

### 6.1 固定证据核对

- 两条路线都通过共同硬门。静态 3D 采用 `docs/superpowers/specs/2026-08-21-static-3d-chess-character-production-contract.md`、四视图联系表、Blender 候选和 `U-CHAR-STATIC-CHESS-PROTO-01` 的归档矩阵；2D 采用 `docs/superpowers/specs/2026-08-21-2d-tactical-character-production-contract.md`、六向联系表和 `U-CHAR-2D-TACTICAL-PROTO-01` 的独立复审归档矩阵。
- 两者均是苻渊的重新生产战斗姿态，且没有把 UI 立绘当作战场输入。静态 3D 的四视图及唯一闭合无动画候选可回指 `assets/generated-character-art/fuyuan-static-chess-battle-pose/fuyuan_static_chess_fourview.png` 与 `开发管理/苻渊静态棋子Blender候选验证记录.txt`；2D 的同源六向样张可回指 `assets/generated-character-art/fuyuan-2d-tactical-sprite/fuyuan_tactical_six_direction.png` 与其 `prompts.md` 哈希记录。
- 两个 Unity 样例均在同一 `AdventureScene/VisualBaselineBoard`、同一正交相机、地块、遮挡物、六向映射 `90/150/210/270/330/30`、六种表现事件和 1920×1080 输出条件下取证。`开发管理/苻渊静态棋子Unity战术样例验证记录.txt` 与 `开发管理/苻渊2D战术精灵Unity样例验证记录.txt` 均证明根节点表现不写回规则；后者的已归档独立复审还确认 2D 与 3D 路线互斥、2D 局部遮挡和 3D 直立／底座位置。

### 6.2 评分与结论

- 评分为相对路线分，`5` 表示在本固定样例和合同下最适合作为后续生产方向，`1` 表示最弱；十项等权。共同硬门先于评分，任一硬门失败不会由总分覆盖。

| 维度 | 静态 3D 棋子 | 2D 战术精灵 | 固定证据结论 |
|------|--------------|-------------|--------------|
| 身份保持 | 3 | 5 | 两者均保留苻渊身份；固定镜头下 2D 保留脸、黑白金服饰和宽袖的大色块更清楚，3D 的细节与材质在远景更易丢失。 |
| 六向辨识 | 3 | 5 | 两者均有六向和规则映射；2D 联系表与 2D-only 固定图更直接区分正、侧、背的轮廓。 |
| 动作语义可读 | 3 | 4 | 两者都只由共享根节点事件表现，规则时点一致；2D 的清晰轮廓令移动、攻击、受击、施法、死亡的根节点变化更容易读取。 |
| 遮挡与占格 | 4 | 4 | 静态 3D 独立底座接地通过；2D 统一 pivot 接地及局部遮挡数值通过，均未以私有变换规避。 |
| 资产稳定性 | 4 | 5 | 静态候选的闭合流形、贴图和无动画验证通过；2D 以同一来源图、六槽哈希和统一导入合同减少模型、贴图与轴适配风险。 |
| 单角色生产成本 | 2 | 4 | 静态 3D 需要四视图、一次受控平台生成、Blender 静态 QA 和 FBX／材质导入；2D 只需合同化六向源图、分槽和导入。 |
| 批量扩展成本 | 2 | 4 | 静态 3D 每角都重复平台、静态结构与导入 QA；2D 可复用同源六向、pivot 和表现合同。 |
| 外观扩展承载 | 4 | 3 | 静态网格与独立底座在单件外观层面更易承载材质／几何变化；这项优势不足以抵销其生产和维护成本。 |
| Unity 复杂度 | 3 | 4 | 两者控制器都只写根节点；2D 省去 FBX、URP 材质、模型轴适配和独立 3D 资产链。 |
| 后续维护风险 | 2 | 4 | 静态 3D 仍需维护模型、贴图、导入轴与底座接口；2D 的输入、方向、pivot 和遮挡边界更集中且可哈希复核。 |
| **总分（50）** | **30** | **42** | **2D 战术精灵胜出。** |

- 结论：选择 **2D 战术精灵** 作为正式战场角色生产方向。静态 3D 样例的共同硬门和隔离技术矩阵仍保留为历史证据，不接入正式单位，也不以本结论重开 Tripo、Blender、骨骼或第三路线。
- 本比较只解锁 `A-CHAR-BATTLE-VISUAL-DIRECTION-01` 的汇总职责；正式角色生产设计、Adventure 接入和外观依赖仍由该父项在后续独立状态事件中收口。

## 八、停止条件

- 需要消费 Tripo credits 而没有新的明确授权。
- 任一路线需要修改战斗规则、方向判定、占格、装备或存档所有权。
- 静态 3D 又需要运行时骨骼动画、换头、宽袖蒙皮或连续局部补丁才能成立。
- 2D 路线只能通过缩小旧立绘、减少六向或逐角色无合同手修才能成立。
- 比较过程中开始叠加第三条工作流、两条路线使用不同测试条件或无法形成唯一结论。
