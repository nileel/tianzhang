## 一、授权、证据与非结论

本方案只定义苻渊在《天章》固定斜俯视六角战场中的静态 3D 动态表现 pilot，以及该 pilot 进入隔离比较入口的生产合同。角色始终是完整的静态微缩模型，而不是字面意义的卡牌；剧情／UI 立绘、正式单位、遭遇、规则和存档都不在本方案范围内。

炉石传说、游戏王与万智牌式数字卡牌／棋子画面只提供 E3 级的产品画面语法：静态承载体可借整体位移、特效、音效和界面／镜头反馈取得事件可读性。它们没有披露《天章》所需的模型、骨骼、材质、特效、声音、运行时结构、工时或成本，不能作为任何生产事实。本方案的机制选择来自用户明确收敛的范围，P1 则只证明苻渊已有六向根节点、抬起—移动—落下和规则隔离的机制家族；它不证明攻击、受击、死亡、宽袖、武器、批量角色、换装或成本已经通过。

唯一角色输入保持已验证的 `FuYuan_StaticChess.fbx`、正确的 BaseColor、现有 URP 材质与 Prefab。Blender 候选的单一静态网格、无 Armature／Action、`Y=0` 接地、`1.03 m` 高度、单位缩放、导出本地 `+Z` 正面／`+Y` 上方，以及 Unity 的 `FuYuan_Model` `-90° X` 资产级导入轴适配继续有效。不得重新导出 FBX、换模型、换 Pose、换头、绑定、蒙皮、动画剪辑或以多模型替换表达动作。

## 二、冻结的表现单位与责任分工

一个可交付 pilot 单位是“苻渊的唯一静态 3D 载体 × 六向 × 六个表现事件”的一个版本。六个事件固定为 `idle`、`move`、`attack`、`hit`、`cast`、`death`，方向固定为索引 `0..5` 与根节点 Y 旋转 `90/150/210/270/330/30°`。方向仍由既有规则 facing 消费；表现层不镜像、不重排、不自行转向，也不拥有位置、占格、路径、伤害、状态、死亡结算或存档。

| 单位 | 冻结内容 | 明确不允许 |
|------|----------|------------|
| 角色模型与 Pose | 已有单一 `FuYuan_StaticChess.fbx`、同一自然定姿、`FuYuan_Model` 和独立 `StaticChessBase`。 | 新 Pose、备用模型、骨骼、AnimationClip、Animator、SkinnedMeshRenderer、武器替换或把底座并入人物。 |
| 根节点动态 | `StaticChessPresentationController` 只写角色根节点的位置／旋转；每个事件结束恢复捕获的根姿态。 | Root Motion、角色根回写规则位置／Facing、按方向或镜头加私有补偿。 |
| 材质 | 继续使用已修正 BaseColor 的 `FuYuan_StaticChess.mat`；黑／灰／金身份主色、材质引用和 URP Lit shader 在所有事件中不变。 | 重压缩／替换 BaseColor、读取其他 PBR 贴图作猜测性补偿、透明化、发光、共享材质写入或以材质遮盖接地／轮廓问题。 |
| 一次性特效 | 一个由 Unity 内置粒子／简单几何构成的 `FuYuan_StaticChessMotionFx.prefab`，只在本节的时点短暂播放。 | 新角色网格、常驻光环、遮住人物／地面／遮挡关系的全屏效果，或使特效成为规则状态所有者。 |
| 音效 | `move`、`attack`、`hit`、`cast`、`death` 各一条短促 cue；`idle` 无 cue。 | 未授权第三方样本、语音／音乐、以声音替代缺失的视觉语义，或把 cue 成本记为零。 |

pilot 在 `assets/source/characters/platform-evaluation/tripo/static-chess-fuyuan/motion-pilot/` 只形成一份 `fuyuan_static_3d_motion_manifest.json`、五条 cue WAV 和生产记录。manifest 必须锁定静态输入的路径／SHA-256、六向映射、下表时点、每个 VFX／cue 的来源与许可、输出 SHA-256、人工判定和失败／返工。没有本地可编辑声音来源、许可或可复核哈希时停止；不得下载、消费 credits 或用未记录的免费素材填充。

## 三、六类语义、时点与复位合同

所有时点以事件自身归一化进度表示；它们只是表现事件内部的节奏，不改变战斗规则已决定的事件次序、命中、位置或结算时点。持续时间先固定为 `move/attack/hit/cast = 0.32 s`、`death = 0.45 s`，pilot 必须记录实际运行测量；若固定镜头下不可读，判为失败而非偷偷延长、缩短或另建事件链。

| 事件 | 整体载体运动与时点 | 特效／音效分工 | 复位与淘汰条件 |
|------|--------------------|----------------|----------------|
| `idle` | 载体、材质、底座静止；只消费已有 facing。 | 无新特效、无 cue。稳定阴影／底座是接地线索，不改变人物。 | 非静止、骨骼呼吸、自动朝向或接地线不可见即失败。 |
| `move` | `0.00–0.15` 抬起；`0.15–0.85` 沿已批准的 world destination 平移；`0.85–1.00` 落下。 | `0.85` 在脚下／底座锚点播放短促接触环，播放 `move` cue；角色材质不变。 | 结束恢复根姿态；任何浮空、穿格、私有路径、子网格／底座变换或未复位即失败。 |
| `attack` | `0.00–0.20` 预备；`0.20–0.55` 沿本地前方短促前探并前倾，`0.55` 为命中画面，随后回收。 | `0.55` 在载体前方播放短促命中火花／切线效果与 `attack` cue；不假定武器存在。 | 结束恢复根姿态；命中点不可读、特效覆盖宽袖／脸、需要挥臂／模型变形或改变攻击时点即失败。 |
| `hit` | `0.00–0.10` 命中顿帧；`0.10–0.55` 小幅横向震动／后仰；随后回收。当前事件不带攻击来源，震动不得猜测来向。 | `0.10` 在载体中心播放短促受击火花与 `hit` cue。 | 结束恢复根姿态；冲击不可读、靠模型变形、把视觉震动写成击退／伤害或要求猜测攻击方方向即失败。 |
| `cast` | `0.00–0.20` 轻抬；`0.20–0.70` 保持；随后落回。 | `0.20` 在脚下以外的根锚点播放小范围施法环与 `cast` cue；现有一次性效果信号只在该时点一次。 | 结束恢复根姿态；常驻光环、特效遮脸／宽袖／接地、手臂／袖袍动画或重复 cue／信号即失败。 |
| `death` | `0.00–0.25` 降低；`0.25–0.70` 向固定本地侧方倾倒并短暂停住，`0.70–1.00` 回收以供隔离矩阵重复触发。 | `0.70` 在接地锚点播放消散／落点效果和 `death` cue；不改变材质透明度。 | 结束恢复根姿态；死亡与待机不可区分、无法看清接地、改变死亡结算／阻挡／占格，或必须隐藏／替换模型即失败。 |

攻击、受击和死亡是 pilot 的首批高风险语义，必须按此顺序先通过全部六向矩阵。苻渊当前没有武器：日志必须写 `weapon=none`，这只说明本样例未覆盖武器；任何含武器的后续角色或换装必须重新跑六向攻击／施法、前后遮挡和接地矩阵，不能继承“已通过”。

## 四、生产、Blender、导出与 Unity 路线

1. 读取批准方案、静态棋子生产合同、Blender 候选记录、材质修正记录和既有 Unity 样例记录；在 manifest 锁定唯一模型、BaseColor、材质、Prefab 与六向输入的路径和 SHA-256。模型或材质输入不匹配立即停止。
2. 建立 manifest 与生产记录，先制作／登记 `attack`、`hit`、`death` 的六向表现表，再登记 `idle`、`move`、`cast`。每次声音／效果 authoring 都记录开始结束时间、操作者、工具版本、实际费用／credits、许可、结果和返工原因。
3. VFX 只以 manifest 中的内置粒子／简单几何配方定义；不启动 Blender 去编辑角色 `.blend` 或 FBX。若选择制作任何非角色 VFX 源，必须先有本卡列出的允许路径、独立来源／许可和不影响角色模型的验证；否则停止而不是另开制作链。
4. pilot 不导出或修改角色 FBX、BaseColor、材质、Prefab、场景或 C#。它把 manifest、cue WAV 和人工矩阵交给 Unity integration；integration 才把 cue 原样导入既有角色目录、由 Builder 创建唯一效果 Prefab，并把引用写到既有表现 controller。
5. Unity 只允许扩展现有 `StaticChessPresentationController`、`VisualBaselineBuilder`、`AdventureSceneBuilder`、`SceneArchitectureValidator` 和它们的直接 EditMode／PlayMode 测试。`CombatPresentationContracts.StaticChessPresentationEvent`、`AdventureUnitSpawner`、相机、光照、九格地块、原静态模型／BaseColor／材质和 2D 样张保持原所有者与行为；不新建第二套表现 controller 或 fallback。

## 五、六向质量、接地与人工验收

自动检查只证明结构：无 Animator／AnimationClip／SkinnedMeshRenderer，所有效果和 cue 只在事件时点播放一次，根节点在每个事件后复位，人物／底座子变换与材质引用未变，六向仍为 `90/150/210/270/330/30`，规则快照不变。它不能判断动作冲击力、身份、遮挡、声音或画面可读性。

人工检查必须在 `AdventureScene/VisualBaselineBoard` 的同一相机、光照、地块、世界尺度、占格和 `1920×1080` 输出下，遍历六个方向和每一事件的开始／关键时点／结束，共 108 个观察点。每点记录“通过／失败、证据位置、判定者”；特别逐项核对：

- 背向镜头的两个方向与其余四向一样可辨，不因方向私有旋转、镜像或镜头偏移得到通过；
- 脸、顶髻／后发、短须、炭黑／灰白／金主色、宽袖、袍摆、双足与当前无武器事实保持一致；如未来有武器，另按第三节重跑；
- 人物脚底、独立底座、阴影／接触环或落点反馈至少有一条稳定可见的接地线索，且宽袖、腿部、武器（如有）与前后遮挡不掩盖它；
- 攻击、受击、死亡分别可读，效果不替代载体运动，不遮住身份／关键时点，不通过 Always On Top、私有地块、私有缩放或更换镜头掩盖问题；
- 以与 2D 相同的身份、服饰主色、尺度、镜头、光照、地块和战斗事件时点作最终比较；pilot 的视觉通过不替用户作路线选择。

任一方向、接地、宽袖／腿部遮挡、身份、关键语义、复位、规则隔离或声音／效果来源失败时，只保留实际证据、费用和失败原因并停止。不得以额外模型、额外 Pose、材质补偿、重新生成、credits、规则修改、运行时 fallback 或第三条视觉路线补洞。

## 六、成本、返工与扩展计量

苻渊 pilot 只记录实际值，不估算或折扣：一次性流程建立分钟、每个 cue／VFX 配方的分钟、工具及版本、外部费用／credits、制作次数、失败次数、返工次数、Blender（如实际发生）、Unity 导入、运行时接入、自动检查和人工 QA 分钟。未发生的项写“未发生”，未知项写“未知”，不得写为零。

## 七、下游卡冻结

`A-CHAR-STATIC3D-MOTION-PILOT-01` 只创建 manifest、五条已授权 cue WAV、生产记录和六向人工矩阵；它不编辑角色模型、Blender 候选、BaseColor、材质、Prefab、场景或 Unity。它只有在攻击、受击、死亡先通过、全部输入／输出哈希和实际成本完整时，才解除 Unity integration blocker。

`U-CHAR-STATIC3D-MOTION-INTEGRATION-01` 只消费完成 pilot 的 source，使用既有 `StaticChessPresentationController` 和隔离 `VisualBaselineBoard` 建立根节点、VFX、cue 和测试证据。它不改 source WAV、模型或事件枚举，不接入 `AdventureUnitSpawner`、正式单位、战斗规则或存档。两张卡的精确允许路径、验证、完成条件和停止条件已写回对应任务卡。
