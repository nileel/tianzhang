# 开发管理文档瘦身设计（方案 2）

## 目标

在不改变既有工作流路径和不删除历史证据的前提下，降低 `AGENTS.md` 与 `开发管理/` 日常入口的上下文噪声。当前文件只保留可执行规则、当前事实和未完成事项；完成过程、旧方案和验证产物迁入仓库内归档。

## 非目标

- 本轮不建立新的 `规则/当前/归档/` 顶层目录结构。
- 不改动游戏设定、Unity、BattleSim、CSV 或资产数据。
- 不删除 Git 可追溯记录，不重写历史提交。

## 保留的稳定入口

- `AGENTS.md`：硬约束、按场景读取入口、`1`/`2` 语义和关键验证要求。
- `开发管理/当前任务队列.txt`：5--10 条待处理任务及完整任务卡。
- `开发管理/任务列表/`：各分线未完成或冻结任务。
- `开发管理/审核入口.txt`、`审核规则.txt`、`状态与建议维护规则.txt`、`自动工作流规则.txt`：各自唯一职责的稳定规则。
- `开发管理/自动工作流状态.txt`、`AI合作沟通.txt`、`未通过审核清单.txt`：仅当前有效状态。

## 历史迁移规则

1. 已完成任务的过程、审核日志、旧方案和已替代的扫描报告进入 `开发管理/任务归档/`，文件名包含日期和主题。
2. 当前文件仅保留归档链接，且只在该链接仍是理解当前状态的必要证据时保留。
3. 专题调查在仍有未解决事项时保留单一当前清单；重复或结论已被更新事实源取代的报告归档。
4. 验证输出随对应任务归档保存，不作为管理根目录的默认读取内容。

## 本轮具体改动

1. 精简 `AGENTS.md`：删除审核历史、表格中的审核标记和重复协作细则；保留身份、事实源、设计/数值约束、按需读取和快捷流程。
2. 精简任务与状态入口：
   - `当前任务队列.txt` 移除完成日志和已完成 TQ-060 卡；保留当前五项任务。
   - `AI合作沟通.txt` 与 `未通过审核清单.txt` 清除已消费记录，仅说明当前为空及路由。
   - `开发优先级.txt`、`设计-当前状态.txt`、`设计总结.txt` 将长历史日志或旧快照归档，留下当前闸门、当前风险和事实摘要。
   - 各分线任务列表移除已完成卡的长说明，只保留必要事实摘要和未完成/冻结任务。
3. 收敛规则重复：审核入口只做路由；审核细则、协作规则、DeepSeek 提示词各自仅保留角色特有规则，并相互链接，不重复完整 `1`/`2` 流程。
4. 处理已识别冲突：
   - 不再把 TQ-060 表述为待处理。
   - 不再把 TQ-038 表述为待复审。
   - `docs-csv-asset-alignment.txt` 明确为旧快照，不作为当前数据一致性结论。
5. 记录后续任务：在任务 backlog 新增“方案 3：开发管理目录重组”，明确其前置条件、范围、风险和验收条件。

## 验证

- 运行 `tools/check-review-text.ps1` 覆盖 `AGENTS.md` 和 `开发管理`。
- 使用 `rg` 检查迁移文件的旧路径引用，确认存在的引用指向有效归档文件。
- 检查当前队列、交接队列、未通过审核清单和任务列表的状态不再互相矛盾。
- 暂存前运行 `tools/check-pending-whitespace.ps1`，暂存后运行 `git diff --cached --check`。

## 后续：方案 3（不在本轮执行）

当 G2/G3 闸门闭环、当前队列稳定且无进行中的跨文件交接时，评估“开发管理目录重组”：建立 `规则/`、`当前/`、`归档/` 分区，迁移根目录管理文件，并全仓修复引用与自动化路由。该工作需要单独设计、迁移清单和流程回归，不得与日常任务混做。
