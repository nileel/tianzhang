# 每小时自动化提交与恢复加固设计

> 日期：2026-07-14
> 状态：待用户复核
> 继承：`docs/superpowers/specs/2026-07-13-hourly-automation-controller-v2-design.md`
> 范围：修复提交命令解析失败与控制器自产脏改恢复自锁；不重构队列、执行器或业务任务路由

## 1. 问题与根因

2026-07-14 的决策归档轮次已经完成文件修改和直接相关验证，但控制器动态拼接的 PowerShell 提交命令漏写字符串结束引号。PowerShell 在解析阶段失败，因而没有执行空白检查、暂存或提交。

下一轮按 v2 规则重新创建工作区 Snapshot。Snapshot 把上轮控制器遗留的 `expectedPaths` 脏改记录为当前基线脏路径，随后普通 `Check` 又把任何与基线脏路径重叠的候选判为 `candidate_conflict`。恢复状态只保存任务、检查点和路径，没有保存原始 baseline 及中断时预期路径的内容指纹，因此无法区分控制器自产残留与后续人工编辑。两次恢复失败后状态机按设计进入 `AUTO-BLOCKED`。

本次故障包含两个独立根因：

1. 提交流程由模型临时拼装复杂 PowerShell 单行命令，语法正确性不可稳定复用。
2. 恢复协议要求证明修改所有权，但本机状态没有保存完成证明所需的跨轮证据。

## 2. 目标与非目标

### 2.1 目标

- 控制器不再动态拼装空白检查、暂存路径核验和路径限定提交的复杂单行命令。
- 已登记任务在提交前中断后，只在预期路径内容与中断证据完全一致时自动恢复。
- 预期路径被人工继续修改、预期路径外发生变化或恢复证据缺失时继续失败关闭。
- 安全提交当前已核验的决策归档，并在永久修复验证通过后解除现有 `AUTO-BLOCKED`。
- 验证限定为控制器状态、工作区保护和提交助手的直接相关回归，不运行 Unity、BattleSim 或全项目数据检查。

### 2.2 非目标

- 不改变每小时调度、任务优先级、低高水位、Codex / DeepSeek 主责或审核规则。
- 不允许仅凭路径名把任意脏改认领为控制器产物。
- 不引入 stash、reset、checkout、clean、自动推送或额外写入型自动化。
- 不把一次恢复成功条件放宽为忽略人工修改。
- 不顺带处理 TQ-057 的业务数据内容。

## 3. 方案选择

### 3.1 只修正当前命令和手工解锁

能够恢复当前轮次，但下一次修改后、提交前中断仍会进入相同恢复自锁，不采用。

### 3.2 固定提交助手加恢复证据

新增固定 PowerShell 提交助手，并在用户级状态目录保存原始 baseline 与中断时预期路径指纹。恢复时同时验证路径外基线不变和路径内指纹完全匹配。这是采用方案，直接覆盖两个根因且保持失败关闭。

### 3.3 事务工作树或自动分支

隔离更强，但会增加分支同步、合并和回滚状态，超出本次局部故障范围，不采用。

## 4. 固定提交助手

新增 `tools/automation-finalize-commit.ps1`，由控制器传入项目根目录、完整 `expectedPaths` 和提交信息。脚本按固定顺序执行：

1. 规范化并拒绝空路径、绝对路径和不安全路径片段。
2. 对完整预期路径运行 `check-pending-whitespace.ps1 -Fix`，随后无 `-Fix` 复检。
3. 记录调用前既有暂存项的路径与 blob，随后使用参数数组执行 `git add -- <expectedPaths>`，不通过字符串拼接构造命令。
4. 运行 `git diff --cached --check`。
5. 要求新增或变化的暂存项只来自 `expectedPaths`；调用前既有的路径外暂存项必须保持原路径、blob 和暂存状态，不要求工作区原本没有暂存内容。
6. 使用参数数组执行 `git commit --only -m <message> -- <expectedPaths>`。
7. 输出提交哈希；任一步骤失败均非零退出，不修改控制器完成状态。

控制器仍负责提交前后的 workspace guard `Verify`、`commit_completed` 检查点和 `Complete`。提交助手不读取任务队列、不修改本机控制器 JSON，也不自动推送。

## 5. 跨轮恢复证据

### 5.1 证据内容

本机控制器状态升级一个 schema 版本，并为活动工作单元保存最小恢复证据引用：

- 初始 Snapshot 的 baseline 文件路径及 payload hash。
- 完整、规范化的 `expectedPaths`。
- 证据生成时的 HEAD。
- 每个预期路径的 Git 状态、索引 blob、工作区内容 hash 和状态指纹。
- 证据对应的 taskId、checkpoint 和生成时间。

证据保存在 `%USERPROFILE%\.codex\automation-state\`，不写入项目、不进入提交。状态机只保存证据路径和摘要 hash，避免把大型快照嵌入控制器 JSON。

### 5.2 生成时机

workspace guard 新增一个窄动作，用原始 baseline、完整 `expectedPaths` 和当前工作区生成原子证据文件。控制器在文件修改完成且进入 `verification_completed` 时生成证据，再把引用写入同一检查点。

若进程在证据生成前中断，下一轮没有所有权证明，继续按现有规则失败关闭并要求人工处理；不得根据任务编号或路径猜测所有权。

### 5.3 恢复判定

恢复轮仍先获取租约并创建本轮 Snapshot，但不再对原恢复任务调用普通候选 `Check`。它调用专用恢复检查，且必须同时满足：

1. 状态中的 taskId、checkpoint、`expectedPaths` 与证据完全一致。
2. 原始 baseline 和证据 payload hash 均有效。
3. 当前 HEAD 与允许的原始 HEAD 关系一致。
4. 原始 baseline 中所有 `expectedPaths` 外的路径、内容和暂存状态均未变化。
5. 当前每个预期路径的完整指纹与中断证据完全一致。

全部满足时，控制器可以从保存的检查点继续。任一预期路径内容不同，返回明确的 `recovery_expected_changed`；路径外变化返回 `baseline_changed`；证据损坏或缺失返回 `recovery_evidence_invalid`。这些情况均不得自动认领或覆盖修改。

成功提交并 `Complete` 后清除状态中的恢复证据引用；证据文件可由控制器在确认完成后删除。失败关闭保留证据，供下一轮或人工审计使用。

## 6. 当前阻塞的处理顺序

1. 保持控制器 `AUTO-BLOCKED`，防止实施期间定时写入。
2. 实现固定提交助手、恢复证据协议及直接相关测试。
3. 更新项目自动工作流规则、控制器提示和静态检查，使后续轮次调用固定助手与专用恢复检查。
4. 运行第 7 节的最小验证。
5. 将当前 `自动工作流状态.txt` 差异与已解析的决策 A、本机 pendingDecision 和原提交基线交叉核对；只提交该已核验状态路径，不包含现有未跟踪日报计划。
6. 通过受支持的自动化更新接口写入新提示；不直接编辑 `automation.toml`。
7. 调用 `ResetBlocked`，理由明确记录为提交助手和恢复所有权协议已修复、遗留状态已安全提交。
8. 读取控制器状态和自动化记录，确认状态为 `IDLE`、恢复指针已清理、自动化配置仍为单写入控制器；不为验证而立即执行业务任务。

## 7. 最小充分验证

只运行以下直接相关检查，并在相关输入未变化时不重复：

1. `tools/test-automation-controller-state.ps1`：覆盖新 schema、证据引用的保存、保留和清除。
2. `tools/test-automation-workspace-guard.ps1`：覆盖自产脏改指纹一致时可恢复、预期路径被人工改写时拒绝、路径外变化时拒绝、证据损坏时拒绝。
3. 新提交助手的临时 Git 仓库测试：覆盖中文路径、预先存在的不相关 staged/unstaged/untracked 改动、路径集合不一致，以及路径限定提交不混入其他内容。
4. `tools/check-automation-workflow.ps1`：确认控制器提示调用固定助手和专用恢复协议，旧写入型工作流仍暂停。
5. 对本轮预期路径运行暂存前空白检查、`git diff --cached --check` 和 workspace guard 提交隔离检查。

不运行 Unity EditMode、`.NET` 游戏构建、BattleSim、数据链检查或无关管理文件全量扫描。

## 8. 完成条件

- 控制器提交阶段不再包含模型临时拼装的复杂 PowerShell 单行脚本。
- 目标回归证明完全一致的控制器自产残留能够跨轮恢复。
- 目标回归证明人工修改预期路径或路径外基线仍会失败关闭。
- 当前决策归档形成路径限定提交，既有未跟踪日报计划保持原样。
- 本机控制器从 `AUTO-BLOCKED` 恢复为 `IDLE`，恢复次数和旧恢复指针清理完成。
- 自动化记录保持一个启用的写入型控制器，不自动推送远端。
