# BattleSim 有界默认矩阵优化设计

## 状态与目标

- 本设计于 2026-07-26 获用户批准。
- 默认 BattleSim 保留完整 Build 两两对阵，不新增快速/完整双模式。
- 每组默认模拟场数从 2,000 降为 100。
- 既有 `--g2-audit` 与 `--g2-attribution` 专项模式继续使用其覆盖门槛要求的 2,000 场；本设计只降低无参数默认命令。
- 仅为 1v1 增加单场 100 回合上限；2v2 保持现有 200 回合上限。
- 默认 Release 命令应在当前机器 10 分钟内以退出码 0 完成并输出最终统计。

## 已确认瓶颈

1. 默认矩阵当前包含 21 个 Build，共 210 组无序对阵。
2. `SIM=2000` 使一张非空 1v1 矩阵约执行 42 万场战斗；默认入口还会继续执行其他阶段矩阵、2v2 与调试统计。
3. 有界 30 秒探针确认修炼阶段已完成，程序停留在“正在计算 21x21 筑基同境矩阵”。
4. `Combat.Simulate` 的 1v1 单场使用无回合上限的存活循环，低伤害、恢复或无法有效接敌的组合可能长期不收敛。
5. `Combat.Simulate2v2Detailed` 已有 200 回合上限和剩余 HP 比例结算；本设计不改变该路径。
6. 首次按上述边界实施后，默认完整运行仍超过 10 分钟；单独计时的高防低攻确定性用例耗时约 199 秒。进一步定位确认，同一场战斗会逐回合重复求解相同的不可变战场射程和攻击位置。

## 方案选择

### 采用方案

- 将默认 `SIM` 改为 100。
- 为 1v1 设置 100 回合上限。
- 超过上限仍未击杀时按双方剩余 HP 百分比判定；百分比完全相同则双方各计 0.5 胜。

采用后，一张 21 Build 的完整 1v1 矩阵由约 42 万场降为约 2.1 万场；每场行动循环也具有明确上界。

### 未采用方案

- 只降低样本数：不能解决单场不收敛。
- 保留 2,000 场只增加回合上限：仍保留不必要的矩阵总量。
- 自适应采样或置信区间提前停止：会引入新的统计策略和不同对局样本量，超出当前最小修复范围。
- 新增快速/完整 CLI 模式：当前没有维护两套默认口径的必要。

## 运行与结算设计

### 默认矩阵

- `simulations/BattleSim/Program.cs` 中的默认 `SIM` 从 2,000 改为 100。
- `--g2-audit` 与 `--g2-attribution` 继续使用 2,000 场，不改变其 `battles >= 2000` 覆盖合同。
- 金丹、筑基和紫府 1v1 矩阵继续复用同一 `SIM`。
- 每个 Build 对阵把 100 场按“样本对 × 双向先手”的稳定顺序分配：先取整数商，再把余数逐项加一；不得继续使用会把 100 截断为 80 的单一 `h = SIM / pairs / 2`。
- 对相同输入，分配顺序和每个方向的场数必须可复现；每个非空 Build 对阵的合计场数必须恰好为 100。
- 现有 `sim2v2 = SIM / 4` 保持不变，因此默认 2v2 每组约执行 25 场。
- 不改变 Build 列表、阶段样本筛选、固定随机种子、成长输入或矩阵输出结构。

### 1v1 回合上限

- `simulations/BattleSim/Combat.cs` 为 1v1 定义 100 回合上限。
- 现有战斗行动、伤害、恢复、状态、移动、随机与冷却逻辑保持不变。
- 任一方在上限前死亡时沿用现有胜负结算。
- 达到上限且双方仍存活时：
  1. 分别计算 `max(0, 当前 HP) / 最大 HP`。
  2. 比例较高方获得 1 胜。
  3. 比例完全相同则双方各获得 0.5 胜。
- 胜场累计改为支持半胜的数值类型；公开返回结构仍为双方胜率和平均回合数，不新增 draw 字段。
- 结算不得默认偏向先手、A 方或 B 方。

### 2v2

- `Combat.Simulate2v2Detailed` 的 200 回合上限、剩余 HP 比例和现有输出保持不变。
- 本设计不统一 1v1/2v2 的上限，也不重构两套战斗实现。

### 不可变战场查询复用

- `HexBattlefield` 在单次实例内缓存完全相同的 `QueryRange` 结果。
- 仅在没有显式 `occupied` 集合时缓存完全相同的 `FindAttackPosition` 结果；群战携带动态占位集合的查询不缓存。
- 缓存键包含影响结果的全部方法输入，不跨战场实例或进程复用。
- 该优化只复用既有查询结果，不改变六边格距离、阻挡、视线、移动或攻击位置规则。

## 测试设计

在 `simulations/BattleSim/BattleSimSelfTests.cs` 增加定向 1v1 超时结算 self-test：

1. 构造 100 回合内无法击杀且最终剩余 HP 比例相同的双方。
2. 断言平均回合数为 100，双方胜率均为 50%。
3. 构造 100 回合内无法击杀但最终剩余 HP 比例不同的双方。
4. 分别交换 A/B 位置运行，断言较高比例方获胜，且不存在固定侧偏差。
5. 保留现有快速正常战斗测试，证明上限前击杀仍沿用原结算。
6. 验证 20 个样本对、双向先手时分配总数恰好为 100，单槽场数只相差 1，且重复计算顺序一致。

验证顺序：

1. `dotnet build -c Release --no-restore simulations/BattleSim`
2. 新增的定向 self-test。
3. 与 1v1/2v2 结算相关的既有 self-test。
4. `dotnet run --no-build -c Release --project simulations/BattleSim`
5. 记录完整运行耗时、退出码和最终输出是否到达。
6. `git diff --check` 与项目要求的路径限定 whitespace 检查。

默认完整运行的验收条件：

- 退出码为 0。
- 输出到达最终调试统计与结束分隔线。
- 当前机器耗时不超过 10 分钟。

若仍超过 10 分钟，停止继续降低样本数或叠加猜测性补丁；先采集具体热点。实际采集已确认重复不可变空间查询为热点，因此只增加实例内精确结果缓存，不新增并行、自适应采样或重试层。

## 文件与提交隔离

允许修改：

- `simulations/BattleSim/Program.cs`：只修改默认 `SIM` 和 1v1 矩阵的确定性整数场数分配。
- `simulations/BattleSim/Combat.cs`：只修改 1v1 回合上限与超时胜负累计。
- `simulations/BattleSim/Battlefield.cs`：只缓存输入完全相同的不可变空间查询结果。
- `simulations/BattleSim/BattleSimSelfTests.cs`：只增加对应定向回归。
- 本设计文档。

明确不修改：

- 成长参数、四阶段分配和道基核心曲线。
- 伤害公式、功法机制、Build 列表、随机种子和阶段筛选。
- 2v2 回合上限或结算。
- 任务卡、队列、自动化配置和 runtime schema。

`Program.cs` 当前已有 `N-FPD-GROWTH-01` 的 162 行未提交成长审计。优化提交必须只暂存 `SIM=100` 与确定性场数分配的精确 hunks，并在提交前核对 cached diff；不得把既有成长审计混入优化提交，也不得 reset、stash、checkout 或 clean 该现场。

## 残留风险

- 每组 100 场在 50% 胜率附近的 95% 抽样误差约为 ±9.8%；固定随机种子保证重复运行一致，但不能消除小样本估计误差。
- 现有 40%/60% 分档附近的结果可能对样本量敏感，后续锁定边界数值时仍应结合定向验证，而不是把单次 100 场矩阵视为高精度估计。
- 1v1 超时按剩余 HP 比例判胜是新的终止结算语义；定向测试必须覆盖位置交换和完全相同比例。
- 空间查询缓存限于单个战场实例；带显式动态占位集合的攻击位置查询继续实时计算，避免复用过期占位结果。
