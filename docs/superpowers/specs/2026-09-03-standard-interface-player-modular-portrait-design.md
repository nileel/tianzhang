# 默认男主标准接口模块化 UI 立绘生产设计

状态：2026-09-03 负责人已逐段确认设计方向、组件合同、首批范围与分阶段预算策略。本设计只批准生产架构，不授权任何图片模型调用，也不授权 Unity／运行时接入。

## 1. 决策与替代关系

本设计取代 `2026-09-02-formal-player-modular-portrait-four-master-design.md` 的“四张完整母图 + 遮罩反向提取”路线。旧路线及其三个编辑遮罩、ComfyUI 提取实验和未执行生产 checkpoint 不再作为后续生产事实源，不得重放。

替代原因不是单纯遮罩精度不足，而是完整人物图天然缺少被头发、衣领和袖口遮挡的头皮、耳根、后颈和身体像素。确定性抠图只能分离可见像素，不能恢复隐藏接口；继续扩大联合包络或追加补全会把组件所有权重新交给组合专用修补，无法形成稳定的可扩展组件库。

新路线以一个批准的标准光头头部为核心接口，直接生成完整透明组件。现有批准默认男主立绘只作为年轻脸身份、年龄气质和项目画风参考，不要求新组件逐像素继承该图，也不再从该图反向抠层。

## 2. 目标与非目标

### 2.1 目标

- 建立一个实际 RGBA 像素冻结的标准光头头部，统一头骨、发际线、耳根、头部注册、朝向、光照和颈部接口。
- 直接生产可独立组合的头部、前后发、衣装身体与面部装饰，不从最终扁平人物图反向猜测隐藏像素。
- 允许每套衣装身体自带一种固定姿势、手势、手脚、鞋和落脚位置；换衣装时身体姿势可以变化。
- 通过固定层序与零变换组合验证四个头部、两套发型、两套衣装和三种胡须。
- 由 ComfyUI 只执行确定性 RGBA 规范化、合成、裁切、联系表和哈希，不执行语义抠图或生成。

### 2.2 非目标

- 不要求 UI 立绘姿势与战棋棋子姿势一致。
- 不把姿势拆成独立可选维度；每套衣装首批只绑定一种姿势。
- 不制作皱纹组件，也不以皱纹作为老龄脸成立的必要条件。
- 不把胡须与年龄绑定；胡须是独立面部装饰。
- 不修改 Unity、CSV、存档、3D 资产或运行时所有权。
- 本设计确认不等于图片生产授权。

## 3. 画布与标准接口

GPT Image 2 的模型原生竖图画布固定为 `1024×1536`。所有图片调用必须显式使用 `background=transparent` 与 `output_format=png`，直接请求带 Alpha 的 PNG；不得把没有 Alpha 的白底、黑底或伪透明输出当作组件。

项目冻结画布仍为 `887×1774`、左上角原点、8-bit sRGB straight/unassociated RGBA。每个模型原生输出只能在组件冻结前执行一次相同的确定性规范化：取中央安全区 `[128,0,768,1536]`，使用固定的预乘 Alpha Lanczos 重采样到 `887×1774`，再还原 straight Alpha，并将透明像素规范化为 `RGBA=(0,0,0,0)`。生成提示必须要求全部有效组件像素位于中央 `768×1536` 安全区内。

标准头部同时冻结模型原生版与项目规范版。后续图片调用使用模型原生版作为注册参考；正式组合只使用项目规范版。上述固定规范化是唯一允许的裁切与重采样，组合阶段仍禁止平移、缩放、旋转或再次重采样。

首个生产对象是标准年轻清秀光头头部。它必须包含完整头骨、五官、耳朵和向下延伸的颈部，不包含头发、胡须、衣服、肩膀或身体。该头部获得单独视觉批准后，其实际解码 RGBA 像素、画布位置、大小、朝向、光照、头骨包络、发际线接口、耳根和颈部安全重叠区共同成为接口事实源。

后续组件不能只依赖抽象坐标近似接口。所有生产输入都必须引用同一冻结标准头部与同一全画布注册；组合阶段不得平移、缩放、旋转或重新采样组件。

衣装身体可以改变肩膀以下的身体姿态、手势和落脚点，但必须保持标准头部接口的位置和朝向。衣领必须覆盖冻结颈部下端的安全重叠区。

## 4. 组件合同

### 4.1 `base-head`

- 完整光头、脸、耳朵和颈部；身体其余区域透明。
- 四个首批变体共享头顶包络、发际线接口、耳根、头部注册、朝向、整体尺度、颈部接口和光照方向。
- 允许改变五官、眉形、眼神、脸部宽窄、下颌、面部骨相（颧骨、眉弓和下颌；不含颅顶、耳根或后颈）、肤色明暗和年龄气质。
- 老龄感通过面部骨相、眼神、眉形、脸部比例与肤色表达；不要求皱纹或胡须。

### 4.2 `hair-back`

- 包含位于标准头部和衣装身体之后的发体、马尾尾段、后披发及必要隐藏根部。
- 每种发型一个全画布透明文件。
- 必须与同名 `hair-front` 配对，并原样适配全部四个头部和两套衣装。

### 4.3 `hair-front`

- 包含头皮发帽、发际线、刘海、鬓发、太阳穴与绕耳侧发；高束马尾的可见顶髻和马尾根也归本层。该层还拥有位于脸、耳、颈或衣领之前的发丝。
- 每种发型一个全画布透明文件。
- 必须在标准头部及全部头部变体上保持发际线、太阳穴、耳根与后颈关系成立。

### 4.4 `outfit-body`

- 包含衣服、完整着装身体、双手、双脚、鞋和该衣装唯一固定姿势。
- 不包含头、头发、胡须或独立颈部皮肤；模型输出出现这些像素即失败，不能从完整人物图切头后冒充正式组件。
- 领口上沿必须位于标准颈部安全重叠区内并覆盖颈部下沿。首批不支持会露出无肩悬空颈部的低开领。
- 不同衣装允许采用不同肩部姿态、手势、身体姿势和落脚点，但不得改变头部接口。
- “改变肩部姿态但保持头颈注册不变”是明确的强生成约束。若第二姿势不能在零变换条件下连接冻结颈部，该衣装失败；不得移动头部或另建第二套接口。

### 4.5 `face-decoration`

- 首批只包含胡须，不包含皱纹。
- 使用标准头部作为嘴角、下唇、下巴和颈部注册参考，不改变头部本身。
- 长须允许向下覆盖衣领，因此组件叠加在衣装身体之上，并在衣装之后执行合成。
- 胡须不与年龄自动绑定；无胡须通过不加载组件实现。

## 5. 固定层序

组合层序固定为：

```text
hair-back
  → base-head
  → outfit-body
  → face-decoration（可缺省）
  → hair-front
```

该层序使后发位于头部和身体之后，衣领覆盖标准头部向下延伸的颈部，胡须可以覆盖衣领，前发最后覆盖脸侧、耳侧与衣领前方。任何组件若只能通过某个组合专用层序、遮罩或覆盖图成立，则判定失败。

## 6. 首批组件范围

### 6.1 四个头部

1. 年轻清秀窄脸：首个标准接口头部。
2. 年轻硬朗宽脸。
3. 清癯仙长老龄脸。
4. 威严宽颌老龄脸。

### 6.2 两套发型

1. 半束长发：`hair-back` + `hair-front`。
2. 高束马尾：`hair-back` + `hair-front`。

共四个发层文件。

### 6.3 两套衣装身体

1. 靛青米白实用长袍，姿势 ID 为 `pose_practical_sword_finger_01`：三分之四直立，右手在胸前作剑指，左臂自然下垂，双脚稳定自然站立，穿深色软靴。旧合同的 `hands_sword_finger_01` 只在本衣装姿势中保留，不再是所有衣装共享的全局手部组件。
2. 灰褐窄袖行装，姿势 ID 为 `pose_travel_relaxed_01`：保持相同头颈位置与朝向，身体三分之四直立，双臂自然下垂，双手放松可见，一脚轻微前置，穿适合行旅的深色软靴；不得抬肩、倾颈或改变领口注册来制造姿势差异。

### 6.4 三个胡须装饰

1. 轻薄上唇须与短下巴须。
2. 山羊须。
3. 仙长须；长度受控，不遮住大面积胸口。

胡须首批统一为墨黑偏深灰，不按年龄自动变白。灰白版本属于未来扩展。

首批共十三个生成文件：四个头部、四个发层、两个衣装身体和三个胡须。无胡须不占文件。

## 7. 生产数据流

### 7.1 标准头部

以现有批准默认男主为年轻脸身份与画风参考，使用 `background=transparent`、`output_format=png` 直接生成模型原生画布的透明标准光头头部，再经唯一固定规范化得到项目画布版本。批准后同时冻结输入、提示、API 参数、原生输出、规范输出、两种解码像素哈希和接口遮罩。

### 7.2 头部变体

其余三个头部都以冻结标准头部作为注册参考，直接输出完整透明 `base-head`。变化必须局限于脸部与年龄表达；共同接口保持一致。

### 7.3 发型套件

每套发型直接输出一对全画布透明前后发组件。生产输入始终包含冻结标准头部作为位置与比例参考。发型组件形成后先与标准头部组合，再与全部头部及衣装交叉验证。

### 7.4 衣装身体

每套衣装使用冻结标准头部作为独立参考输入，直接输出透明背景上的无头 `outfit-body`；标准头部只提供接口上下文，不出现在正式模型输出中。若模型输出含头部或颈部皮肤，整张输出失败，不允许通过切头或语义抠图转为正式组件。衣装形成并规范化后必须本地合成标准头部，确认领口覆盖与整体人物观感。

### 7.5 面部装饰

每个胡须直接输出全画布透明 `face-decoration`，使用标准头部作为注册参考。形成后与全部头部和两套衣装交叉验证。

图片模型输出必须是具名组件本身，不允许先生成最终完整人物，再通过语义分割或人工遮罩反向抠取为正式组件。

## 8. ComfyUI 职责

ComfyUI 只负责：

1. 读取冻结透明组件；
2. 验证模型原生 PNG 具有真实 Alpha，并执行一次冻结的中央裁切、预乘 Alpha Lanczos 重采样、straight Alpha 还原和透明 RGB 清零；
3. 按固定层序完成零变换组合；
4. 输出全身、半身、头像和联系表；
5. 记录输入、API 输出参数、原生与规范输出、节点版本、工作流和解码像素哈希；
6. 证明相同输入重复运行得到相同解码像素。

ComfyUI 不负责语义抠图、色键抠图、隐藏区域补全、扩散重画、自动重试、组合专用补丁或运行时纠偏。工作流不得包含 FLUX、KSampler、LoRA、扩散模型或随机节点。直接透明输出若不能形成可用 Alpha，本路线停止，不自动回退绿幕。

## 9. 分阶段预算与授权门

理论总预算为十三次图片调用，但不得一次性全部授权。

### 9.1 A 门：标准接口，一次调用

- 只生成年轻清秀标准光头头部。
- 验证身份、画风、模型原生画布、中央安全区、`background=transparent`、PNG RGBA、有效连续 Alpha、完整头骨、耳朵、颈部、固定规范化和项目画布注册。
- 未通过则停止，后续十二次不执行。

### 9.2 B 门：最小兼容证明，四次调用

- 年轻硬朗头部一次；
- 半束长发前后层两次；
- 靛青米白衣装身体一次。

使用 A、B 门得到的五个组件证明：两张头部共用同一发型，同一衣装身体连接两张头部，前后发、发际线和衣领接口成立，全部组合不需要变换或补丁。未通过则停止。

### 9.3 C1 门：老龄接口证明，一次调用

- 先只生成清癯仙长老龄头部。
- 与两套已通过头部使用相同接口检查，并与 B 门发型、衣装交叉组合。
- 老龄面部骨相若迫使颅顶、耳根、后颈或颈部接口变化，则停止，后续七次不执行。

### 9.4 C2 门：完成首批库，七次调用

- 威严宽颌老龄头部；
- 高束马尾前后两层；
- 灰褐窄袖衣装身体；
- 三个胡须装饰。

A、B、C1、C2 四门分别需要独立、明确的生产授权，预算总计仍为 `1+4+1+7=13` 次。任何门未通过，剩余预算不自动消费；修改提示后重试也需要新的授权。

## 10. 组合矩阵与验证

最终矩阵为：

```text
4 头部 × 2 发型 × 2 衣装 × 4 胡须状态 = 64 套
```

四个胡须状态包含无胡须与三个胡须组件。每套 composite 生成全身图及固定头像／半身裁切，总计 `64×3=192` 张 PNG。manifest 必须按 `headId/hairId/outfitId/faceDecorationId/cropId` 记录组合与来源哈希；联系表每页最多展示 16 套组合，因此首批至少四页，不把 64 套压缩到单页。

逐项检查：

- 头顶、发际线、太阳穴、鬓角、耳根和后颈；
- 标准颈部与衣领覆盖；
- 胡须与嘴、下巴、颈部和衣领；
- 胡须与前发、鬓发及长发在脸侧和衣领区域的固定前后遮挡；
- 长发与两套衣装肩部的前后遮挡；
- `hair-back` 被不透明头部和身体遮住的区域应不可见，只允许预期的轮廓外沿、马尾和后披发露出；完全被遮住的隐藏根部不作为缺失；
- 透明边缘、透明 RGB、画布注册；
- 无偏移、缩放、旋转、重新采样或组合专用补丁；
- 重复运行解码像素哈希一致。

## 11. 失败处理与停止条件

- 不自动重试，不随机替代组件。
- 标准头部未批准时停止全部后续生产。
- 模型原生 PNG 没有真实 Alpha、透明背景不稳定、有效组件超出中央安全区，或固定规范化产生不可接受边缘时停止；不得自动改用绿幕或人工抠图。
- 单个组件不能原样匹配标准接口时停止该阶段，不通过变换或局部覆盖救图。
- 前后发不能作为一套同时适配全部头部和衣装时，该发型失败。
- 衣装领口不能连接全部头部时，该衣装失败。
- 胡须不能适配声明支持的全部头部和衣装时，该胡须失败。
- 任何组件需要组合专用版本、专用遮罩、覆盖图或第二套接口模板时停止并重新评估结构。
- 若图片模型持续无法直接交付某类透明独立组件，重新评估该组件合同，不回退到完整人物反向抠图。
- 每次失败保留输入、提示、输出、参数、哈希和具体接口问题；是否调整提示并再调用一次，必须形成新的生产 checkpoint。

## 12. 当前授权状态与后续管理投影

本设计获得书面确认后，只完成架构决策。当前不得调用 GPT Image 2、FLUX 或任何消耗图片额度的模型。

后续独立管理写入应：

1. 将现有四母图设计、三个编辑遮罩、四母图提示合同和 ComfyUI 提取证明标记为被本设计取代，不作为生产证据；
2. 重写 `input-contract.json`、提示合同、任务卡范围、路径和完成条件，使其对应十三个标准接口组件、模型原生与项目规范双版本、六十四组合矩阵、192 张裁切输出、manifest 命名字段和分页联系表；
3. 在 A 门前展示标准头部完整提示、参考输入、透明输出合同、一次调用预算和失败处理，取得新的明确授权；
4. A 门通过后分别为 B、C1 和 C2 门建立新的 checkpoint；
5. 不在管理投影任务中顺带生成图片或操作 Unity。

## 13. 完成定义

只有以下条件全部满足，首批标准接口模块化 UI 立绘库才算完成：

- 一个批准并冻结的标准光头头部接口；
- 四个完整头部、两套配对前后发、两个衣装身体和三个胡须全部可追溯；
- 十三个组件都是直接生产的全画布透明 RGBA，不是从最终扁平人物反向抠取；
- 六十四组合及固定裁切全部通过；
- 不存在组合专用补丁、组件变换、可见区域本地重画或运行时纠偏；
- ComfyUI 工作流纯确定性且重复运行哈希一致；
- 负责人书面批准最终联系表的画风、接口兼容性与 UI 使用效果。

本设计完成不等于生产完成，也不授权后续 Unity 接入。
