# Unity 验证日志归档设计

## 目标

将根目录现有的 Unity 批处理验证日志集中到可发现的归档目录，保留 TQ-016、TQ-019 与 Unity 6 升级期间从失败到成功的完整诊断链，同时不改变 Unity 项目、测试命令或 Git 忽略策略。

## 目录与数据流

历史日志移动到 `artifacts/logs/unity/2026-06_07/`，保留原始文件名和内容。该目录中的日志继续受根目录 `.gitignore` 的 `*.log` 规则约束；只有说明文件 `README.md` 被 Git 跟踪。

`README.md` 记录归档范围、各文件组对应的验证任务、这些日志不应被当成当前构建状态的依据，以及后续日志的存放约定：临时日志应直接输出至按 `YYYY-MM` 分组的 `artifacts/logs/unity/` 子目录；只在需要保留可复现诊断证据时保留它们。

## 范围

本次移动根目录的 15 个 `*.log` 文件，包括：Unity 6 升级日志、TQ-016 的 red/green 验证日志、TQ-019 的测试日志，以及通用 batchmode 验证日志。不移动 `*.xml` 测试结果或任何 `src/`、`Temp/` 下的运行文件。

## 失败处理与验证

移动前若目标文件已存在，则停止操作，不覆盖已有归档。完成后验证：15 个文件均位于目标目录；根目录不存在这些源日志；每个文件的 SHA-256 与移动前记录一致；`git status` 只显示预期的说明文件（日志本身保持忽略）。
