# 关中基础攻击生产迁移与正式薄切片 UI 文本任务设计

状态：已获用户方向确认，供建立两张独立任务卡使用。本文只冻结任务拆分、事实源、范围、顺序与验收，不实施业务代码、CSV、asset、场景或 UI 修改。

## 一、已确认问题

### 1. 基础攻击生产链缺失

Unity 的统一攻击档案消费者已经启用，`TacticalCombatController` 会在建立战斗会话前要求每名参与者的两个基础攻击外键恰好一个非空，并解析对应 `AttackProfileData`。当前正式链存在三个连续缺口：

1. `CharacterCreationRules.BuildProfile` 生成的新玩家没有填写基础攻击外键；现有玩家 `CharacterData` asset 也没有生产绑定。
2. `enemy_shijiahou` 的 `combatTemplate` 没有填写基础攻击外键。
3. 仓库只有非生产 `AttackProfiles.fixture.csv`，没有生产 `AttackProfiles.csv`、生产 `AttackProfileData` asset；`AdventureScene` 的 `ExplorationController.attackProfiles` 为空。

因此当前接敌首先返回 `basic_attack_binding_missing_or_ambiguous`；只补一个玩家 ID 会继续暴露 `basic_attack_profile_not_found` 和敌人绑定缺失，不能用局部补丁关闭问题。

### 2. 正式薄切片 UI 直接显示内部字段

当前运行画面已出现稳定拒绝码、档案 ID、地表／现象 ID 等内部值直接展示给玩家的情况。内部稳定 ID 和失败原因仍需要保留给数据、日志与测试，但正常玩家界面需要消费已批准的显示文本，不能把内部协议字段当成成品文案。

用户已确认 UI 任务覆盖完整正式薄切片：新建角色、世界、关中城、悬赏、关中野外、战斗与返回链；不只修复当前 AdventureScene 面板。

## 二、任务拆分与固定顺序

建立两张互不混合的 P1 任务卡：

1. `D-COMBAT-PROD-01` · 关中薄切片基础攻击生产迁移。
2. `U-GZ-UI-TEXT-01` · 关中正式薄切片基础 UI 文本接入。

两张卡都使用 `external_execute / deepseek`，完成后转换为 `codex_review / codex`，由 Codex 独立复审。建卡时按新鲜队列保留 `U-GZ-FORMAL-E2E-01` 的实际状态与活动现场：若它仍在队列，新卡按上述顺序排在其后；若它已完成或转为非 ready，则新卡按上述顺序占据相应的最前 P1 位置。`D-COMBAT-PROD-01` 先恢复可进入战斗的生产链，`U-GZ-UI-TEXT-01` 再以可运行的完整薄切片核对玩家可见文本。

不得把两项合并：前者拥有统一攻击档案、数值投影和角色装配边界，后者拥有玩家可见文本投影；合并会扩大实现与复审范围。也不另建纯调查卡，因为当前根因、内容授权与停止条件已经足以形成 runnable 任务。

## 三、D-COMBAT-PROD-01 设计

### 3.1 唯一生产内容

只生产一个稳定的通用无装备基础攻击档案，稳定 ID 固定为 `basic_unarmed`，绑定种类为 `unarmed_fallback`。新建玩家与当前明确无装备的石甲兽共同引用该档案。

其执行字段逐项迁移自 BattleSim 已有 `GameData.UnarmedBasicAttack`，并补齐统一契约要求的显式字段：

- `profileKind=basic`
- `basicBindingKind=unarmed_fallback`
- `effectType=physical`
- `damageElementId=element_none`
- `physicalDamageMultiplier=1.0`
- `resourceKind=none`
- `resourceCost=0`
- `cooldownTicks=0`
- `minCastRange=1`
- `maxCastRange=1`
- `targetingMode=single`
- 其余仅适用于术法、神通或范围攻击的字段为空

显示名使用生产 `Language.csv` 中的独立键，中文文本为“徒手”。CSV 行仍是唯一攻击参数事实，asset 只能由现有严格导入器生成或更新。

### 3.2 绑定与消费

- 新建角色装配所有者必须显式写入 `unarmedBasicAttackProfileId=basic_unarmed`，不能在战斗调用点补默认值。
- `Enemies.csv`／正式敌人模板导入链必须显式使 `enemy_shijiahou` 引用同一无装备档案；不得按名称或遭遇 ID 在运行时推断。
- 正式 `AdventureScene`／其场景构建所有者必须把生成的档案加入 `ExplorationController` 已有 `attackProfiles` 输入。
- 现有缺失、歧义、未知 ID 和绑定种类错误的失败关闭语义保持不变。

### 3.3 禁止项

- 不新增武器、主战法宝、装备槽或第二个基础攻击档案。
- 不从测试 fixture、显示名、功法名、旧 Unity 默认值或调用方常量回退。
- 不修改石甲兽或玩家属性、伤害公式、AI、CTB、范围规则、掉落或奖励。
- 不把本任务扩大为术法／神通生产迁移或完整 BattleSim 统一档案切换。
- 若现有生产导入链无法在不建立第二数据源的情况下表达上述显式绑定，停止并交回 Codex，不叠加兼容分支。

### 3.4 验收

- 生产 CSV、生成 asset、玩家绑定、石甲兽绑定与场景引用形成单向可追溯链。
- 接近石甲兽可成功建立战斗会话，不再返回三类基础攻击装配错误。
- 玩家和石甲兽均能在相邻格执行同一档案定义的基础攻击。
- BattleSim 运行证明迁移值没有改变现有普攻结论；Unity EditMode 覆盖生产行、导入、绑定及非法输入；PlayMode 覆盖正式关中接敌入口。
- 相关数据链、任务卡、空白与暂存差异检查通过。

## 四、U-GZ-UI-TEXT-01 设计

### 4.1 覆盖范围

扫描并修复完整正式薄切片的玩家可见文本投影：

1. 新建角色与开局确认。
2. 世界节点与关中城入口。
3. 关中城功能、悬赏接取／进度／领取和已接入的单据点交互。
4. 关中野外副本、环境反馈、遭遇与战斗 UI。
5. 战斗结果、普通掉落、返回来源与保存／读取后的玩家反馈。

只处理当前正式生产 ID 和已批准内容。未接入或冻结系统不因本任务生成占位文本。

### 4.2 显示规则

- 玩家界面显示既有实体的中文显示名和可理解状态，不直接显示稳定 ID、字段名、枚举名、档案 ID 或机器拒绝码。
- 优先复用现有 `Language.csv` 键；仅为已存在的正式实体、状态或反馈补齐最小缺失键。
- 内部稳定 ID、失败原因和原始枚举继续保留在数据对象、日志与测试断言中。UI 在既有表现所有者处做单向显示映射，不修改业务状态语义。
- 失败文本必须保持可理解且不伪造成功；未知或非法输入仍失败关闭，并在日志中保留稳定原因。
- 不以通用正则替换所有下划线文本；以正式路径的实际控件和已登记实体逐项建立可审计清单，防止误改玩家自定义名称或合法文本。

### 4.3 禁止项

- 不修改 UI 布局、Canvas 结构、字体、颜色、动画、美术资源或交互流程。
- 不新建第二套本地化服务，不把显示文本写回稳定 ID 字段。
- 不扩写剧情、NPC、怪物、悬赏、物品、册界条目或其他冻结内容。
- 不借文本任务改变战斗、掉落、奖励、存档或地区规则。
- 若某个玩家可见字段没有批准的直接事实且需要创作新设定，保留内部值和证据并停止该项，不自行编写设定。

### 4.4 验收

- 正常玩家路径从新建角色到关中野外战斗、结算与返回，不再直接显示本任务清单内的字段名、稳定 ID、档案 ID 或拒绝码。
- 生产 `Language.csv` 与现有显示消费者形成单向映射；缺键、未知键和非法状态的失败边界有直接测试。
- EditMode 对每类映射覆盖至少一个生产实体和一个非法输入；PlayMode／现有正式场景 runner 覆盖完整薄切片的关键面板与状态转换。
- 测试明确区分玩家显示文本与开发日志中的稳定原因；不以隐藏控件或吞掉错误冒充完成。
- 相关数据链、任务卡、空白与暂存差异检查通过。

## 五、管理产物

正式建卡时同步：

- 新建 `开发管理/任务卡/D-COMBAT-PROD-01.txt`。
- 新建 `开发管理/任务卡/U-GZ-UI-TEXT-01.txt`。
- 在 `开发管理/任务列表/数据链路任务.txt` 增加基础攻击生产迁移短投影。
- 在 `开发管理/任务列表/场景与Unity任务.txt` 增加正式薄切片 UI 文本短投影。
- 按建卡时的新鲜状态保留现有 ready 行与活动任务顺序，并以 `D-COMBAT-PROD-01 -> U-GZ-UI-TEXT-01` 的固定相对顺序插入最前可用 P1 位置。

每张活跃卡必须包含自身任务卡路径与未来精确归档路径，列出实施前必须重新扫描确认的完整 expectedPaths、直接测试、完成条件与停止条件。建卡管理切片只登记任务，不实施上述业务变化。
