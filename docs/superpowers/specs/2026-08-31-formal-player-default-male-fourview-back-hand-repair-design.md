# 默认男主四视图槽位订正与背视右手修复设计

## 1. 问题与根因

本轮阻塞来自两套方向定义混用：旧任务卡和既有提示词用“角色自身左右”解释侧视槽位，而 Tripo 四视图槽位按画面中的面部朝向命名。项目现行权威映射为：

- 左上：正面；
- 右上：face-left-side，鼻尖朝画面左侧；
- 左下：face-right-side，鼻尖朝画面右侧；
- 右下：背面。

因此，当前候选四视图的两个侧视槽位顺序正确，`fourview_side_slots_swapped` 不是有效阻塞原因。候选图仍不能通过，真正问题是右下背视图的角色右手：右前臂、衣袖和剑指之间缺少可信的连续连接，手部呈漂浮或断裂状态。

## 2. 目标与非目标

### 目标

1. 保留当前错误候选图作为可追溯的否决证据，不覆盖它。
2. 另存一张修正版四视图母图。
3. 保持前三格、四格排布、角色身份、服装、发型、配色、光照和整体风格不发生实质变化。
4. 只修复右下背视图的角色右臂链路，使右上臂、肘部、前臂、袖口、手腕和右手剑指形成可信、连续、与同一姿势一致的结构。
5. 订正任务卡中的槽位口径和当前阻塞原因，避免后续自动化再次以错误坐标系判定。

### 非目标

- 本轮不上传 Tripo，不消耗三维平台额度。
- 本轮不进入 Blender 或 Unity。
- 本轮不生成独立四格裁图和 manifest；修正版母图须先经负责人视觉批准。
- 本轮不自动重试。若一次定点编辑未满足验收条件，保持阻塞并报告差异。

## 3. 文件与审计策略

- 将当前错误候选图复制到项目内的否决证据目录，并使用带日期和缺陷含义的文件名保存；记录尺寸、文件哈希和来源。
- 将修正版母图保存到任务卡约定的规范输入路径 `assets/source/characters/combat-pieces/formal-player-static-3d-v2/input/formal_player_default_male_fourview.png`。
- 既有提示词和旧设计文档保留为历史审批证据，不回写成仿佛当时就采用了正确口径；本设计文档和订正后的任务卡对本轮修复具有优先解释权。
- 任务卡正文保留旧候选的否决记录，同时移除只代表旧候选决策的活动态 checkpoint/reply 元数据，防止它们被误认为修正版的当前结论。

## 4. 图片定点编辑合同

采用一次基于现有四视图母图的精确图片编辑，而不是整图重新设计。

允许改变的区域仅为右下背视格中的角色右臂末端链路。修复结果必须满足：

- 右臂保持与其余视图一致的抬臂姿势；
- 衣袖自然包覆上臂和前臂，肘部转折可信；
- 袖口、手腕和手掌连续连接，不得漂浮、断裂或多出肢体；
- 右手保持剑指：食指与中指并拢伸直，其余三指收拢；
- 手的朝向必须符合背视观察关系，并与正面及两个侧视图描述的是同一姿势。

以下内容视为冻结项：前三格全部内容、四格槽位顺序、人物比例、脸型、服装结构、发型、颜色、材质、背景、相机尺度、光照、构图以及无文字要求。若编辑工具导致任一冻结项发生实质漂移，该候选直接判为不合格，不追加自动修补。

## 5. 任务卡订正

任务卡采用平台面部朝向口径：

- `front`：正面；
- `face-left-side`：鼻尖朝画面左侧；
- `face-right-side`：鼻尖朝画面右侧；
- `back`：背面。

撤销 `fourview_side_slots_swapped` 作为当前原因，改记为“背视右手、前臂与衣袖连接错误”。生成修正版后，任务仍保持不可自动推进，状态原因改为“修正版候选已形成，等待负责人视觉批准”。只有负责人明确批准后，才可以继续独立裁图、manifest 和后续三维流程。

## 6. 验收与停止条件

修正版母图必须同时通过：

1. 槽位检查：右上鼻尖朝画面左，左下鼻尖朝画面右；
2. 背视解剖检查：右臂、袖口、手腕、手掌和剑指连续且可信；
3. 姿势一致性检查：四格表达同一套左右手动作；
4. 冻结项检查：前三格与原候选相比无实质变化；
5. 文件检查：原错误图和修正版均已落入项目路径，来源、尺寸和哈希可追溯；
6. 任务卡检查：错误阻塞码已撤销，正确缺陷及“等待视觉批准”停止条件已写明。

任一检查失败即停止，不调用第二次图片编辑，不进入裁图、三维上传、Blender 或 Unity。最终放行条件是负责人对修正版母图给出明确视觉批准。
