# 默认男主模块化 UI 立绘四母图生产设计

状态：2026-09-02 用户已批准方向并授权管理投影；四母图输入合同、提示合同和任务卡边界已按本设计更新。本轮不调用图像模型、不运行 ComfyUI 生产，也不授权 Unity／运行时接入。

## 1. 背景与根因

`A-CHAR-PORTRAIT-STYLE-01` 当前合同要求九个图层组件分别接受一次独立生成／编辑输入，再以 2～3 px 接缝容差组合成八套立绘，并禁止重试。该方法把人物整体一致性、精确注册和图层所有权同时交给九次彼此独立的图像输出，首轮成功率不可接受。

另一方面，单独生成全部八套完整立绘虽然能优先保证单张视觉质量，但首批已接近组件数量；脸型、发型或服装增加后，完整立绘数量按组合数相乘，不能作为可扩展的创角立绘生产方式。

现有批准母版已经提供 `f01/h01/o01` 的完整身份、姿势、画风和基准配色。后续不需要重新生成八张完整组合，也不应继续执行九次互相独立的组件生成。生产改为“一个批准基准母版 + 三个单变量完整编辑源 + 本地图层提取与八组合验证”。

## 2. 目标与非目标

### 2.1 目标

- 以四张完整母图覆盖首批两种脸型、两种发型和两套服装的唯一变化来源。
- 每张新增母图只改变一个维度，使身份漂移、姿势漂移和接缝失败可以定位到具体组件。
- 由 ComfyUI 承担分割、蒙版、前后层划分、透明化和批量重组，不让本地 FLUX 重新绘制已批准的可见人物像素。
- 从四张母图提取现有九个稳定组件路径，并确定性组合出八套全身、半身和头像结果。
- 保留未来按组件加法扩展的路线，不把完整组合数量变成长期生产单位。

### 2.2 非目标

- 不在本设计中生成图片、修改提示合同、消费 API 或第三方额度。
- 不要求本地 FLUX 文生图达到正式立绘质量；该能力不是本流程前置。
- 不自动修补组合专用像素，不建立逐组合覆盖层。
- 不修改 Unity、CSV、存档、3D 资产、运行时目录或 `PortraitComposer`。
- 不扩大首批规模；仍固定为两种脸型、两种发型和两套服装。

## 3. 四张完整母图

四张母图固定使用同一 `887×1774` 画布、身体中心轴、落脚点、三分之四直立姿势、右手剑指、左手下垂、镜头、光照方向和项目画风。

| 母图 ID | 脸型 | 发型 | 服装 | 来源 |
|---|---|---|---|---|
| `source_f01_h01_o01` | `face_young_refined_01` | `hair_half_up_long_01` | `outfit_practical_long_robe_01` | 现有批准母版 |
| `source_f02_h01_o01` | `face_young_defined_01` | `hair_half_up_long_01` | `outfit_practical_long_robe_01` | GPT Image 2 单变量脸型编辑 |
| `source_f01_h02_o01` | `face_young_refined_01` | `hair_high_ponytail_01` | `outfit_practical_long_robe_01` | GPT Image 2 单变量发型编辑 |
| `source_f01_h01_o02` | `face_young_refined_01` | `hair_half_up_long_01` | `outfit_narrow_sleeve_travel_robe_01` | GPT Image 2 单变量服装编辑 |

现有批准母版不重复生成，因此首轮只需要三个新的完整编辑输入。三个编辑都必须以批准母版为图像输入并使用具名编辑遮罩；不得通过纯文本重新生成相似人物。

### 3.1 单变量编辑边界

- 脸型编辑只允许改变当前合同的脸部变化区域及其必要的下颌抗锯齿边缘；头骨、发际线、发型、耳根、颈部、身体、手和服装保持不变。
- 发型编辑允许在预先冻结的发型联合包络内替换前后发；脸、耳、颈、身体、手和服装保持不变。遮罩必须容纳新马尾轮廓，不能只使用旧发型可见像素。
- 服装编辑允许在预先冻结的两套服装联合包络内替换衣领、袖子、袍身、腰带和靴子；脸、发型、裸露手、身体中心轴、手腕位置和落脚点保持不变。
- 任一输出在遮罩外产生可见身份、姿势或结构变化即失败，不通过“看起来差不多”放行。

## 4. 图层所有权与提取

最终仍交付当前目录合同中的九个组件：

- 两个 `hair-back`；
- 两个 `base-face`；
- 两个 `outfit`；
- 一个固定 `hands-front`；
- 两个 `hair-front`。

这些组件不再分别由九次独立图像生成得到，而从四张完整母图的批准可见像素和具名遮罩中提取。

旧合同中 `base-face` 拥有“固定完整身体”的定义在本路线中废止。新的像素所有权固定为：

- `base-face` 只拥有脸、头部、耳、颈部可见皮肤，以及位于两套发型和两种衣领联合包络下的安全重叠边；身体其余区域透明，不生成或保存被衣服遮住的裸模像素；
- `outfit` 拥有对应服装下的完整着装身体轮廓、袖子、腰带、袍身和靴子，但不拥有裸露手、脸、头颈或头发；
- `hands-front` 拥有两只固定裸露手及腕口下的安全重叠边；
- `hair-front` 与 `hair-back` 仍按相对脸、颈和服装的遮挡顺序划分，并在联合包络内保留安全重叠。

因此组合始终要求一个 `base-face`、一个 `outfit`、一个 `hands-front` 和同一发型的一对前后发层同时存在；不允许隐藏服装或把 `base-face` 当作可见裸体角色使用。

### 4.1 ComfyUI 职责

ComfyUI 工作流只负责：

1. 读取四张完整母图及冻结遮罩；
2. 分割脸／头颈、前发、后发、服装、手部和剩余透明区域；
3. 保留源像素，不对已批准可见区域执行本地扩散重绘；
4. 按项目既有规则完成绿幕转透明、边缘去绿、透明像素归零和完整画布注册；
5. 输出九个全画布 RGBA 图层、四张来源重组图、八张交叉组合图和联系表；
6. 保存工作流、遮罩、节点版本、输入／输出哈希和参数，保证同输入可复现。

本地 FLUX 文生图是否能生成高质量国风角色，不影响上述职责是否成立。ComfyUI 试验应转向蒙版、分层、透明边缘和重组验证。

### 4.2 遮挡区域

完整母图只包含可见像素，不能通过分割恢复被头发、衣领、袖子或袍身遮挡的内容。因此：

- 每个组件必须在全部预期遮挡者的联合包络下保留足够重叠区域；
- 若交叉组合暴露透明洞、旧轮廓残留或缺失纹理，先记录精确组件、组合和遮罩；
- 只有用户另行批准后，才能把该精确隐藏区域遮罩交给 GPT Image 2 做局部补全；
- 局部补全不得改动母图中原本可见且已批准的像素；
- 若需要某一组合专用补丁，模块化路线判定失败，不建立兼容层。

## 5. 数据流

```text
批准母版 f01/h01/o01
    ├─ 脸型遮罩编辑 ─> f02/h01/o01
    ├─ 发型遮罩编辑 ─> f01/h02/o01
    └─ 服装遮罩编辑 ─> f01/h01/o02

四张完整母图 + 冻结遮罩
    └─ ComfyUI 分割／透明化／前后层划分
         ├─ 九个稳定组件
         ├─ 四张来源重组图
         └─ 八张交叉组合图
              └─ 全身／半身／头像裁切与联系表
```

完整母图是视觉来源；遮罩定义组件所有权；九个 RGBA 图层是模块化交付；八个 composite 只用于证明交叉兼容和 UI 风格，不成为新的独立绘制事实源。

## 6. 分阶段执行门

### 6.1 第一门：完整母图编辑

- 现有母版哈希和批准记录保持不变。
- 三张新增母图各自只改变一个冻结维度。
- 四张母图的画布、姿势、身体中心、手腕、落脚点和未编辑区域一致。
- 任一单变量编辑失败时停止，不继续拆层或生成其他组合。

### 6.2 第二门：来源重组

- ComfyUI 从每张来源图提取对应图层后，必须能按固定层序重组回该来源图。
- 可见源像素不得被本地生成器改写；透明化造成的边缘变化必须由固定算法解释并记录。
- 四张来源重组任一出现洞、双边、绿边、错层或结构丢失时停止。

### 6.3 第三门：八组合兼容

- 使用同一组九个组件生成全部八种矩阵组合。
- 检查脸与发际线、耳根、后颈、领口、肩、袖口、手腕、腰线、衣摆、鞋底和前后发遮挡。
- 全身、半身和头像只从对应 composite 固定裁切，不调用第二套图像生成。
- 八组合全部通过后，才形成负责人视觉评审联系表。

## 7. 失败处理与停止条件

出现以下任一情况立即停止，不追加工作流复杂度：

- GPT Image 2 单变量编辑无法保持遮罩外身份、姿势或结构；
- ComfyUI 必须使用本地 FLUX 重画已批准的可见区域才能完成分层；
- 组件需要按组合平移、缩放、旋转或改锚点；
- 需要组合专用补丁、覆盖层或第二套身份母版；
- 隐藏区域补全开始改变可见批准像素；
- 同一组件不能原样用于它的全部四个引用组合；
- 为完成本流程必须修改 Unity、存档、3D 或运行时所有权。

失败证据只记录具体来源图、组件、组合、遮罩和可见问题；不自动重试，不以新增兼容分支掩盖根因。

## 8. 成本与扩展边界

首批完整组合共有八种。独立完整立绘路线需要八个视觉来源；本设计复用一个现有批准母版，只新增三个单变量完整编辑来源。

首批完成后：

- 新增一个脸型原则上新增一个单变量脸型母图和一个 `base-face` 组件；
- 新增一个服装原则上新增一个单变量服装母图和一个 `outfit` 组件；
- 新增一个发型原则上新增一个单变量发型母图及一对前后发组件；
- 新组件仍必须与全部既有维度做交叉兼容验证，但不为每个组合重新绘制完整立绘。

若实际维护证明每次新增组件都必须生成全部完整组合才能修复，则模块化的成本假设不成立，应另行决策是否改为有限预制组合。

## 9. 对现有任务合同的后续投影

本设计批准后，后续独立管理写入应：

1. 保持 `A-CHAR-PORTRAIT-STYLE-01` 暂停，废止当前“九次独立组件生成”的 checkpoint，不重放负责人此前对旧问题的选择；
2. 修订 `input-contract.json` 的来源、组件所有权、编辑遮罩、来源母图、来源重组门和遮挡补全边界；
3. 修订样张卡的提示合同和 `expectedPaths`，加入三张单变量母图、遮罩、ComfyUI 工作流及来源重组证据的字面量路径；
4. 在任何图片生产前重新执行原子性、风险预检和负责人批准；
5. 不在管理投影任务中顺带生成图片或操作 ComfyUI。

旧输入冻结设计中“不从批准扁平母版反向抠出并冒充正式可换装图层”的风险判断仍然成立。本设计不是机械抠图：它以单变量完整编辑、冻结遮罩、联合包络、来源重组和必要时单独批准的隐藏区域补全共同证明图层可用性。

## 10. 完成定义

只有以下条件全部满足，四母图生产路线才算通过：

- 一个批准基准母版与三个单变量完整编辑源齐全并可追溯；
- 九个稳定组件全部来自具名母图和冻结遮罩；
- 四张来源重组通过；
- 八个交叉组合及固定裁切全部通过；
- 不存在组合专用补丁、可见区域本地重绘或运行时纠偏；
- 负责人书面批准八组合联系表的 UI 立绘风格与模块兼容性。

本设计完成不等于生产完成，也不授权后续 Unity 接入。
