# 可信度闸门与最小纵向切片任务体系设计

日期：2026-07-10

状态：用户已批准设计，等待规格复核

适用范围：开发管理任务体系，不直接修改 Unity、BattleSim、CSV、asset 或设计正文

## 1. 目标与决策

当前项目的场景方向、战棋战斗方向和数据驱动方向可以保留，但任务优先级必须从“继续扩写内容”切换为“先证明项目结果可信且正式构建可玩”。

本设计采用以下唯一执行路线：

1. 冻结新的剧情、角色、功法、术法、神通和世界设定扩写。
2. 建立三道 P0 闸门：正式构建链、BattleSim 数值可信度、数据链路语义可信度。
3. 三道闸门通过后，只解冻一个能够进入真实运行时的薄内容切片。
4. 大型控制器拆分、asmdef 边界和持久化基础作为 P1 架构治理继续推进。

“冻结内容”不禁止修复既有内容的数据错误、补齐运行时必需字段或处理已进入复审队列的工作；它只禁止新增内容规模。

## 2. 本轮实施边界

本规格对应的实施计划只负责更新开发管理文件和任务卡，不执行下列任务本身。每个 Unity、BattleSim 或数据任务都必须在被领取时重新完成事实源读取、运行时所有者证明和独立验证。

本轮允许修改：

- `开发管理/当前任务队列.txt`
- `开发管理/开发优先级.txt`
- `开发管理/任务列表/场景与Unity任务.txt`
- `开发管理/任务列表/数据链路任务.txt`
- `开发管理/任务列表/数值与战斗任务.txt`
- `开发管理/任务列表/内容设计任务.txt`
- 一份任务队列重排前归档文件

本轮明确不修改：

- `src/` 下任何 Unity 代码、场景、Prefab、asset 和 Build Settings
- `simulations/BattleSim/` 下任何代码
- `docs/` 下游戏设计正文和剧情正文
- `data/` 或其他 CSV 数据源
- 审核结论、未通过审核清单和现有交接结论

## 3. 闸门结构与状态规则

任务按以下依赖关系推进：

```text
G1 正式构建链 ─┐
G2 BattleSim  ─┼─> GATE-EXIT-01 解冻判定 ─> 一个运行时薄内容切片
G3 数据语义链 ─┘

G1/G2/G3 通过后：P1 架构治理与薄内容切片可并行；世界级内容扩写仍不恢复。
```

每道闸门只有 `未开始`、`执行中`、`阻塞`、`通过` 四种状态。单个任务完成不等于闸门通过；只有该闸门的出口任务验证全部验收条件后，才能标记为 `通过`。

任何验证命令出现以下情况都视为失败：

- 测试结果文件缺失或无法解析；
- 测试用例未完整执行；
- 失败数量大于零；
- 检查脚本发现被定义为错误级的语义风险；
- 验证前后出现未预期的场景、Build Settings、Prefab、asset 或生成文件改动；
- BattleSim 输入不符合角色创建规则，或结果缺少规定样本。
