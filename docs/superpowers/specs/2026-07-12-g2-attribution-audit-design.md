# G2 极端对局归因审计设计

## 背景与目标

TQ-055 的 400 轮金丹审计已达到每 Build 200 个样本、每矩阵格 2,000 场的覆盖门槛，但同境矩阵存在大量 0%/100% 胜率。当前任务不是调参，也不把极端结果直接归类为设计预期或缺陷；目标是提供可重复运行的反事实审计，量化先天属性、功法成长/权重及远程资格对每个已覆盖极端对局的影响。

## 已比较的方案

1. 推荐：为每个已覆盖极端对局运行固定的一组反事实，输出逐局结果和汇总。这能保留可复现性、直接支持后续分类，并控制运行量。
2. 全矩阵全排列：对所有 21×21 对局、所有属性和机制组合展开。信息量更大，但会产生难以阅读的输出和不必要的运行成本。
3. 人工挑选少量日志：实现成本最低，但没有完整性保证，也不能作为回归证据。

采用方案 1。

## 命令与边界

新增独立入口：

```text
dotnet run --no-build -c Release --project simulations/BattleSim -- --g2-attribution --cycles 400
```

- `--cycles` 复用 G2 审计的正整数规则；省略时保持 200 轮默认值。
- 默认模拟、`--g2-audit` 的输出、随机种子、数值参数和战斗规则均不改变。
- 审计仅处理金丹目标矩阵中覆盖达标、且基线胜率恰为 0% 或 100% 的非对角对局；未达到覆盖的项目明确跳过而非作归因结论。
- 每个反事实仍使用相同的确定性角色配对和每格 2,000 场战斗，输出胜率与相对基线的百分点差。
- 反事实结果是“单层替换的影响”，不是可相加的因果分解，也不自动形成平衡判定。

## 反事实模型

对一个极端有向对局 A 对 B，先建立与 G2 审计相同的角色池和基线胜率；随后分别运行下列条件：

| 条件 | 保持不变 | 替换内容 | 用途 |
|---|---|---|---|
| 基线 | 全部 | 无 | 当前已观察结果 |
| 先天交换 | A/B 的 style、功法、成长表、机制 | 双方创建用先天属性，重新跑各自功法权重下的修炼 | 检验根骨及其他创建属性的贡献 |
| 功法包交换 | A/B 的 style、创建属性 | `GongFaName`、功法星级权重、对应成长表和元素 | 检验已设计成长表、临时回退与元素包的贡献 |
| 远程资格统一 | A/B 的角色属性、功法与技能配置 | 太一、符修、太虚/玄感的术法或神通也获得与现有 `magic` 相同的远程惩罚规则 | 检验当前 `style == "magic"` 的资格边界是否造成系统性弱势 |

所有替换都重新构建角色的一级/二级属性与技能配置，避免只改显示字段。远程资格使用仅对本次模拟有效的覆盖参数；默认 `Combat.Simulate` 保持现有行为。

## 输出

输出先列出基线覆盖与筛选数，再按对局给出：

```text
【G2 归因：A vs B】
基线：A 胜率=100.00%，配对=200，场次=2000
先天交换：A 胜率=…%，变化=…pp
功法包交换：A 胜率=…%，变化=…pp
远程资格统一：A 胜率=…%，变化=…pp
```

结尾按条件汇总极端对局的数量、平均绝对变化和最大变化对局，作为排查优先级；不会输出“已平衡”或“设计极端”的自动结论。

## 实现边界

- 在 BattleSim 内提取可重用的角色池构建与反事实配置；不得修改 `GameData` 中任何平衡数值或默认 Build 定义。
- 为 `Combat.Simulate` 增加可选的、默认关闭的远程资格覆盖。现有调用不传该覆盖时必须逐字节保持原有战斗路径。
- 新增专属 self-test suite。测试必须先失败，随后以最小实现通过。
- 不更新 G2 状态、任务状态或数值设计文档；本功能只产生诊断证据。

## 验证

1. 新 self-test 验证极端筛选只接收覆盖充分的非对角 0%/100% 对局。
2. 新 self-test 验证三个反事实各只改变声明的输入层，且默认战斗调用没有远程资格覆盖。
3. 新 self-test 验证命令参数的默认值、合法显式轮数与非法输入的失败关闭。
4. 运行 Release build、新 self-test、400 轮归因审计、默认模拟、`git diff --check` 及仓库规定的文本检查。
