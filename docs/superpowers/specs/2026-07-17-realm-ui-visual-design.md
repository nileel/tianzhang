## 一、界面目标

境界界面承担四项核心职责：

1. 展示当前大境界、小阶段与修行进度。
2. 展示与当前境界直接相关的结构，例如练气期的丹田灵气、筑基期的道基与独立紫府、金丹期的位格和唯一丹相状态。
3. 作为大境界突破的确认与演出入口。
4. 让玩家直观看见自己的修行结构如何从上一境界连续转化，而不是只看到数字增长。

角色全部属性不默认堆进本界面。境界页只显示与当前修行和突破直接相关的少量信息；完整属性汇总放在独立属性页，或通过可收起的详情抽屉查看。

## 二、已确认视觉方向

暂定采用第一版概念样图的黑金视觉方向，并以 PC 横屏重制样图作为当前基准：

- 全幅深色背景，中央修行结构自发光，形成体内观想与丹田内景的封闭感。
- 每个大境界拥有全新的中央视觉主体和构图，不把所有境界套入同一个固定容器。
- 保留较强的仪式感、空间层次和高对比度，不强求与浅色角色立绘使用同一背景。
- 与角色立绘的统一主要来自中国修仙题材、纹样、材料、色彩和笔触，而不是所有界面都改成同一种平面水墨设定页。
- 金色边框与装饰目前随第一版一起保留为暂定基准；后续可调整用量，但不在本轮继续生成折中版本。
- 单个境界界面按 PC 16:9 横屏设计，不使用手机竖屏比例或纵向卡片构图。
- 四境界总览改为 2×2 接触表，只用于验证形态继承与突破转化；每个分区代表一张独立的 16:9 游戏界面，不是最终游戏中的四宫格页面。
- 四个境界均采用统一的中轴构图：核心修行主体、底部行动区和突破演出焦点全部居中，不混用左对齐与居中对齐。

后续探索中产生的浅纸 2.5D、重复丹田腔室和亮纸沉墨版本不作为当前基准。它们分别暴露了天外秘境感、宗教解剖图感和脏污纸面感等问题。

## 三、界面总体结构

每个大境界使用独立中央舞台，但保留稳定的外围交互位置，避免玩家每次突破都重新学习操作：

- 中央：当前境界的核心修行结构固定在画面水平中轴，可轻微旋转、悬停或点击查看组成部分。
- 上方：境界名、小阶段和最简进度信息。
- 侧边：具体信息职责、常驻程度、宽度与视觉权重暂不锁定。筑基单界面探索已经证明，机械追求左右等重会使不同层级的信息被误读为同类内容。
- 下方：沿画面中轴放置修炼、突破或确认按钮；不满足条件时显示缺失项，不只显示灰色按钮。
- 详情：点击道基、紫府、镇府神通或位格后打开局部信息，不常驻铺满屏幕。

大境界变化时，中央舞台完全重构；外围导航、返回、帮助和属性入口尽量保持稳定。中央主体继续使用统一中轴逻辑，但情境详情不要求与固定摘要左右对称。侧边信息结构留待正式功能开发时结合真实字段与交互状态确定。

## 四、各境界的视觉与状态

### 4.1 练气期

核心意象是盘坐修士与腹部丹田空腔。

- 丹田中展示灵根结构。
- 灵气随练气九品进度逐渐填充空腔，不只使用一条普通经验条。
- 灵气颜色依据角色当前主修功法或主要灵力属性变化；项目正式术语使用“灵力/功法属性”，不继续扩散“内力属性”称呼。
- 多属性角色不能只靠混合颜色表达，必须同时使用纹理、流动方式或分层结构，避免色盲问题和颜色混浊。
- 练气圆满时，空腔接近充盈，但仍需展示筑基方案、相容灵根、地点、资源、固定周期进度与失败后果；筑基不显示一次最终抽签式成功率。

突破至筑基时，丹田空腔与其中灵气向中心压缩，最终凝成道基的基础形态。

### 4.2 筑基期

核心意象是角色独有的道基，以及命、魂、识、悟、运五类紫府的独立建造状态。

- 不同道基类型应拥有不同的轮廓、材料与纹样；不显示已删除的天地玄黄道基品级。
- 太一道庭的初授法箓是道基的一种。界面可使用法箓、法司纹样和授箓结构表现门派身份，但仍须展示统一四阶段、天然容量、扩府与五座紫府状态。
- 五类分别为命府、魂府、识府、悟府和运府。视觉上可以使用五座微缩建筑或五个内部空间，但必须让玩家看出它们是不同职责、每类最多一座的独立紫府，而不是五个等价技能槽。
- 每类紫府分别显示未建、府胚、建成状态；实际建成总数可以是 0～5，不预设主府、辅府或主修二至三府。
- 建成紫府固定显示一项府体效果和一项镇府神通，不设置空置神通位、本命术法候选槽或同府多神通。
- 镇府神通可以拥有独立图像或微缩模型；原型阶段先使用可区分的符号资源，正式资产量在美术预算确认后再扩展。

界面须分别展示天然容量、当前已释放天然容量、扩府层数、总容量、已建数量和尚未使用的容量。灵根只决定天然容量；功法软亲和只能改变筑造过程，不能把某类紫府显示为最终残缺或禁用。

筑基内部统一显示四个连续道基阶段，正式名称未锁定前只使用“第一阶段”至“第四阶段”：

- 筑基成功后立即进入第一阶段，显示道基本相与核心效果的当前连续进度。
- 第二至第四阶段按天然容量释放规则更新“已释放天然容量”，天然容量为零的角色仍可完成四阶段。
- 紫府蕴养与开府是玩家主动选择的固定周期行动，使用已释放天然容量或扩府容量推进，不等同于阶段名称。
- 第四阶段完成且至少建成一座完整紫府后，才显示结丹最低结构条件已满足；同时提示未用容量会在丹成后永久失效。

因此，道基阶段、容量释放、府胚／建成状态和镇府神通必须作为相互关联但不混同的四组信息展示。

### 4.3 金丹期

突破演出将完成第四阶段的道基、全部已建紫府及其镇府神通共同压缩为一颗金丹，再拉近视角进入金丹内部。

金丹内部暂用三层视觉隐喻：

- 中心凝实核心：源位。
- 中间流动层：化位。
- 外部包覆层：界位。

三部分只表示不同职责，不表示源高于化、化高于界。每部分必须能够独立处于已获得、未获得、暂寄、不稳定或失去等视觉状态，并显示所属道路纹理。

当前事实源允许角色按自由顺序取得一至三个稳定真实位格，每个位格使用不同镇府神通担任主承载，全部紫府仍共同进入一个丹枢核心和一个丹相。三层独立点亮不能暗示固定取得顺序、位格独占某座紫府或每个位格生成一颗新丹相；具体运行时字段仍待实现设计。

### 4.4 元婴期

元婴是远期、NPC 与资料片方向，当前玩家完整成长链止于金丹。本轮只记录视觉锚点，不排入近期实现。

- 三个位格条件满足后，突破演出可表现为元婴从源位核心孕生，并破开金丹外壳。
- 元婴应明显带有“新生”与“破壳”意象，不能画成普通成年元神。
- 元婴界面根据道路更换中央主视觉，但建议保留共享外围交互骨架，避免十七条道路都制作完全无关的整套 UI。
- 阴/阳道路示例可使用阴阳图中的两个婴孩形态；角色实际承接哪一道路，就点亮对应形态，另一形态保持暗淡或虚影。该表现不能暗示角色同时持有两个元婴位格。
- 每个具体元婴位格仍须保持唯一性，不出现可批量复制的通用元婴模板。

## 五、突破动画语法

各境界使用同一条“压缩、固化、破壳”的连续视觉语法：

1. 练气至筑基：空腔与灵气压缩并固化为道基。
2. 筑基至金丹：道基、全部已建紫府和镇府神通纹理向中心坍缩，凝为唯一金丹结构。
3. 金丹至元婴：内部条件完成后孕生元婴，金丹从内向外破壳。

动画必须让上一境界的材料、纹样和选择痕迹进入下一境界，不能只用白光遮屏后替换模型。不同道基、实际紫府组合、镇府神通和位格道路应改变转化后的细节。

## 六、适配判断

该方向总体合适，核心优点是：

- 把境界成长变成可见、可记忆的个人修行结构。
- 每次大境界突破都有自然的形态转化依据，仪式感强。
- 道基、独立紫府、镇府神通和位格不再只是列表字段，可直接承载 Build 差异。
- 中央视觉信息强，外围可以保持简洁，符合单界面少信息的审美偏好。

主要风险是：

- 每个境界、道基和道路都完全独立制作会造成较高美术资产量。
- 镇府神通独立模型会随内容数量快速膨胀，应先验证图像、符号和少量关键模型的混合方案。
- 金丹一至三稳定位格与唯一丹相的设计事实已锁定，但 UI 不得先于数据结构和交互状态锁死运行时字段。
- 只靠颜色表示灵力、紫府类别或位格会造成可读性和无障碍问题。
- 高阶元婴界面不属于当前版本近期交付范围。

## 七、当前结论与后续验证

当前结论：PC 横屏重制样图作为阶段性视觉基准试用。它保留第一版的深色丹田内景、黑金材质和境界仪式感，同时将每个境界改为独立 16:9 横屏构图，并统一采用中央主体居中的布局规则。该样图仍是方向稿，不代表控件尺寸、文字排版和最终资产已经定稿。

筑基单界面已经进行过一轮视觉探索，但未达到采用标准，现阶段不再继续迭代。正式功能开发启动后，应先确定道基、容量、独立紫府与镇府神通的真实展示字段、选择状态和信息展开路径，再重新制作单界面样稿；本次未采纳样图不得直接转为 Unity 布局。

单界面样稿通过标准：

1. 不看文字也能识别当前境界和核心进度。
2. 五类紫府可区分，但不会被误解为五个普通技能槽或必然全部建成。
3. 天然容量、扩府层数、总容量和 0～5 座实际紫府状态清晰。
4. 突破入口明显，但不抢夺中央结构的视觉焦点。
5. 默认界面保持简洁，详细数值按需展开。
6. 能说明关键状态如何由数据驱动，而不是每种组合都依赖一张完整静态图。

## 八、筑基单界面未采纳方案

归档样图：`assets/generated-ui-art/realm-ui/foundation-realm-ui-unadopted-v1.png`。

该图仅记录本轮探索过程，不代表正式界面。图中的“黄白道基”“命府”和“玉液周天”用于测试信息层级；不得据此认定该组合是默认 Build、教程角色配置或正式 UI 示例。

未采纳原因：

1. 左右信息虽然取消了实体底板，仍使用近似的标题、字号和行数，视觉比重再次趋同，没有体现固定道基信息与当前紫府情境信息的层级差异。
2. 命府主要依靠紫色亮度表现状态，但紫色同时承担紫府类别色，静态画面无法明确区分“默认发光”和“当前选中”。
3. 更早的厚重石板、金边卡片和大按钮尝试呈现出明显页游组件感，与项目希望的简洁、克制、有设计感的 PC 单机界面不符。
4. 当前迭代以生成图反复覆盖布局问题，缺少正式功能字段、默认态、悬停态、选中态、未建／府胚／建成态和详情展开态的交互原型支撑；继续叠加视觉修补会增加复杂度而不能解决根因。

后续恢复条件：进入境界功能正式开发时，先基于真实数据结构确定信息优先级与交互状态，再重新设计筑基界面。可保留中央道基、五类紫府方位和深色内景作为探索参考，但不继承本图的左右信息布局、文字层级、选中表现或突破入口样式。
