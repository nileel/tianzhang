# 养基、筑府与闭关行动生命周期设计

状态：✅ 已确认（C-FPD-CULTIVATE-01，2026-07-25）；本文件锁定行动生命周期与非数值边界，不锁定周期长度、资源量、损耗比例、成功阈值、数据 schema 或运行时实现。

## 一、目的与不可变边界

本设计承接《筑基、紫府与丹相承接系统设计》《修行境界》和《寿元与时间尺度设定》，统一养基、府胚蕴养、筑基考验、开府考验与闭关重复的行动边界。

- 功法每日被动灵力是唯一不需要主动行动的修炼收益。其他成长都由角色选择合法行动，并按同一个固定修炼周期推进。
- 闭关不是独立成长来源、第二套修炼系统或离线奖励，只负责重复当前已选定的合法行动并推进世界时间。
- 玩家与 NPC 使用同一行动合法性、时间、资源、进度、暂停、完成和失败规则；两者只在行动选择者和优先级来源上不同。
- 筑基与开府失败不会生成残缺道基、低品道基、残缺紫府或劣等外府。
- 本文件只描述可由后续数值与数据任务直接消费的语义，不规定字段、枚举、默认值、参数取值或平衡公式。

## 二、统一行动生命周期

下列名称只表示设计语义，不是数据 schema 或代码状态枚举：

```text
准备／可开始
    ↓ 通过当前事实校验
进行中
    ↓ 提交一个固定修炼周期；考验节点在周期边界结算
继续 ──→ 暂停 ──→ 重新校验后恢复
  ├────→ 完成
  ├────→ 失败
  └────→ 主动终止
```

### 2.1 开始

角色开始行动时必须一次性明确行动种类、目标以及该行动要求的直接选择，例如养基目标、目标府属、源术法、主修功法、地点或已准备资源。系统只读取角色境界、既有进度、知识、资源、环境和行为记录等真实事实判断是否合法，不创建脱离事实源的“已获资格”对象。

开始校验至少保证：

- 角色当前能够行动，且没有与本行动冲突的不可离开流程。
- 境界、目标、知识、地点、环境和直接前置仍满足该行动的硬条件。
- 下一次周期或当前考验节点所需的时间与资源可以完整结算。
- 行动不会越过紫府容量、同类府唯一性、源术法状态或结丹后的永久锁。

校验失败只拒绝开始，不推进时间、不消耗资源、不增加进度，也不自动改选另一个目标。

### 2.2 单周期原子推进

每个固定修炼周期按同一原子边界结算：

1. 周期开始前重新检查行动仍合法，并确认本周期所需资源可完整支付。
2. 提交本周期的时间、资源和行动结果，世界时间同步推进，世界事件照常结算。
3. 写入本周期产生的连续进度、阶段节点、伤势、资源变化或其他明确结果。
4. 在已提交周期的稳定边界检查目标完成、失败、待响应事件、资源耗尽和停止条件，再决定继续或停止。

一个周期要么完整提交，要么完全不提交。不得出现只扣资源不推进时间、只增加进度不支付成本、读取后重复结算或通过中途退出保留有利部分结果的半周期。

手动执行一个周期后即把控制权交还给行动选择者。闭关继续使用同一周期结算，只在稳定边界自动申请下一周期。

### 2.3 暂停与恢复

暂停保留已经完整提交的时间、资源、连续进度、阶段节点、府胚目标和待处理事件，不回退、不退款，也不把进度转换成另一个目标。暂停本身不等于失败或主动终止。

恢复只能从最近稳定边界继续，并必须按当前世界事实重新校验原行动。条件重新满足时继续原目标；条件暂不满足时保持暂停；目标已失效、角色已越过允许境界或永久锁已生效时不得恢复，也不得静默改选行动。

角色可以暂停一个连续行动后执行其他合法行动。重新开始原行动时仍沿用原有目标和已提交进度；需要改变固定目标时，必须先按主动终止边界结束原尝试。

### 2.4 完成、失败与主动终止

- **完成**：行动已达到开始时指定的合法目标，或其自身没有下一步可推进内容。完成结果先结算，再停止重复。
- **失败**：只有行动或考验的明确规则给出失败结果时成立。资源不足和普通事件中断只导致暂停，不自动算失败。
- **主动终止**：角色在允许离开的稳定边界明确结束当前尝试。已提交的时间和资源不退还；终止不会留下残缺道基或残缺紫府。
- **强制失败**：不可离开考验遭遇规则明确的致命中断或失败结果时使用，按该考验既有失败后果结算，不能降格为无损暂停。

失败与主动终止必须分别结算。具体损耗、伤势和回退幅度由后续数值任务锁定；本文件只锁定哪些成果可以保留、哪些完整成果不得生成。

## 三、行动专属边界

### 3.1 筑基考验

- 练气九品圆满、相容灵根、主修功法、地点和辅助资源等前置满足后，角色才能开始筑基考验。
- 考验按固定修炼周期推进，只在关键考验节点、资源耗尽或需要响应的外部事件处暂停。玩家可在允许离开的节点继续准备、处理事件或主动终止。
- 完整处理全部考验后必定成功，形成唯一道基并进入第一阶段；不存在最终抽签或随机品级判定。
- 普通失败只保留已经发生的时间、资源损耗和可恢复伤势，恢复后可重新开始；不形成道基实例、道基裂纹、残缺道基或低品道基。

### 3.2 连续养基

- 养基只对已成功筑基、尚处筑基期且未完成第四阶段的角色合法。
- 每个周期只向同一条连续道基进度提交结果。跨越阶段节点时自然进入下一阶段并结算该节点的既有收益，不创建新的突破考验。
- 已跨越的阶段节点与已提交连续进度在暂停、换做其他行动或读取存档后保持不变。
- 达到指定阶段目标时当前行动完成；第四阶段完成即筑基圆满，此后养基不再合法。普通养基周期没有独立随机失败，也不会因暂停生成残缺道基。

### 3.3 府胚蕴养

- 开始时固定目标府属和源术法，并检查筑基期、已释放容量、同类府唯一性、兼容源术法、升格知识、行为条件、资源和环境。
- 每个周期只增加该目标的府胚进度。府胚可以暂停并恢复，目标府属和源术法不会在恢复时自动替换。
- 府胚不是完整紫府，不启用府体效果或镇府神通，也不正式占用已建紫府容量。
- 为防止同一容量被多个暂停府胚重复承诺，开始与恢复时必须把现存府胚一并计入可建造性检查；已建紫府与现存府胚的承诺不得超过当前总容量。
- 府胚完成只表示正式开府考验已经可选，不自动建成紫府、不消耗源术法，也不触发府体或神通效果。
- 在允许离开的稳定边界主动放弃府胚时，已经提交的时间与资源不退还，源术法不消失，容量不被占用，也不留下残缺紫府。
- 府胚承诺在开府成功时转换为完整紫府的容量占用，在主动放弃时释放；开府失败后仍随回退后的府胚保留。开始结丹前必须完成开府或显式放弃所有现存府胚，不能把不可恢复的府胚状态带入金丹期。

### 3.4 正式开府考验

- 只有完整府胚及其原目标、源术法和当前全部开府硬条件仍然有效时，才能开始正式开府。
- 开府是一次不能中途离开的完整考验。考验内每次产生进展仍提交一个固定修炼周期，普通步骤之间不交还控制权；普通暂停、闭关停止条件和手动停止只能在开始前或终局结算后生效，不能把考验截成可反复重抽的片段。
- 成功时才原子建成目标紫府、占用对应容量，并按升格方案处理源术法、建立该府唯一镇府神通和固定府体效果。
- 失败时紫府不建成、容量不被占用、源术法不消失；只按后续数值规则回退部分府胚进度与投入资源，并造成可恢复伤势。恢复后从失败结算后的府胚状态重新满足条件并重试。
- 失败、强制中断或读取存档都不能生成残缺紫府，也不能保留只包含府体或只包含镇府神通的半成品。

## 四、停止原因与闭关重复

闭关只保存“当前选择的合法行动 + 目标 + 停止条件”，每次仍请求同一行动完成一个固定周期；不可离开考验只是在周期边界自动继续其下一个合法步骤。闭关不修改行动成功规则，不预支未来收益，也不绕过世界事件、章节边界、角色寿元或境界解锁。

闭关在下列边界停止：

- 出现需要角色或玩家响应的事件，或到达筑基考验的关键选择节点。
- 下一周期资源无法完整支付；未开始的周期不扣资源、不推进时间、不增加进度。
- 行动目标完成，包括养基目标、府胚完成、考验成功或其他已选目标达成。
- 行动失败、遭遇强制失败，或恢复所需伤势尚未处理。
- 行动因境界、目标、地点、环境、知识、容量、源术法状态或永久锁变化而不再合法。
- 达到玩家事先设定的时间、资源保留、进度或世界事件停止条件。
- 到达不可跨越的章节或系统解锁边界。
- 玩家在允许离开的稳定边界手动暂停。

停止时必须向玩家说明已经提交到哪个稳定边界、停止原因、是否可恢复以及恢复前仍缺少什么。多个原因同一边界发生时，行动的完成或失败结果先结算；其他原因不得覆盖已发生的终局结果。

闭关执行开府考验时不会在考验内部自动暂停或自动重试。考验成功或失败后闭关立即停止；失败后的疗伤、资源补充和再次开府必须重新选择合法行动。

## 五、玩家与 NPC 的共同规则

- 玩家只能直接为自身选择行动、目标和闭关停止条件，不能逐人编排其他角色的修炼计划。
- NPC 先用与玩家相同的硬条件过滤非法行动，再按既有基础权重、性格、门派、境界目标、寿元、资源和环境修正选择合法行动。
- NPC 的寿元压力只能改变合法行动之间的优先级和主观风险阈值，不能绕过灵根、道基阶段、容量、紫府、知识、资源或证位硬条件。
- NPC 的单周期结算、暂停、恢复、资源耗尽、事件响应、失败回退和完整成果边界与玩家一致。不得以离屏模拟或 AI 便利直接跳过周期、资源、事件或失败。
- 玩家与 NPC 的差异只属于控制来源和决策权重；后续数据或运行时不得维护两套行动结果规则。

## 六、保存与读取边界

保存与读取只恢复行动事实，不重算已经提交的周期或改变既有结果。

- 可稳定保存的边界包括行动开始前、每个完整周期提交后、暂停后、考验明确允许保存的周期安全节点，以及完成、失败或主动终止结算后。
- 保存必须保留当前行动及固定目标、已提交进度与阶段、已支付时间与资源、府胚承诺、待处理事件或选择、停止条件和当前可恢复性。这里描述的是语义事实，不规定字段或序列化格式。
- 读取后从最近已提交的稳定边界恢复。已经提交的周期不得再次扣费、再次增加进度、再次触发收益或重抽考验结果；尚未提交的周期不得保留部分成本或部分收益。
- 对不能中途离开的开府考验，只有考验内容明确提供可重复且结果确定的安全节点时才能在内部保存；否则保存请求延后到终局结算。读取不能被用来退出考验、规避失败或刷新结果。
- 若读取后的世界事实使行动暂时不合法，行动保持暂停并显示原因；若结丹永久锁等不可逆事实已经生效，则原养基、府胚或开府行动不得恢复。
- 玩家与 NPC 使用相同的持久化语义。世界时间和事件状态必须与行动边界一同恢复，不能只恢复角色进度而回滚外部世界。

## 七、后续任务接口

- `N-FPD-GROWTH-01` 只确定四阶段一级属性预算与连续道基核心成长曲线，不改写养基生命周期。
- `N-FPD-CULTIVATE-01` 为固定周期长度、行动资源成本、考验损耗、回退幅度和目标时间尺度锁定参数；资源不足、事件暂停、目标完成和存读档原子边界保持不变。
- `D-FPD-SCHEMA-01A` 以本文件与《五府府体效果机制设计》共同定义静态契约和正反 fixture；必须能区分暂停、完成、失败、主动终止、府胚承诺、结丹永久锁与闭关停止原因，但不得反向猜测默认数值。
- 后续 Unity 与保存任务只消费已确认的行动语义，不新建第二套角色成长服务，不为 NPC、闭关或读取存档建立绕过合法行动的入口。
