## 输入冻结与本次改动

人体、袖子源、FBX、蒙皮、袖幅、96 个固定点、360 个自碰撞点、3 对双球代理和 Retune 01 的全部 Cloth 参数不变。运行报告确认弯曲 0.70、拉伸 0.88、最大位移 0.38 m、456 顶点、渲染节点世界缩放约为 (1,1,1)。没有重建人体、增加袖子或新 Cloth 系统。

本次只修正实验驱动及取证：

1. 姿态曲线在抬放、挥臂、转向各段边界连续；不再以姿态跳变冲击布料。
2. 根节点以 1.25 m/s 匀速移动 1 秒，然后位置保持，形成真实速度突停。**这里是隔离平移惯性的根节点移动，没有播放完整走路步态**；不能等同覆盖正式角色跑步动画。
3. 六个朝向各独立跑完整 12 秒。方向复位时先禁用 Cloth、下一帧启用并清除变换运动，随后留约 2 秒明确标出的 RESET / SETTLE；复位不计入动作位移峰值。
4. 录制按整数帧驱动 60 Hz 模拟，每 5 帧在 EndOfFrame 测量并截取实际画面；不使用墙钟补抓旧时间标签。初始窗口／Shader 预热排除在 72 秒之外。
5. 同一人物、同一 Cloth 实例被三个相机观察：左为近景；右上为黄色躯干、青色上臂、洋红前臂的 X-ray 代理线框；右下为固定俯角 38°、正交尺寸 6.2 的战棋投影。线框只是诊断叠加，没有向物理增加碰撞器。

**尺度限制：**右下战棋面板的原始视口为 640×360，正交尺寸采用项目的 6.2；它验证相同世界尺度／视角下的轮廓，不是正式游戏全屏像素大小和完整 UI 环境验收。不能用缩小的面板替近景问题开脱。

## 数值探针：未通过，禁止据此归因

通过当前 `renderer` 变换把 `Cloth.vertices` 转成世界坐标，并与 CPU 四权重蒙皮预测的固定点位置对照。在 858 个 Cloth 启用的采样中，只有 42 个的最大固定点误差小于 5 mm；816 个不通过。整轮误差范围约为 0.000001–0.180400 m。因此：

- **本轮所有“穿透深度／代理体内顶点数／超出运动约束量”的物理解释都暂缓，不取其最大值作为根因证据。**原始 JSON 保留 `coordinateProofValid` 供审计，不代表该探针经过验证。
- 不能把 18 cm 的校验差直接称为实际袖根脱离 18 cm。Cloth 顶点索引、CPU 蒙皮对应、坐标转换或求解状态关系中哪一项造成差异，本轮未区分。
- 即使固定点校验通过，也只能验证这些固定点，不能证明所有自由点与原网格索引一一对应。自由区约束超量尤其不能据此独立归因。
- 双球对的深度公式按连续锥形胶囊计算，而非两颗离散球。右上线框显示实际注册的代理体范围，但不等于人体精确表面。
- 该探针不检测布面三角形穿过人体三角形、自交或采样间短暂贯穿；零代理体穿透也不能推出“人体不穿模”。

相关官方行为参照：[Cloth.vertices](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Cloth-vertices.html)、[固定步长录制](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Time-captureFramerate.html)、[EndOfFrame 截图](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/ScreenCapture.CaptureScreenshotAsTexture.html)。

- GIF 第一次封装遇到 RGBA 调色板格式限制，转换为 RGB 后重新封装已有帧；没有改帧内容、物理或重跑 Unity。GIF 帧时长按 80/80/90 ms 循环，整段合计 72,000 ms，片段 12,000 ms。

暂不建议进入双袖／袍摆。修正输入后视觉问题确实仍在，但要继续应先单独查清固定点校验差和碰撞代理与真实表面的关系，而不是继续增加布料或购买插件；本轮到此停止。
