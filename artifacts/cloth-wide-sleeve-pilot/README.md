# Unity 自带 Cloth 单侧宽袖最小可行性试验

结论：**部分可行，但当前基线不通过进入双袖／袍摆的门槛；一次受控加硬对照也没有改变该结论。** 基线的慢速抬放臂、静止下垂和急停回落可用；明显挥臂与身体转向会产生不可接受的压扁、翻卷和扫入躯干轮廓。Retune 01 收紧位移并提高弯曲刚度后，抬放臂更利落，但快速动作变成更明显的整片横甩、板状翻卷与停止后不回落。本结论来自实际 Unity 6000.3.18f1 Development Player 运行，不是生成视频或 Blender 预览。

## Retune 01：是否调得太软

这次只改两类 Cloth 参数，其他输入全部冻结：弯曲刚度由 `0.42` 提高到 `0.70`；袖根至袖腹的最大运动约束梯度由 `0 → 0.12 → 0.40 → 0.64 m` 收紧为 `0 → 0.10 → 0.24 → 0.38 m`。拉伸刚度 `0.88`、456 顶点网格、96 个固定点、3 组碰撞对、自碰撞、动作、镜头、采样频率、Blender 源和冻结 FBX 均未变化。

- `unity-cloth-wide-sleeve-pilot-retune-01.gif`：Retune 01 的 32 秒真实 Unity 播放器实录，720×405、256 帧、循环播放；SHA-256 `082CDCB404AFB1D2A596A1D49C56CD35535E3942FDD7FF9E534F562CFCF84BF8`。
- `runtime-report-retune-01.json`：同次运行报告；最大运动约束实测 `0.38 m`，平均 `55.02 fps`。最大单帧 `2728.62 ms` 仍包含抓帧开销，不能作为稳态 Cloth 成本。
- 有效原始帧位于本机 `D:\Temp\TianZhang-Blender\cloth-wide-sleeve-retune-02-capture\`。第一次 Retune 抓帧因播放器隐藏窗口而全黑，已判为无效证据；第二次仅改为可见窗口重录，没有再改物理参数。

受控对照证实：**基线确有偏软成分，但“参数太软”不是快速动作失败的充分原因。** 单纯提高弯曲刚度、减少自由位移会把软塌问题转化为整片布面横甩、硬折与残余翻卷，因此不继续围绕同一假设反复调参。当前场景和构建器保留 Retune 01，基线实录与报告继续保留用于直接比较。

## 结构与运行事实

- 一个 Quaternius Universal Base Characters Standard 免费绑定人体，Humanoid 有效；没有导入付费 Source 包。
- 一只本轮新建的左宽袖，不读取或复用旧苻渊网格；456 顶点、432 四边面／864 三角面，袖根与袖口为预期开放边界，除此之外非流形边、退化边、零面积面均为 0。
- Unity 内只有一个 Cloth：96 个固定袖根顶点、360 个自碰撞顶点、3 组躯干／上臂／前臂球体对碰撞器、180 Hz Cloth solver。基线最大运动约束为 0.64 m；当前可重现场景采用 Retune 01 的 0.38 m。
- 单角色 Development Player 最终实录平均 54.48 fps；最大帧时间 2702.92 ms。报告没有记录峰值所在帧，且采样包含截图开销，因此不能把该峰值解释为 Cloth 稳态成本。该数字只证明单角色小样能运行，不是同屏多角色性能结论。
- 场景：`src/Assets/Tests/Scenes/ClothWideSleeveExperimentScene.unity`，没有加入 BuildSettings。
- 可编辑源：本机项目路径 `assets/source/characters/cloth-wide-sleeve-pilot/TZ_ClothWideSleevePilot_v001.blend`；Git 规则将 `assets/source/` 作为本地源美术工作区忽略。
- 冻结 FBX：`src/Assets/Tests/ClothWideSleevePilot/Models/TZ_ClothWideSleevePilot_v001.fbx`，SHA-256 `5BD14D613A68881ED5202F03CE6A494535382DBB541C5BC4310CC6A30E0367A4`。

## 已证实原因、未知项与返工

- 已证实：Blender 源是米制且对象均为 1 倍缩放；首版 FBX 把单位换算留在 Unity 节点的 100 倍缩放中，导致 Cloth 局部约束量纲错误。改用 Blender `FBX Units Scale` 后，Unity 局部与世界肩腕长度均为 0.494476 m、渲染节点缩放为 1，场景才进入有效物理试验。
- 已证实：快速挥臂／转向失败不是旧苻渊坏拓扑造成，因为本轮袖网格从零建立并通过拓扑检查；自碰撞和三组身体碰撞也确实处于启用状态。失败与高速角运动同时出现，慢动作和最终静止不持续异常。
- 已证实：Retune 01 同时提高弯曲刚度并收紧约束后，抬放臂改善，但挥臂、转向、六方向和急停回落没有通过，部分板状翻卷更严重；因此“整体太软”不是充分根因，不能靠继续加硬解释并解决同一现象。
- 仍未知：剩余瓶颈在当前碰撞体近似、约束方向／渐变、运动传递尺度和网格作为整片布面的响应中各占多大比例，尚未用独立变量继续区分。本轮命中停止条件，没有围绕同一失败继续叠加参数。
- 实际返工：一次 Unity 6 API 类型修正（`useVirtualParticles` 为浮点属性）；一次 FBX 单位导出修正；基线第一次录制发现急停段被固定相机裁切，物理参数不变，仅让同角度相机跟随角色后重录；Retune 01 第一次录制因隐藏窗口得到全黑帧，判为无效后以同构建可见窗口重录。没有购买、替换 Cloth 系统或重建人体。

## 投入建议与风险

不建议直接进入双袖或袍摆。若要继续，只应另行批准仍限定为单袖、一次只验证一个剩余假设的对照；不再重复“继续加硬／继续缩小位移”的路线。在明显挥臂、转向和急停回落通过之前，不应增加第二只袖子或袍摆。

同屏多角色性能风险未覆盖：当前单袖已有 456 个 Cloth 顶点、360 个自碰撞点和 180 Hz solver。多角色数量增加时 CPU 布料、自碰撞和碰撞器成本可能明显增长，必须在目标阵容与目标硬件上单独采样，不能按本次 54.48 fps 线性外推。
