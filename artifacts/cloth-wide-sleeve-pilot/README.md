# Unity 自带 Cloth 单侧宽袖最小可行性试验

结论：**部分可行，但当前基线不通过进入双袖／袍摆的门槛。** 慢速抬放臂、静止下垂和急停后的回落可用；明显挥臂与身体转向会产生不可接受的压扁、翻卷和扫入躯干轮廓。本结论来自实际 Unity 6000.3.18f1 Development Player 运行，不是生成视频或 Blender 预览。

## 结构与运行事实

- 一个 Quaternius Universal Base Characters Standard 免费绑定人体，Humanoid 有效；没有导入付费 Source 包。
- 一只本轮新建的左宽袖，不读取或复用旧苻渊网格；456 顶点、432 四边面／864 三角面，袖根与袖口为预期开放边界，除此之外非流形边、退化边、零面积面均为 0。
- Unity 内只有一个 Cloth：96 个固定袖根顶点、360 个自碰撞顶点、最大运动约束 0.64 m、3 组躯干／上臂／前臂球体对碰撞器、180 Hz Cloth solver。
- 单角色 Development Player 最终实录平均 54.48 fps；最大帧时间 2702.92 ms 发生在启动／首帧捕获阶段。该数字只证明单角色小样能运行，不是同屏多角色性能结论。
- 场景：`src/Assets/Tests/Scenes/ClothWideSleeveExperimentScene.unity`，没有加入 BuildSettings。
- 可编辑源：本机项目路径 `assets/source/characters/cloth-wide-sleeve-pilot/TZ_ClothWideSleevePilot_v001.blend`；Git 规则将 `assets/source/` 作为本地源美术工作区忽略。
- 冻结 FBX：`src/Assets/Tests/ClothWideSleevePilot/Models/TZ_ClothWideSleevePilot_v001.fbx`，SHA-256 `5BD14D613A68881ED5202F03CE6A494535382DBB541C5BC4310CC6A30E0367A4`。

## 已证实原因、未知项与返工

- 已证实：Blender 源是米制且对象均为 1 倍缩放；首版 FBX 把单位换算留在 Unity 节点的 100 倍缩放中，导致 Cloth 局部约束量纲错误。改用 Blender `FBX Units Scale` 后，Unity 局部与世界肩腕长度均为 0.494476 m、渲染节点缩放为 1，场景才进入有效物理试验。
- 已证实：快速挥臂／转向失败不是旧苻渊坏拓扑造成，因为本轮袖网格从零建立并通过拓扑检查；自碰撞和三组身体碰撞也确实处于启用状态。失败与高速角运动同时出现，慢动作和最终静止不持续异常。
- 仍未知：主要瓶颈究竟是当前碰撞体近似、约束渐变、网格分布还是 Cloth 参数组合，尚未通过单变量实验区分；本轮按最小试验停止，没有用反复调参扩大范围。
- 实际返工：一次 Unity 6 API 类型修正（`useVirtualParticles` 为浮点属性）；一次 FBX 单位导出修正；第一次录制发现急停段被固定相机裁切，物理参数不变，仅让同角度相机跟随角色后重录。没有购买、替换 Cloth 系统或重建人体。

## 投入建议与风险

不建议直接进入双袖或袍摆。若要继续，只应先批准一次仍限定为单袖的对照试验，逐项验证碰撞体、约束渐变和网格分布；在明显挥臂与转向通过之前，不应增加第二只袖子或袍摆。

同屏多角色性能风险未覆盖：当前单袖已有 456 个 Cloth 顶点、360 个自碰撞点和 180 Hz solver。多角色数量增加时 CPU 布料、自碰撞和碰撞器成本可能明显增长，必须在目标阵容与目标硬件上单独采样，不能按本次 54.48 fps 线性外推。
