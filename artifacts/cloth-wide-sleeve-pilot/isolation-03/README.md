## 已证实原因，以及不能据此声称的结论

**已确认：96 个固定蒙皮目标中有 28 个在放臂初始姿态位于躯干代理内部超过 5 mm，最深 0.125308 m。** 该冲突在 t=0、Cloth 尚未启用时已经存在，t=1／2／7 s 的同姿态复查一致；上臂和前臂代理内的固定目标数均为 0。这使用经 A 校准的 CPU 蒙皮位置和实际注册双球代理的连续几何计算，不依赖 `Cloth.vertices` 的转换，也不是把两颗球之间误算成空隙。

源顶点索引为：`360,361,362,363,364,365,367,369,400,401,402,403,404,405,406,407,408,409,410,411,412,413,445,447,449,451,453,455`。这些点同时被要求保持固定蒙皮位置、又落在身体排斥区域内，构成当前配置的明确几何冲突。

辅助隔离证据：静态 B 在 t=1／2／7 s 的全部 96 个固定点与候选 Cloth 世界坐标最大差仅 0.000000287 m；同姿态 C 有 28 点超出 5 mm，按索引最大差约 0.134–0.147 m。即使忽略索引、寻找任意最近 Cloth 顶点，C 仍有目标相距约 0.11254 m。这支持“开启身体代理引入额外差异”，但不等于已经查明求解器内部的约束优先级。

同时，**A 纯蒙皮画面本来就有横向包腰背的参考形状**。因此碰撞冲突不是当前自然形状失败的唯一解释；关闭碰撞也不会自动得到合格宽袖。现有蒙皮参考形状与运动自由度对最终包身形状各贡献多少，尚未分离。

证据边界：

- 12.53 cm 是固定蒙皮目标进入碰撞代理的最大深度，**不是测得真实人体三角面穿透 12.53 cm**。代理对真实人体的覆盖精度、布面／人体三角形贯穿、自交仍未量化。
- 静态 B 的坐标／索引校准不能推广为所有动态帧和自由顶点都有效；动态 B 已出现约 1.96 cm 固定点差。开启 Cloth 的 B／C 中，BakeMesh 不能充当独立纯蒙皮参考。
- 保留原诊断数据及校验标志，不用未通过的深度值证明防穿模失效，也不把设置自碰撞等同于无自交。

## 唯一修正及复验判定

只将上述 28 点的 `maxDistance` 从 0 改为**原来已经存在的最大值 0.38 m**，其余 68 点保持固定，其他全部约束和物理参数不变。没有缩袖幅、改权重、改代理、加刚度或换系统。原 360 点自碰撞集合也保持不变，释放的 28 点没有另外加入；这限制了该候选的解释范围，但本轮不再叠加第二个变量。

修正作为实验控制器的可选开关保留，**默认关闭**；没有把失败候选设成场景默认方案。

| 动作／检查 | 判定 | 实际观察 |
| --- | --- | --- |
| 抬臂／放下 | 基本跟随部分通过，整体未通过 | 袖体跟随并保留下垂部分，但硬折、翻起边与肩部开口仍影响形状，袖根不能判定稳定合格。 |
| 明显挥臂 | 失败 | 仍出现横跨身体的大幅包身形状；例如 330° 的 frame0628（52.33 s）。 |
| 身体转向 | 失败 | 腰背包裹与硬折未消除，没有达到自然宽袖轮廓。 |
| 移动后突然停步 | 输入有效，布料回落失败 | 150° frame0284（23.67 s）已停 2.67 s，仍明显包在腰背，带有肩部开口和上翻硬边。 |
| 近景／战棋尺度／六方向 | 未通过 | 近景仍暴露缺陷；战棋投影保留异常轮廓。全部方向与失败段已保留，不以遮挡或缩小画面宣称成功。 |
| 持续抖动、拉尖、自交与人体穿插 | 未获全面排除 | 可见硬边、折片和疑似交叠，不能凭离散关键帧声称已证明或消除每一种故障。 |

修正后剩余 68 固定点的旧探针门槛在 858 个启用采样中有 774 个通过，最大误差约 0.059768 m。**这不能与旧 96 点的 42／858 直接比较：被测集合减少了，恰好排除了 28 个冲突点；绝不据此宣称原 96 点已修好。** 动态／自由顶点解释仍受上述校准限制，视觉失败不因数值通过率而豁免。

## 验证、成本与停止点

- 本轮新增 A／B／C 模式、只读蒙皮／代理快照，以及一个默认关闭的 28 点释放开关，均归属实验 asmdef `TianZhang.ClothWideSleevePilot`；控制器引用只存在于实验场景。未修改正式角色、Adventure、战斗、存档、BuildSettings 或任何业务模块依赖。
- [首次 10／10 EditMode 检查](editmode-results.xml)，加入唯一修正后 [11／11 检查](pin-release-editmode-results.xml) 通过，包括动作连续、真实突停、独立场景／源文件存在、释放仅影响 28 点且不修改保存场景。构建成功不等于效果通过。
- 实际工作包括 3 次播放器构建，A／B／C 各 8 s、C 几何取证 8 s、一次候选 72 s，共 104 s 新模拟；最终录制 4,320 步、864 帧。无第二次修正或参数搜索。构建时许可刷新警告未阻止成功；几何取证播放器有 D3D 时间戳回退警告，没有据此更改模拟输入。
- 这是在既有建模、导入、调硬和驱动返工之后的又一轮诊断成本，没有新增模型制作、付费内容或源文件返工；没有完整工时记录，不虚报总人时。当前结果不能支持“低成本量产角色”。
- 按 `tianzhang-blender-pipeline` 保留源与导出不变；按 `unity-agent-workflows` 核验实验运行时所有者、隔离路径、实际画面和数值边界。主工作区与隔离 worktree 的自动化／集成状态按项目规则检查，Unity 构建产生的无关序列化改动已清除。
- **停止扩大实施。** 一项确定冲突被隔离，但修正后整体形状仍失败，后续若获单独批准，应先判断纯蒙皮参考形状和运动约束是否适合宽袖，而不是继续叠加“防穿模脚本”。本轮没有证据支持换布料系统或购买插件，也不建议进入双袖／袍摆。

单角色性能仍未知：最终 86.2679 s 墙钟时间包含 72 s 固定模拟、三相机、CPU 诊断和 PNG 写盘，**不是稳态帧率或单角色 Cloth 成本**。同屏多角色、双袖互碰、多层服装、正式步态与低配目标硬件均未覆盖，不能按单角色录制数字线性外推。
