> 2026-07-04 Codex / gpt-5.5：新增 `开发管理/任务列表/` 分线 backlog；`当前任务队列.txt` 只保留近期可执行任务，设计/开发下一步建议改为索引入口。
> 2026-06-17 Codex / ChatGPT5.5 复审通过：用于把事实状态、短期任务和长期建议分层维护，降低每次启动的默认上下文消耗。依据：26e8210。

## 文件分层

| 文件 | 角色 | 默认读取时机 |
|------|------|--------------|
| `开发管理/当前任务队列.txt` | 近期可执行任务，`1` 的首选入口 | 用户发送 `1`、规划本轮要做什么 |
| `开发管理/设计-当前状态.txt` | 已验证事实、当前风险快照、版本状态 | 需要判断当前系统事实或写总结 |
| `开发管理/任务列表/` | 分线 backlog：场景/数据/数值/内容/审核 | 当前队列为空、需要扩展路线或拆任务 |
| `开发管理/设计-下一步建议.txt` | 设计 backlog 索引 | 需要判断设计侧下一步入口 |
| `开发管理/开发-下一步建议.txt` | 开发 backlog 索引 | 需要判断开发侧下一步入口 |
| `开发管理/审核入口.txt` | 审核、复审和 `2` 的短入口 | 涉及审核、复审、未审核标记、用户发送 `2` |
| `开发管理/AI合作沟通.txt` | 当前交接队列 | 需要消费另一个 AI 的交接或写交接 |

## 状态文件规则

1. `设计-当前状态.txt` 只写事实：已验证结果、当前版本、已知风险、数据快照。
2. 未执行的“下一步应该做什么”不写入状态文件正文；只保留必要的风险说明和事实依据。
3. 状态标记统一：
   - `✅ 已审核`：已通过规定审核/复审，或 Codex / ChatGPT5.5 自产工作已完成必要验证并闭环。
   - `⚠️ 已修改/未审核`：已改但未通过审核。
   - `⚠️ 待复核`：已有实现或数据，但验证不足。
   - `❌ 未接入`：明确尚未实现。
4. 任何“已完成”必须能指向验证命令、提交号或审核依据；否则写“待复核”。

## 任务队列规则

1. `当前任务队列.txt` 只放 5-10 条近期任务，必须能在一轮或少数几轮内提交；不放待复审或长交接。
2. 每条任务必须包含：ID、优先级、主责、类型、状态、必读文件、验证命令、完成条件。
3. Codex / ChatGPT5.5 自产任务完成后优先改为“已完成待归档”或直接归档；DeepSeek V4 Pro 或外部交接任务完成后改为“待复审”，由 `2` 流程处理。
4. 队列任务不得保存长解释、历史争论或完整审核过程；这些内容写入归档、回复、commit log 或 PR 描述。
5. 分线 backlog 放入 `开发管理/任务列表/`；只有进入近期执行的条目才复制到 `当前任务队列.txt`。

## 建议文件规则

1. 设计/开发下一步建议作为索引，不作为 `1` 的默认全文入口。
2. 进入当前 5-10 条最高优先级的任务，先从 `开发管理/任务列表/` 复制为完整任务卡，再执行。
3. 已完成且通过审核的条目，从建议文件移除或移到已完成摘要；不在建议文件中长期保留大段完成过程。
4. 若某条建议只剩事实说明，应转入 `设计-当前状态.txt`；若只剩历史过程，应归档。
5. 瘦身前旧版长文归档到 `开发管理/任务归档/` 或 `开发管理/AI合作归档/`，现行入口只保留路由和必要状态。

## 完成闭环

1. 执行任务前：从 `当前任务队列.txt` 取 ID，并按任务卡读取事实源。
2. 执行任务后：运行任务卡验证命令，回复中列修改文件、验证结果和残留风险。
3. 提交后：更新任务队列状态；Codex / ChatGPT5.5 自产任务按验证闭环同步状态文件或建议文件，DeepSeek V4 Pro 或外部交接任务待 `2` 复审通过后再同步。
4. 推送远端后：从队列移除已归档任务，必要时从 backlog 补入下一条。
