# 状态与建议维护规则

## 文件分层

| 文件 | 角色 | 默认读取时机 |
|------|------|--------------|
| `开发管理/当前任务队列.txt` | 近期可执行任务，`1` 的首选入口 | 用户发送 `1`、规划本轮工作 |
| `开发管理/设计-当前状态.txt` | 已验证事实、当前风险快照、版本状态 | 判断系统事实或写总结 |
| `开发管理/任务列表/` | 分线 backlog：场景/数据/数值/内容/审核 | 当前队列为空、扩展路线或拆任务 |
| `开发管理/设计-下一步建议.txt` | 设计 backlog 索引 | 判断设计侧入口 |
| `开发管理/开发-下一步建议.txt` | 开发 backlog 索引 | 判断开发侧入口 |
| `开发管理/审核入口.txt` | 审核、复审与 `2` 的短入口 | 审核、未审核标记或用户发送 `2` |
| `开发管理/AI合作沟通.txt` | 当前交接队列 | 消费或写交接 |
| `开发管理/自动工作流规则.txt` | 定时控制器稳定规则 | 修改或诊断自动工作流 |
| `开发管理/自动工作流状态.txt` | 最近有效自动化结果、队列校验、人工阻塞 | 判断自动化闭环或人工处理 |

## 自动工作流分层

1. `自动工作流规则.txt` 是稳定策略事实源；控制器提示只引用，不复制规则。
2. 租约、检查点、预期变更路径和恢复次数只写本机 JSON，不进入 Git。
3. `自动工作流状态.txt` 只记录有效结果、队列路由变化和 `AUTO-BLOCKED`；普通空转、有效锁和人工脏工作区不更新。
4. 队列审计仅在队列少于 5 条、含完成未归档项、依赖错误、主责不匹配、冻结内容入队或距上次成功校验超过 12 小时时触发。
5. 项目内容未变化时，只更新本机校验时间和 automation memory，不制造项目提交。

## 状态与队列

1. `设计-当前状态.txt` 只写已验证结果、当前版本、已知风险和数据快照；未执行的下一步不写入正文。
2. 状态标记使用“审核完成”“⚠️ 已修改/未审核”“⚠️ 待复核”“❌ 未接入”。任何完成结论必须可指向验证命令、提交号或审核证据；否则写“待复核”。
3. `当前任务队列.txt` 只放 5–10 条可在少数轮内提交的近期任务，每条包含 ID、优先级、主责、类型、状态、必读文件、验证命令和完成条件；不放待复审或长交接。
4. Codex / ChatGPT5.5 任务完成后改为“已完成待归档”或归档；DeepSeek / 外部交接完成后改为“待复审”，由 `2` 处理。
5. 队列不保存长解释、历史争论或完整审核过程；分线 backlog 放在 `开发管理/任务列表/`，进入近期执行后才复制到队列。

## 建议与闭环

1. 设计/开发下一步建议只作索引，不作 `1` 的默认全文入口。
2. 需要进入近期任务的条目，先从分线 backlog 复制为完整任务卡。
3. 已完成条目从建议中移除或移到短摘要；事实说明转入当前状态，历史过程转入归档。
4. 执行前从当前队列取得 ID 并按任务卡读取事实源；执行后运行任务卡验证，回复中记录修改文件、结果和风险。
5. 提交后更新队列状态；推送后移除已归档任务，并按需从 backlog 补入下一条。

## 检查脚本入口

- 文本/审核材料机械检查：`powershell -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths AGENTS.md,CLAUDE.md,开发管理`
- docs/CSV/Unity asset 数据链路检查：`powershell -ExecutionPolicy Bypass -File tools/check-data-chain.ps1`
- 严格缺失 asset 检查：`powershell -ExecutionPolicy Bypass -File tools/check-data-chain.ps1 -FailOnMissingAssets`
- 资产版本边界检查：仅当变更涉及 `.gitattributes`、`src/Assets/Art/` 或 `docs/资源管理/美术资源登记册.md` 时运行 `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-asset-versioning.ps1`。
