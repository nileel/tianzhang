# 状态与建议维护规则

## 文件分层

| 文件 | 角色 | 默认读取时机 |
|------|------|--------------|
| `开发管理/当前任务队列.txt` | 近期可执行任务，`1` 的首选入口 | 用户发送 `1`、规划本轮工作 |
| `开发管理/设计-当前状态.txt` | 已验证事实、当前风险快照、版本状态 | 判断系统事实或写总结 |
| `开发管理/任务列表/` | 分线 backlog | 当前队列为空、扩展路线或拆任务 |
| `开发管理/设计-下一步建议.txt` | 设计 backlog 索引 | 判断设计侧入口 |
| `开发管理/开发-下一步建议.txt` | 开发 backlog 索引 | 判断开发侧入口 |
| `开发管理/审核入口.txt` | 审核、复审与 `2` 的短入口 | 审核、未审核标记或用户发送 `2` |
| `开发管理/AI合作沟通.txt` | 当前交接队列 | 消费或写交接 |
| `开发管理/自动工作流规则.txt` | 定时控制器稳定规则 | 修改或诊断自动工作流 |
| `开发管理/自动工作流状态.txt` | 迁移事实、人工阻塞与恢复证据 | 判断自动化闭环或人工处理 |

## 自动工作流分层

1. `自动工作流规则.txt` 是稳定策略事实源；控制器提示只引用，不复制实现规则。
2. 本机 runtime 只保存租约、recovery、pending resume、阻塞计数和最后结果；实时自动化配置不复制到项目状态文件。
3. `自动工作流状态.txt` 只记录需长期保留的迁移事实、人工阻塞、恢复所有权和已核验提交；普通空转、有效锁和逐轮轨迹不写入 Git。
4. 仅在三类均无安全候选时维护队列：先从分线 backlog 提升满足条件的完整任务卡；没有可提升项时，再从权威 backlog、状态和建议新增 1–3 个最小、完整、可验证、可提交的任务卡。本轮不执行新任务。
5. 权威来源不足以形成完整任务卡时才记录阻塞；项目事实没有变化时不制造提交。

runnable 必须同时满足：状态待处理；前置完成；主责已授权给可用执行器；没有待决策；内容冻结与项目闸门满足；任务卡能给出完整预期修改路径与验证；预期路径不与现有人工改动冲突。外部 CLI 只在真实选中合法候选并取得租约后预检；不得因执行器临时不可用改派主责。

## 状态与队列

1. `设计-当前状态.txt` 只写已验证结果、当前版本、已知风险和数据快照；未执行的下一步不写入正文。
2. 状态标记使用“审核完成”“⚠️ 已修改/未审核”“⚠️ 待复核”“❌ 未接入”。完成结论必须可指向验证命令、提交号或审核证据。
3. `当前任务队列.txt` 的近期任务必须包含 ID、优先级、主责、类型、状态、依赖、必查范围、完整预期修改路径、验证命令和完成条件。
4. `必查范围` 优先使用 `文档路径#章节`、`代码路径::类型.符号`、`CSV/JSON路径::实体ID` 或 `资源目录::用途/资源ID`；路径自身已经是不可再分的短事实源时可以只写路径。
5. 既有任务卡的路径级 `必读` 默认要求先定位其中与任务相关的章节、符号或实体，不表示整份加载。只有任务卡明确写“完整文件”、无法保持语义边界、检索无结果或存在事实冲突时才读取全文；修改前仍须读取目标完整逻辑单元。
6. Codex 任务完成后归档；外部 AI 业务提交进入待复审，由 `2` 处理。
7. 队列不保存长解释、历史争论或完整审核过程；长期任务留在分线 backlog。

## 建议与闭环

1. 设计/开发下一步建议只作索引，不作 `1` 的默认全文入口。
2. 需要进入近期任务的条目，先从分线 backlog 复制为完整任务卡并去重。
3. 已完成条目的事实说明转入当前状态，历史过程转入归档。
4. 执行前从队列取得 ID，按任务卡必查范围先定位、后读取；发现新依赖时补读，修改前读取目标完整逻辑单元。执行后只运行任务卡要求的最小充分验证。
5. 提交后更新队列状态；推送后再移除已归档任务，并按需补入下一条。

## 检查脚本入口

- 文本/审核材料：`pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths AGENTS.md,CLAUDE.md,开发管理`
- docs/CSV/Unity 数据链路：`pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-data-chain.ps1`
- 严格缺失 asset：`pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-data-chain.ps1 -FailOnMissingAssets`
- 资产版本边界仅在相关路径变化时运行 `tools/check-asset-versioning.ps1`。
