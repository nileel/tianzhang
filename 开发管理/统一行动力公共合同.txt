## 二、单位、类型与严格缺失处理

CSV／Content 用 lowerCamelCase，纯运行时／DTO 对应 PascalCase；下表的名称与单位是合同。AP 精度常量 S=1000，AP_ref=100，基础上限为 100000 AP 最小单位。后缀 Units 表示整数最小单位，不能直接显示为整数 AP；显示除以1000，保留最多三位小数。

| 字段 | 类型／单位／合法范围 | 唯一生产者与消费者 | 缺失／序列化 |
|---|---|---|---|
| actionPointCostUnits | int，AP 最小单位，主动收益攻击 >0；≤int.MaxValue | AttackProfiles → AttackProfileData → CombatAttackProfile → CommandService／BattleSim | 新表头必填整数；零、负、分数、溢出或旧列代用整批拒绝；只入配置资产，不入角色存档 |
| minimumNetCostUnits | int，AP最小单位，主动收益动作>0且≤基础费用 | 同一攻击行或普通行为定义 → CommandService减耗／返还 | 必填正下限；来源修正不得降低此下限，未知生产值标待验证而非默认1；只入配置，不入临时账本 |
| ctPenalty | int，CT，0～int.MaxValue−100；回合累计也不得超过该界 | 同一攻击行；普通行为显式定义 → CommandService → TurnScheduler | 0 必须显式声明；不得从重用 CD 推导；配置持有，不保存临时累计 |
| reuseCooldownTicks | int，全局整数刻，0～int.MaxValue | 同一攻击行／能力原型 → CombatantSnapshot 唯一冷却账本／BattleSim | 必填；不能读旧回合 CD 作默认；存档不保存会话 CD，局部回溯仍按 L2 白名单 |
| actionPointMaximumUnits | int，AP 最小单位，>0，≤int.MaxValue | CharacterData → CharacterAttributes／snapshot → Adventure → CombatantSnapshot | 显式长期基础输入；缺失或0拒绝角色创建／恢复，不夹成100000；保存归 CharacterRecord |
| movementEfficiencyMilliUnits | int，每100基准AP的普通等效距离×1000，0～int.MaxValue；v=该值/1000 | CharacterData → CharacterAttributes／snapshot → Adventure → CombatantSnapshot | 必填；0合法但禁止自主移动，负／缺失拒绝；保存归 CharacterRecord；与地图 K 无关 |
| actionEconomyInputsPresent | bool，字段存在标记，必须true | Character 长期输入构建／CharacterRecord | 用于区别合法 v=0 与缺失字段；不得用v>0判断存在；新存档缺标记拒绝 |
| ActionPointLimitAtTurnStartUnits | int，AP 最小单位，合法有效上限 | CombatSession.BeginTurn 快照 | Combat 临时字段；回合途中不改，不序列化、不回溯 |
| ActionPointsRemainingUnits | int，0～本回合快照上限 | BeginTurn 发放，CommandService 成功提交扣／返还，结束清0 | 同一角色一个余额；不保留 MovePoints 作为第二预算；不序列化、不回溯 |
| PendingCtPenalty | int，累计CT，0～int.MaxValue−100 | 成功根命令的 ctPenalty 求和 | 只由 CombatSession.RecordAction 写入；失败不改；结束结一次，不序列化、不回溯 |
| TurnSequence／StateVersion | long，非负、递增且checked | CombatSession；TurnSequence 只在新个人回合递增，StateVersion 在权威事实成功改变时递增 | 报价失效证据；显示刷新不能重新发AP；会话临时值，不写存档 |
| GlobalTick | int，非负全局整数刻，checked | 唯一 CTBEngine.CurrentTick，模拟器同合同 | 不是动作数或演出秒；不得以每命令调用推进；会话临时值 |
| sourceInstanceId／sourceDefinitionId | 非空稳定string，Ordinal比较 | 原有成长／装备／能力来源 → CharacterCombatModifiers 的行动经济来源记录 | sourceInstanceId 唯一；未知定义、冲突重复或缺叠加合同拒绝；可重建来源存其输入，不重复存有效值 |

Characters.csv 的两行与 Enemies.csv 的五行新增前两项长期数值列；EnemyData.combatTemplate 是角色值唯一投影，不在 EnemyData 再复制一套。Char_Player／Char_Enemy 及正式新建玩家不来自这两行 CSV，必须由其真实创建所有者显式提供同单位输入，不以 C# 默认字段值补齐。

修正输入记录位于既有 CharacterCombatModifiers.cs，冻结为 ActionEconomyModifierInput；各字段的生产者均为 sourceDefinitionId 指向的既有、显式声明行动经济效果，Character 只验证／投影，Combat 只消费不可变标量副本：

| 字段 | 类型、单位、范围 | 消费与保存 |
|---|---|---|
| actionPointMaximumBonusUnits | int，AP最小单位，可为负；checked聚合后有效上限>0 | 下个人回合上限；可由装备／功法输入重建的增量不单独保存 |
| movementEfficiencyBonusMilliUnits | int，距离×1000，可为负；有效v≥0 | 每次移动读取；由同一来源重建，不持久化地图单位 |
| actionKind／profileId | 受控命令枚举／可选稳定ID，至少有合法匹配范围 | 限定减耗与返还；未知类别或未知非空ID拒绝，不自动匹配全部行为 |
| fixedReductionUnits | int，AP最小单位，≥0 | 动作报价固定减耗；路径移动不消费此项 |
| retainedCostPermille | int，保留比例千分比，0～1000；1000无比例减耗 | 同类来源先按已有互斥／叠加合同聚合，不擅自连续相乘 |
| ctPenaltyReduction／reuseCooldownReductionTicks | int，非负CT／非负全局tick，各不超过其原声明值 | 仅原型明确授权时分别减对应量，结果非负；没有来源声明时不产生修正，不能跨量纲复制 |

无行动经济修正时显式空数组，返还预算为0，不构造无来源默认效果。暂未有获准生产来源时只承载协议与夹具，不生产新功法／装备效果。无法从现有已存来源重建的合法独立成长输入才加入 CharacterRecord 的 actionEconomyModifierInputs 数组；序列化同上述字段和两项来源ID，恢复时先验证全数组及引用，再整体发布。Combat 的使用次数、已返还总量、根动作结算记录始终不保存。

## 三、普通行为、生产数值与迁移边界

CombatSession.cs 内冻结 CombatOrdinaryActionDefinition（Kind、ActionPointCostUnits、CtPenalty、ReuseCooldownTicks、MinimumNetCostUnits）；它只描述 Guard／SwapSpell 等现有非攻击行为。Wait／EndTurn 明确0费、0惩罚／重用CD；Move 只由路径定价。Guard／SwapSpell 为正费，当前额外CT惩罚投影为0；换入术法重用CD保持60 tick，每战更换上限保持2。

普通行为参数沿现有会话创建链传入，正式唯一配置位置为 AdventureScene.unity 的 AdventureSceneInstaller 序列化普通行为定义，再由 CombatEntryAdapter.TryCreateSession 注入，不在按钮、AI或Resolver各写一份常量。没有正费定义时拒绝建立正式会话。此位置复用现有组合根，不创建新表／组件／执行器；U-COMBAT-AP-FLOW-01 与 U-COMBAT-AP-TUNING-01 准备ready前须补齐该现有场景路径及其真正生成者，见§九。本文不写场景配置或生产费用。

攻击表只用 actionPointCostUnits、ctPenalty、reuseCooldownTicks 替换旧 cooldownTicks 的双职责。严格新表不同时接受旧／新列，不以 FormerlySerializedAs 将一旧字段同时映射到两新字段。既有资产由同ID严格导入更新，GUID保持；SpellData／DivineSkillData 的遗留 cooldownTicks 不再回填权威攻击费用，若仍有独立消费者，先定位并在下游ready准备中冻结该消费者的路径和单位，不能静默迁移。

## 四、路径原始边费与AP报价

Spatial 保有K=SpatialQueryLimits.UnitsPerRange（int>0）和有界MaxQueryRange；基础普通边长为K。每条合法有向边记录 From／To（HexCoord）、MetricDistanceUnits（int≥1）和进入目标格 MovementBurdenUnits（int≥0）；d_e=checked(二者之和)。原始距离、移动负担分别保留，不把两者当攻击射程。Path不含起点，按现有FindPath顺序包含经过格及终点；无变化目的地拒绝，不计免费收益移动。

ICombatSpatialQuery.QueryMovement／FindReachable 的预算改为 ActionPointsRemainingUnits，并显式接收当前有效 MovementEfficiencyMilliUnits；CombatMovementQueryResult 扩为不可变原始边列表、K、ActionPointCostUnits及选中路径。SpatialQueryTypes.cs 冻结 SpatialMovementEdgeCost（From、To、MetricDistanceUnits、MovementBurdenUnits）和 SpatialMovementPathResult（Path、Edges、UnitsPerRange、ActionPointCostUnits、Reason）。这些是现有查询边界的数据，不是第二地图、缓存或寻路器。

v=movementEfficiencyMilliUnits/1000；概念量v_u=K×v。不得先整数截断v_u或使用float。等价精确整数式为：

edgeAP_u = max(1, floor(100 × S × d_e × 1000 / (K × movementEfficiencyMilliUnits)))
pathAP_u = checked(Σ edgeAP_u)

乘法与除法中间量用checked long；最终费用必须可表示为int且不超预算，溢出返回稳定数据错误，不绕成负值或夹限。v=0先拒绝自主移动，不进入除法。每条边单独取整，再求和；不执行现有Adapter的(cost+K−1)/K，也不在命令末尾再取整。普通移动优惠只并入v，不按段数固定减耗／返还。

FindReachable／FindPath／选中路径／报价使用Traverse同一个合法边遍历和同一AP边权；保留原用途距离查询，不把原始距离最短路径直接当AP最便宜路径（逐边取整后可能不同）。预算直接用AP最小单位，不先反算整格预算裁掉压缩边。相等费用按现有确定性六向遍历与FrontierEntry的坐标次序处理，不增加第二选择策略。

确认必须重查占位、形态、高度、有向边、环境版本、K、v及完整选中路径；同一路线／v／负担的分段之和完全一致，插入施法不重置舍入。事实变化拒绝旧报价，重新选择才形成新报价，不能偷偷换更便宜路线。强制位移不扣目标AP；移动术法只付自身动作成本，只有原型明确声明的额外自主路径段才追加边费。

扩展现有 CombatCommandPreview 为唯一报价对象，不再增加预览执行器。它由 CombatCommandService.Preview（沿CombatSession.ValidateCommand）生产，Validate／合法候选／Execute复用同一规则；Gameplay DTO只复制，不保存Combat对象引用。

CT当前值继续使用现有float边界（待机可保留半CT），反应为每全局刻整数CT输入，非正反应在创建处拒绝而不是让新输入依赖旧Register夹限。时间与CD仍是整数刻；轴预览使用ceil并复用现有非就绪角色至少等待1刻的ChargingTicks语义。

非路径减耗顺序：基础费→固定减耗→保留比例→minimumNetCostUnits正夹限→最小单位向上取整。有效minimumNetCostUnits取动作定义与匹配来源下限的最大值；导入／来源验证保证每一匹配下限不超过该动作基础费。比例计算保留整数分子／分母到最后：C=max(minimumNetCostUnits, ceil(max(0,base−fixed)×retainedCostPermille/1000))。多来源只有在已有叠加合同明确时先聚合；同一sourceInstanceId只计一次，不由MP减耗推导AP减耗。CT／tick修正也只能作用于各自明确量纲，不能套AP折扣。

成功根动作返还 R=min(满足条件的声明量, 本人剩余总预算, 该来源剩余预算, C−minimumNetCostUnits, 回合快照上限−扣费后余额)，各项均非负；按sourceInstanceId、TurnSequence、rootActionId计一次成功触发，同时扣该来源次数、来源预算和全角色总预算。本人开始快照来源的次数／预算，全角色总预算为各合法唯一来源预算的checked和；途中新增来源下回合才取得预算，移除／重新装入同来源保留本回合原使用记录。同实例换profile、换装备或改目标不创建新额度。返还／派生／免费自动响应不是付费根动作，不能递归；所有可重复收益主动命令净支出C−R≥正下限。普通路径移动不触发动作段优惠；合法免费主动收益若有原型，须另有有限次数合同，本轮不新增这类生产内容。

事务顺序冻结如下，仍沿现有唯一Execute链：

1. 纯读取验证actor／就绪个人回合、报价版本、命令身份、目标／完整路径、授权／控制／冷却、全部费用与次数、checked惩罚和结果可提交性；预览与失败确认不取随机数。
2. 在任何写入前准备全部资源与结果候选；攻击只有通过全部校验后才取确定性rolls。物品／装备候选须由Adventure与其现有领域所有者准备完成，不能先扣库存再让Combat尝试执行。
3. 同步无yield的权威提交：完整扣AP／MP／库存／次数，成功收益动作先退出Guard，应用已准备结果、启动唯一CD、累加CT惩罚，结算根动作返还／事件与版本。提交阶段不再包含能业务拒绝的步骤；后续物品／装备合同若无法证明此条件，停止准备ready，不增加补偿／重试层。
4. 成功后发布已提交投影并演出；AP=0、死亡或战斗终结进入唯一结束入口。取消、陈旧／重复确认、非法输入、任一资源不足、准备失败保持AP／MP／库存／位置／Guard／CD／CT惩罚／计数及随机源不变。

未命中、合法治疗／聚灵目标已满属于成功结果，照常付费与加惩罚；合法提交后状态写入被祛禁阻止属于L2§一.11的部分结果，其他结果继续、费用不退。不得把这两类结果误判为事务失败。重复旧报价拒绝；冷却0时新报价允许再次使用同动作，不设通用次数上限。

## 六、三时钟、回合事件与状态

事件由原所有者在明确边界调用，下面名称是核对点，不要求新事件总线、调度框架或自由字符串注册。

| 时钟／核对点 | 唯一入口与顺序 | 不允许的替代 |
|---|---|---|
| GlobalTickAdvanced | CTBEngine推进下一整数刻；存活者CT加反应，重用CD按实际TicksElapsed减到0；清完同刻队列才再推进 | 命令、输入等待、演出秒、快照刷新或他人子动作不能减CD |
| OwnTurnStarted | 新就绪角色→清Guard→本人开始状态／DOT／控制／到期→若仍活则HP／MP恢复一次→快照上限和有限返还预算→可行动者发AP；控制跳过AP=0 | 再次Advance当前角色返回0刻、不得重发AP／恢复／额度；开始死亡不恢复或复活 |
| RootActionCommitted | 一个命令全部目标／效果共享一个rootActionId；动作、命中、受击依原型触发 | 多目标不多扣费，不刷新每回合一次账本；移动事后事件按整段命令一次 |
| OwnTurnEnded | 本人结束效果／持续／计数一次→清AP→正常CT=0、nextThreshold=100＋累计惩罚→释放控制权 | AP耗尽、主动结束、控制跳过重复回调不得多结算；结束没有额外恢复 |
| WaitEnded | 无收益动作且非控制跳过才可待机；结束事件一次，CT保留50%，门槛100，AP清0 | 成功移动／攻击／防御／换术／道具／换装后不可待机；取消仍可待机 |
| CombatTerminated | 原结果所有者终结，清会话预算／姿态；长期资源沿原结果提交链 | 不新增回合、继续恢复、保存临时AP或把终结当新的可付费命令 |

就绪顺序保留反应降序、CT降序，并在完全平手时按Ordinal稳定战斗ID升序；CTBEngine现有CompareReadyValues缺最后一项，CORE负责补齐，两个模拟入口用相同顺序。这是确定性平手合同，不是宣称现行源码已有该行为。

持续N个人回合按受影响角色后续结束计：本人当前回合施加时当前结束不减，下一本人结束首次减；他人回合施加时目标下一本人结束首次减。持续tick只读全局刻。眩晕跳过、定身仅禁自主移动、封灵禁对应施法；AP或返还不解除控制。

旧AdvanceActionState必须按原文分类而非按出手统一增加：抱元守一经“本回合未移动、回合结束＋1”按本人结束一次，并记录成功自愿移动；云篆度人经“回合结束＋1”按本人结束一次，“符箓施放消耗”按对应术法根动作；九霄雷劫录受伤叠层、对应出手消耗按原型结果／动作。拒绝、未造成伤害、多目标合并及其他条件以各原文为准；不凭旧方法名开放多倍叠层，不顺带迁移未选中的篇章生产参数。

普通Guard只在成功激活时收费，重激活拒绝且不延长；肉防／魂防各×1.5进入原伤害公式，不保留最终伤害×0.5作为等价实现。成功移动／攻击／施法／道具／换术／换装在其效果前退出；失败／取消不退出，EndTurn保留，下一本人开始／死亡／离场清除。

特殊时空边界保持L2：AP余额、快照上限、累计CT惩罚及返还／回合额度不进入回溯白名单；外部已提交成本重放不再次扣AP／累计CT。因价不得改AP／v／CT／CD；果先因后按原债务记录分别保留AP、CT惩罚和tickCD，不把补因改成新回合或提前结果白名单扩张。此合同不实现新时空能力。

## 七、长期输入可重建性与保存合同

源码判断：CharacterRecord存角色原始属性、modifier标量、装配和Progression引用，没有独立AP／v，也没有能够唯一回查原CharacterData的定义ID。正式创建者以先天生成定义，runtime characterId为player；这个ID不是CSV角色ID。独立可成长AP／v不能从现有reaction、gongFaId或realmMultiplier唯一重建。因此保存其基础长期输入是必需的，不为了临时余额版本化。

冻结新写入schema为4：CharacterRecord增加actionEconomyInputsPresent、actionPointMaximumUnits、movementEfficiencyMilliUnits，以及确实不可由已存来源重建的actionEconomyModifierInputs；数组保存§二字段。有效装备／功法派生值由来源重建，不和基础值重复累加。新增字段也进入HasCharacterPayload检查；hasPlayer=false但携带任一新字段／来源时仍拒绝，不能隐藏角色payload。

旧档合同按以下明确迁移／拒绝，不删除档案，不读写用户真实档：

| 输入schema／条件 | 处理 | 原因与边界 |
|---|---|---|
| 4，新字段完整且合法 | 按现有GameSaveEnvelope.Restore构造所有新领域对象，整体成功才发布；往返幂等 | 合法v=0可存；AP上限必须正；引用／任一字段失败不替换任何live owner |
| 4，缺字段／存在标记false／未知来源／溢出 | 拒绝，稳定原因action_economy_save_invalid | 不把JSON缺失导致的0解释为合法不可移动，不补100000／2000 |
| 3，hasPlayer=true | 拒绝，稳定原因legacy_action_economy_input_missing | 旧payload缺唯一v来源和新成长输入；本合同未授权凭反应回算或把候选v写入旧档。保留原文件；以后若获得逐来源迁移批准，须在原保存卡准备阶段明确修订此合同，不能加静默兼容分支 |

| 未知schema、坏JSON、presence矛盾 | 拒绝 | 不重试、降级、覆盖或删除 |

该旧schema3拒绝是无法证明长期输入时的保存边界，未声称旧玩家已成功迁移。SAVE卡须验证可用的新档往返及旧档拒绝证据；任何要求保留旧玩家可加载而又没有明确映射的准备属于负责人决定，不能用夹具遮掩。

## 十一、交付边界与准备剩余项

本合同冻结结构与语义，公共边界有真实所有者，三现有攻击旧CT／tick投影有依据，角色v候选逐来源列出，长期保存必要性与旧schema边界明确，全部blocked代码叶有符号和验证入口。新增数值／内容决定、正式创建配置资产定位、签名直接调用点、普通行为场景生成者与准确资源路径须由有权维护者在相应卡ready前收口；本轮不替下游造内容、解除前置或提升队列。

AP费用／净费下限／返还预算及未映射的旧Art／Divine配置仍标待验证；文档夹具不等于代码通过，schema4及旧3拒绝尚未实现，用户“移动后不能出手”尚未复现。冻结合同不关闭完整AP父项、数值平衡或用户运行时问题。
