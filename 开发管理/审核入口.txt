# 审核入口（⚠️ 已修改/未审核）

> 2026-06-17 Codex / ChatGPT5.5 新增：用于降低审核、复审和 `1` 自动推进的默认上下文消耗，待后续复审。

## 先读规则

涉及审核、复审、未审核标记、交接消费、`1` 自动推进选题时，默认先读本文件。只有命中下方路由时，再读取对应长文件或事实源。

## 不可省略的硬规则

1. 修改与审核分离：本轮执行修改的 AI 只能标「⚠️ 已修改/未审核」，不得同轮标「✅ 已审核」。
2. 审核以 `git diff`、提交号、文件清单和事实源为准，不以交接自述为准。
3. 审核结论只能是“通过 / 部分通过 / 不通过”；未运行必要验证时不得给通过结论。
4. 通过后清理正文临时审核记录；详细过程进入回复、commit log、PR 描述或归档文件。
5. `AI合作沟通.txt` 只保存当前有效交接队列；历史长记录按需查 `开发管理/AI合作归档/`。

## 按需加载路由

| 场景 | 必读 | 仅命中时读取 |
|------|------|--------------|
| 审核某提交或当前 diff | 本入口、`git status`、`git diff` 或指定提交 | 被改文件、对应事实源、相关测试输出 |
| 复审未通过项 | 本入口、`开发管理/未通过审核清单.txt` 中对应条目、修复 diff | `开发管理/审核规则.txt` 复审细则、相关事实源 |
| 消费 DeepSeek 交接 | 本入口、`开发管理/AI合作沟通.txt` 当前匹配条目 | 交接引用的归档条目、DeepSeek 提交 diff |
| 设计内容审核 | 本入口、被改设计文件 | 对应设计规范、模板、`docs/` 原文 |
| CSV / asset 审核 | 本入口、被改 CSV / asset / 对齐清单 | `src/Assets/DataConfig/README.txt`、统计脚本或检查命令输出 |
| 代码审核 | 本入口、被改代码 diff | `开发管理/开发-技术经验.txt`、相关测试、Unity / BattleSim 命令 |
| 数值结论 | 本入口、数值改动 diff | `docs/基础设定/角色数值设计.txt`、BattleSim build + run 输出 |
| 用户发送纯 `1` | `AGENTS.md`、本入口、`开发管理/当前任务队列.txt`、`AI合作沟通.txt` 当前队列 | 队列为空或不适用时读下一步建议文件；选定任务后再读对应细则和事实源 |

## Token 节流规则

- 默认摘取当前任务相关条目，不全仓重读、不全文件重读历史归档。
- 交接条目写短 ID、提交号、文件范围、验证命令和风险；长过程移入归档。
- DeepSeek 任务先读 `DeepSeek工作提示词.txt` 路由，再按任务类型读取一个任务卡，不默认读取全部任务模板。
- 未通过清单只读当前要修复或复审的编号；完成并通过后从清单移除，详细过程归档。
- `1` 自动推进优先从 `当前任务队列.txt` 取任务；设计/开发下一步建议作为长期 backlog，不作为默认全文启动上下文。
- 高频机械检查优先调用 `tools/check-review-text.ps1` 与 `tools/check-data-chain.ps1`，再按输出决定是否读取长文细节。
