# 审核入口

涉及审核、复审、未审核标记或交接消费时，先读本文件；只在命中路由后读取细则和事实源。

## 最小规则

1. Codex / ChatGPT5.5 自产工作完成必要验证后可直接闭环；DeepSeek、外部交接或用户明确要求复审的修改，先标为「⚠️ 已修改/未审核」，再由 Codex / ChatGPT5.5 独立审核。
2. 审核以目标提交或当前 diff、文件清单和直接事实源为准，不以交接自述替代证据。
3. 结论为“通过 / 部分通过 / 不通过”；验证按影响面最小化执行，并说明未运行项目及原因。
4. 审核完成后清理正文临时审核记录；详细过程进入回复、commit log、PR 描述或归档文件。
5. `AI合作沟通.txt` 只保存当前有效交接；历史按需查 `开发管理/AI合作归档/`。

## 按需加载路由

| 场景 | 必读 | 命中时追加 |
|------|------|------------|
| 审核提交或当前 diff | 本入口、`git status`、目标提交或限定 diff | 被改文件必要段落、任务卡完成条件、最小验证输出；复杂或争议时读 `开发管理/审核规则.txt` |
| 复审未通过项 | 本入口、`开发管理/未通过审核清单.txt` 对应条目、修复 diff 或目标提交 | `开发管理/审核规则.txt` 复审细则、相关事实源 |
| 消费 DeepSeek 交接 | 本入口、`开发管理/AI合作沟通.txt` 当前匹配条目 | 目标 diff、引用归档；分工或结论冲突时读 `开发管理/AI协作规则.txt` |
| 设计内容审核 | 本入口、被改设计文件 | 对应设计规范、模板、`docs/` 原文 |
| CSV / asset 审核 | 本入口、被改 CSV / asset / 对齐清单 | `src/Assets/DataConfig/README.txt`、统计脚本或检查输出 |
| 代码审核 | 本入口、被改代码 diff | `开发管理/开发-技术经验.txt`、相关测试、Unity / BattleSim 命令 |
| 数值结论 | 本入口、数值改动 diff | 修改 BattleSim、数值参数、CSV 或新增数值结论时，读 `docs/基础设定/角色数值设计.txt` 并运行 BattleSim |

## 轻量审核流程

1. 查看 `git status --short`，限定本轮文件范围。
2. 审核提交时看 `git show --stat --name-only <commit>` 与目标 patch；审核当前改动时看限定路径 diff。
3. 只读取被改文件必要段落、任务卡完成条件和直接事实源。
4. 按影响面选择最小验证：文档/管理文件运行 `tools/check-review-text.ps1` 与 `git diff --check`；CSV/asset 运行 `tools/check-data-chain.ps1`；代码运行相关 build/test；BattleSim 代码、数值参数或新增平衡结论才运行 BattleSim。
5. 回复只记录结论、依据、已运行检查及未运行原因。

纯 `1` / `2` 的完整选题、身份确认和标题规则见 `开发管理/AI协作规则.txt`；本文件只提供其审核路由。
