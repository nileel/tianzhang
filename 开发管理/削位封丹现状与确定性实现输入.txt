# 削位／封丹现状与确定性实现输入

> 对应 `N-SUPPRESS-01A`。本记录只锁定现状、迁移边界和待决定输入；不改变 BattleSim、旧审计结论、数值或设定。

## 结论

`GoldenCoreSuppressionExitStats` 是单一控制台出口使用的历史压力审计，不是现行削位／封丹结算：其“削位”只按 `15/30/45` 百分比压低克隆金丹样本的 `MP`，其“封丹”只清空克隆样本的神通字段。它没有事件、合法目标、版本化授权、资源扣除、持续状态、冲突结算或稳定拒绝原因，不能作为 `N-SUPPRESS-01B` 的输入或默认值。

现行规则已给出约束而未给出这两项动作的业务档案：跨阶操作无有效 `CrossTierChallengeGrant` 时必须失效／`SUPPRESSED`；grant 必须逐项声明来源、变量、操作、对象、范围、受益者、支点、资源、容量、时效、版本与显示来源。真实稳定金丹位格的剥离、毁坏或转移只能走原子死亡结算；`UNSTABLE`、资源耗尽、效果结束、庇护撤回和 `TEMPORARY` 权限失效均不得误写成失位。

因此 `N-SUPPRESS-01A` 停在 `pending_decision`。不得以旧百分比、符修／玄感标签、样例 grant 或开关补全缺失字段。

## 可复用的现行边界

1. `GameData.CrossTierChallengeGrant`／`CrossTierChallengeArchive` 与 `Combat.ResolveCrossTierChallenge` 已提供版本、来源、变量、挑战者、对象、范围、受益者、支点、资源／容量账本引用和时效的确定性资格重验。它只返回授权或 `JD_CHALLENGE_*` 原因，不扣资源、不决定冲突胜负，也没有现成的削位／封丹档案。
2. `GoldenCoreConflictCandidates`／`GoldenCoreConflictResolver` 已接收显式变量权限、合法目标、兼容档案、成本档案、现实支点、已付成本、持续承载、脉冲成本与冷却；它只能结算两份准备好的金丹同阶候选，不能替削位／封丹猜测上述输入。
3. `Combat.ResolveGoldenCoreCarrierDeath` 与 `Character.ResolveGoldenCoreCarrierDeath` 是真实稳定位格失去时的唯一原子死亡路径。封丹或暂时压制不得调用它；新结算也不得写 `FinalOccupancyState`、拆除 `GoldenCoreAssembly` 或改写 `JindanCoreBinding`。

- 迁移策略：01B 先将 `GoldenCoreSuppressionExitStats` 及 TQ-015C-8～10 明确标为 legacy audit，并把 `Program` 的对应输出明确标为历史审计。保留其计算和结果，禁止新结算调用；`15/30/45`、开关、样本风格标签与 MP／神通字段清空不得映射到新输入。随后在同一既有文件中接入独立的确定性动作入口，不能复用旧类型或 profile。
- 旧审计与新结算测试必须分离：保留旧三组测试仅保护历史输出；新测试只消费负责人确认的动作档案和固定事件输入。

## 01B 自测矩阵

| 分类 | 固定输入／断言 |
|---|---|
| 资格 | 完整 grant 的版本、挑战者、变量、来源与时效匹配授权；未知、失效、撤销、版本或挑战者／变量不匹配返回既有稳定 `JD_CHALLENGE_*` 原因且不改变状态 |
| 合法目标 | 削位、封丹各自仅接受负责人确认的目标状态、对象与范围；不匹配返回确认的动作拒绝原因，不能用“待争席”或“未占据”猜测通过 |
| 成本与承载 | 缺账本、成本不足、容量／支点或持续条件不满足时不扣费、不设状态；成功时只按确认的账本和时机结算 |
| 冲突 | 对两份已确认的候选分别覆盖优先级胜负与脉冲平局；不把既有同阶 resolver 的输入常量当作动作默认值 |
| 暂时状态 | 封丹与任何暂时压制只验证所确认的效果禁用／期限；`UNSTABLE`、资源耗尽、`TEMPORARY` 与庇护撤回保持非死亡、非失位 |
| 真实失位隔离 | 断言新入口不调用 carrier-death 路径、不改 assembly／核心／最终占据；既有 N-JD-RULE-01C 死亡自测继续独立覆盖真正剥离 |
| 幂等与旧审计 | 同一事件重复处理不二次扣费或写半状态；TQ-015C-8～10 的历史结果不变且不能作为新结算断言 |

## 待负责人决定

决策编号：`DEC-20260728-NSUPPRESS01A`。

必须对“削位”和“封丹”各自给出下列可存档值，或明确取消该项结算：

1. `TargetVariableId`、`AllowedOperationId`、`TargetId`、`ScopeId`、`BeneficiaryId`，以及唯一的合法目标状态；是否可作用于稳定实位必须明确。若为是，必须转交 N-JD-RULE-01C 的真实失位／死亡事务，不能由 01B 实现。
