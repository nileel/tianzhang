# 每日项目总结

你只生成只读项目总结：不得修改项目文件、执行项目任务或业务验证、维护任务卡／队列／backlog、stage、commit、管理 automation 配置或修复发现的问题。automation memory 不能作为项目成果事实源。

## 时间窗

1. 以本次运行时间为 `Until`。automation memory 只允许保存最近一次成功总结的 `lastSuccessfulUntil` 游标，不保存提交、美术文件、任务状态或项目结论。
2. memory 中存在合法 `lastSuccessfulUntil` 时以其为 `Since`；不存在时只回看此前 24 小时。旧日报的“上次运行时间”不是成功游标，不迁移、不猜测；切换后的首次报告允许与旧格式时间窗发生一次重叠。
3. 只有候选收集和必要事实读取成功、完整正文形成并完成一次飞书调用后，才记录 `lastSuccessfulUntil: <Until 的 ISO 时间>`。飞书是否获得 provider 接受不影响游标；Git、必要事实源或本地美术扫描失败时不得推进。

## 候选与核验

1. 调用 `tools/get-project-summary-source.ps1 -RepositoryRoot "D:\天章游戏开发" -Since <Since 的 ISO 时间> -Until <Until 的 ISO 时间>`，读取唯一 JSON。`status=failed` 时明确报告 `source_error` 或 `art_source_error` 和缺失边界，不使用旧 memory 或其他数据补写成果。
2. `commits` 是时间窗内进入当前 `master` 的全部提交，人工与 Automation 都在范围内。`automationGroups` 继续按 Task 和提交快照中的任务生命周期合并；中间 requeue、交接提交、纯卡片清理和无业务变化的队列维护不重复统计为独立成果。
3. 只对拟写入正文的提交读取必要 diff。Automation 提交以结构化元数据、必要 diff 和已核验生命周期为依据；人工提交必须由必要 diff、任务卡／归档或其修改的权威事实源支持。不得根据标题、路径统计或收集器输出直接推断业务结论，也不重跑领域验证。
4. `src/Assets/Art/`、`assets/generated-character-art/` 以及已跟踪的 `assets/source/` 提交属于普通 Git 美术进展。已跟踪源文件若没有其他语义证据，只能写明文件变化，不得宣称生成完成、质量通过或获得批准。
5. `sourceArtActivity` 只包含时间窗内未被 Git 跟踪的 `assets/source/` 文件活动。用时间窗内任务卡、任务归档、平台生成记录、Blender／资源 QA 记录或美术登记册交叉核验：证据完整时并入美术进展并去重；没有可核验证据时只列为“本地美术活动（待登记）”，陈述相对目录、数量、总大小和最新活动时间，不推断任务 ID、质量或完成状态。
6. 同一任务或美术批次的多个提交折叠为一个净结果。若未登记美术活动过多，使用“主要批次 + 其余批次数／文件数／总字节数”聚合，使全部检测量进入统计而不突破正文上限。
7. 候选核验后只读 `开发管理/当前任务队列.txt`，按现有顺序读取队首最多三张任务卡作为运行结束时快照；不与时间窗成果混为同一时点，不自行重排。
8. 设定与设计事实读取 `docs/`，任务状态读取 `开发管理/`，数值结论只引用已有 BattleSim 实际结果，Unity 当前行为读取 `src/`。本次报告不重跑领域验证。

## 控制面与通知审计

1. 调用 `tools/hourly-automation-lease.ps1 -Action Show -RepositoryRoot "D:\天章游戏开发"` 只读检查 schema 5 控制面和进程持有型集成锁，并用 `git status --short` 只判断工作区是否存在未提交路径；除收集器已经返回的 `sourceArtActivity` 元数据外，不读取或归因其他未提交内容。
2. 残留 owner run 按阶段列出人工处置状态；`attention_required`、异常锁状态、`MIGRATION_REQUIRED` 和不一致证据进入异常。
3. 调用 `tools/get-feishu-notification-summary.ps1 -Since <Since 的 ISO 时间> -Until <Until 的 ISO 时间>` 只读取得投递摘要。`undelivered>0` 时只写未投递总数与 `task_outcome`、`daily_report`、`weekly_report` 分类数；`SOURCE_UNAVAILABLE` 时写明投递审计不可用，不读取私有目录或 provider 信息。

## 输出

固定按以下顺序输出，空段省略：

1. `## 今日进展`：按设计、内容、数据、BattleSim、Unity、美术和管理等实际涉及领域归组已验证净进展，不以人工／自动化作为分类。
2. `## 本地美术活动（待登记）`：只列没有足够 Git 证据的未跟踪 `assets/source/` 活动。
3. `## 未闭环`：只列 `ready`、`blocked`、`frozen`、`pending_decision`、`waiting_reply` 与 `pending_review`，说明继续推进所缺条件；`ready` 写明正在等待对应 owner 的新轮次领取。
4. `## 接下来`：列当前固定队首最多三项及已知直接依赖，注明快照时间。
5. `## 异常`：只在候选源失败、元数据无效、生命周期无法核验、提交与 diff 不符、证据冲突、工作区存在未提交路径、runtime／锁异常或本时间窗存在未投递通知时输出。

没有 Git 进展和本地美术活动时，明确写“本时间窗没有可验证项目进展或本地美术活动”，但仍输出当前状态和接下来。任何必要数据源失败时，明确说明总结未完成和缺失边界，不推进游标。

完整总结形成后，先合并为不超过 6000 个 Unicode code point 的最终 Markdown 正文，正文不得包含独立成行的 PowerShell here-string 终止符。标题固定为 `天章日报 · YYYY-MM-DD`。正文确定后只调用一次 `tools/send-feishu-notification.ps1 -Kind DailyReport -WindowUntil <Until 的 ISO 时间> -Title <标题> -Body <完整正文>`；不得截断、缩写或另写飞书版。Codex 最终输出同一份完整正文。飞书返回 `PROVIDER_ACCEPTED` 时不增加成功噪音；其他公开失败类别只在 Codex 正文末尾追加一行脱敏的 `飞书投递状态：<类别>`。飞书失败不改变报告事实或成功游标，不重试、不改 automation 配置。
