# 每日自动化推进简报

你只生成只读简报：不得修改项目文件、执行项目任务或业务验证、stage、commit、管理自动化配置或修复发现的问题。automation memory 不能作为项目成果事实源。

1. 以上次运行时间为 `Since`、本次运行时间为 `Until`；调用 `tools/get-automation-briefing-source.ps1` 取得时间窗内候选 JSON。没有上次运行时间时只回看此前 24 小时。
2. 只对候选业务提交读取支持元数据 `Result`、`Impact`、`Verify` 所需的最小 diff；确认提交内容与声明一致，但不重跑验证、不代做领域复审。
3. 按 `Task` 合并同一任务的多个业务提交，以窗口内最新候选提交中的任务事实分类：归档任务为 `completed`；活跃任务保留 `blocked`、`frozen`、`pending_decision` 或 `waiting_reply`；外部 `businessCommit` 保留 `pending_review`；缺少可核验生命周期时记录 `outcome_unverifiable`。卡片清理、中间提交和未带 Automation 元数据的 `handoffCommit` 不重复统计为独立成果。
4. `queue_maintenance` 只有在 diff 证明它实际改变 ready 候选、固定顺序、依赖或阻塞时才进入正文；不得把维护提交数量当作业务成果。
5. 在候选核验后只读 `开发管理/当前任务队列.txt`，按现有行顺序读取队首最多三张任务卡。将它们作为运行结束时的当前快照，不与时间窗内成果混为同一时点，也不自行重排。
6. 输出固定为以下四段，空段省略：
   - `## 净成果`：按任务说明解决的问题、实际产出、已确认影响和元数据声明的验证。
   - `## 未闭环`：只列 `blocked`、`frozen`、`pending_decision`、`waiting_reply` 与 `pending_review`，并说明继续推进所缺条件。
   - `## 接下来`：列当前固定队首最多三项及已知直接依赖，注明快照时间。
   - `## 异常`：只在元数据无效、生命周期无法核验、提交与 diff 不符、工作区存在未提交路径或 runtime 存在需人工介入的异常时输出。
7. 调用 `tools/hourly-automation-lease.ps1 -Action Show` 只读检查控制面，并用 `git status --short` 判断工作区是否存在未提交路径；不得读取或归因无关 diff。有效租约属于正常运行，不作为异常；逻辑暂停、遗留 recovery 或其他需人工介入的控制面状态才进入异常。
8. 没有候选时明确写“本时间窗没有带有效 Automation 元数据的业务提交”，但仍输出当前队首；候选源失败时明确报告 `source_error`，不得用旧 memory 填充。
