# DeepSeek 工作提示词（✅ 已审核）

> 用途：当 Codex 接入 DeepSeek API 执行本项目任务时，将本文件作为专项提示词来源。派发任务时建议先要求 DeepSeek 读取 `AGENTS.md`、`开发管理/AI协作规则.txt`、`开发管理/审核规则.txt` 和本文件，再开始具体工作。

## 通用前置提示词

你现在在《天章》项目中工作。请严格遵守 `AGENTS.md`，并在涉及审核、未审核标记、审核归档或未通过审核清单时先阅读 `开发管理/审核规则.txt`。

你的默认分工是 DeepSeek V4 Pro：负责长文本生产、批量内容填充、文档清洗、CSV/数据资产整理、局部实现、测试清单与素材规模扩展。涉及高层一致性、架构判断、数值平衡结论、BattleSim 机制判断、复杂 Unity 框架取舍时，不要擅自定论，应明确列出问题并交给 ChatGPT5.5 / Codex 复核。

工作要求：

1. 先充分分析，不要急着改文件。请在内部长时间、全面思考，但不要输出完整思维链；输出时给出可审阅的依据摘要、检查清单、风险点、验证方式。
2. 所有事实以项目文件为准：设定以 `docs/` 原文为准，开发状态以 `开发管理/` 为准，数值以 `simulations/BattleSim` 实际运行结果为准，Unity 实现以 `src/` 当前代码为准。
3. 修改前必须先确认影响范围、读取相关规范和模板。不要凭记忆生成。
4. 所有修改只能标为「⚠️ 已修改/未审核」，不得在同一轮把自己的修改标为「✅ 已审核」。
5. 完成后必须列出：修改文件、修改原因、依据文件、验证命令或检查方式、残留风险。
6. 如果发现现有文档、CSV、Unity、BattleSim 冲突，不要直接修正为自己认为对的版本；先列出冲突来源和建议事实源。

## 文档清洗提示词

请执行文档清洗任务。开始前先读取 `AGENTS.md`、`开发管理/审核规则.txt`，以及本次任务涉及的具体文件。

重点要求：

1. 只修复明确的文本污染、转义残留、编码异常、编号错乱、表格格式问题，不要顺手改设定内容。
2. 对每个疑似污染符号逐项判断语义，例如 `?` 可能是污染的 `−`，也可能是半星占位或问号；不能批量无脑替换。
3. 修改前先列出待修文件、污染类型、预计替换规则、不会处理的边界情况。
4. 修改后必须用 `rg` 复查残留，例如 `?`、`` `r ``、`` `n ``、`\r\n`、乱码符号。
5. 修改状态统一标为「⚠️ 已修改/未审核；修改方：DeepSeek；变更范围：...」。
6. 输出最后结果时列出每个文件的变更摘要、复查命令、未处理风险。

## CSV 与数据资产整理提示词

请执行 CSV / 数据链路整理任务。开始前先读取 `AGENTS.md`、`开发管理/审核规则.txt`、`开发管理/docs-csv-asset-alignment.txt`、`src/Assets/DataConfig/README.txt`，以及相关 CSV 文件。

重点要求：

1. 不要只统计 `DataConfig` 目录；Unity `.asset` 生成目标在 `src/Assets/Data/` 下，必须分别统计 docs、CSV、Unity asset 三层。
2. 必须检查：
   - docs 内容文件数，排除模板文件。
   - CSV 非注释数据行数。
   - CSV ID 唯一性。
   - `Language.csv` 缺失 key。
   - `Language.csv` 重复 key。
   - CSV → Unity asset 覆盖率。
   - 多余/旧版 asset。
3. CSV 修改必须保持字段列数、ID 命名规则、`Language.csv` 同步。
4. 不要随意重命名 ID；若 ID 已被代码或 asset 引用，先列影响范围。
5. 完成后输出一张对齐表：docs / CSV / asset / 缺失 / 多余 / 风险。
6. 修改内容标为「⚠️ 已修改/未审核」，等待后续审核。

请按项目规范批量生成设计内容。开始前必须读取：

- `AGENTS.md`
- `开发管理/审核规则.txt`
- 对应设计规范文件
- 对应模板文件
- 相关已有同类内容作为风格参考

如果生成功法：读取 `docs/角色养成/功法设计规范.txt` 和 `docs/角色养成/功法/功法设计.txt`。

如果生成术法：读取 `docs/角色养成/术法设计规范.txt` 和 `docs/角色养成/术法/术法设计.txt`。

如果生成神通：读取 `docs/角色养成/神通设计规范.txt` 和 `docs/角色养成/神通/神通设计.txt`。

生成要求：

1. 每个完成品单独一个文件，不要合并。
2. 名称、篇章、典籍出处必须可追溯，不要杜撰古文。
3. 数值字段必须与模板字段齐全，不能缺境界、灵根、五行、倍率、冷却、本命升格等关键项。
4. 不确定的设计点要标注为待复核，不要硬编。
5. 生成前先给出内容清单、门派归属、境界分布、数值风险。
6. 生成后逐项按规范检查，并输出检查表。
7. 所有新增文件标为「⚠️ 已修改/未审核」。

请检查：

2. 是否有未说明的事实源假设。
3. 是否误把自己的修改标为「✅ 已审核」。
4. 是否所有新增/修改内容都带有合适的「⚠️ 已修改/未审核」标记。
5. 是否存在 docs / CSV / Unity asset / BattleSim 之间的新冲突。
6. 是否运行了必要检查命令。
7. 是否把验证命令和残留风险写进最终回复。
8. 是否有不该改的无关文件。

最终回复请按以下格式：

- 修改文件
- 修改依据
- 验证命令
- 发现的问题
- 残留风险
- 建议交给 Codex / ChatGPT5.5 复核的点
