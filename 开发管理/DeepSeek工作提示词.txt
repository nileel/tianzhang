## 收到 `1` 时的自动执行流程（✅ 已审核）

当用户消息去除首尾空白后**严格等于 `1`** 时，DeepSeek V4 Pro 自动选择并推进一个 DeepSeek 主责范围内最高优先级、可验证、可提交的任务。若用户消息不是纯 `1`，按用户明确要求执行，不触发本流程。

### 必读文件

1. `AGENTS.md`
2. `开发管理/AI协作规则.txt`
3. `开发管理/审核规则.txt`
4. `开发管理/DeepSeek工作提示词.txt`
5. `开发管理/AI合作沟通.txt`
6. `开发管理/设计-下一步建议.txt`
7. `开发管理/开发-下一步建议.txt`

### 任务选择顺序

1. 未通过审核清单中 DeepSeek 能修复的文档、CSV、数据资产、格式或机械检查问题。
2. `AI合作沟通.txt` 中请求 DeepSeek 执行、返工或补充检查的事项。
3. 当前阶段 P0/P1 中属于 DeepSeek 主责的文档清洗、CSV/Language/asset 对齐、批量内容补齐、测试清单或局部实现任务。
4. 能独立完成且验证明确的小型执行任务。

### 默认允许范围

- 文档清洗、格式修复、残留转义和编码污染处理。
- CSV / Language / asset 对齐清单修正与机械统计。
- 设计内容批量补齐，必须遵守一内容一文件和对应规范。
- 明确边界内的局部代码修复。
- 测试清单、回归步骤、统计脚本输出和可重复检查命令。

### 默认禁止范围

- 给出战斗公式、CTB、修炼或数值平衡最终结论。
- 决定 Unity 架构取舍或复杂系统方案。
- 执行 ID 全链路重命名。
- 删除 asset、迁移 GUID 或清理可能被场景/Prefab 引用的资源。
- 把 DeepSeek 自己的修改标为「✅ 已审核」或预填审核方结论。

### 执行要求

1. 先运行 `git status --short`；若有非本轮改动，只处理本轮相关文件并在回复中说明。
2. 修改文件时标「⚠️ 已修改/未审核；修改方：DeepSeek；变更范围：...」。
3. 按任务类型运行验证：
   - 文档任务：用 `rg` 检查控制字符、残留转义、重复标记和明显乱码。
   - CSV 任务：检查数据行数、重复 key、缺失 Language key、CSV→asset 有效覆盖口径。
   - 代码任务：按影响面运行 build/test；涉及 BattleSim 必须 build + run。
4. 更新 `开发管理/AI合作沟通.txt`，写明 `DeepSeek → Codex / ChatGPT5.5` 交接。
5. 提交本轮相关文件；提交信息必须体现 `DeepSeek` 与 `待Codex复审`。
6. 最终回复必须包含：任务选择原因、修改文件、验证命令、提交号、残留风险、下一次发送 `1` 建议。
