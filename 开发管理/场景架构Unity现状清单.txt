### 2.2 地图与探索

| 脚本 | 命名空间 | 职责 | 阻塞风险 | 后续归属 |
|------|----------|------|----------|----------|
| `Map/ExplorationController.cs` | `TianZhang.Map` | **职责过重**（~900 行）：地图生成、玩家/敌人生成、探索输入、战斗触发、CTB 战斗循环、掉落、UI 刷新。状态机含 Loading/Exploration/BattlePrep/Combat/Ended 五态 | **高风险**：战斗循环与探索状态耦合在同一类中；`CombatLoop()` 是 `while(battleActive)` 主循环，拆分时需精确保留行为 | 拆为 `AdventureSceneController`（探索+地图）+ `TacticalCombatController`（战斗循环） |
| `Tilemap/HexTilemapManager.cs` | `TianZhang.HexTile` | 六角格坐标缓存、网格生成、屏幕↔六角格转换、高亮范围、角色标记放置。暴露 `HexGrid Grid` 公共属性 | **中风险**：无 `ITacticalRenderer` 接口抽象；战斗规则通过 `tilemapManager.Grid` 直接依赖 Tilemap 层 | 包装为 `TilemapTacticalRenderer : ITacticalRenderer`，保留现有公共 API |

## 三、场景流转现状

**当前无任何场景流转机制**：所有功能在单一 `ExplorationScene` 中运行。

- `GameManager` 只做 DontDestroyOnLoad，无 `LoadScene`/`UnloadScene` 调用
- `SectSelectionManager.OnStartGame` 不在 StartMenu 场景中执行，而是在探索场景内动态创建门派面板
- 战斗不切换场景：`ExplorationController.CombatLoop` 原地切换 `GameState.Combat`
- 无 `GameSession`、`SceneFlowManager`、`SceneReturnTarget` 等流转基础设施

## 四、阻塞风险汇总

| 风险 | 等级 | 描述 | 影响的任务 |
|------|------|------|------------|
| ExplorationController 职责耦合 | **高** | 探索+战斗+UI 刷新在同一类中，拆分 `CombatLoop` 时行为一致性难以保证 | TQ-014 Task 8（TacticalCombatController） |
| 无 ITacticalRenderer 抽象 | **中** | 战斗规则直接依赖 `HexTilemapManager.Grid`，2.5D 渲染替换需要先建接口 | TQ-014 Task 2（TacticalGridModel/ITacticalRenderer） |
| UICanvas 重复创建 | **高** | `BattleUIManager.Awake` 无条件创建；`SectSelectionSetup` 也创建。跨场景时需统一判断 | TQ-014 Task 4（会话流转骨架） |
| SectSelectionManager 硬依赖 ExplorationController | **高** | 门派选择通过 `FindObjectOfType<ExplorationController>` 延迟查找；已弃用 API（CS0618） | TQ-014 Task 9（StartMenu 迁移） |
| 无场景生成通用方法 | **中** | `SceneBuilder` 只有 `BuildExplorationScene()`，无参数化 `BuildEmptyScene(rootName)` | TQ-014 Task 5（四场景脚手架） |
| GameManager 无会话管理 | **中** | 只存 `PlayerCharData` 不存存档/场景状态/返回点 | TQ-014 Task 4（会话流转骨架） |
