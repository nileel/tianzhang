# 四阶段成长与道基核心曲线数值验证记录

状态：✅ 已验证（N-FPD-GROWTH-01，2026-07-26）

## 范围与口径

- 本记录只锁定旧筑基五段一级属性总预算向道基四阶段的迁移规则，以及道基核心可数值化参数随连续养基进度变化的代表性曲线；不创作功法专属机制，不修改伤害、槽位、位格、丹相或非数值效果。
- 旧五段输入继续由 `GameData.GongFaTables` 或已登记的 `SubGrowthBase` 加权回退提供，只作为迁移基线。每部功法、每项一级属性的旧累计预算为现行单段增量乘以五。
- 移力由境界固定值决定，不参与成长节点迁移。练气和金丹既有成长输入不在本任务调整范围。
- 本任务验证的是四阶段累计预算在金丹入口前与旧五段累计预算守恒，不把默认运行中缺少有效金丹样本伪装成金丹战斗平衡结论。

## 锁定输入

四阶段预算份额按稳定顺序锁定为：

| 道基阶段 | 预算份额 |
|---|---:|
| 第一阶段 | 18% |
| 第二阶段 | 22% |
| 第三阶段 | 27% |
| 第四阶段 | 33% |

分配规则：

1. 四阶段份额之和必须为 100%，且逐阶段严格递增，不采用旧五段总额平均除以四。
2. 整数总额先为每阶段保留 1 点，再按 18%／22%／27%／33% 对剩余预算取整；尾差按小数余数从大到小、阶段顺序从前到后稳定分配。
3. 非整数总额直接按四阶段份额分配，最后一阶段吸收浮点尾差。
4. 每部功法、每项属性迁移前后累计预算差不得超过 `1E-9`。

道基核心代表性连续曲线锁定为：

```text
normalizedMagnitude
  = 0.35 + (1.00 - 0.35) × progress^1.25
progress ∈ [0, 1]
```

| 阶段锚点 | progress | normalizedMagnitude |
|---|---:|---:|
| 第一阶段 | 0.000 | 0.350 |
| 第二阶段 | 0.333 | 0.515 |
| 第三阶段 | 0.667 | 0.742 |
| 第四阶段 | 1.000 | 1.000 |

该曲线只提供连续数值参数接口。非数值效果仍须由功法的统一效果绑定显式声明阶段或进度条件，不能由本曲线自动启用。

## 可复现验证与结果

执行命令：

```powershell
dotnet build -c Release --no-restore "D:\天章游戏开发\simulations\BattleSim"
dotnet run --no-build -c Release --project "D:\天章游戏开发\simulations\BattleSim"
```

结果：

- Release 构建通过，0 个警告、0 个错误。
- 默认完整运行使用 20 种子、每种子 200 修炼周期、21 个 Build；进程以退出码 0 在 `489.456` 秒结束，并到达最终调试统计和结束分隔线。
- `Program.RunFoundationGrowthAudit` 覆盖全部 21 个 Build；练气出口的道基成长贡献为 0，迁移前后差值为 0。
- 每个 Build 的四阶段累计成长与旧五段累计成长差不超过 `1E-9`，因此金丹入口前的筑基一级属性累计预算不变。
- 代表性物理、神魂与符修 Build 的四阶段分配均逐阶段增长；曲线锚点单调，起点为 0.35，终点为 1.00。
- 默认修炼结果没有产生有效金丹样本，金丹矩阵为 NA；本任务不据此声明金丹内部或跨阶战斗平衡。

## 结论与残留风险

- 18%／22%／27%／33% 形成后段更重的四阶段成长节奏，同时严格保留每部功法旧五段累计预算；旧五段只保留为可追溯迁移基线。
- `0.35 → 1.00`、指数 `1.25` 的代表性曲线允许道基核心数值参数连续成长，且不会在早期阶段平均释放全部强度。
- 本任务只锁定迁移算法和代表性曲线接口；29 部功法的实际四阶段表、筑基方案与效果绑定由 `C-FPD-GONGFA-01` 逐项迁移，底层旧五段运行时结构由后续数据 schema／迁移任务删除。
- 默认矩阵每组 100 场在 50% 胜率附近的 95% 抽样误差约为 ±9.8%；该误差不影响本任务的确定性预算守恒断言，但后续锁定具体战斗平衡边界时仍须运行对应定向验证。
