# 金丹槽位与丹枢加成数值验证记录

## 结论

2026-07-28，`N-SLOT-01` 以 BattleSim 锁定金丹普通槽位的显式丹枢加成方案。筑基基准为术法
`5`、普通神通 `2`；只有 `STABLE` 真实位格的一条合法 `DanshuSlotEffectBinding` 可提供一个
`+1` 单位。令 `a` 为术法绑定数、`d` 为普通神通绑定数、`s` 为稳定实位数，则：

```text
术法槽 = 5 + a
普通神通槽 = 2 + d

a、d 为非负整数；a ≤ 3，d ≤ 2，a + d ≤ s，s ∈ {1, 2, 3}
```

初结／温养／圆满只把总可分配单位上限依次开放到 `1/2/3`，不自动发放。最终硬上限为术法
`8`、普通神通 `4`。这保留旧迁移识别范围 `5~8 / 2~4`，但不再以紫府数量、旧府位或境界倍率
推导槽位。

## 合法接口、输入和输出

一条计划中的 `DanshuSlotEffectBinding` 必须同时声明：

- `bindingId`、目标矩阵开放的 `danshuInterfaceId = DANSHU_SLOT_CAPACITY_V1`，以及与类别匹配的
  `effectId`：`DANSHU_SLOT_ART_CAPACITY` 或 `DANSHU_SLOT_ORDINARY_DIVINE_CAPACITY`。
- 同一唯一 `JindanCoreBinding.danshuCoreId`、目标稳定 `positionId`／`positionType`、目标位格的
  `primaryCarrierAbilityInstanceId` 与已验证的 `compatibilityProfileId`。
- `slotKind = ART` 或 `ORDINARY_DIVINE`，并固定 `delta = +1`。

输出只增加战斗准备时的普通容量。一个稳定实位最多一条绑定，不能同时增加两类槽位；绑定不创建
术法、普通神通、基础效果装配槽、位格、丹相、丹枢或资源／冷却／充能账本。镇府神通、丹相主／辅
承载和金丹基础效果的行动／持续承载都不属于普通神通槽。

当前矩阵、CSV、Unity 和 BattleSim 角色运行时尚未保存该接口记录，所以现有运行时的金丹加槽为
零。后续实现只能逐个加入显式绑定，不得以本审计模型替代数据字段或批量回填自动加成。

## 可复现输入与命令

- 审计入口：`simulations/BattleSim/Program.cs::RunJindanSlotBudgetAudit`。
- 装配输入：沿用 `CreateDanxiangBudgetInput` 的完整紫府、独立主承载、唯一丹枢／丹相和实例账本；
  `EvaluateJindanSlotBudget` 只读取稳定实位和显式绑定，不改变 `GoldenCoreAssembly`。
- 全量分配：对每个合法 `1～5 府 × 1～3 位` fixture 穷举所有满足 `a ≤ 3`、`d ≤ 2`、
  `a+d≤s` 的绑定分配。

```powershell
dotnet build -c Release --no-restore simulations/BattleSim
dotnet run --no-build -c Release --project simulations/BattleSim
```

## 拒绝回归与边界

- `delta=+2`、未声明丹枢接口、效果类别与 `slotKind` 不匹配、非目标主承载、同一实位双绑和
  普通神通累计 `+3` 均以稳定拒绝原因终止审计。
- 辅助引用只组织现有实例，不可冒充目标实位主承载、复制绑定或扩大单次 `+1`。
- `TEMPORARY`、暂寄、未占据、失稳和缺少独立主承载不属于 `STABLE`，槽位输出恒为零。
- 第四、第五府保留 `1.00` 完整输入预算、府体和合法辅助连接；不生成术法槽、普通神通槽、
  第四实位、第二丹相、第二丹枢或普通效果槽。
- 本任务未修改矩阵权限、五十一个基础效果、紫府容量、占据／争位、削位／封丹、伤害表、CSV、
  Unity 数据或运行时 UI。
