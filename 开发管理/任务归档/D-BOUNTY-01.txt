# D-BOUNTY-01 · 悬赏目标、状态与奖励数据契约

## 来源与当前边界

- `C-GZ-BOUNTY-01` 已锁定 `bounty_guanzhong_shijiahou` 的发布地点、`defeat_enemy` 目标、`guanzhong_wild` 地点约束、一次性规则、四状态生命周期和奖励类别；`D-SETTLEMENT-01`、`D-ENEMY-01` 与 `D-ITEM-01` 已分别锁定城市、敌人和物品的单向数据契约。
- 本卡只定义后续 `BountyData` 的字段、跨表引用、状态与失败关闭语义，不创建 CSV、Language、asset、导入器、只读目录、悬赏运行时、背包授予、存档迁移、界面或场景消费。
- 奖励物品、授予数量、掉落概率与 `maxStack` 均无批准参数，仍由 `N-GZ-REWARD-01` 处理；本卡不得以候选 CSV、物品名称、默认值或测试 fixture 填充它们。

## 实施范围

- 新建 `docs/superpowers/specs/2026-07-30-guanzhong-bounty-data-contract.md`，定义 `BountyData` 的稳定 ID、文本键、生产范围、发布城市、目标类型、目标敌人、目标数量、允许冒险、奖励条目与一次性策略，并固定 docs -> CSV -> 导入器 -> 保持 GUID 的 asset -> `ContentCatalogData` -> 消费者的单向边界。
- 为首批石甲兽悬赏写明可表达的已审核身份、城市、敌人、地点、`defeat_enemy` 和 `one_time` 引用；将奖励条目的正式 `itemId` 与正整数数量、物品 `maxStack` 和掉落参数保持为 `N-GZ-REWARD-01` 的参数闸门，不生成生产行或 fixture 值。
- 定义 `Available -> Accepted -> ObjectiveCompleted -> Claimed` 的合法状态、结构化 `adventureId + enemyId` 计数入口、单场最多一次计数、与背包原子授予的同次提交要求，以及缺失／未知引用、非法状态、进度、目标、地点或奖励时的失败关闭条件。
- 写出后续整表、跨表与运行时正反 fixture 规格，明确在参数未批准、目录未实施或状态所有者未迁移前，契约不声称悬赏已可接取、计数、领奖或保存。

## 禁止项

- 不修改 CSV、Language、Unity asset、导入器、`ContentCatalogData`、`GameSession`、`QuestStateStore`、背包、掉落、悬赏、存档、UI、场景、测试或现有内容档案。
- 不填入奖励物品、授予数量、掉落概率、`maxStack`、价格、库存、经济强度或任何未批准参数；不把 `Enemies.csv` 候选掉落或现有库存状态当作正式数据。
- 不新增其他悬赏、目标类型、随机任务池、每日刷新、通用条件表达式、第二套任务／状态／背包／场景／存档所有者、默认奖励或兼容 fallback。
