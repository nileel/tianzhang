# U-CHAR-2D-BATTLE-ANIM-INTEGRATION-01 · 苻渊2D战斗动画样例Unity接入

## 来源与当前边界

- 本卡只消费完成的 2D pilot、其 manifest 与用户批准的 pipeline，不生产、重画、重选技术或修订 source atlas。2026-08-25 上游已冻结唯一 `.spine` 母源和六份三帧六方向 RGBA atlas；本卡无需再猜测 source 方法、帧数、哈希或生产成本。
- 运行时只接入隔离比较入口，不能接入正式 `AdventureUnitSpawner` 或改变规则结果。旧 `TacticalSpritePresentationController`／`TacticalSpriteProbeGroup` 是静态样张所有者，保持不变，不能作为动态动画 fallback。
- 动态资产唯一使用 `FuYuanBattle` 文件夹、`BattleAnimationSpritePresentationController` 和 `BattleAnimationSpriteProbeGroup`；pilot 未完成、文件／manifest 不完整或运行时所有者不唯一时不能进入 ready。

## 必查范围

- 批准的 2D pipeline 规格完整正文、pilot 的 manifest／source-selection／生产记录／六个 source atlas，以及 `开发管理/苻渊2D战斗动画样例生产记录.txt`。
- `src/Assets/Scripts/Modules/GameplayContracts/CombatPresentationContracts.cs::StaticChessPresentationEvent`、`src/Assets/Scripts/Modules/Features/CombatPresentation/TacticalSpritePresentationController.cs`、`src/Assets/Scripts/Editor/VisualBaselineBuilder.cs::BuildTacticalSpriteAssets`、`src/Assets/Scripts/Editor/AdventureSceneBuilder.cs::BuildVisualBaselineMatrix/CreateTacticalSpriteProbes`、`src/Assets/Scripts/Editor/SceneArchitectureValidator.cs::ValidateAdventureVisualMatrix` 及其直接测试。
- `src/Assets/Tests/EditMode/VisualBaselineEditorTests.cs`、`src/Assets/Tests/PlayMode/TacticalSpritePresentationPlayModeTests.cs`、`src/Assets/Scripts/Modules/Spatial/HexCoord.cs::Directions` 与 `src/Assets/Scenes/AdventureScene.unity` 的直接引用；先确认新 controller 是唯一必要扩展，再改动允许路径。

## 实施范围

- 将六个 source atlas 原样复制到冻结 `FuYuanBattle` 路径，配置 multi-sprite grid、`512 PPU`、Custom pivot `(0.5,0.18)`，由 pilot manifest 验证格网、帧、事件索引与 SHA-256；不导入 source 母文件。
- 新建受限 `BattleAnimationSpritePresentationController` 和单个动态 Prefab，只消费既有 `StaticChessPresentationEvent`，为同一状态选择六向帧并在结束复位；施法最多一次既有特效信号，不能拥有规则或提供静态／缺失资源 fallback。
- 仅在 `VisualBaselineBoard` 建立默认关闭、显式切换的 `BattleAnimationSpriteProbeGroup`。保持静态 3D probes、旧静态 2D 样张、相机、地块和正式单位不变；活动动态组与非目标路线互斥。
- 记录运行时活动 atlas、方向、状态、事件帧、复位、规则快照与实际接入分钟。完成后才分别解除 playable compare 与 cost evidence 的本卡 blocker。

## 禁止项

- 不手修 source atlas、不新增正式单位，不修改战斗、方向、占格、装备、AI、结算或存档；不把 Source 方法运行时化为骨骼、SkinnedMeshRenderer、Animator 或 Animation。
- 不通过镜头、光照、尺度、地块、方向私有 pivot／缩放／位移、镜像、默认启用新组或私有事件时序优化本路线；不改旧静态样张控制器作兼容分支。
- 不在 pilot／manifest／业务 expectedPaths 未冻结时实施；缺状态、方向、帧、资产、事件索引或唯一所有者即停止，不新增 fallback。

## 验证

- 运行 pipeline 冻结的 manifest／atlas SHA、multi-sprite grid、六状态／六方向、`512 PPU`、pivot、事件索引、Prefab 单一 renderer／controller、隔离路线和无 Animator／SkinnedMeshRenderer 的 EditMode 检查。
- 运行 PlayMode 在固定 `1920×1080` 矩阵证明六方向的每个状态、攻击／受击／死亡事件时点、施法单次信号、根节点复位、真实遮挡、活动 atlas 与规则快照不变；人工矩阵另行判定冲击力、身份、宽袖／武器和多单位可读性。
- 运行 `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/run-unity-editmode-tests.ps1`、`pwsh -NoProfile -ExecutionPolicy Bypass -File tools/run-unity-playmode-tests.ps1`、`pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-asset-versioning.ps1`、`pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-data-chain.ps1` 与状态变更后的 `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-task-cards.ps1`。

## 完成条件

- 2D 动态样例在隔离比较入口可重复运行：活动 atlas、六方向、六状态、事件索引、施法信号、根节点复位、真实遮挡与规则快照证据完整，且没有正式接入或规则变化。
- 下游两卡移除本 blocker，并按各自剩余依赖保持正确状态；Unity 接入时间进入成本证据记录，不把未试批量扩展写成结论。

## 完成记录

- 六份冻结 atlas 已逐字节复制到 `src/Assets/Art/Characters/TacticalSprites/FuYuanBattle/`；导入为 `512 PPU`、Custom pivot `(0.5,0.18)` 的六个 `6×3` multi-sprite grid，并由 manifest 的 SHA-256、格网和事件索引失败关闭验证。
- `BattleAnimationSpritePresentationController` 只消费 `StaticChessPresentationEvent`，以 six-direction／three-frame state atlas 播放 idle、move、attack、hit、cast、death；施法只在 release frame 发出一次效果信号，动作结束恢复根节点，未写规则快照。
- `AdventureScene/VisualBaselineBoard` 已增加默认关闭的 `BattleAnimationSpriteProbeGroup`，其显式切换会关闭旧静态 2D 与静态 3D probe；现有旧组、正式 `AdventureUnitSpawner`、相机、光照、地块和规则所有者保持不变。
- 运行证据、命令和约三分钟可测 Unity 接入／验证窗口记录在 `开发管理/苻渊2D战斗动画Unity接入验证记录.txt`；下游两卡仅移除此 blocker，仍等待静态 3D 动态路线接入。
