# U-2_5D-01 · 2.5D 战棋表现隔离小场景原型

## 完成交付

- `HybridTacticalRenderer` 以同一 `TacticalGridModel` 建立六角棱柱地块、`HeightLevel` 纯表现高度、2D billboard 单位标记与地面阴影；它不写回模型，也不从 Transform、Camera、Renderer 或 Collider 推导规则。
- `HybridTacticalPrototypeController` 使用现有 `SpatialQueryBoardFactory` 和生产 `env_guanzhong_wild` 档案初始化快照；鼠标射线只把 collider 的绑定 `HexCoord` 交给共享查询，再显示移动／攻击范围反馈。
- `SceneBuilder.BuildHybridTacticalPrototypeScene()` 生成不注册 Build Settings 的 `HybridTacticalPrototype.unity`，其中仅有斜俯视正交相机与原型根对象；未修改 `AdventureScene`、`ExplorationScene`、`SceneFlowManager` 或正式 Build Settings。
- `HybridTacticalRendererTests` 覆盖坐标/高度表现映射、raycast 绑定坐标、2D/2.5D/2D 同一规则输出、单柱占位表现、控制器输入映射及正式 Build Settings 排除原型场景。

## 实施范围

- 建立半径 5～7 的隔离原型场景，以同一 `TacticalGridModel` 和 `SpatialQueryBoard` 输入生成 2.5D 六角地块、斜俯视正交相机、2D billboard 单位标记、地面阴影和已有 `HeightLevel` 的纯表现映射。
- 鼠标射线只负责命中表现地块并还原其绑定的 `HexCoord`；移动、距离、范围、视线、障碍、占位和拒绝原因继续读取共享规则查询结果。
- 固定同一 fixture 对照 `Tilemap2D` 与 `Hybrid2_5D` 的规则输出；切换表现不得写回、重建或改变规则状态。
- 更新兼容验证清单，记录同一 case 的 2D／2.5D 输出、可见表现证据及正式 Build Settings 未变化的检查结果。

## 禁止项

- 不修改 CTB、伤害、冷却、寻路、技能范围、空间查询算法、环境档案或玩法数值。
- 不新增三维占位、同柱多单位、飞行高度规则、格边类别、默认档案、兼容分支或第二份规则服务。
- 不修改 `AdventureScene`、`ExplorationScene`、`SceneFlowManager` 或正式 Build Settings；原型不得成为第二个正式冒险入口。
- 不用 Transform、Collider、Camera、Renderer、模型间距或欧氏距离推导任何战斗规则；Collider 只可返回已绑定的 `HexCoord` 作为输入选择。

## 完成条件

- 隔离场景以相同规则输入呈现半径 5～7 的 2.5D 六角地块、billboard 单位、高度表现、点击选格和移动／攻击范围反馈。
- 清单中的同 case 规则输出在 2D 与 2.5D 间一致；改变模型 Transform、镜头或纯视觉对象不改变距离、范围、视线、障碍、占位或行动合法性。
- Unity 编译、EditMode、数据链与文本检查通过，正式冒险入口仍唯一为 `AdventureScene`，原型未进入 Build Settings。

## 停止条件

- 实施必须改变正式冒险入口、共享空间规则、战斗语义或环境数据，必须引入三维占位／未定义高度资格，或无法在隔离场景内用现有接口完成同输入对照时停止并请求负责人决定。
