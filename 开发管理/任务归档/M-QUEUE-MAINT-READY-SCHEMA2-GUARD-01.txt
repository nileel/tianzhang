# M-QUEUE-MAINT-READY-SCHEMA2-GUARD-01 · QueueMaintenance ready schema 2 过渡门

## 来源与当前边界

- 唯一批准设计：`docs/superpowers/specs/2026-09-01-queue-maintenance-ready-schema2-transition-guard-design.md`，设计提交 `e7749d1378ee80a531df59c7240c4f25daf7c047`。
- 单一结果：QueueMaintenance 新建 ready 卡或把非 ready 卡恢复为 ready 时，candidate、canonical 重放和正式集成复查均拒绝 schema 1 或非实时 schema 2 投影，同时保持 base 与当前都为 ready 的既有 schema 1 卡合法。
- 已证实根因是 QueueMaintenance 两层完成检查只调用普通全局任务卡检查，无法区分既有 ready schema 1 与本轮新进入 ready 的 schema 1；提示合同也未要求同提交写入现有预检生成的 schema 2 投影。

## 必查范围

- 批准设计全文，重点是第 3、5、6、7、8 节。
- `tools/check-task-cards.ps1` 的参数合同、活动卡枚举、`Assert-Schema2Projection` 与所有 postcondition 分支。
- `tools/invoke-codex-candidate.ps1` 的 QueueMaintenance 提示、candidate 完成检查及其直接测试。
- `tools/invoke-hourly-owner.ps1` 的 canonical 重放、正式集成后 postcondition 复查及 `tools/test-queue-maintenance-completion.ps1` 的对应编排 fixture。
- `开发管理/自动工作流规则.txt` 与 `开发管理/自动工作流恢复规则.txt` 的 schema 5、QueueMaintenance、失败关闭、canonical 重放和正式集成合同。

## 实施范围

- 扩展现有 `tools/check-task-cards.ps1`，新增 `QueueMaintenanceReadySchema2Guard` postcondition 与 `-BaseCommit`；该 postcondition 必须携带 BaseCommit，其他 postcondition 和全局检查不得携带。
- BaseCommit 必须解析为提交且是当前 HEAD 的祖先；base 活动卡只用 `git ls-tree` 枚举并用 `git show <base>:<path>` 读取，base 缺失按不存在处理。
- 命中集合严格为当前 ready 且 base 不存在，或 base 的 `dispatchState` 不是 ready；命中卡必须 schema 2，且 `riskPreflight` 只含 `explicitRefs/matched/gates` 三数组，并复用现有 `Assert-Schema2Projection` 实时重算验证。
- Candidate、最新 master canonical 重放和正式 fast-forward 后复查调用同一 postcondition；canonical 必须使用实际重放 base 重新计算，不复用 candidate 命中列表。
- QueueMaintenance 提示明确：新建或重新 ready 前调用现有预检，在同一提交写入 schema 2 与实时投影；预检失败、过宽或缺少门禁指针时不得 ready。
- 完成时归档本卡；`M-EXP-READY-SCHEMA2-ACTIVATE-01` 只在本卡完成后由后续正常 QueueMaintenance 重新预检并以 schema 2 投影解阻塞，不在本卡直接激活。
