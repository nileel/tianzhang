# M-EXP-READY-SCHEMA2-ACTIVATE-01 · ready 卡 schema 2 激活迁移

## 来源与当前边界

- 单一结果：在同一原子提交中重算当时全部 ready 卡、升级为 schema 2，并让检查器从该提交开始拒绝 schema 1 ready 卡。
- 直接事实源是修订规格“任务卡投影/迁移口径”、通过的 schema/L0/小时入口／每日收集器归档和执行瞬间的有序队列。
- 本卡是一次迁移，不保留长期 feature flag；技术实施主责 DeepSeek，完成后必须 Codex 独立复审。

## 必查范围

- `tools/check-task-cards.ps1` 的 schema 1/2 兼容逻辑与 `test-check-task-cards.ps1` 全部投影测试。
- `开发管理/当前任务队列.txt` 的完整 ready ID 集合和每张对应活动卡全文。
- `tools/get-experience-risk-preflight.ps1` 的实时 matched/gates 结果；当前风险索引只读。
- `M-EXP-DAILY-COLLECTOR-01` 归档及其测试证据，确认激活后新整理卡能机械生成 schema 2 实时投影，且非技术卡仍 blocked。
- 本卡 `expectedPaths` 中冻结的全部当前已知 active 卡路径；它们是迁移允许上界，不表示非 ready 卡应改写。

## 实施范围

- 取得同一 Git 基线上的 ready 快照；若任一 ready 卡路径不在本卡 `expectedPaths`，立即停止并请求重新冻结路径，不扩大授权。
- 对每张 ready 卡重算 `explicitRefs/matched/gates`，升级 schema 2；零命中也写三个空数组。非 ready schema 1 卡保持原样。
- 本卡自身从 external_execute 转 `codex_review/codex/ready` 时也必须是 schema 2。
- 同一提交把检查器从“兼容 schema 1 ready”切换为“拒绝 schema 1 ready”，补正反例；没有开关、旧模式或过渡提交。
- Codex 复审通过后归档本卡并只解锁 20 任务观察卡。

## 禁止项

- 不迁移 completed 归档、不改 blocked/frozen/pending_decision/waiting_reply schema 1 卡、不修改索引或经验正文。
- 不使用通配授权、feature flag、时间判断、第二检查器或“预检失败继续”。
- 不触及执行时不在 ready 集合的业务卡，即使路径已授权。

## 验证

- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/test-check-task-cards.ps1`，覆盖 schema 1 非 ready/归档仍合法、schema 1 ready 拒绝、schema 2 ready 零命中/正常/显式/旧投影失配。
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-task-cards.ps1 -OutputJson`，证明 `readyCount` 与队列相等且不存在 schema 1 ready。
- 对每张迁移卡独立运行预检并核对投影，记录 ready ID、任务卡 digest 与索引 digest。
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths 开发管理,tools` 与 `git diff --check`。

## 完成条件

- 同一提交中所有且仅当时 ready 卡为 schema 2、投影实时一致，检查器立即拒绝 schema 1 ready；非 ready 和历史归档未批量迁移。
- Codex 独立复审通过后归档本卡，观察卡只移除本 ID。

## 停止条件

- ready 集合含未授权路径、实时预检失败／过宽／缺指针、L0／小时入口／每日收集器任一未通过、无法单提交回滚，或需要长期开关、兼容分支与第二迁移模式。

## 回滚边界

- 激活提交是唯一回滚单元；回滚必须同时恢复检查器强制和该提交迁移的 ready 卡，不允许只回退一侧或保留混合强制状态。
