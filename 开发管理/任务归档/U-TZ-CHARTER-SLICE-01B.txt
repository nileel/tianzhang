# U-TZ-CHARTER-SLICE-01B · Settlement 单据点交互与最小 UI

## 来源与当前边界

- 唯一批准依据是 `docs/superpowers/specs/2026-08-04-tianzhang-charter-site-vertical-slice-task-decomposition-design.md`，尤其是“五、玩家交互与数据流”“六、UI 与场景边界”“七、失败关闭与原子性”“8.3”和“九、验证矩阵”。
- 本卡只消费完成并通过独立复审的 01A 动作、preparation 和结果；不得在 Settlement 层重建前置状态、请求、冲突或提交规则。
- 现有 `SettlementScene`、`SettlementSceneController`、`SettlementSceneView` 和唯一 `UICanvas` 保持正式所有者；父项 `U-TZ-CHARTER-SLICE-01` 不直接执行。

## 目标与非目标

- 目标：在正式 `guanzhong_city` 的旧水驿入口打开唯一站点面板，以明确顺序提交 01A 动作并显示真实稳定 ID、缺口、结果和失败原因。
- 目标：新增独立 `CharterSiteController`／`CharterSiteView`，重建正式 `SettlementScene` 后保持全部序列化引用完整。
- 非目标：不在 UI 实现规则、candidate、长期状态、存档、冲突排序或环境投影；不创建第二 Canvas、第二 Settlement 场景或全局 UI 单例。

## 根因与生产契约

- 根因是现有 Settlement 没有册界站点入口；若把规则塞入既有控制器、SceneBuilder 默认值或 UI 布尔，会绕过 01A 的唯一生产入口并让表现层成为状态所有者。
- `SettlementSceneController` 只从 `ContentCatalogData` 精确取得当前站点、提供同一 `GameSession` 引用并打开面板；`CharterSiteController` 只调用 01A 动作／评估入口，`CharterSiteView` 只提交和刷新结果。
- 面板显示的完成度只能来自 `CharterSiteInteractionProgress` 或正式调用后的 `GameSession.CharterRuntimeState`；通行不能自动授予管理权，UI 不得伪造 recognized／connected／registered。

## 实施范围

- 新增独立、序列化引用的 `CharterSiteController` 与 `CharterSiteView`；在现有 `SettlementSceneView` 下持有面板，由 Settlement 控制器只在当前正式据点、唯一启用站点和目录引用合法时打开。
- 面板按批准的通行、管理、节点、登记／授权／供给、金丹、元婴、正式调用顺序提交 01A 动作；每次调用后刷新站点、当前步骤、真实 ID、授权缺口、节点、供给、冲突决定、状态和稳定原因。
- 从长期状态重建正式提交后的显示；离开面板前尚未提交的 progress 可按 01A 契约丢弃，不把临时步骤保存到 UI 或会话。
- 扩展 `SceneBuilder.BuildSettlementScene` 和正式场景序列化引用；新增直接视图／控制器用例和场景构建断言，将实际结果写入验证记录。

## 禁止项

- 不修改 `CharterSiteInteractionRuntime`、`GameSession`、`CharterRuleRuntime`、`CharterConflictRules`、schema 4、CSV、asset、Adventure 环境规则或 BattleSim。
- 不把步骤规则塞入 `SettlementSceneController`／`SettlementSceneView`，不以按钮可用性、显示文本、SceneBuilder 默认或本地布尔代替实际结果。
- 不创建第二 Canvas、第二场景、全局 UI 单例、完整册界编辑器、九域地图、动态经济面板、NPC／剧情任务或表现资源精修。

## 失败关闭要求

- 站点缺失、重复、禁用、非当前据点，目录／会话引用缺失或未知请求时返回稳定原因且不打开面板、不推进 progress。
- 任一步失败只显示 01A 的实际原因和此前合法临时进度；不得写长期状态、自动跳步、补默认 ID 或把通行提升为管理资格。
- 金丹和元婴结果必须显示真实未提交状态；正式失败不把 candidate 写进会话。重新生成场景若引用不完整或出现第二 Canvas，验证失败并停止。
