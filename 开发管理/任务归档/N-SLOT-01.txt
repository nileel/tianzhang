# N-SLOT-01 · 金丹槽位与丹枢加成数值方案

## 来源与当前边界

- 2026-07-20 筑基／紫府／丹相集成规格。
- N-GC-BASE-01 已完成。

## 必查范围

- `docs/superpowers/specs/2026-07-20-foundation-purple-mansion-danxiang-integration-design.md`。
- `docs/基础设定/角色数值设计.txt`、`docs/基础设定/境界特性.txt`、`docs/基础设定/元婴锚点与金丹位格设定.txt`。
- `docs/角色养成/术法槽位设计.txt` 与 `simulations/BattleSim/Program.cs`。

## 实施范围

- 基于已通过的 G2 覆盖和新主／辅预算，提出并验证术法槽、普通神通槽与合法丹枢接口方案。
- 方案明确槽位与丹枢的输入、输出、适用边界、目标指标和数值阈值，并覆盖 1～5 府与 1～3 稳定位格。

## 禁止项

- 紫府数量、府属、第四／第五府和稳定位格数量都不得自动生成普通槽位；任何槽位修正必须来自明示效果绑定。
- 不得提前实施 N-SEAT-01 的占据结算、N-SUPPRESS-01 的冲突规则或伤害表调整。

## 验证

- `dotnet build -c Release --no-restore simulations/BattleSim`。
- `dotnet run --no-build -c Release --project simulations/BattleSim`。
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths 开发管理,docs,simulations`。
- `git diff --check`。

## 完成条件

- 方案明确槽位与丹枢的输入、输出、适用边界、目标指标和数值阈值。
- 覆盖 1～5 府与 1～3 稳定位格，不让第四、第五府失效或凭数量增槽，并保留可复现的 BattleSim 证据。

## 停止条件

- N-FPD-MANSION-01 或 N-FPD-DANXIANG-01 尚未完成，或方案必须依赖府数自动加槽、额外位格／丹相或未确认府体数值。

## 完成记录

- 2026-07-28：锁定术法／普通神通槽的 `5/2` 筑基基准和显式丹枢容量公式：`术法=5+a`、`普通神通=2+d`，其中 `a≤3`、`d≤2`、`a+d≤当前稳定实位数`。初结／温养／圆满只分别开放 1／2／3 个可分配单位，最终硬上限为 `8/4`。
- 合法 `DanshuSlotEffectBinding` 必须匹配矩阵接口、唯一丹枢、稳定目标位格、独立主承载、兼容档案、类别和 `delta=+1`；无绑定、`TEMPORARY`、失稳、府数和辅助连接的输出均为零。
- `RunJindanSlotBudgetAudit` 穷举 1～5 府 × 1～3 位的所有合法分配；独立主承载不足的组合被既有 `JD_PRIMARY_CARRIER_DUPLICATE` 拒绝，`+2`、未声明接口、类别错配、非目标主承载、同实位双绑和普通神通 `+3` 也稳定拒绝。Release 构建与完整 BattleSim 通过；详情见 `开发管理/任务归档/验证记录/金丹槽位与丹枢加成数值验证记录.txt`。
- 未实现矩阵／CSV／Unity 数据字段、角色运行时重算、UI 或任何占据、削位、封丹与伤害结算；后续实现必须逐项填入显式接口记录。
