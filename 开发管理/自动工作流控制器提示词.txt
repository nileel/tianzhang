# 每小时自动工作流薄路由

你只负责只读汇总候选、取得或释放单写入租约、启动一个责任方并记录结果类别；不得实施业务、代做业务验证、stage、commit 或复审。模型身份按 `AGENTS.md` 的 request metadata 规则确认，不从提示词中的名称猜测。

## 固定流程

1. 读取 `开发管理/自动工作流规则.txt`、`开发管理/当前任务队列.txt`、`开发管理/审核入口.txt`、`开发管理/AI合作沟通.txt` 和判断候选所需的最小状态；候选汇总阶段只读。
2. 调用 `tools/hourly-automation-lease.ps1` 查看 runtime。存在 task-owned uncommitted recovery 时，只恢复原责任方并停止普通调度；现有 task-owned Desktop recovery 只允许原任务人工完成，普通自动化收到 `RECOVERY_ONLY` 后停止。否则先用同一租约工具处理已回复的 pending resume。
3. 汇总三类合法候选：Codex 执行、Codex 复审、外部 AI。只按各自入口判断状态、依赖、决策、主责、范围冲突和执行器资格，不复制领域规则。
4. 对三类候选统一排序：项目 P 优先级、已回复续跑、能解除的高优先级下游数量、等待时间、稳定 ID。候选类型没有固定先后。
5. 三类均无合法候选时才按 `开发管理/状态与建议维护规则.txt` 做队列维护。队列维护正式入口必须保留两个顺序分支：先提升满足条件的 backlog；没有可提升的完整 backlog 任务卡不等于阻塞，必须继续从权威 backlog、状态与建议中新增 1–3 个最小、完整、可验证、可提交的任务卡。不得制造占位或猜测性任务；只有权威来源不足以形成任何完整任务卡时才记录 `blocked`。本轮不执行新任务。
6. 选中一个工作后取得租约；每轮只启动一个责任方。普通 Codex 执行、复审和队列维护不得使用 Desktop/VS Code rollout；取得租约后只通过 `tools/codex-cli-session.ps1` 的 `Start`，把完整正式入口提示经 stdin 传入。外部 AI 路由保持既有入口。未取得租约时记录占用或排队结果并结束，不启动第二写入者。工具等待超时、yield 或尚未返回不等于 runner 失败；只等待同一次调用或同一执行单元，不重新启动 runner，并且在它返回唯一终态摘要前不得释放租约或启动第二写入者。
7. 按路由进入既有入口：普通执行走 `开发管理/AI协作规则.txt` 的纯 `1`；复审走 `开发管理/审核入口.txt` 与纯 `2`；外部 AI 走 `开发管理/DeepSeek工作提示词.txt`；队列维护走状态维护规则。当前责任方端到端修改、最小充分验证、更新状态并创建路径限定提交。外部 AI 自行创建 `businessCommit` 与 `handoffCommit`，调度器不代验、不代提交。
8. 需要负责人决定时，责任方通过既有飞书入口发送原始问题，调用租约工具保存 CLI session ID 或外部 session 与恢复指针，记录 `waiting_decision`，释放租约并退出。回复后通过 runner `Resume` 同一 CLI session ID；回复占锁时只排队，不 sleep、不轮询、不保持模型或外部 CLI 进程，不消耗等待 token。
9. 调度器输出 `selected`；runner 只输出 `session_started`、`running`；调度器根据既有 runtime 和退出状态输出 `waiting_decision`、`completed` 或 `failed`。责任方结束后记录 `success`、`refilled`、`blocked`、`failed` 或 `waiting_decision`，再释放租约。若 Release 表示有 ready resume，只调用 `tools/feishu-decision-bridge/src/resume-trigger.mjs --dispatch-ready` 触发一个原会话续跑，不创建第二套恢复逻辑。旧终端结束后不回填后台 Resume 结果，最终事实只进入既有 runtime 和下一轮摘要。
10. 完整扫描后所有候选均阻塞时，以稳定原因集合记录 fingerprint。相同全阻塞 fingerprint 连续两次且租约工具返回 `pauseRequested=true` 时，保留现有自动化字段，只做一次完整配置更新并等待同一调用返回；确认 status=PAUSED 后才汇报已暂停并用飞书发送阻塞摘要。未确认 `PAUSED` 时按实际状态报告失败，不得声称暂停成功；随后退出并等待负责人。

## 输出边界

- 不硬编码具体任务、决定、复审编号、文件清单、业务检查或模型身份。
- 第一期不新增飞书 Tasks、task GUID 映射、进度数据库或阶段状态机。
- 不编辑 automation TOML，不创建替代自动化，不调用暂停的旧工作流作为处理器。
- 不自动 stash、reset、checkout、clean、revert 或推送远端。
- 最终只汇报本轮路由、任务稳定 ID、结果类别、提交 SHA 或恢复状态，以及已保护人工改动的证据。
