当本项目同时使用 ChatGPT5.5 与 DeepSeek V4 Pro 开发时，默认按以下职责分配任务。用户明确指定时以用户当次指令为准，但仍必须遵守 `AGENTS.md` 和本文件规则。

## 总原则

- **单一事实源**：设定与设计内容以 `docs/` 原文为准；开发进度与阶段判断以 `开发管理/` 为准；数值结论以 `simulations/BattleSim` 实际运行结果为准；Unity 实现以 `src/` 当前代码为准。
- **短入口优先**：涉及审核、复审、未审核清单、`1` 执行或 `2` 复审时，先读 `开发管理/审核入口.txt` 和必要队列文件，再按任务路由读取细则、清单或事实源，不默认读取全部管理文件。
- **分工不分裂**：一个任务若同时涉及设计、模拟器、Unity，应由主责 AI 产出方案，另一个 AI 只做校验或补充，不各自另起一套规则。
- **交接留痕**：完成任务后，在回复中说明修改文件、验证命令、残留风险；有疑点、待判断或复审请求时更新 `开发管理/AI合作沟通.txt` 当前队列。
- **状态分层**：`当前任务队列.txt` 只放近期可执行切片；`设计-当前状态.txt` 只放已验证事实和当前风险快照；设计/开发下一步建议只放中长期 backlog。维护细则见 `开发管理/状态与建议维护规则.txt`。
- **审核记录归档**：审核通过后删除正文临时审核记录。详细审核过程、验证命令、修改方/审核方与依据进入 git commit log、PR 描述、审核回复或 `开发管理/AI合作归档/`。
- **沟通材料不替代事实源**：`AI合作沟通.txt` 只记录当前交接线索、疑点和待复审项；任何结论仍必须回到 docs、开发管理文件、BattleSim、Unity 代码或 git diff 独立验证。
- **定时控制器唯一入口**：定时自动推进先读 `开发管理/自动工作流规则.txt`；该文件是调度、选题、租约、恢复与失败关闭的唯一规则源。

## ChatGPT5.5 / Codex 主责

ChatGPT5.5 / Codex 默认负责高层一致性、架构判断和需要跨文件推理的任务：

- 系统设计与规则整合：统一战斗、修炼、境界、五行、功法机制等跨文档规则。
- 架构与代码评审：审查 BattleSim、Unity 框架、数据管线、状态机、战斗结算、AI 行为等结构性问题。
- 数值评估与模拟结论：运行 BattleSim，解释矩阵、样本、同境/跨境口径，判断结论是否可靠。
- 任务规划与优先级：维护阶段路线、阻塞项、设计缺口、BattleSim→Unity 同步策略。
- 总结与管理文档更新：用户说“总结”时，完整执行 `开发管理/总结规则.txt`。
- 复杂 Unity 功能方案：群战 CTB、机制同步、数据驱动重构、存档/经济/地图循环等需要架构拆分的开发任务。

## DeepSeek V4 Pro 主责

DeepSeek V4 Pro 默认负责长文本生产、批量内容填充、机械一致性检查和执行型开发任务：

- 设计内容批量生产：按规范生成单个功法、术法、神通、门派、敌人、道具、地图等内容文件；必须一内容一文件，不合并。
- 文档清洗与格式统一：修复 `.txt` 中的转义残留、编码污染、字段缺失、编号错乱、表格格式问题。
- CSV 与数据资产整理：维护 `src/Assets/DataConfig/*.csv`、Language 文本 ID、导表字段完整性和 docs→CSV 对齐清单。
- 局部代码实现与修复：实现已明确设计的 Unity/BattleSim 小功能、bug fix、UI 文案接入、导入器字段补齐。
- 测试用例与回归清单：补充可重复验证步骤、边界用例、导入前后数量核对、模拟器输出对比。
- 素材规模扩展：古修/散修内容补齐、敌人模板、掉落表、经济数值初稿等大批量填充任务。

## Claude CLI / WF3-CLAUDE-ONE 执行边界

WF3 定时器当前暂停；未来人工恢复或用户明确调用时仍适用以下边界。Claude CLI 是 DeepSeek/Claude 执行范围的代理，不是新增的 Codex 主责角色。它必须先区分实际身份、产物修改方和任务授权，再选择任务：

1. 当 `ANTHROPIC_BASE_URL` 为 `http://127.0.0.1:15721/claude-desktop` 时，实际身份和修改方为 `DeepSeek V4 Pro`；否则为 `Claude Code`。
2. 两种环境的 WF3-CLAUDE-ONE 任务授权相同：仅限“待处理、非复审、主责明确为 `DeepSeek V4 Pro`、`Claude Code` 或 `Claude / DeepSeek`”的任务。原生 Claude Code 读取 `开发管理/DeepSeek工作提示词.txt` 时，只继承任务路由、边界和交接格式，不继承 DeepSeek 身份或修改方名称。
3. 主责为 `Codex`、`ChatGPT5.5`、`Codex / gpt-5.5` 或未明确授权给 DeepSeek/Claude 的任务一律不可领取；不得因任务看似属于局部实现、文案、数据整理或机械检查而放宽该限制。用户当次明确指派 Claude Code 的具体任务除外。
4. 选题前必须在 Claude 输出和 automation memory 记录实际身份、修改方、允许主责及候选任务 ID/主责/状态。没有合格候选时，写 `skipped_cleanly` 并退出，不改任何项目文件，不生成替代任务；只有真实交接或 `AUTO-BLOCKED` 才更新项目管理文件。

## 定时自动工作流

1. 唯一写入型定时任务为 `TZG Hourly Controller`；WF1、WF3、WF4 保持暂停，不得与控制器同时启用。
2. 控制器每轮只恢复或完成一个工作单元，按 `自动工作流规则.txt` 动态选择恢复、复审、必要维护或 Codex 执行任务。
3. 每日简报只读；不得修改文件、stage、提交或为生成日报执行任务。
4. 无任务、有效锁、身份确认失败或人工脏工作区只记 automation memory，不制造项目提交。

## 协作流程

- **设计任务**：Codex 先定规则边界与检查清单；DeepSeek 再批量生成内容；Codex 复核一致性与数值风险。
- **开发任务**：Codex 先评估架构和影响面；DeepSeek 可执行局部实现；涉及战斗公式、CTB、修炼、导表核心链路时，Codex 必须复核。
- **测试任务**：DeepSeek 负责列回归清单和跑机械检查；Codex 负责判断测试是否覆盖真实风险。
- **总结任务**：Codex 主责更新核心管理文件；DeepSeek 可先做文件统计、git log 摘要、已完成条目候选清单。

## 交接工作流

1. 派工前定边界：指定主责 AI、任务类型、允许修改范围、必须读取的事实源和预期验证命令。
2. DeepSeek 执行中留清晰边界：只能标「⚠️ 已修改/未审核」，不得写“审核方：Codex / ChatGPT5.5”“已复核”“已审核”等结论。
3. DeepSeek 交接写入 `AI合作沟通.txt` 当前队列，必须包含短 ID、日期与方向、任务/提交范围、修改文件、已验证、未验证、残留风险、请求判断和建议下一步。
4. Codex 消费交接时，先读 `审核入口.txt` 和当前匹配条目，再以 git diff、事实源和可重复命令重新验证。
5. 长期阻塞项进入 `未通过审核清单.txt` 或下一步建议文件；已通过且无后续价值的交接条目移入 `AI合作归档/`。

## 快捷工作流：用户发送 `1` 或 `2`

当用户消息去除首尾空白后**严格等于 `1`** 时，收到消息的 AI 自动推进一个最高优先级、可闭环的工作计划任务；不执行复审任务。

当用户消息去除首尾空白后**严格等于 `2`** 时，Codex / ChatGPT5.5 自动推进一个最高优先级复审任务；DeepSeek V4 Pro 不得自审，只能补齐交接材料或请求 Codex / ChatGPT5.5 复审。

若用户消息不是纯 `1` / `2`，按用户明确要求执行，不触发本流程。

### 通用步骤

1. 先确认自身身份，再进入任务选择：Codex / ChatGPT5.5 使用 Node REPL 读取 `nodeRepl.requestMeta['x-codex-turn-metadata'].model`；DeepSeek V4 Pro 按 `开发管理/DeepSeek工作提示词.txt` 的身份锚定输出身份确认；WF3-CLAUDE-ONE 还必须执行“Claude CLI / WF3-CLAUDE-ONE 执行边界”的身份与授权自检。
2. 读取 `AGENTS.md`、`开发管理/审核入口.txt`、`开发管理/当前任务队列.txt` 与 `开发管理/AI合作沟通.txt` 当前队列；`2` 流程还要读取 `开发管理/未通过审核清单.txt`；DeepSeek 还必须读取 `开发管理/DeepSeek工作提示词.txt`。
3. 检查 `git status --short`；若存在非本轮改动，只处理与本次任务相关文件，不 stage 无关改动。
4. `1` 按固定顺序选一个最小执行型任务切片：
   - `开发管理/当前任务队列.txt` 中匹配当前 AI 主责的 P0/P1。
   - `开发管理/未通过审核清单.txt` 中当前 AI 可修复的项。
   - `AI合作沟通.txt` 中请求当前 AI 执行、返工或补充的非复审项。
   - 当前阶段 P0/P1 下一步建议中当前 AI 主责的项。
   - DeepSeek 主责的批量/整理/机械检查任务。
   - Codex 主责的架构、数值、任务规划或复杂 Unity 判断项。
5. `2` 按固定顺序选一个复审任务切片：
   - 当前队列或交接中风险最高的待复审项。
   - `开发管理/未通过审核清单.txt` 中已返工、可复核的项。
   - `AI合作沟通.txt` 中 DeepSeek 请求 Codex / ChatGPT5.5 复审或判断的项。
   - 用户指定提交、diff 或文件范围。
6. `1` 遇到“待复审”任务时一律跳过并继续向下选择下一条“待处理”任务；`2` 才处理“待复审”任务。
7. 若当前任务队列为空、过期或无匹配主责任务，再读取 `设计-下一步建议.txt` 与 `开发-下一步建议.txt` 的待办项。
8. 选定真实工作对象后、读取实施细则前，调用 `tools.codex_app__set_thread_title`：`1` 命名为 `TZG｜<中文简述>`，`2` 命名为 `TZG｜复审：<中文简述>`。简述取当前任务卡或复审事实源的面向人中文标题，不得只用 TQ/HANDOFF 编号；无候选不改名，改名失败只记录当前对话执行说明，不阻断原流程。
9. 选定任务后，再读取 `审核入口.txt` 路由指定的细则、任务卡和事实源。
10. 当前 AI 不处理另一个 AI 主责的高风险任务；应在 `AI合作沟通.txt` 中写清请求、边界和所需判断。
11. 完成后按影响面验证，并只提交本轮相关文件；完成队列任务时同步更新 `当前任务队列.txt` 状态。

### Codex / ChatGPT5.5 收到 `1`

- 优先做工作计划中的架构判断、数值评估、任务规划、复杂 Unity 方案或 Codex 主责执行型任务。
- 不处理 DeepSeek 交接复审、不消费待复审队列；这些进入 `2`。
- Codex / ChatGPT5.5 自产内容完成必要验证后可直接闭环，不再标为“待复审”。

### Codex / ChatGPT5.5 收到 `2`

- 优先复审 DeepSeek 交接、待复审项、未通过清单返工项或用户指定提交/diff。
- 通过后可按审核规则改为「✅ 已审核」并提交；不通过时写入或更新 `开发管理/未通过审核清单.txt`。
- 不新开执行型工作计划任务，除非复审所需的最小修正文档属于当前审核结论记录。

### DeepSeek V4 Pro 收到 `1`

- 直接执行 DeepSeek 主责范围内最高优先级任务，可改文件、运行检查并提交。
- 所有 DeepSeek 修改必须标「⚠️ 已修改/未审核；修改方：DeepSeek」，不得写“审核方：Codex / ChatGPT5.5”“已复核”“已审核”。
- 完成后必须在 `AI合作沟通.txt` 新增 `DeepSeek → Codex / ChatGPT5.5` 交接条目，包含任务选择原因、修改文件、验证命令、未验证项、残留风险、请求复审点和下一次 `1` 建议。
- 提交信息应包含 DeepSeek 和待 Codex 复审语义，例如 `docs: DeepSeek修复数据链路口径（待Codex复审）`。

### DeepSeek V4 Pro 收到 `2`

- 不得复审自己的修改，也不得标「✅ 已审核」。
- 若存在待复审成果，只补齐交接材料、验证输出和请求复审范围，并提示需要 Codex / ChatGPT5.5 执行 `2`。

## 冲突处理

- 若两个 AI 结论冲突，优先级为：用户当次明确指令 > `AGENTS.md` > `开发管理/` 当前状态 > `docs/` 原文 > BattleSim/Unity 实际代码。
- 数值问题最终必须以 BattleSim 运行结果和对应代码为准。
- 若发现 `docs/`、BattleSim、Unity 三者不一致，不得直接凭印象修正；先指出冲突来源，再选择一个主事实源并同步其他文件。
- 任何 AI 不得在未运行 BattleSim 的情况下给出数值平衡定论；不得在未读取设计规范的情况下新增功法、术法或神通。
