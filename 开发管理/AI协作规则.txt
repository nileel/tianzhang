# AI协作规则（✅ 已审核）

> 2026-06-16 Codex / ChatGPT5.5 复审通过：补充 DeepSeek ↔ Codex / ChatGPT5.5 的交接、返工、复审材料消费与沟通记录归档流程。

当本项目同时使用 ChatGPT5.5 与 DeepSeek V4 Pro 开发时，默认按以下职责分配任务。用户明确指定时以用户当次指令为准，但仍必须遵守 `AGENTS.md` 和本文件规则。

## 总原则

- **单一事实源**：设定与设计内容以 `docs/` 原文为准；开发进度与阶段判断以 `开发管理/` 为准；数值结论以 `simulations/BattleSim` 实际运行结果为准；Unity 实现以 `src/` 当前代码为准。
- **先读后改**：任何 AI 接手任务前，必须先按 `AGENTS.md` 的查看规则读取对应管理文件和规范文档。
- **分工不分裂**：一个任务若同时涉及设计、模拟器、Unity，应由主责 AI 产出方案，另一个 AI 只做校验或补充，不各自另起一套规则。
- **交接留痕**：完成任务后，必须在回复中说明修改文件、验证命令、残留风险；完成并推送远端后，按规则更新 `开发管理/` 中的下一步建议与当前状态。
- **审核记录归档**：审核通过后，应删除正文中的临时审核记录；文档保留当前有效内容和必要的简短状态即可。详细审核过程、验证命令、修改方/审核方与依据应进入 git commit log、PR 描述或审核回复，避免管理文档随每次审核持续膨胀。
- **沟通材料不替代事实源**：`开发管理/AI合作沟通.txt` 只记录交接线索、疑点和待复审项；任何结论仍必须回到 docs、开发管理文件、BattleSim、Unity 代码或 git diff 独立验证。

## ChatGPT5.5 主责

ChatGPT5.5 默认负责高层一致性、架构判断和需要跨文件推理的任务：

- **系统设计与规则整合**：统一战斗、修炼、境界、五行、功法机制等跨文档规则，发现版本冲突并给出取舍。
- **架构与代码评审**：审查 BattleSim、Unity 框架、数据管线、状态机、战斗结算、AI 行为等结构性问题。
- **数值评估与模拟结论**：运行 BattleSim，解释矩阵、样本、同境/跨境口径，判断结论是否可靠。
- **任务规划与优先级**：维护阶段路线、阻塞项、设计缺口、BattleSim→Unity 同步策略。
- **总结与管理文档更新**：当用户说“总结”时，ChatGPT5.5 为默认主责，完整执行 `开发管理/总结规则.txt`。
- **复杂 Unity 功能方案**：群战 CTB、机制同步、数据驱动重构、存档/经济/地图循环等需要架构拆分的开发任务。

## DeepSeek V4 Pro 主责

DeepSeek V4 Pro 默认负责长文本生产、批量内容填充、机械一致性检查和执行型开发任务：

- **设计内容批量生产**：按规范生成单个功法、术法、神通、门派、敌人、道具、地图等内容文件；必须一内容一文件，不合并。
- **文档清洗与格式统一**：修复 `.txt` 中的转义残留、编码污染、字段缺失、编号错乱、表格格式问题。
- **CSV 与数据资产整理**：维护 `src/Assets/DataConfig/*.csv`、Language 文本 ID、导表字段完整性和 docs→CSV 对齐清单。
- **局部代码实现与修复**：实现已明确设计的 Unity/BattleSim 小功能、bug fix、UI 文案接入、导入器字段补齐。
- **测试用例与回归清单**：补充可重复验证步骤、边界用例、导入前后数量核对、模拟器输出对比。
- **素材规模扩展**：古修/散修内容补齐、敌人模板、掉落表、经济数值初稿等大批量填充任务。

## 协作流程

- **设计任务**：ChatGPT5.5 先定规则边界与检查清单；DeepSeek V4 Pro 再批量生成内容；ChatGPT5.5 复核一致性与数值风险。
- **开发任务**：ChatGPT5.5 先评估架构和影响面；DeepSeek V4 Pro 可执行局部实现；涉及战斗公式、CTB、修炼、导表核心链路时，ChatGPT5.5 必须复核。
- **测试任务**：DeepSeek V4 Pro 负责列回归清单和跑机械检查；ChatGPT5.5 负责判断测试是否覆盖真实风险。
- **总结任务**：ChatGPT5.5 主责更新四个核心管理文件；DeepSeek V4 Pro 可先做文件统计、git log 摘要、已完成条目候选清单。

## 沟通工作流

1. **派工前定边界**
   - 指定主责 AI、任务类型、允许修改范围、必须读取的事实源和预期验证命令。
   - 涉及数值、战斗、CTB、导表链路或审核状态时，必须同时说明最终需要 Codex / ChatGPT5.5 复核。

2. **DeepSeek 执行中留清晰边界**
   - DeepSeek 只能标「⚠️ 已修改/未审核」，不得写「审核方：Codex / ChatGPT5.5」「已复核」「已审核」等结论。
   - 遇到事实源冲突、影响面扩张或无法验证的命令时，不自行定论；写入交接记录并在最终回复中点明。

3. **DeepSeek 交接必填项**
   - 若任务完成后存在疑点、风险、未跑验证、需要架构判断或待复审项，更新 `开发管理/AI合作沟通.txt`。
   - 每条交接必须包含：日期与方向、任务/提交范围、已修改文件、已运行验证及结果、未运行验证及原因、残留风险、请求 Codex / ChatGPT5.5 判断的问题、建议下一步。
   - 交接中的数据快照必须写清口径；例如 Unity asset 同时区分“目录下文件总数”“按 CSV ID 匹配的有效覆盖数”“额外/旧版 asset 数”。

4. **Codex / ChatGPT5.5 消费交接**
   - 审核前先读 `开发管理/AI合作沟通.txt`，但必须以 git diff、事实源和可重复命令重新验证。
   - 审核输出按 `开发管理/审核规则.txt` 分为“通过 / 部分通过 / 不通过”，不得只复述 DeepSeek 自述。
   - 若发现阻塞项，写入审核回复；需要长期跟踪的事项进入 `开发管理/审核规则.txt` 未通过审核清单或对应下一步建议文件。

5. **返工闭环**
   - DeepSeek 返工时引用审核清单编号逐项修复，并在交接记录中写“修复方：DeepSeek；状态：待 Codex / ChatGPT5.5 复审”。
   - Codex / ChatGPT5.5 复审只移除已通过项；未通过项继续留在未通过审核清单，不用交接记录替代清单。

6. **归档与清理**
   - `AI合作沟通.txt` 只保留当前有效交接、疑点和待判断事项；已通过审核且无后续价值的长过程记录，应移入回复、commit log 或 PR 描述，不长期堆在正文。
   - 临时审核标记、预填审核方、不可见控制字符和无口径的数据快照，均视为交接质量问题，复审时应要求修正。

## 冲突处理

- 若两个 AI 结论冲突，优先级为：用户当次明确指令 > `AGENTS.md` > `开发管理/` 当前状态 > `docs/` 原文 > BattleSim/Unity 实际代码；数值问题最终必须以 BattleSim 运行结果和对应代码为准。
- 若发现 `docs/`、BattleSim、Unity 三者不一致，不得直接凭印象修正；先指出冲突来源，再选择一个主事实源并同步其他文件。
- 任何 AI 不得在未运行 BattleSim 的情况下给出数值平衡定论；不得在未读取设计规范的情况下新增功法、术法或神通。
