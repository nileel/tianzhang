# 自动工作流规则

本文件定义每小时自动化的稳定调度、隔离、集成和恢复边界。业务事实、领域验证、审核和任务维护仍以各自入口为准。

## 事实源与实时配置

- 任务唯一活跃事实是 `开发管理/当前任务队列.txt` 的有序 ready 行与同 ID 任务卡；任务卡 schema 2 的 `workerPaths`、`coordinatorPaths` 和 `expectedPaths` 是路径授权事实。
- 生产 prompt、schedule、workdir 和 status 只由普通管理上下文通过自动化管理能力变更；不得编辑 `~/.codex/automations/**/automation.toml`，自动化任务不得管理自身配置。
- 私有 runtime 使用 schema 4，保存协调器 lease、未关闭 batch、通用 `lanes[]`、旧决定/中断 recovery、阻塞计数和最后结果；不得保存 provider token、tenant key、用户标识或消息标识原文。
- 仓库实现、实时 prompt 和生产状态未同时通过契约检查时，不启用并行生产模式。

## Show、协调器租约与恢复优先

1. 每轮在读取队列或项目路由源前先调用 `tools/hourly-automation-lease.ps1 -Action Show`。
2. `pauseRequested=true` 时立即报告 `suspended`，不读取队列、不取得租约、不启动 Worker。
3. `Show.state.batch != null` 时不选择新任务：开放 batch 调用 `tools/invoke-automation-lane-batch.ps1 -Action Recover`；已关闭且保留证据的 batch 只报告 `held_conflict`、`stale_selection`、`needs_decision` 或证据不一致，等待普通管理上下文处理。
4. 没有 batch 时才读取有序队列；只有 `leaseStatus=active` 表示占用，过期 lease 由 `ResumeBatch` 或新 `Acquire` 按现有证据处理。
5. 同一仓库同一时间只有一个协调器 lease。它保护队列快照、task claim、自动 worktree、固定集成器、共享任务投影和 runtime；Worker 不持有主工作区写权限。
6. 旧 decision/interruption recovery 继续按 `开发管理/自动工作流恢复规则.txt` 的条件读取；普通责任方仍只在实际到达新决定事件时读取“创建决定恢复”。

## 通用 lanes[] 与生产配置

- 生产配置由 `tools/automation-lane-core.ps1` 返回：`maxConcurrent=2`，只启用 `codex` 与 `deepseek`。
- `codex` 接受 `codex_execute`、`codex_review`；`deepseek` 接受 `external_execute` 且 `owner=deepseek`，身份固定为 DeepSeek V4 Flash。
- lane 保存 `laneId`、owner、identity、acceptedRoutes、invoker、taskClaim、worktree、branch、baseCommit、workerPaths、coordinatorPaths、factPaths、process/session、workerTerminal、integrationState 和原队列序号。
- 数据结构、选择算法和两两冲突检查不得依赖两个固定数组位置。测试可注入模拟第三 lane；生产配置不得包含虚假第三 AI。

## 每小时选题与 task claim

1. 取得协调器 lease 后重新读取 Git HEAD、队列、任务卡和人工 staged/unstaged/untracked 路径，防止选择与认领之间竞态。
2. 按队列原行序扫描，为每个空闲 lane 选择遇到的第一项安全任务；每 lane 每 batch 最多一项，本 batch 结束前不滚动补位。
3. 候选必须是同一 ready 投影，route/owner 与 lane 匹配，且不与已选任务存在直接/传递依赖、workerPaths/factPaths 冲突、同一 taskId 或人工路径冲突。
4. 没有安全第二项时无损退化为单路；一路失败、blocked 或 needs_decision 不取消另一独立 lane。
5. claim 在 `Show.state.batch.lanes[].taskClaim` 可见。手动选题必须跳过已 claim 的同一任务，除非普通管理上下文明确取消该 lane。
6. 队列为空时仍只运行一次既有 `QueueMaintenance` 串行入口，本轮不执行新业务任务；维护不占用第二个业务 lane，也不滚动补位。

## Worker 路径与候选提交合同

- 自动 Worker 使用各自唯一分支和自动 worktree；不得共享 Git index、分支、session，不得访问其他 lane worktree，不得切换分支、创建额外 worktree、推送或调用租约收尾。
- 自动 worktree 固定使用主仓库内的短路径 `.worktrees/automation/<batchId>/<laneId>`；私有 StateRoot 只保存 runtime 与证据，不承载仓库 checkout。协调器先创建 detached worktree，成功后才创建 lane 分支，避免 checkout 失败遗留分支。
- `tools/invoke-codex-lane-worker.ps1` 与 `tools/invoke-external-lane-worker.ps1` 只允许候选提交包含 `workerPaths`。`coordinatorPaths` 不得由 Worker 写入、stage 或提交。
- completed 终态必须包含 batch/lane/task/identity/session、完整 candidate SHA、实际 changedPaths、验证结果、正式提交九个事实字段、期望 transition 和 coordinatorChanges。候选父提交必须等于 lane baseCommit，changedPaths 必须是 workerPaths 子集，worktree 必须干净。
- 候选提交不是正式交付，不使用正式 Automation 元数据，不发送成功通知。
- DeepSeek completed 必须提议 `codex_review/codex/ready` 以及正式交接内容；不得自审或预填 Codex 结论。

## 完成事件、串行集成与正式提交

- 固定协调器内的固定串行集成器监听每个 lane 的结果文件/进程事件。前序先完成可立即集成；后序先完成只保存终态，等待所有更前序 lane 进入稳定终态。
- 前序失败、blocked 或 needs_decision 后，后序若无依赖仍继续集成；本 batch 不补新任务。
- 每次集成前重新核验主分支 HEAD、同一队列行、任务卡 hash、route/owner/state、依赖、人工路径、已集成本 batch 提交、候选父提交和 changedPaths。
- 人工修改 workerPaths 返回 `held_conflict`；人工修改同一任务卡、队列投影、coordinatorPaths 或 factPaths 返回 `stale_selection`。不自动解决冲突，不 stash、reset、checkout 覆盖、clean 或覆盖人工文件。
- 固定集成器先以 `git apply --check` 验证候选补丁，再应用 worker 修改；共享 coordinatorChanges 按“lane 基线、当前主分支、Worker 提议”机械三方合并，同一任务投影行或其他共享内容冲突时保留为 `held_conflict`，不覆盖前序已集成结果。随后运行任务卡后置条件、路径/空白/Git 检查，并通过现有 finalizer 创建每任务独立 canonical businessCommit。
- DeepSeek 任务的 businessCommit 使用 `State: pending_review`，随后只修改 `开发管理/AI合作沟通.txt` 创建 handoffCommit；handoff 不使用 Automation 元数据、不重复领域验证。Codex 任务使用 `State: completed`。
- 两个任务不压成批次大提交；正式通知只在对应任务 canonical 提交和投影核验后发送。

## 失败、恢复与安全清理

- workerTerminal 沿用 `completed`、`needs_decision`、`blocked`、`failed`；integrationState 使用 `pending`、`waiting`、`integrating`、`integrated`、`held_conflict`、`stale_selection`、`failed`。
- 控制器中断后，`Recover` 只接受同 batch/lane/task/worktree/branch/base/process/session/result 链：进程仍运行则继续等待；结果已完成则继续原序集成；证据不一致则保留现场并失败关闭，不猜测或重建提交。
- 已 integrated lane 不重复执行、提交或通知。未关闭 batch 处理完成前不领取新任务。
- 只有 integrated，或 confirmed clean 且没有候选/业务修改的 blocked/failed lane 才删除自动 worktree；needs_decision、held_conflict、stale_selection、completed 但集成失败或证据不完整的 lane 保留现场。
- batch 尚未写入 runtime、Worker 尚未启动时，初始化失败只在逐项确认自动 worktree 干净、分支仍位于 baseCommit 且路径属于固定短路径后清理，并记录失败、释放协调器 lease；任一证据不满足则保留现场与 lease，不猜测清理。
- batch 有保留证据时可以释放过期协调器进程，但 batch claim 保留在 `Show`，后续普通轮次不得选择新任务。
- 通知失败只记录脱敏投递状态，不改变提交、任务卡、batch、lane 终态或退出码，不自动重试。

## 固定入口与等待

- 新业务 batch 只调用 `tools/invoke-automation-lane-batch.ps1 -Action Start`；恢复只调用同脚本 `-Action Recover`。控制器不得临时拼装 Codex/Claude 命令、worktree 或集成步骤。
- Codex lane 由固定 wrapper 调用 `tools/codex-cli-session.ps1`，外部 lane 只由固定 wrapper 调用 Claude CLI；`owner=deepseek` 只接受已核验的 `http://127.0.0.1:15721` 同源端点。
- 外层工具调用使用 3300000 毫秒单轮上限；返回 `Script running with cell ID ...` 时继续等待同一 cell。yield、空输出或尚未返回都不是终态，不得重新启动或启动第二批。
- 每个 Worker 最长 3000 秒，协调器预留 300 秒完成终止证据、串行集成、runtime 和通知收尾。

## 提交元数据

canonical businessCommit 继续由 `tools/automation-finalize-commit.ps1 -RequireAutomationMetadata` 创建，使用：

- `Result: 问题=<原问题>；完成=<具体交付>`
- `Impact: 影响=<实际行为变化>；边界=<明确未涉及范围>`
- `Verify: 验证=<关键检查与结果>；后续=<解锁项、剩余依赖或下一状态>`
- `Plain: 发生=<负责人短句>；影响=<负责人短句>；需要=<负责人短句>`

九个子字段必须非空、单行并由实际任务与验证支持；三个通俗字段各不超过 200 个 Unicode code point。Worker 候选不得伪造该正式状态。
