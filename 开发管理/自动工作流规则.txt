# 自动工作流规则（✅ 已审核）

> 2026-07-11 Codex：按用户批准设计，将四条三小时写入工作流收束为一个每小时串行控制器。设计依据：`docs/superpowers/specs/2026-07-11-hourly-automation-controller-design.md`。

## 自动化拓扑

- `tzg-hourly-controller` 是唯一写入型 `TZG Hourly Controller`，每小时第 15 分钟触发；旧记录 `tzg-wf2-codex-execute-1` 已在替换记录创建、邮件规则和真实运行验证后删除。
- WF1、WF3、WF4 暂停但保留历史配置与 memory；不得与控制器同时启用。
- 每日简报只读，不修改项目、不 stage、不提交。

## 每轮顺序

1. 通过 Node REPL 确认实际模型身份；失败则只读退出。
2. 用 `tools/automation-controller-state.ps1` 获取三小时本机租约。
3. 检查恢复状态和完整 Git 工作区；来源不明脏改只读退出。
4. 单轮只选择一个分支：恢复中断任务 → 最高风险待复审 → 必要队列维护 → 一个 Codex 待处理任务 → 安静退出。
5. 选定真实工作对象后、读取实施细则前，从 Node REPL 本轮元数据取得并交叉校验 `currentThreadId`，再调用 `%USERPROFILE%\.codex\automation-tools\set-thread-name.mjs`：执行、维护或恢复任务命名为 `TZG｜<中文简述>`，复审命名为 `TZG｜复审：<中文简述>`。简述来自当前任务卡或复审事实源的面向人中文标题，不得只用 TQ/HANDOFF 编号；不得调用 `list_threads` 猜测当前任务，不得硬编码或复用历史任务 ID。无候选、锁占用、身份失败、人工脏工作区或 `currentThreadId` 校验失败时不改名。助手失败或五秒超时只记录 automation memory，不影响任务路由、验证、提交或失败关闭。
6. 按检查点续期；验证通过才提交；结束时释放租约。暂存前必须在同一 PowerShell 会话运行 `& tools/check-pending-whitespace.ps1 -ExpectedPaths '<以 | 分隔的 expectedPaths>' -Fix`，随后不带 `-Fix` 复检，再执行 `git add`；仅命中本轮 `expectedPaths` 内的文本行尾空白由 `-Fix` 直接清理并继续本轮，不得为此失败关闭或留待下一轮。任何非文本、路径外或复检仍失败的问题仍按失败关闭。暂存后必须运行 `git diff --cached --check`。前者覆盖未跟踪新文件，后者保留 Git 原生二次校验。

   若本轮 `expectedPaths` 包含 `.gitattributes`、`src/Assets/Art/` 或 `docs/资源管理/美术资源登记册.md`，在暂存前追加运行 `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-asset-versioning.ps1`；其他路径变更跳过该检查，且无论是否运行都保留本步骤的行尾空白、暂存差异与任务自身验证要求。

   Unity EditMode 通过 `tools/run-unity-editmode-tests.ps1` 运行时，脚本会在启动前快照全部已追踪的 `Assets/**` 与 `ProjectSettings/**` 文件，并在成功、失败或结果就绪后退出的所有路径精确恢复；这包含 Unity 重写的 `.asset.meta`，不得再把该类测试副作用当作控制器路径外脏改。自动工作流相关 PowerShell 验证统一使用 `pwsh -NoProfile -ExecutionPolicy Bypass -File ...`，不得再以 `powershell` 隐式落到 Windows PowerShell 5.1。

## 本机标题助手维护

- 标题助手通过 App Server 的 `thread/name/set` 工作，私有运行时固定为 `@openai/codex@0.144.3`；不得自动追随最新 CLI，也不得用 heartbeat 或固定任务 ID 代替。
- Codex Desktop 更新后出现协议错误或超时、官方接口契约变化，或固定版本存在相关兼容/安全修复时，才评估升级。候选版本必须先旁路安装，完成 5 项测试及真实金丝雀改名/恢复后才能替换当前运行时。
- 完整升级、回滚步骤和版本历史位于 `%USERPROFILE%\.codex\automation-tools\MAINTENANCE.md`。自动化提示只引用稳定助手路径；仅升级 CLI 时通常不需要更新自动化记录，除非助手路径、参数、标题约束或失败策略改变。
- 迁移或重装本机时，必须先恢复该用户级目录并通过金丝雀验证，再启用写入型控制器。

## 动态选题

- 禁止在自动化提示或本规则中硬编码具体 TQ、HANDOFF 或审核清单编号。
- 复审走 `审核入口.txt`；执行走纯 `1` 的 Codex 路由。
- 内容冻结、主责边界和 G1/G2/G3 依赖均为硬约束。
- 每轮最多处理一个复审对象、一次维护或一个最小任务切片。

## 待你决策

- 当多个方案会改变架构、运行时行为、数据语义、对外体验、任务范围、冻结边界或主责，且事实源不能唯一推出结论时，控制器必须创建待决策项；删除真实资产、保存数据迁移、外部发送及覆盖有歧义人工改动也必须请求决定。
- 待决策项不是失败关闭：控制器完成当前安全检查后释放租约，跳过该项及其依赖项，并继续选择其他主责匹配、依赖满足且不依赖该决定的候选。
- 每次仅保留一个未解决决策。它必须同时写入本机状态、`自动工作流状态.txt` 的“待你决策”区、自动化任务标题/消息，并尝试发送邮件；收件地址、回信地址和搜索条件只保存在本机私有配置。
- 回信查询必须先在全邮箱按允许发件人和同一 `decisionId` 搜索；自定义标签只能作为可选缩小条件，不能作为有效回复的硬条件，也不得因标签缺失排除候选。
- 自动路径只接受允许发件人对同一决策编号的严格回复 `DEC-…：选 A` 或 `DEC-…: 选择 A`。未知发件人、编号不符、多个选项或模糊回复均不得推进任务；负责人明确手动接管时，可由人工以 `ResolveDecision -ReplySource manual -ManualOverride` 记录选择后清除决策，不得伪造为邮件回复。
- 邮件发送或读取失败时保留待决策状态并受限重试；不得自动选择、失败关闭、AUTO-BLOCKED 或制造空提交。有效回复恢复原任务后才清除该项。

## 队列维护触发

仅在队列少于 5 条、含完成未归档项、依赖状态错误、主责不匹配、冻结内容入队，或距上次成功校验超过 12 小时时维护。无项目内容变化时只更新本机校验时间和 memory，不提交时间戳。

## 锁与恢复

- 运行状态位于 `%USERPROFILE%\.codex\automation-state\tzg-hourly-controller.json`，不得写入 Git 锁。
- 租约三小时，在 `task_selected`、`mutation_started`、`verification_completed`、`commit_completed` 等检查点续期。
- 首次中断不计恢复次数，随后最多恢复两次；第二次恢复仍失败转 `AUTO-BLOCKED`。
- 只有 Git 变更路径全部属于已记录 `expectedPaths` 时才能恢复；额外路径一律阻塞。
- `ResetBlocked` 只能由人工在处理原因后明确调用。

## 提交与失败关闭

- 只 stage 本轮相关文件，不覆盖、回退或提交人工改动，不自动推送远端。
- 身份未知、状态损坏、主责/依赖不明、恢复路径不符或验证证据无效时失败关闭。
- 无任务、有效锁和人工脏工作区只进入自动化 memory，不改项目状态、不制造提交。
- `开发管理/自动工作流状态.txt` 只在产生有效结果、队列路由变化或 `AUTO-BLOCKED` 时更新。
