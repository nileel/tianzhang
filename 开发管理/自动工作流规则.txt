# 自动工作流规则

本文件只定义每小时薄路由的稳定调度边界。业务实施、领域验证、审核与任务维护继续以各自入口为准。

## 单写入租约

- 候选汇总只读；任何项目写入前必须通过 `tools/hourly-automation-lease.ps1` 取得租约。
- 每轮只启动一个责任方。租约占用时不启动第二写入者；过期且存在 recovery 时只允许对应的决定触发或中断恢复路径。
- `Show` 返回的 `leaseStatus` 是租约有效性的唯一调度判断：只有 `active` 表示占用；`expired` 且无 recovery 时不得报告 occupied，继续候选判断并由 `Acquire` 替换过期租约。
- 调度器只读取状态、选择任务、取得租约、调用固定责任方入口并报告已核验结果；不实施、不验证、不 stage、不 commit、不复审。Codex 路由的结果记录与租约释放由固定调用器统一完成，责任方不得自行 `RecordResult` 或 `Release`。

## 候选资格与统一排序

- Codex 执行候选来自当前队列中待处理且主责属于 Codex 的任务；Codex 复审候选来自审核入口和有效交接；外部 AI 候选必须待处理、非复审且主责明确授权给外部执行范围。
- 候选必须满足依赖、负责人决策、内容冻结、主责、范围可判断和执行器可用等条件。外部 CLI 只在真实选中外部候选并取得租约后预检。
- 三类候选统一排序：项目 P 优先级、解除高优先级下游数量、等待时间、稳定 ID。候选类型没有固定优先顺序。
- 任务范围与人工 staged、unstaged 或 untracked 改动冲突时跳过；责任方修改前仍调用 workspace guard 作最终判断。不 stash、reset、checkout 或 clean 人工改动。

## 四种路由责任

- 普通执行按纯 `1`；复审按审核入口与纯 `2`；外部 AI 按其工作提示词；队列维护按状态与建议维护规则。四种责任方都自行读取事实源、修改、最小充分验证、更新状态并提交。
- 普通 Codex 执行、复审和队列维护不得使用 Desktop/VS Code rollout；取得租约后只调用 `tools/invoke-codex-responsibility.ps1`，由该固定入口向 `tools/codex-cli-session.ps1` 的 `Start/Resume` 写入标准输入。控制器不得临时拼装 ProcessStartInfo、编码或 here-string 启动逻辑；已在 Node REPL 核验的模型值通过固定入口传给 runner 与责任方。外部 AI 启动边界不变。
- runner 工具等待超时、yield 或尚未返回只表示外层仍未取得终态，不等于责任方失败。调度器只等待同一次调用或同一执行单元；runner 返回唯一终态摘要前不得记录失败、释放租约或启动第二写入者。
- 进度只投影 `selected`、`session_started`、`running`、`waiting_decision`、`completed`、`failed`；调度器和 runner 不从模型正文猜测阶段，不输出 prompt、原始 JSONL、回复或 child stderr。
- 所有由控制器启动的 Codex 执行、复审、队列维护和外部 AI `businessCommit` 都通过 `tools/automation-finalize-commit.ps1 -RequireAutomationMetadata` 创建路径限定提交。`CommitMessage` 只传单行标题，稳定任务 ID、状态、结果、影响和验证分别通过 `AutomationTask`、`AutomationState`、`AutomationResult`、`AutomationImpact`、`AutomationVerify` 传入；finalizer 固定生成 `Automation: tzg-hourly-controller` 正文。Codex 与队列维护传入 `AutomationState=completed` 并生成 `State: completed`，外部业务传入 `AutomationState=pending_review` 并生成 `State: pending_review`。没有已确认下游影响时写“无已确认的下游影响”，不得猜测。
- 外部 AI 创建两个连续本地提交：`businessCommit` 含业务修改、待复审状态和直接验证结果；随后只修改 `开发管理/AI合作沟通.txt` 创建 `handoffCommit`，登记真实业务 SHA、已验证、未验证和残留风险。第二次不重跑领域检查。
- `handoffCommit 不使用 Automation 标记`，也不启用 `RequireAutomationMetadata`；它只关联业务 SHA，日报不得将其重复统计为业务产出。
- 外层调度器不读取外部业务 diff、不重验、不 stage、不 commit；外部 AI 不自审、不扩大授权路径、不并行派发、不推送。

## 决策恢复与阻塞暂停

- 修改前等待决定时保存 `trigger=decision`、TaskId、owner、repository、DecisionId 和消费请求路径，释放租约并退出。schema 3 的 decision recovery 不保存 session ID，不保存未提交修改，也不把半成品交给下一责任方。
- 只有 `send-decision.mjs` 返回 `PROVIDER_ACCEPTED` 后，原发送请求路径已原子转换为消费请求；责任方必须把该同一路径作为 `DecisionRequestPath` 交给 `SaveRecovery`，其他发送结果不得保存 recovery。
- 旧 `pending-bindings.json` 不是新决策的互斥锁；责任方不得因看到旧 binding 就跳过发送或直接记录 `waiting_decision`。新 accepted send 会原子更新 binding，租约工具只接受对应的消费请求。
- 飞书桥收到 A/B/C 或自定义回复后只写入签名证据并确认，不取得租约、不启动模型、不 Resume、不轮询；已处理证据可按同一 DecisionId 幂等读取。
- 后续每小时控制器遇到 decision recovery 时直接调用 `consume-reply.mjs` 读取对应消费请求。无回复时不得 Acquire；有回复时以精确 DecisionId 调用 `Acquire -ResumeRecovery`，再由固定调用器使用 `-Action Start -Route Recovery` 启动新的责任方 session。不存在独立决定触发器，不得恢复等待决定的原 session。
- 已有未提交任务修改时停止普通调度，只允许中断恢复路径处理，不把半成品交给另一责任方。
- CLI 责任方异常退出且相对启动基线产生新改动时，固定调用器以原 session ID 和新增路径保存 `trigger=interruption` recovery；没有唯一 session ID 时保留租约和现场并转人工阻塞，不伪造恢复指针。下一轮只允许完全匹配的原任务通过 `Acquire -ResumeRecovery` 取得新租约并 Resume。
- interruption recovery 保留 session ID，只有该路径允许 Resume 原 session；decision recovery 不得包含 `resumeKind` 或 `resumeId`。
- 现有 task-owned Desktop recovery 只允许原任务人工完成；普通自动化收到 `RECOVERY_ONLY` 后停止，不转换、复制或迁移 rollout。
- 每轮在读取当前任务队列或任何候选事实源前，先调用租约工具 `Show`。pauseRequested=true 表示工具级逻辑暂停；立即输出 `suspended` 并结束，不读取队列、不扫描候选、不取得租约、不启动责任方，也不读取或更新自身自动化配置。
- 所有候选均阻塞时记录稳定 fingerprint；相同 fingerprint 连续两轮使 pauseRequested=true 后，先记录结果并释放租约，再报告“runtime 已逻辑暂停，界面尚未同步”并结束。逻辑暂停期间普通 `Acquire` 返回 `SUSPENDED`。成功、成功补任务或阻塞集合实质变化会重置计数。
- 自动化任务不得调用自动化管理能力管理自身，也不得等待自动化管理服务。界面 `PAUSED` 只由自动化任务之外的外部普通管理上下文同步。
- 逻辑暂停恢复只由外部普通管理上下文执行：确认 lease 与 recovery 均为空，先调用 `ClearBlocking` 成功清除逻辑暂停，再通过自动化管理能力把完整现有配置设为 `ACTIVE`。

## 队列补充顺序、私有状态与回滚

- 三类均无合法候选时才补队列；队列维护正式入口必须依次保留“提升满足条件的 backlog”和“没有可提升的完整卡时，从权威 backlog、状态与建议形成合法任务卡”两个分支。队列维护结束时，权威来源足够时至少包含 2 张合法可执行任务卡，单次最多新增 3 张；完成、阻塞、冻结、待决定、执行器不可用或与人工改动冲突的卡不计入深度。权威来源不足时不得制造任务，应补入全部能够安全形成的卡并在提交结果中记录不足原因；只有无法形成任何合法任务卡时才记录阻塞。本轮只提交队列维护，不执行新任务。
- schema 3 私有 runtime 只保存租约、条件化恢复指针、阻塞计数和最后结果；decision recovery 无 session 字段，interruption recovery 才有 session 字段。飞书状态继续保存于用户级私有目录并使用 ACL 与原子写入。不得保存 provider token、tenant key 或消息标识原文。
- 第一期不新增飞书 Tasks、task GUID 映射、进度数据库或阶段状态机；有限进度不增加长期 runtime 字段。
- 生产 prompt、schedule、workdir 和 status 只由外部普通管理上下文通过 Codex 自动化管理能力变更，不编辑 TOML。
- 失败时保持或恢复 `PAUSED`，保留提交、runtime 与日志；不自动 reset、revert、clean 或删除旧私有备份。只修复受影响切片并重跑直接检查。
