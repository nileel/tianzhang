# A-CHAR-FOURVIEW-TRIPO-WORKFLOW-01 · 通用角色立绘到 Tripo 静态模型固定工作流实施

## 来源与当前边界

- 唯一设计事实源是 `docs/superpowers/specs/2026-08-17-character-portrait-fourview-tripo-static-model-workflow-design.md`；两轮 DeepSeek V4 Pro 0813 只读审核意见已经收口到该规格，实施不得重新采用审核前语义。
- 本卡交付一个可复用的“已批准立绘 → 四视图 → 飞书批准 → Tripo 静态模型 → 飞书批准”闭环，正常人工卡点固定为两个。
- 工作流止于静态模型外观批准，不拥有平台绑定、动画、下载、Blender、Unity 或某个角色的后续资源生产。

## 必查范围

- 上述设计规格的完整正文，特别是批次、提示词追溯、飞书图片、一次付费账本、价格区间、免费重试、任务候选绑定和失败语义。
- `tools/feishu-decision-bridge/src/` 中现有卡片构建、发送意图、自定义回复、签名与幂等逻辑，以及对应直接测试。
- `开发管理/AI协作规则.txt` 的自动化控制面、视觉主责、写入隔离和独立复审边界。
- `assets/generated-character-art/README.md` 中角色立绘事实源、提示词与生成产物规则。

## 实施范围

- 为现有飞书决策桥增加受限图片上传与卡片图片组件，保留现有配对、签名、首次有效回复和旧卡失效语义；实现图片金丝雀、上传失败与投递失败分离、私有 `image_key` 生命周期。
- 实现批次、四视图 manifest、提示词版本、角度名称和两种固定自定义回复 `PRICE_RANGE=<min>-<max>`、`SELECT_TASK=<exact-platform-task-id>` 的确定性合同。
- 实现独立最小 Tripo 操作账本，覆盖一次付费原子 claim、任务 ID 哈希、显示价格与余额对账、两次共享免费重试计数，以及 `OUTCOME_UNKNOWN`／`ACCEPTED_ANOMALY` 失败关闭。
- 复用浏览器已有 Tripo 登录会话；实现只读预检与操作指令的冻结证据，不建立 Tripo API 充值路线，不保存 cookie、token、飞书收件目标或操作者原始标识。
- 建立确定性单元／协议测试和一次飞书图片金丝雀；实施记录写明实际路径、测试、尚未执行的付费动作和回退边界。

## 禁止项

- 不建立第二个飞书机器人、第二套决策桥、通用浏览器状态机、通用文件库或新的调度器。
- 不用重试层、超时吞噬、默认批准、固定 Tripo 价格或固定任务 ID 掩盖页面事实与账本不一致。
- 不在实现验证中发起付费 Tripo 生成；任何实际 credits 消费仍必须来自规格定义的负责人 A 回执。
- 不把 Codex 视觉判断改写成确定性脚本或 DeepSeek 结论，不把工作流扩展到下游 3D 资源接入。

## 验证

- 运行飞书决策桥现有全套 Node 测试，并覆盖图片上传／重投／过期、价格区间回复、候选任务改选和旧卡失效。
- 运行新账本与工作流核心测试，覆盖并发 claim、崩溃恢复、价格 TOCTOU、免费重试共享计数、非零重试扣费和新批次边界。
- 飞书图片金丝雀必须在当前负责人会话显示可放大的正确图片；失败时不得降级为纯文字视觉批准。
- 运行任务卡、审核文本、空白和 Git 暂存差异检查；若修改共享自动化入口，再运行其直接协议测试，不扩大到无关 Unity／BattleSim 回归。

## 完成条件

- 现有飞书控制面能够按批准规格承载两次视觉验收；批次、提示词、图片、价格、付费授权、免费重试和唯一模型候选均可审计并在异常时失败关闭。
- 实施记录、确定性测试和飞书图片金丝雀齐全；没有付费生成、凭证入库、第二套机器人或下游资源接入。

## 停止条件

- 需要改变现有飞书配对／签名所有权、保存第三方凭证、购买 Tripo API credits、降低视觉验收门、扩大到绑定／Blender／Unity，或发现预期路径不足以保持一个主智能体统一复核时停止；最后一种情况按 `task_requires_decomposition` 交回 Codex 一次性完整拆分，不叠加临时路径或兼容分支。
