# U-TZ-CHARTER-SLICE-01A · 会话交互桥与原子提交

## 来源与当前边界

- 唯一批准依据是 `docs/superpowers/specs/2026-08-04-tianzhang-charter-site-vertical-slice-task-decomposition-design.md`，尤其是“二、现状根因与采用方案”“四、所有权与运行时边界”“4.1”“五、玩家交互与数据流”“七、失败关闭与原子性”“8.2”和“九、验证矩阵”。
- 本卡只在 `D-TZ-CHARTER-SITE-01` 完成并通过独立复审后执行；只消费其唯一生产 `CharterSiteData` 和既有册界静态目录。
- `GameSession` 继续是唯一长期 `CharterRuntimeStateData` 所有者；父项 `U-TZ-CHARTER-SLICE-01` 仍不直接执行。

## 目标与非目标

- 目标：实现无场景依赖的 `CharterSiteInteractionRuntime`、短生命周期 `CharterSiteInteractionProgress`，以及从五类真实动作证明构造不可直接持久化 `CharterInvocationPreparation` 的唯一生产入口。
- 目标：为金丹、元婴和正式调用分别从同一 candidate 派生各自形态的 `InvocationRequest`，并由 `GameSession` 唯一原子提交有效 `NextState`。
- 非目标：不实现 Settlement UI、Adventure 环境表现、第二会话／存档／冲突所有者，不修改 schema 4、`CharterRuleRuntime` 或 `CharterConflictRules`。

## 根因与生产契约

- 根因是现有 `CharterRuleRuntime.Invoke` 要求调用前状态已含天章／界印识别、授权、连通节点、覆盖和已登记供给，而生产代码只在读档时替换长期状态；合法候选构造目前仅存在测试 `BuildValidState` helper。
- `CharterSiteInteractionRuntime` 是前置状态／candidate 生产者，只拥有本次打开站点后的临时证明；candidate 和 progress 都不是第二套长期状态，离开场景可丢弃，不能保存或直接赋给会话。
- `CharterInvocationPreparation` 固定 candidate、站点静态引用、临时 `CrossTierChallengeArchive` 和目录版本，不携带单一可变请求。三次评估必须各自新建请求：金丹请求带完整左右候选与 challenge，元婴请求只置 `YuanyingAnchored` 且不带候选／challenge，正式请求不带冲突介入。
- 首次正式成功只允许在 `NextState.TryValidate` 通过且目录版本一致时，把 `CharterRuntimeState` 与 `CharterDefinitionCatalogVersion` 从 0 原子替换；首次失败两者保持 null／0。已有长期状态必须继续使用当前状态，不能重新自举 registered candidate 绕过重复消费拒绝。

## 实施范围

- 实现严格有序的五类临时证明：通行、管理、节点接通、条目／天章／授权确认、三个既有现实供给准备；每步校验站点静态身份与实际动作结果，只推进对应 progress。
- 仅在五类证明全部成立后构造 candidate：`worldSealState`／`charterRelicState`／授权为 `recognized`，实际节点为 `connected`，实际供给为 `registered`；`registeredRuleEntryIds`、占用、提交结果和 `currentRegionRuleEntryIds` 在调用前必须为空。
- 从同一 preparation 独立构造并执行三次请求；金丹稳定返回 `charter_conflict_not_won`，元婴稳定返回 `TZ_CHARTER_CONFLICT_YUANYING_ANCHORED`，二者 `NextState` 与事件输出为空且不提交。
- 在 `GameSession` 建立唯一正式提交入口；正常调用只接受完整、可校验且目录版本一致的 `NextState`，首次成功原子写入长期状态与目录版本，重复调用继续消费现有长期状态。
- 新增直接 EditMode 用例，从空 `GameSession.CharterRuntimeState` 自举，不再用旧 `BuildValidState` helper 冒充生产入口；扩展 schema 4 保存／读取、首次失败、首次成功和重复消费断言，并记录实际验证。

## 禁止项

- 不修改 `CharterRuleRuntime.cs`、`CharterConflictRules.cs`、`SessionStateSnapshots.cs` 或保存 schema；不复制合法性、冲突排序、结算、静态目录或保存格式。
- 不让 preparation 携带或复用一个可变 `InvocationRequest`；不把 candidate、progress、临时 archive 或 UI 状态保存到 `GameSession`。
- 不实现 UI、场景、Adventure 投影、第二账本、默认 recognized／connected／registered、fixture fallback、全局角色 ID、完整 M7 或数值。

## 失败关闭要求

- 动作越序、目录缺失、未知／禁用／非当前据点站点、静态身份与动作结果不一致时返回稳定原因；失败只保留本次交互已完成的此前临时步骤，不写长期状态。
- 缺任一证明、candidate 不能通过现有静态／动态校验，或三种请求形态字段互相污染时不得构造／执行正式 preparation，不得用 helper、默认值或 UI 布尔补齐。
- 金丹未获胜、元婴受锚、首次正式失败均不得改变长期状态；首次失败目录版本保持 0。已有长期状态的重复失败保持原实例内容不变。
- 若必须修改 shared 规则、冲突语义或 schema 4 才能完成，立即停止并建立独立根因任务。
