# A-CHAR-BATTLE-VISUAL-USER-DECISION-02 · 战场角色视觉方向用户实机决定

## 来源与当前边界

- `-02` 表示第二轮方向决定，不表示存在同名 `-01` blocker。
- 本卡只在 playable compare 通过 Codex 技术复核且 cost evidence 完成后进入 ready。
- 用户是唯一视觉方向决策者；Codex 只提供入口、操作说明、成本证据和已知风险。

## 必查范围

- 批准规格 §二、§七、§八、§九。
- 完成的可玩比较操作说明、Codex 技术复核记录和同口径成本证据。
- 父项、旧比较归档和 `开发管理/任务列表/场景与Unity任务.txt` 中暂停生效的方向事实。

## 实施范围

- 向用户提供可运行入口和成本证据，要求用户实际运行后作出 A“2D”、B“静态 3D”或 C“两者均不接受”。
- owner run 建立合法 `automationCheckpoint` 并转 `waiting_reply`；没有用户回复时不推进。
- A／B 只记录用户选择、旧结论失效原因和新方向事实，并允许父项汇总关闭。
- C 记录“两者均不接受”后完成本卡；父项不得关闭，转批准规格规定的维护型 A／B／C 后继决定。

## 禁止项

- 不用自动评分、截图、录屏、Codex 观感或成本最低替用户选择。
- 不在用户实机前预填结论，不自动建立第三路线，不恢复旧 2D 胜出结论。
- 不修改角色资产、Unity、战斗规则或生产流程。

## 验证

- checkpoint 选项、用户回复证据、记录结果和父项／backlog 状态完全一致。
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-task-cards.ps1`。
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths AGENTS.md,CLAUDE.md,开发管理`。

## 完成条件

- A／B：用户决定记录与现行方向事实一致，父项可按唯一选择关闭。
- C：用户决定记录明确为两者均不接受，父项保持非完成并建立合法后继决定；不产生第三路线。

## 停止条件

- 可玩入口不能运行、技术条件未通过、成本证据缺失、用户未实机或回复含糊。
- 需要 Codex 解释为相近选项、替用户选方向或直接规划第三路线。
