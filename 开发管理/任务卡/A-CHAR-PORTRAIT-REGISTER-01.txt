# A-CHAR-PORTRAIT-REGISTER-01 · 现有立绘组件全身注册与资源重处理

## 来源与当前边界

Codex 交付一个可复核的“现有五组件全身注册包”：固定布局、每件资源的一次入库校准参数、五个校准 RGBA、两张零变换组合及确定性验证。此结果只证明现有资源能否复用；B 门书面验收仍由 A-CHAR-PORTRAIT-INTERFACE-01C 承担。2026-09-04 建卡轮次只准备任务与冻结输入，后续领取本卡的执行轮次负责资源重处理。

## 已确认问题与来源

- 旧 Codex run `c16f0095-65cf-4459-a063-1f6b661aad5d` 的会话为 `01a0676b-710d-7f92-aa5a-e9d059feb693`，冻结 base 为 `35e6eaacd4e9996f163543f9bf8985a0212c467c`。四次 B 门生成额度均已用完，未形成 candidate 或正式组件。
- 前发原生 Alpha 包围盒为 `[170,133,946,1404]`（含端点），右侧有 1657 个可见像素处于旧中央裁切范围外，其中 816 个完全不透明；完整 1024×1536 画布可保留它们。
- 2026-09-04 原尺寸复核发现更根本的注册失败：A 门头颈高度为 1169 像素，约占画布高度 76%；衣装按全身比例填满同一画布，领口接近顶部。原位叠加时，衣装覆盖标准头部 476773 / 574868 个不透明像素，眼、鼻、嘴三个样点均被衣装完全遮挡。前发也未与头骨充分贴合。
- 四张重建原生 RGBA 的 SHA-256 与旧运行逐一相等；输入包中的 validation 与原位组合图是失败基线，不是验收通过证据。不得把旧“安全区检查失败”当成唯一待修项。

## 授权与原子边界

- 负责人已批准使用完整 `1024×1536` 原生画布生产和组合；`887×1774` 只属于后续展示导出，不再通过预先裁掉左右各 128 像素来决定组件可用性。本任务不锁定未批准的最终 UI 导出布局。
- 负责人已批准先确定全身构图的头部大小、位置和领口，再重新处理现有资源。本任务允许每个具名组件在入库时使用一组固定的等比缩放和平移参数，并从原生 RGBA 一次预乘 Alpha 重采样生成最终校准图。它是对旧合同“入库也禁止变换”的本次明确修订。
- 同一具名组件只保留一套校准结果和参数，必须在两个头部组合中原样复用。校准后的组合阶段仍禁止任何平移、缩放、旋转、变形、重新采样、专用遮罩或局部覆盖。
- 只涉及已存在的标准清秀头、硬朗头、半束后发、半束前发、实用长袍。允许同步更新本任务 expectedPaths 中的当前合同、提示与 manifest，使它们指向校准后的统一坐标；保留 A 门原生头与历史证据不动，旧 887×1774 产物的历史批准不等于新注册通过。
## 禁止项

- 不调用图片模型，不消费 C1/C2，不做 Unity、CSV、3D 或其他角色工作；不顺带修改或解锁直接下游任务卡。任务内所有写入只在本 run 的 worktree 和 expectedPaths 内。

## 实施范围

1. 核对输入哈希和解码格式。先在全身画布上确定可用身体比例、头部框、颈口锚点及落脚位置，形成 layout.png；不能继续分别把头部、头发和身体自动撑满画布。
2. 在 registration.json 记录每个组件的来源哈希、共同坐标、固定缩放系数和平移量、头颈锚点、重采样方法与输出哈希。参数只描述资源入库，不包含按组合选择的分支。
3. 使用单个 `build_registered_components.py` 从原生源图重建五个 layers 图与两张组合；变换顺序固定，并从源数据一次重采样，禁止在前一版结果上反复缩放。
4. 按 `hair-back → base-head → outfit-body → hair-front` 原位组合清秀头与硬朗头，检查头身比例、露头皮、耳根、后颈、领口、手势和足部。同一发型和衣装必须复用相同文件及哈希。
5. 形成含五个单件、两张组合和关键接口近景的 contact-sheet.png；validation.json 明确客观检查、视觉检查、未证明事项和是否可交 B 门签收。
6. 仅在两张组合均成立时，同步当前设计、input-contract、prompts 与 manifest 的共同画布、来源、校准、后续生成注册参考和组合路径。新生成注册参考应使用校准后的标准头部全身画布；原生特写只保留为源数据。不得覆盖历史 A 门批准记录或将本次处理写为 B 门已批准。

## 验证

- 来源及恢复 RGBA 哈希与 automationInputs / A 门源图一致；五个校准图均为 1024×1536 RGBA，透明 RGB 为零，有效像素不因原中央裁切而丢失。
- 相同源图和 registration.json 连续构建两次，解码像素哈希一致；两张组合使用同一套发型／衣装文件，不带按组合变化的参数。
- 人工查看全图及发际线、太阳穴、耳根、后颈和领口近景：无脸部被衣装覆盖、明显头身比例错误、露头皮或颈口悬空。不能仅凭包围盒、点位或哈希宣布接口成立。
- 校准件从 sources/native 重建，导出裁切不参与组合；manifest/contract/prompt 的当前读路径一致，旧历史产物不混入当前矩阵。
- 按变更路径运行任务卡、审核文本、数据链、空白和 Git 差异检查。原本已通过且输入未变的全项目或历史 A 门检查不重复运行。
