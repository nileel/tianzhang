# D-CHAR-2D-BATTLE-ANIM-PIPELINE-01 · 2D战斗动画生产流程详细方案

## 来源与当前边界

- 2D reference 已完成；用户已于 2026-08-24 明确回复“两个方向都进入详细方案”，本卡授权门已满足。
- 用户指定《龙胤立志传》的实际战棋表现为 2D 方向可接受下限；其方格地形只作为迁移差异，不降低《天章》斜俯视六角战场的动作与反馈要求。
- 本卡制定流程，不生产苻渊动画或修改 Unity。

## 必查范围

- 批准规格 §二、§四.1、§五.2、§八。
- 完成后的 2D reference 调研全文，以及用户 2026-08-24 对《龙胤立志传》表现下限和两个方向进入详细方案的明确回复。
- 既有 2D 战术精灵合同、苻渊源图用途与 Unity 消费所有者，只读取与新战斗动画资产边界直接相关的部分。

## 实施范围

- 以《龙胤立志传》的实战完成度为可接受下限，冻结《天章》六角战场的画面质量、战斗可读性、动作／方向／状态内容边界及理由；不得只用静态截图或“能放入棋盘”代替动态验收。
- 冻结资产单位、源文件、导出物、Unity 消费形状和完整生产／修订／导入／验证流程。
- 定义换装、武器、批量角色、新增动作及人工时间、工具成本、返工和 QA 的计量方法。
- 冻结 2D pilot 与 Unity integration 卡的确切 expectedPaths、允许路径、验证、完成条件和停止条件。
- 写完并自审后建立 `automationCheckpoint` 转 `waiting_reply`：A 批准并解锁 pilot，B 仅修订方案后再次等待，C 冻结路线。

## 禁止项

- 不在调研或用户进入许可前启动，不把初步参考直接写成项目既定流程。
- 不生成图片、Sprite Sheet 或动画，不修改 Unity、正式单位、战斗规则或旧立绘用途。
- 不用猜测性自动化折扣批量成本，也不隐藏人工返工。

## 验证

- 规格自审覆盖占位符、内部一致性、范围、歧义和下游卡原子性。
- 下游两张卡的业务 expectedPaths、验证与停止条件已冻结到可执行程度。
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths docs,开发管理`。
- 状态变更和下游卡更新后运行 `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-task-cards.ps1`。

## 完成条件

- 用户在 checkpoint 选择 A；批准规格已落盘，下游卡合同完整，pilot blocker 被移除并按当时剩余条件决定是否 ready。
- B 只产生修订并再次等待，不完成；C 冻结本卡和下游路线。

## 停止条件

- 书面方案未获 A 批准或下游路径仍不完整；方案写完后必须按 checkpoint 停止等待，不得越过批准门启动 pilot。
- 方案必须修改战斗规则、剧情立绘职责、正式存档或建立第三条视觉路线。
