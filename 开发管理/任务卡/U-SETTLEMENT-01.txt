# U-SETTLEMENT-01 · 关中数据驱动据点与功能分发

## 来源与当前边界

- `U-CONTENT-CATALOG-01` 已完成 `guanzhong_city` 的 CSV、保持 GUID 的 `SettlementData`、`ContentCatalogData` 只读查询及其直接 EditMode 验证；本卡只消费这些已验证输入，不改动目录、CSV、asset 或导入器。
- 当前 `SettlementSceneController` 仍以 `PrototypeSettlements`、运行时动态 UI 和服务 placeholder 处理三座原型据点；这与关中正式链要求的稳定 ID 查找、功能分发及失败关闭不符。现有 `GameSession`、`SceneFlowManager`、World/Adventure 进入与返回上下文已经是唯一所有者，必须复用。
- 首批正式范围仅为 `guanzhong_city`、唯一启用功能 `bounty_board` 与唯一冒险入口 `guanzhong_wild`。`U-BOUNTY-01A`／`01B`／`01C` 尚未完成，本卡不得实现悬赏状态、奖励、存档或悬赏面板。

## 实施范围

- 仅将正式 `SettlementScene` 的关中读取从原型定义迁移为经序列化引用取得的 `ContentCatalogData.TryGetSettlement(GameSession.CurrentSettlementId)`；未知、缺失或不在首批生产范围的据点不得回退到默认据点，仍保留现有返回主世界出口并给出稳定失败状态。
- 将展示职责从控制器拆到独立据点视图，并用 `SceneBuilder` 生成／更新场景中的序列化组件和引用；不得手写 Unity YAML、创建第二 Canvas 或扩展现有运行时大控制器。
- 建立本地 `SettlementFeatureDispatcher`：只按 `featureId` 分发，首批仅登记 `bounty_board` 的窄入口；禁用、未知、缺注册处理器或处理失败时均不得进入 placeholder 成功流程，必须得到稳定原因。该入口不得领取、结算、保存或展示悬赏，后续由 `U-BOUNTY-01C` 接入面板。
- 保持 `guanzhong_wild` 经既有 `SceneFlowManager.EnterAdventure` 进入且胜负均返回 `Settlement(guanzhong_city)`；只更新直接 EditMode 回归和验证记录。

## 禁止项

- 不修改 `ContentCatalogData`、CSV、导入器、`SettlementData` asset、Language 键、城市内容、怪物、物品、掉落、奖励、经济或任何数值。
- 不实现完整悬赏状态机、奖励授予、背包、存档迁移、悬赏面板、随机悬赏池、每日刷新、通用条件表达式、其他城市或服务。
- 不新增服务器、数据库、联网接口、第二场景／会话／存档所有者、默认城市回退、名称映射、兼容路径或 `ExplorationScene` 入口。

## 验证

- 直接 EditMode 覆盖：关中按稳定 ID 读取并显示；`bounty_board` 只到已注册窄入口；禁用、未知和未注册功能的稳定失败原因；未知城市不回退且仍可返回主世界；`guanzhong_wild` 的进入与返回上下文不变；场景序列化引用由 `SceneBuilder` 生成并可通过批处理只读验证。

## 完成条件

- 关中据点仅以稳定 ID 从已验证目录消费正式数据，功能点击不再走原型字符串或 placeholder；失败关闭不误导为可用功能，且 World/Adventure 的唯一进入与返回链保持不变。
- `U-ITEM-GRANT-01`、`U-ENEMY-01` 与 `U-BOUNTY-01A` 的现有阻塞投影不被提前解除；本卡完成后再按真实依赖维护队列。

## 停止条件

- 若目录／关中 asset／场景序列化引用无法提供所需稳定 ID，或 `bounty_board` 的最小入口必须抢先实现悬赏规则、奖励、存档或面板，停止并将本卡转为 `blocked` 或 `pending_decision`；不得补充默认值、兼容回退或第二所有者。
