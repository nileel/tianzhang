# U-ARCH-REBUILD-01E2 · 正式调用链原子切换

## 来源与当前边界

- 对应阶段 5 的生产切换切片；批准边界读取任务重划设计当前修订 §3.3。只有 01E1A 归档并证明纯内核已覆盖全部生产命令入口后才可解阻塞。

## 必查范围

- 01E1 与 01E1A 完成归档及新内核完整公开契约；`Character`、`ExplorationController`、`BattleUIManager`、`AdventureSceneController`、`FormalEncounterResult`、`EnemyAI`、`SpellData`、`TianZhang.Gameplay.asmdef` 的完整相关逻辑；所有 `TacticalCombatController`、`CTBEngine`、`CTBUnit`、`CombatResolver.ActionResult` 和 `TacticalCombatEndOutcome` 直接引用及对应测试。

## 实施范围

- `Character` 移除 CTB 运行时所有权；Adventure 只投影参战快照并消费战斗结果；Exploration、Battle UI 与正式结果链改用新会话、命令和结果契约。
- 在 GameplayContracts 新建实现无关的 `ICombatCommandHandler`，固定提供基础攻击、术法、神通、防御、等待、移动与换法七个入口；参数只使用稳定 ID、槽位／档案 ID 与坐标整数等稳定原语，不暴露 Combat、Spatial、Character、GameObject 或场景类型。Gameplay 组合层把请求转换为 01E1A 已验证命令，`TianZhang.Gameplay` 显式引用 GameplayContracts。
- `EnemyAI` 只消费合法行动集合；按钮和日志只经 GameplayContracts／现有调用方输出，不进入 Combat。全部生产调用方和直接 EditMode／PlayMode 测试在同一提交中切换。

## 禁止项

- 不保留新旧生产双写、shadow compare、运行时选择开关、旧控制器 adapter 或 fallback；不提前删除尚用于编译的旧类型，不进入 GameRuntime、Feature 重写或场景壳职责。
- 不修改 `CombatCommand`、`CombatSession`、`CombatActionResolver`、`CombatCommandService`、`CombatActionResult`、`CombatantSnapshot`、`CombatAttackProfile`、`CombatantRegistry`、`CombatTurnScheduler`、`CombatResultBuilder`、`CombatLegalActionService` 或 `Combat/Turns`；GameplayContracts 不引用 Game、Feature、Combat、Spatial 或场景实现，Combat 也不引用 GameplayContracts。

## 验证

- 运行受影响的 EditMode、`GuanzhongBasicAttackPlayModeTests` 或实时冻结的等价 PlayMode、`AssemblyBoundaryEditorTests`、`tools/check-unity-assembly-boundaries.ps1`、生产旧入口引用扫描、审核文本、pending whitespace 与 staged diff 检查。
- 证明正式路径只调用新 Combat 内核且固定战斗结果未变；缺失被忽略的 `.csproj` 只记录，不替代 Unity 编译和测试。

## 完成条件

- 新 Combat 内核成为唯一生产可达战术运行时；Character、Adventure、Exploration、Battle UI 与 EnemyAI 均不再调用旧 Controller、Core CTB 或 Character CTB 状态；所有直接测试改用新入口。

## 停止条件

- 必须双运行或增加兼容 adapter、生产切换仍需补任一纯 Combat 内核能力、需要提前改 GameRuntime／Feature／场景壳、出现新增 Unity 回归失败，或固定数值语义发生变化时停止并返回 01E1A，不在本卡叠补。
