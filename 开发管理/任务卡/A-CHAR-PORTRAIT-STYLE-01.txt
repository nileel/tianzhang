# A-CHAR-PORTRAIT-STYLE-01 · 默认男主四母图模块化 UI 立绘八组合样张

## 来源与当前边界

- 事实源为批准的四母图设计、`input-contract.json` v2、批准默认男主透明母版及其 manifest、项目立绘 README。
- 本卡只生产默认男主两脸型、两发型、两服装的模块化 UI 立绘样张；不包含 3D Toon、Unity、存档或运行时接入。
- 旧“九次独立组件生成”提示与 checkpoint 已被四母图设计替代，不得恢复、吸收或重放。

## 必查范围

- `docs/superpowers/specs/2026-09-02-formal-player-modular-portrait-four-master-design.md`。
- `assets/generated-character-art/player-modular-portrait-style-v1/input-contract.json` 与 `prompts.md`。
- 批准母版、母版 manifest、项目立绘 README，以及 ComfyUI 实际节点／工作流能力。

## 实施范围

1. 以批准母版 `source_f01_h01_o01` 为唯一身份、姿势和注册基准，先形成三个冻结编辑遮罩和可复核的 ComfyUI 工作流；这一步不调用图像模型。
2. 形成干净 checkpoint，向负责人展示三个完整提示、遮罩、工作流能力证据和调用预算；只有新决定明确批准后，才使用 GPT Image 2 各执行一次具名遮罩单变量编辑：只换脸、只换发型、只换服装。
3. 遮罩外正式像素始终取批准母版；模型输出只在对应遮罩内成为来源像素。
4. 建立一个可保存、可复核的 ComfyUI 工作流，只负责分割、图层蒙版、透明化、四来源重组、八组合、裁切和哈希，不用本地 FLUX 重画批准可见像素。
5. 从四张完整母图提取九个稳定组件，先重组四张来源，再按固定层序组合八个全身、八个半身和八个头像，并提交 manifest 与联系表供书面评审。

## 图层所有权

- `base-face` 只拥有脸、头、耳、颈和联合包络下安全重叠；身体其余区域透明，不生成被服装遮住的完整裸模。
- `outfit` 拥有完整着装身体轮廓、衣领、袖子、腰带、袍身和靴子，但不拥有裸露手、脸、头颈或头发。
- `hands-front` 固定拥有两只裸露手及腕口安全重叠。
- 同一发型的 `hair-front`／`hair-back` 按遮挡顺序划分，并在两套服装联合包络下保留安全重叠。

## 禁止项

- 不纯文本重新生成人物，不自动重试，不使用随机替代或第二身份母版。
- 不用本地 FLUX 或其他扩散节点重画正式可见人物像素。
- 不生成组合专用层、逐图补丁、覆盖图或运行时纠偏。
- 不修改 Unity、CSV、存档、3D 资产或运行时所有权。

## 验证

- 三张单变量母图的规范化遮罩外像素相对批准母版零漂移；画布、中心轴、姿势、双手、手腕和落脚点不变。
- 四张来源重组全部通过后才允许组合八矩阵；来源重组检查洞、双边、绿边、错层和结构丢失。
- 八组合检查脸与发际线、耳根、后颈、领口、肩、袖口、手腕、腰线、衣摆、鞋底和前后发遮挡。
- 全身、半身和头像只从同一 composite 固定裁切；重复运行产生相同解码像素哈希。
- 运行任务卡、审核文本、数据链、空白和 Git 差异检查。

## 完成条件

- 一个批准基准母版、三个单变量完整编辑源、三个编辑遮罩、九个稳定组件、九个图层蒙版、一个 ComfyUI 工作流、四张来源重组、八组合及其固定裁切全部齐全可追溯。
- 八组合获得 UI 立绘风格与模块兼容性书面批准；所有输出、遮罩、参数、节点版本和哈希记录在 manifest。

## 停止条件

- 单变量编辑无法保持遮罩外批准身份、姿势或结构时停止。
- 来源重组未通过，或必须重画批准可见像素才能分层时停止。
- 任何组件只能用于某一组合，或需要偏移、缩放、旋转、组合补丁、不同身份母版时停止。
- 隐藏区域缺失只记录精确遮罩；未经负责人另行批准不得补全。补全会改变批准可见像素时停止。
- 需要修改 Unity、存档、3D 或运行时所有权时停止并重新判断原子性。
