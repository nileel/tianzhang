# N-FPD-MANSION-01 · 五府府体预算

## 来源与当前边界

- `C-FPD-MANSION-01` 已完成并归档；命、魂、识、悟、运五项府体机制、触发、条件、目标、效果类型和参数名均已确认。
- 2026-07-25 负责人要求纠正本卡仍显示依赖已完成前置的陈旧状态；本卡只锁定数值预算，不改写五项机制。

## 必查范围

- 完整读取 `docs/superpowers/specs/2026-07-21-five-mansion-body-effects-design.md`。
- `docs/superpowers/specs/2026-07-20-foundation-purple-mansion-danxiang-integration-design.md` 中五府、府体、镇府神通、结丹输入和数值任务边界。
- `docs/基础设定/境界特性.txt` 中筑基、紫府与金丹直接规则。
- `simulations/BattleSim/Program.cs` 中现有角色构建、成长输入、批量运行与结果输出逻辑。

## 实施范围

- 为五项府体效果分别锁定参数区间、共同预算、差异预算、目标指标和上限。
- 建立单府、三府、五府代表 Build 与五类极端样例，验证 1～5 府组合的边际收益。
- 保证第四、第五府具备实际收益，软亲和不影响最终强度，且府数不自动生成槽位、位格、丹相或效果槽。
- 在 `开发管理/五府府体预算数值验证记录.txt` 保存可复现输入、输出、结论和残留风险。

## 禁止项

- 不修改五项府体的触发、条件、目标或效果类型，不新增府体、镇府神通、递归效果包或第二套预算系统。
- 不按府数自动增加术法槽、神通槽、金丹实位、丹相或效果槽。
- 不提前实施 N-FPD-DANXIANG-01 的主承载／辅助输入预算，不修改无关伤害表。

## 验证

- 运行 `dotnet build -c Release --no-restore simulations/BattleSim`。
- 运行 `dotnet run --no-build -c Release --project simulations/BattleSim`。
- 核对单府、三府、五府代表 Build 和五类极端样例均有可复现结果。
- 运行 `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths 开发管理,docs,simulations` 与 `git diff --check`。

## 完成条件

- 每类府体都有明确参数区间、共同／差异预算、目标指标、上限和回归样例。
- 1～5 府边际收益可复现，第四、第五府有效但不产生数量越权。
- 完成后归档本卡，并解除 N-FPD-DANXIANG-01 与 N-SLOT-01 对本卡的依赖投影。

## 停止条件

- 既有机制无法在统一平铺效果绑定中表达，必须新增递归效果系统，或结论需要修改战斗规则而非府体成长输入时停止并转为 `pending_decision`。
