# D-CHAR-STATIC3D-MOTION-PIPELINE-01 · 静态3D战斗动态表现详细方案

## 来源与当前边界

- 静态 3D reference 已完成；用户已于 2026-08-24 明确回复“两个方向都进入详细方案”，本卡授权门已满足。
- 用户指定参考炉石传说、游戏王与万智牌等数字卡牌／棋子载体：角色载体内部不播放模型动画，战斗反馈主要由整个载体的位移、旋转、缩放、材质、特效、音效与必要镜头反馈承担。
- 本卡据此聚焦单一静态 3D 角色载体，不采用多套独立 Pose 换模，不消费 credits，不制作模型或修改 Unity。

## 必查范围

- 批准规格 §二、§四.1、§五.4、§八。
- 完成后的静态 3D reference 调研全文，以及用户 2026-08-24 对炉石传说／游戏王／万智牌式整体载体动效和两个方向进入详细方案的明确回复。
- 既有静态棋子生产合同、Blender 候选记录、Unity 所有者链和 material correction 事实，只读取与新动态表现边界直接相关的部分。

## 跨对话必须纳入的复核输入（2026-08-24）

- “载体”必须转译为把苻渊完整静态 3D 模型当作惰性棋子／微缩模型；不得字面换成卡牌，也不得恢复多 Pose 换模、模型内部动画、蒙皮或统一骨架路线。
- 炉石传说、游戏王与万智牌只作为 E3 级产品画面语法参考，用于观察静态载体怎样以整体运动、特效、音效和界面反馈形成战斗可读性；它们不补齐生产管线证据，也不证明《天章》的实现方式、资产结构、工时或成本。
- P1 既有苻渊样例只证明六向表现根节点、抬起—移动—落下和规则隔离属于已运行的机制家族；不能据此宣称攻击／受击／死亡质量、宽袖／武器、批量角色、换装、维护或成本已经通过。
- 验收必须覆盖全部六向，特别是背向镜头的两个方向；必须提供稳定可见的接地线索，但阴影、底座、接触光或落点反馈由方案论证，不预设唯一实现。固定斜俯视下的身份、宽袖／武器、腿部与接地线遮挡须按角色×方向检查。
- 攻击、受击和死亡列为 pilot 首批高风险语义，逐项冻结整体运动、顿帧／事件时点、材质／特效／音效分工、复位和失败淘汰条件；真实制作、返工和批量成本只读取本项目 pilot 记录。
- 3D 的运行时机制风险可以因复用 P1 家族而降低，但不得外推为整体视觉路线、生产规模或成本已低风险；最终比较仍须与 2D 使用同身份、服饰主色、尺度、镜头和事件时点。

## 实施范围

- 在用户选定的“单一静态载体整体动效＋特效”边界内冻结动态表现机制；逐项定义方向、移动、攻击、受击、施法和死亡的载体运动、事件时点、特效／音效分工、复位、最小验证和淘汰条件。
- 冻结模型／Pose／动画／材质／特效资产单位、身份一致性和生产／Blender／导出／Unity 流程。
- 定义方向、宽袖、武器、换装、批量角色、新增动作，以及工时、credits、失败生成、返工和 QA 的计量方法。
- 冻结静态 3D pilot 与 Unity integration 卡的确切 expectedPaths、允许路径、验证、完成条件和停止条件。
- 写完并自审后建立 `automationCheckpoint` 转 `waiting_reply`：A 批准并解锁 pilot，B 仅修订方案后再次等待，C 冻结路线。

## 禁止项

- 不把相邻参考冒充成熟 Pose 换模先例，不恢复旧换头、蒙皮或统一骨架路线。
- 不生成、下载、编辑模型，不启动 Blender／Unity，不消费未单独授权 credits。
- 不用未验证平台成功率折扣成本或隐藏失败生成。

## 验证

- 规格自审覆盖占位符、内部一致性、范围、歧义、自研风险、上述跨对话复核输入和下游卡原子性。
- 方案逐项回指载体转译、E3 证据边界、P1 已证／未证边界、六向／接地／遮挡合同、高风险语义顺序和同条件比较合同。
- 下游两张卡的业务 expectedPaths、验证与停止条件已冻结到可执行程度。
- `pwsh -NoProfile -ExecutionPolicy Bypass -File tools/check-review-text.ps1 -Paths docs,开发管理`。

## 完成条件

- 用户在 checkpoint 选择 A；批准规格已落盘，下游卡合同完整，pilot 只在 material correction 也完成时解除全部 blocker。
- B 只产生修订并再次等待，不完成；C 冻结本卡和下游路线。

- 方案需要未授权 credits、修改战斗规则／存档、恢复冻结旧链或建立第三条视觉路线。
