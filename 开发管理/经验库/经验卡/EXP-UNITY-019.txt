# EXP-UNITY-019 · 战斗前置功能验收须隔离受控夹具与自然流程

## 状态

active；最后核验日期：2026-10-13；事实源：`U-GZ-R2-BOUNTY-01` 的候选、验证记录及定向 PlayMode 复测。

## 开工前

仅在 Unity PlayMode 需经正式战斗结算到达 UI 状态，且使用 `ICombatResolutionRandomSource` 或受控战斗前置时适用。先核对命中阈值、闪避、攻击容量和结算链；自然流程、非战斗 UI 或不改变战果的测试排除。不得把单个随机样本当作必定未命中；战斗规则或随机入口替换时重新核验。

## 正确处理

将功能验收与角色平衡分开：保留正式命令、攻击、战斗完成和回城／结算链；若需要确定性前置，只以明确、受控的临时战斗状态缩短流程，并说明它不主张自然角色战力。固定随机源前，按实际正式规则计算各次样本的结果；验收断言应验证目标 UI 状态而不是夹具本身。

## 根因与弯路

悬赏按钮验收把随机值 99 误作必定未命中，但基础命中为 100%、玩家闪避为 0，因此该样本仍命中；提高攻击输入也无法绕过凡人徒手攻击容量 30。测试在进入领奖状态前重复战败。经负责人确认，将临时敌人生命从 657 降至 1，并保留正式攻击和结算链后，完整按钮验收通过。

## 证据

`CAND-U-GZ-R2-BOUNTY-01-01`；`开发管理/任务归档/U-GZ-R2-BOUNTY-01.txt` 的 2026-10-12 完成证据；`bounty-acceptance.xml`、`bounty-repair-final.xml`。前者记录 36 次攻击后玩家 0／敌 117 与 Defeat；后者记录正式击杀、回城、悬赏结算和双分辨率按钮验收通过。

## 失效条件

战斗不再是该 UI 状态的前置、测试不再使用受控战斗或随机源、命中／闪避／攻击容量／结算入口替换，或受控夹具不再能保留正式结算链时，停止引用并重新核验。
