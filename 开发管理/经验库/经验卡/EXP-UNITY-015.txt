# EXP-UNITY-015 · 战斗动作条费用文字须量化双分辨率边界

## 状态

active；最后核验日期：2026-10-11；事实源：`U-COMBAT-AP-HUD-01-C01`、`U-COMBAT-AP-HUD-01` 正式动作条费用诊断及双分辨率图形 PlayMode 验收。

## 开工前

改动 `CombatActionBarView.PresentAction`／`PresentArt` 固定按钮的 AP、MP、冷却或本地化费用文字，且涉及 `fontSize`、`ActionPointCostUnits`、`PresentAction` 或 `PresentArt` 时，先核对正式写入者和 Label Rect；在 1920×1080、1366×768 测量最长文案的 `preferredWidth`、`preferredHeight` 和换行，再验收 Game View。尺寸不足只缩短该按钮费用文案或由直接所有者局部调字号后复验；不得仅凭大分辨率通过。

不涉及固定尺寸动作条按钮的文字、自动布局或 TMP 文字、没有新增或变更费用／冷却／本地化文案的任务排除。按钮尺寸、直接 Label、字体生成方式、Canvas 缩放或正式验证入口被替换时，停止引用并重新核验。

## 正确处理

从 `CombatActionBarView` 的正式刷新路径取最长实际字符串，并在目标分辨率直接测量文字区域与字体偏好尺寸。保留既有 Canvas、布局和字体资源，在局部所有者内选择能容纳的短文案或字号；随后以两种 Game View 分辨率确认文本既未换成超高多行，也没有被裁断，且动作条费用仍与权威报价一致。

## 根因与弯路

防御 Label 的固定 Rect 为 82×36，20 号“防御 · 50 AP”在 1920×1080／1366×768 的偏好宽度为 111／112.445、偏好高度为 58／56.223，因而被裁断。聚灵术费用行在 1366×768 的宽度为 186.94，超过 184；换行后三行高度为 84.334，超过 60。问题不是坐标转换：同一 Canvas 在两种分辨率下输出。只检查 1920×1080 未能发现较小 CanvasScaler 缩放下的额外换行。

## 证据

`U-COMBAT-AP-HUD-01` 的 `ap-hud-geometry.xml`、`ap-hud-final.xml` 与四张已查看的正式截图记录：防御费用缩为“防御50AP”并局部改为 18 号后，1366×768 的偏好宽／高为 77.306／23.895；聚灵术费用缩为“25AP / 0MP · CD5”后为 170.073／56.223。最终图形 PlayMode 6/6 通过，两个分辨率均显示真实费用、剩余 AP 和条件时间轴。

## 失效条件

`CombatActionBarView.PresentAction`、`PresentArt`、动作条按钮的直接 Label、字体生成方式、Canvas 缩放、正式 Adventure 场景入口或图形 Game View 验收入口被替换，或动作条改为自动布局、TMP 或其他渲染链时，停止引用并重新核验。
