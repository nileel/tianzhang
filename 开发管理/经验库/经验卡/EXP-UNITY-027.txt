# EXP-UNITY-027 · 图形 PlayMode 的 Game View 取证须先显式打开并固定视口

## 状态

active；最后核验日期：2026-10-17；事实源：`U-JD-COMBO-FIRE-DOMAIN-01.GAMEVIEW`、`U-JD-COMBO-FIRE-DOMAIN-01` 的图形 PlayMode 12/12、四张最终 Game View 图和 `docs/superpowers/specs/2026-10-14-jindan-fire-domain-implementation-evidence.md` 的取图实录。

## 开工前

适用：隔离 Unity 场景的图形 PlayMode 需要保存真实 Game View，且 Canvas 文字或布局须由该画面证明。先显式打开 Editor Game View，选择并固定目标视口，再创建场景、Canvas 或动态文字；记录实际 Game View 尺寸以及 Screen、Canvas 和画面尺寸。批处理规则测试、`Screen.SetResolution`、运行时 Screen 值或目标尺寸标签都不能证明 Editor 视口已打开或已处于目标尺寸。没有真实 Game View／Canvas 取证、只验相机世界层、只做无图形功能验证，或现有场景不会在创建后改变视口的任务排除；Game View 后端、测试 runner、Canvas 创建时机或截图入口变化时停止引用并重新核验。

## 正确处理

在有图形设备的隔离 runner 中，先打开 Game View 并用既有视口配置选中目标尺寸，确认实际视口；随后载入场景并创建 UI，最后取图和读取布局边界。不要依赖 `Screen.SetResolution` 控制 Editor Game View，也不要逐图切换已建 Canvas 的视口；后者会让旧文字网格按新视口缩放而模糊。取证结束后卸载场景，并用既有快照恢复 Game View 尺寸、临时尺寸条目和焦点，再确认工作树只留下预期差异。

## 根因与弯路

批处理运行虽通过了 11 项规则测试，却没有自动打开 Game View，因而不能保存画面。实际 Editor 中 `Screen.SetResolution` 只改变运行时 Screen，不改变 321×531 的 Game View；在这个小视口创建 UI 后才切到 1920×1080，会使旧文字网格与实际渲染上下文不一致并出现模糊。显式打开视口并在场景／UI 创建前固定 1920×1080 后，四张画面均可读。

## 证据

`docs/superpowers/specs/2026-10-14-jindan-fire-domain-implementation-evidence.md` 的“取图与报告问题实录”记录了失败的批处理取图、321×531 的实际 Game View、Canvas scale 0.1671875 及修正后的顺序；同文档记录 opening、expansion、gap、ending 四张 1920×1080 PNG、实际视口／布局值和临时尺寸条目恢复。来源任务的图形 PlayMode 12/12 通过，四张最终图均经目视复看。

## 失效条件

Unity Editor 的 Game View 打开或尺寸选择机制、图形 PlayMode runner、隔离场景／Canvas 的创建顺序、截图方式或视口恢复入口被替换时，停止引用并重新核验。
