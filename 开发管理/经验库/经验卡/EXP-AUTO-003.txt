# EXP-AUTO-003 · 决策检查点重放须隔离任务卡冲突

## 状态

active；最后核验日期：2026-10-16；事实源：`U-GZ-R2-AOE-INPUT-01-CP-TASK-CONFLICT` 的失败 run、检查点与人工 worktree 路径比对。

## 开工前

适用：自动化实施或验证任务的任务卡包含 `checkpoint`，且批准选项或恢复流程已改写同一任务卡正文、待重放的旧 checkpoint 也包含该卡改动。先比较旧 checkpoint 与当前任务卡的差异，再独立核对业务路径；任务卡冲突不能被当作业务冲突，也不能以重放成功代替业务路径核验。普通业务 checkpoint、未改写同一卡正文的恢复和无任务卡改动的重放排除。若业务路径也冲突、任务卡之外出现额外冲突，或无法证明批准文本与业务差异各自来源，停止并按既有处置合同处理。

## 正确处理

保留批准选项或恢复流程产生的当前任务卡文本；只在逐路径确认业务差异与 checkpoint 一致后恢复业务改动。完成后分别记录任务卡冲突原因和业务路径核验结果，不把任一方的结论外推到另一方。

## 根因与弯路

旧 checkpoint 在任务正文末尾追加验证记录，而 ResumeReady 已按批准选项改写同一正文；完整重放旧任务卡补丁时发生上下文冲突。该 run 的12个业务文件没有冲突，人工 worktree 中它们与 checkpoint 一致。

## 证据

来源候选 `U-GZ-R2-AOE-INPUT-01-CP-TASK-CONFLICT`；checkpoint `254238d072cbfc1c69c8db61eee6799f7ed3907c`；失败 run `c4f95bd2-e8e6-40fd-9cb2-68d798671158`；来源归档中的候选字段与直接证据。

## 失效条件

检查点不再同时携带业务变更和任务记录，或恢复流程能按批准文本对任务卡完成可证明的语义合并时，停止引用并重新核验。
