## 三阶段推进路线

### 阶段一：战棋原型验证 ✅ 已完成（v0.3，2026-06-14）

> 成果：CTB充能引擎 + 六角格战棋 + A*寻路 + 朝向系统 + 简易AI + 完整行动循环 + 太一道庭数据接入

### 阶段二：最小可玩循环 ✅ 已完成（v0.4–v0.5，2026-06-14）

> 成果：修炼引擎 + 功法成长 + 地图探索 + 敌人生成 + 术法槽位UI + 掉落提示 + 探索→战斗循环

### 阶段三：规模化填充与正式开发前校准 ← 当前阶段

**目标**：在不破坏已跑通战棋原型的前提下，把规则口径、场景架构、数据字段和数值闸门校准到可以长期开发的状态。

**分线推进**：

#### 3.1 多门派数据接入 ✅ 已完成

- 玉清崖、混元山、太虚观数据已进入 CSV/asset 链路。
- docs/CSV/Unity asset 数量检查当前为 Missing 0、ExtraOrLegacy 0。
- 仍需注意：数据导入完成不等于所有功法机制在 Unity 已完成手感验证。

#### 3.2 稳定化校准与境界体系迁移 ✅ 主体完成，金丹压制口径已确认

- TQ-011/TQ-012/TQ-013/TQ-013A-D/TQ-008 已闭环或归档。
- BattleSim 已收束为凡人、练气、筑基五段、金丹三段，并接入源/化/界席位、成丹状态、席位竞争、紫府输入占位、筑基矩阵、金丹压制战出口、削位/封丹开关与削位强度扫描。
- 当前验证结论：紫府圆满正面对抗金丹初期为 0.0% 胜率；削位15/30/45 + 封丹强扫也仍为 `全档0.0%`。用户已确认该结果符合“金丹对筑基/紫府应形成强度碾压”的设计预期。
- 后续若继续拆破府输入或战术触发概率，只服务战略削弱、剧情条件、席位/府位争夺或高阶反制展示，不再作为正式开发前 P0 数值闸门。

#### 3.2.7 场景架构与 2.5D 战棋表现 ⚠️ 待复审与实机验证

- TQ-014 实施计划已审核通过并归档。
- DeepSeek 已提交会话流转骨架、四场景脚手架、World/Settlement 数据壳等低风险切片；这些提交只能视为“已修改/待 Codex 复审”，不能视为架构完成。
- 正式进入完整开发前，需要在 Unity Editor 中验证 StartMenu/World/Settlement/Adventure 场景生成、加载、返回、UICanvas/GameSession 单例和输入系统表现。

#### 3.3 完整游戏循环（正式开发阶段，尚未开始）

- 主世界节点、宗门/城市、冒险副本、探索/战斗返回链路正式化。
- 背包、掉落、商店、交易和经济循环。
- PvE 2v2/多单位群战 Unity 端。
- 古修/散修内容补全。
- 多门派 AI + Boss 战。

**进入条件**：场景架构复审通过并可在 Editor 端跑通；CSV/asset 技能属性字段不再混用；当前未审核/未通过任务不再污染核心事实源。

## 核心原则

1. **一门派深耕 → 多门派扩展**：太一道庭已跑通全流程，以此为模板扩展到其他门派
2. **机制按需求优先级同步**：先同步对玩法影响最大的机制（守一/符胆），群战/水修后置
3. **手感验证贯穿始终**：每接入一套新机制，先跑 1v1 对战验证手感
4. **模拟器护航**：任何数值调整先在 BattleSim 跑矩阵，确认不崩再进游戏
5. **设计不再超前**：不新增术法/功法/神通正式内容，现有 29 功法、75 术法、34 神通的有效链路已足够支撑下一阶段
6. **同步节奏**：每接入一套功法机制到 Unity，更新 `设计-当前状态.txt` 的 Unity 行
7. **文档跟着代码走**：模拟器参数调完，必须同步更新对应 docs 设计文档
