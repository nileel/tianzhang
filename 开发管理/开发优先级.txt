## 三阶段推进路线

### 阶段一：战棋原型验证 ✅ 已完成（v0.3，2026-06-14）

> 成果：CTB充能引擎 + 六角格战棋 + A*寻路 + 朝向系统 + 简易AI + 完整行动循环 + 太一道庭数据接入

### 阶段二：最小可玩循环 ✅ 已完成（v0.4–v0.5，2026-06-14）

> 成果：修炼引擎 + 功法成长 + 地图探索 + 敌人生成 + 术法槽位UI + 掉落提示 + 探索→战斗循环

### 阶段三：规模化填充 ← 当前阶段

**目标**：扩门派、扩境界、同步高级机制，向完整游戏靠拢。

**分三步推进**：

#### 3.1 多门派数据接入（近期）

- Unity 端接入玉清崖、混元山、太虚观 3 大门派数据（功法 + 术法 + 神通）
- 每门派至少 1 套功法机制在 Unity 复现（守一/雷劫/含弘/玄感）
- 门派选择界面或开局 Build 选择流程

**预估**：2–3 周

#### 3.2 境界扩展 + BattleSim 机制同步（中期）

- 境界从金丹推到元婴/化神（需扩 CultivationEngine 境界表）
- 同步已接入 BattleSim 的高级机制到 Unity：
  - 守一印记（太一·抱元守一经）
  - 符胆印记（太一·云篆度人经）
  - 雷劫印记（玉清·九霄雷劫录）
  - 五行元素克制（土→水→火→金→土）
- PvE 2v2 群战接入（利用 v6.0 群战引擎结论）

**预估**：3–4 周

#### 3.2.5 稳定化校准（当前最高优先级，插入阶段）

- ✅ 已完成首轮：修复 BattleSim 对称性与同境过滤问题，重跑 1v1/2v2 金丹过滤矩阵，更新“金丹同境”结论。
- 统一基础设定规则口径：优先修正道基→金丹映射、伤害结算顺序、五行 v5.10、先天/二级属性脱钩、v3.4 成长模型与旧版附录冲突。
- 统一 Unity 战斗循环：决定恢复真 CTB，或正式将原型改为交替回合并同步文档；若保持 CTB，先修 `CTBEngine` 量纲与冷却惩罚。
- 对齐 Unity `DamageCalculator` 与 BattleSim/设计文档，尤其是双线伤害公式、格挡/魂盾/闪避/暴击顺序、五行 v5.10 内外圈规则。
- 建立 docs → CSV → ScriptableObject 数量与字段一致性检查，防止设计资产导入缺口被误判为已完成。
- 清洗基础设定与规范文档中的文本污染、换行残留和旧版数值残留。

**预估**：3–7 天（先做校准，不新增大规模内容）

#### 3.3 完整游戏循环（远期）

- 9 域地图扩展 + 关卡化
- 经济系统（商店/交易/掉落完整循环）
- 炼虚期内容 + 领域碰撞
- 古修/散修内容补全
- 多门派 AI + Boss 战

**预估**：3–6 个月

## 核心原则

1. **一门派深耕 → 多门派扩展**：太一道庭已跑通全流程，以此为模板扩展到其他门派
2. **机制按需求优先级同步**：先同步对玩法影响最大的机制（守一/符胆），群战/水修后置
3. **手感验证贯穿始终**：每接入一套新机制，先跑 1v1 对战验证手感
4. **模拟器护航**：任何数值调整先在 BattleSim 跑矩阵，确认不崩再进游戏
5. **设计不再超前**：不新增术法/功法/神通文档，现有 131 个养成资产完全够用
6. **同步节奏**：每接入一套功法机制到 Unity，更新 `设计-当前状态.txt` 的 Unity 行
7. **文档跟着代码走**：模拟器参数调完，必须同步更新对应 docs 设计文档
