## 筑基、紫府与丹相后续 Unity 任务卡

### U-FPD-RULE-01 · 道基与紫府运行时

- 依赖：D-FPD-SCHEMA-01；N-FPD-GROWTH-01、N-FPD-MANSION-01、N-FPD-CULTIVATE-01；至少一组合法与非法 fixture。
- 预期路径：`src/Assets/Scripts` 中现有角色成长／会话所有者、相关数据模型，`src/Assets/Tests/EditMode`；不得新建第二套角色成长服务。进入当前队列前由实时扫描展开字面量路径。
- 范围：接入唯一道基、四阶段连续进度、容量释放、最多两层扩府、五类紫府两段建造、每府唯一镇府神通、平铺效果绑定、固定周期行动、闭关重复和结丹永久锁。
- 验证：允许／拒绝 fixture 覆盖凡品筑基、下品零府、两层扩府、重复府属、失败回退、结丹后养基／扩府／开府、递归效果包和同府多神通；运行相关编译与 EditMode。
- 完成条件：所有硬门槛有单一持久化所有者和可观察状态，不以 UI、默认值或兼容分支代替规则。
- 停止条件：现有所有者无法容纳新状态且需要新建平行成长服务，或数据契约／数值尚未锁定。

### U-FPD-AI-01 · NPC 自主修炼

- 依赖：U-FPD-RULE-01、N-FPD-NPC-01。
- 预期路径：现有 NPC 决策／世界时间所有者、权重数据、相关 EditMode 测试；进入队列前展开字面量路径。
- 范围：先过滤非法行动，再读取基础、性格、门派、境界目标、寿元、资源与环境权重；只在规定事件重算，不每日扫描全世界。
- 验证：固定世界状态得到稳定排序；寿元将尽不能绕过道基第四阶段、至少一府或证位条件；玩家不能替 NPC 逐人设计划。
- 完成条件：权重可由数据调整，行为顺序不写死，NPC 与玩家共享行动成本与硬条件。
- 停止条件：实现要求 NPC 读取未知事实、每日全世界扫描或用硬编码顺序替代权重数据。

### U-FPD-SAVE-01 · 筑基与紫府持久化

- 依赖：U-FPD-RULE-01；S-SAVE-01 的存档版本与迁移基础已由 TQ-070 完成。
- 预期路径：S-SAVE-01 确认的存档所有者、角色成长快照、相关 EditMode 测试；不得另建平行存档格式。
- 范围：持久化道基身份／进度、天然与扩府容量、五府状态、镇府神通实例／强化节点、当前修炼行动、停止原因和结丹永久锁。
- 验证：新档、合法旧档迁移、非法档拒绝、保存读取幂等、结丹后篡改容量或紫府失败关闭；不可重复领取扩府层或修炼结算。
- 完成条件：读档后所有不可逆事实和唯一实例 ID 保持稳定，没有半迁移状态。
- 停止条件：S-SAVE-01 尚未提供版本／迁移边界，或需要另建平行存档格式和兼容读取层。

### U-FPD-UI-01 · 筑基与唯一丹相界面

- 依赖：U-FPD-RULE-01、D-FPD-MIGRATE-01、N-SLOT-01、N-FPD-DANXIANG-01；使用 2026-07-17 UI 规格，不复用未采纳样图布局。
- 预期路径：现有境界／角色 UI 所有者、相关 UI 数据适配与 EditMode／PlayMode 测试；进入队列前展开字面量路径。
- 范围：显示第一至第四阶段、天然／已释放／扩府／总容量、0～5 座紫府未建／府胚／建成、每府府体与镇府神通、结丹不可逆确认，以及一个丹枢核心／一个丹相中的 1～3 主承载与辅助输入。
- 验证：0、1、3、5 府角色及一至三稳定位格快照；未知信息不泄露；第四、第五府可见但不生成额外位格、丹相或槽位。
- 完成条件：界面只消费真实字段，不从颜色、名称或静态图推断规则状态。
- 停止条件：真实字段、槽位预算或丹相主辅数据尚不可用；不得用静态假数据先锁死布局。

## 《天章》册界体系后续 Unity 任务卡

共同事实源：`docs/superpowers/plans/2026-07-22-tianzhang-cosmology-story-and-rules-migration.md`、`docs/基础设定/册界天章与地区规则交互规则.txt`、三项核心遗产文件，以及 D-TZ-CHARTER-SCHEMA-01／SAMPLE-01 的有效数据。三项任务均属于 M8，实现授权前不得进入当前任务队列。

### U-TZ-CHARTER-MODEL-01 · 三项遗产与册界纯规则模型

- 依赖与状态：D-TZ-CHARTER-SCHEMA-01、D-TZ-CHARTER-SAMPLE-01 完成并提供有效与非法 fixture；用户明确授权 M8。当前冻结。
- 预期路径：现有世界状态、据点交互、设施权限、规则冲突与地区事件所有者，相关数据模型和 `src/Assets/Tests/EditMode`；进入当前队列前必须实时扫描并展开字面量路径，不得先假设新服务名称。
- 范围：《开阖九章》只处理旧门禁／传送阵目标识别、通行许可与稳定失败原因；太玄界印只处理公共设施的管理者、受益者、守卫／档案响应；册界模型只处理完整条目登记、节点连通、版本化授权、据点级覆盖、现实供给、正负原子提交和地区事件输出。
- 冲突：命中同变量金丹介入时复用既有 `RuleConflictInstance` 和版本化 `CrossTierChallengeGrant`；没有挑战资格就拒绝覆盖。命中元婴道路锚点固定进入受锚状态，不把它降格为金丹冲突，也不自动获胜。
- 失败关闭：通行、归属和规则调用分别校验，任一遗物不能代替另外两件；缺条目、授权、节点、支点、供给、代价或合法覆盖集合时不提交半状态，不提供默认成功或旧逻辑 fallback。
- 验证：以 D-TZ-CHARTER-SAMPLE-01 的有效与非法 fixture 覆盖通行不等于管理、管理不等于改规则、节点断开、覆盖越界、原子提交、金丹冲突、元婴受锚和事件唯一记录；运行相关 .NET／EditMode 构建与测试、文本和差异检查。
- 完成条件：纯规则层可在不加载场景或 UI 的情况下确定性返回成功结果或稳定拒绝原因；所有持久化事实只有一个运行时所有者，未建立第二套节点、授权、冲突或世界状态服务。
- 停止条件：现有所有者无法容纳状态而需要平行服务，或实现必须新增任意脚本编辑器、完整九域模拟、上界地图和未定义数值。

### U-TZ-CHARTER-SAVE-01 · 册界状态持久化

- 依赖与状态：U-TZ-CHARTER-MODEL-01 完成；复用 S-SAVE-01 已建立的版本、迁移和失败关闭边界；用户明确授权 M8。当前冻结。
- 预期路径：S-SAVE-01 确认的存档所有者、世界／地区状态快照与直接相关 EditMode 测试；进入当前队列前展开全部字面量路径，不另建平行存档格式。
- 范围：持久化玩家已登记条目、太玄界印认主／权限状态、册界节点完好与连通状态、版本化组织授权、当前覆盖集合、条目／节点占用、正负提交结果及当前地区规则；《开阖九章》只保存确有持久事实的识别／通行状态。
- 验证：新档、合法旧档迁移、未知 ID 拒绝、保存读取幂等、调用中断无半提交、节点断开后的重检、授权版本变化、占用释放和重复读取不重复结算；篡改覆盖或删除负面提交必须失败关闭。
- 完成条件：读档后条目、界印、节点、授权、覆盖、占用和地区规则与保存前一致，唯一事务不会重复提交，旧档缺失新体系时使用明确的未接入状态而非伪造默认授权。
- 停止条件：需要第二套存档、静默兼容层、不可追溯默认 ID 或无法区分定义版本与实例状态；保留失败证据并返回数据契约任务。

### U-TZ-CHARTER-SLICE-01 · 单据点纵向可玩切片

- 依赖与状态：U-TZ-CHARTER-MODEL-01、U-TZ-CHARTER-SAVE-01 与 U-ENV-RULE-01 完成，D-TZ-CHARTER-SAMPLE-01 可用；用户明确授权 M8。当前冻结。
- 预期路径：现行唯一 `AdventureScene` 冒险入口、一个已有据点／设施交互所有者、战场环境档案消费接口、统一 `UICanvas` 下的最小状态反馈和直接相关 EditMode／PlayMode 测试；进入当前队列前实时扫描并展开字面量路径。
- 可玩流程：识别并开启一个旧门禁 → 以界印或合法组织授权确定一个公共设施的管理者与受益者 → 修复／接通一个册界节点 → 登记并调用 `水府地纪` → 输出一个确定性 `environmentProfile` 引用 → 分别观察一个金丹介入冲突和一个元婴受锚拒绝 → 保存、退出并读档复核。
- 表现边界：UI 只显示真实字段、覆盖集合、授权缺口、现实供给、正负提交和稳定失败原因；不创建完整册界编辑器、九域地图面板、动态经济看板或第二 Canvas。战场环境只消费引用，不反向修改长期地区状态。
- 验证：据点级正常流程和每个失败节点均可观察；EditMode 验证规则与存档，PlayMode 验证交互和统一 UI，数据链验证引用完整；不涉及新数值时不运行 BattleSim，涉及倍率、概率或产量时停止并先建立数值任务。
- 完成条件：一个据点内完整证明通行、归属、节点、条目、环境引用、金丹冲突、元婴受锚与保存读取闭环；第一章和关中现有任务不被重写，正式冒险入口仍唯一。
- 停止条件：切片需要第二据点、整域天气／经济模拟、任意规则编辑器、新剧情任务、上界地图、完整境界表或未确认资源数值。
