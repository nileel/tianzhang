## 运行时角色美术、URP 与 2.5D 后续任务

共同事实源：`docs/superpowers/specs/2026-08-05-character-art-and-modular-appearance-design.md`。该设计已批准运行时角色采用固定正交斜俯视的 2.5D 低模 3D“水墨棋偶”，但当前项目仍是 Built-in Render Pipeline；以下八项必须保持独立任务边界，依赖满足并完成实施路径扫描后再建立活跃任务卡，不提前进入 ready 队列。

固定顺序为 `U-URP-MIGRATE-01 -> U-CHAR-3D-PROTO-01 -> U-CHAR-HUMANOID-PROTO-01 -> U-SHIJIAHOU-3D-PROTO-01 -> D-CHAR-APPEARANCE-01 -> A-CHAR-PORTRAIT-STYLE-01 -> U-CHAR-3D-FORMAL-01 -> U-CHAR-CREATION-VISUAL-01`。正式场景替换必须等待技术、数据、存档与风格闸门全部通过。

### U-URP-MIGRATE-01 · Built-in 到 URP 独立迁移

- 范围：安装与当前 Unity 版本相容的 URP，建立并绑定 Pipeline Asset 与 Quality 配置，迁移现有材质并处理 Tilemap、Sprite、UI、TextMesh Pro、六角地块和透明高亮兼容。
- 回归：正式场景入口、相机、透明排序、选格射线、色彩空间、UI、Tilemap、高亮和已有验证必须保持成立；`HybridTacticalPrototype.unity` 不能替代正式 Adventure 回归证据。
- 边界：不新增角色模型、外观字段、换装、动画或正式美术资源；不得保留两套渲染管线、复制场景或增加静默材质回退。若迁移需要修改 CTB、六角空间、伤害、AI 或场景流转规则，立即停止并回查根因。
- 建卡条件：先实时扫描 Unity 版本、Packages、Graphics／Quality 设置、正式 Build Settings 场景、全部现有材质／Shader、相机、Tilemap、UI／TMP、高亮与选格所有者，并展开精确 expectedPaths、回滚边界和直接 EditMode／PlayMode 验证。

### U-CHAR-3D-PROTO-01 · 2.5D 真实单位表现接口与测试台

- 只在现有 `HybridTacticalPrototype.unity` 建立真实 3D 单位表现接口，先用正面明确的几何占位体验证缩放、六向旋转、地块高度、阴影、选中反馈和相机裁切。
- 六个 `Character.Facing` 索引必须复用批准的唯一角度表，并与对应规则邻格中心方向逐项对齐；场景不接入 CTB、AI、伤害或正式遭遇，也不成为第二套战斗所有者。

### U-CHAR-HUMANOID-PROTO-01 · 人形模块化技术样例

- 生产男、女基础体型、各一个脸型、两种发型、一套双体型整身服装和一件主手器物；两种体型共用同一 Humanoid 骨架、绑定姿势和基础动画。
- 证明模块组装、固定六向映射、Toon 材质、批准动作中的蒙皮稳定，以及服装与身体之间无明显穿模或接缝；不扩成完整捏脸、身体滑杆、任意散件或全部创角内容。

### U-SHIJIAHOU-3D-PROTO-01 · 石甲兽重型四足技术样例

- 生产石甲兽模型、重型四足骨骼和待机、移动、受击、倒地、基础攻击、防御动作，直接消费既有 `enemy_shijiahou`、正式 `EnemyData.combatTemplate` 与 AI 结果。
- 只证明非人形表现管线；不得重建或修改敌人规则、攻击档案、数值、占格或 AI，也不得套用人形外观档案和骨架。

### A-CHAR-PORTRAIT-STYLE-01 · Toon 材质与玩家模块化全身立绘样张评审

- 只批准风格样张，不生产完整首版创角资源，也不把技术草图或现有重要 NPC 独立立绘直接定为玩家模块化成品。
- 分别评审运行时角色 Toon 材质样张与玩家标准姿势全身立绘样张。玩家立绘至少选择 2 种发型、2 套服装和 2 个脸型，并覆盖完整笛卡尔积，最低八种组合；必须与现有 NPC 立绘并排比较线稿、水彩、比例、精细度、主配色与身份一致性。
- 全身、对话半身和行动轴头像必须来自同一合成结果的裁切；样张需证明固定锚点、图层遮挡、面部清晰度和组合稳定性，不为每个 UI 表面另造不同身份结果。
- 未通过评审时只保留技术图层样例，不批量生产脸型、发型和服装立绘；若组合必须依赖随机替代、手工逐图修补、不同 UI 专用母版或修改规则／装备／存档所有权，停止并回到图层规范或数据根因。

### U-CHAR-3D-FORMAL-01 · 正式 Adventure 3D 单位表现替换

- 在正式 `AdventureScene` 中，以已验证的 3D 单位表现替换 `ExplorationController` 通过 `PlaceUnitMarker` 创建的 Sprite／Billboard 标记。
- 保留 `AdventureSceneController`、`ExplorationController`、`TacticalCombatController`、CTB、AI、伤害、结算与返回所有权；接入前后六角坐标、占位、可达格、射程、视线、拒绝原因和战斗结果必须一致。

### U-CHAR-CREATION-VISUAL-01 · 首版创角外观内容批次

- 技术、风格、数据与存档闸门全部通过后，按批准范围补齐两种体型各 3 个脸型、4 档肤色、6 种发型、6 种发色、3 套双体型初始服装及少量服装辅色，并接入正式角色创建 UI。
- 不新增面部或身体滑杆、任意上下装散件、布料／发丝模拟、完整装备外观或未批准妖兽；正式资源须遵守 `docs/资源管理/美术资源版本管理规范.md` 与资源登记册流程。
