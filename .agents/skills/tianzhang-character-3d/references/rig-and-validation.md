# 绑定、静止形状与动作验证

本文件针对会动的角色和已有模型修复。参数、顶点号和骨名从当前模型读取，苻渊的数值仅作为案例。

## 保存前先确认正在编辑的状态

检查目标 Blend 的实际路径、当前模式、未保存修改及正在进行的变换。用户最后确认的关节位置优先。若肘点仍处于等待鼠标确认的交互操作，只提醒用户完成确认，不能代定位置或通过切模式结束操作。

Charakuru 有有效 `sourceBlend` 时，从对应当前模型的源件继续。若用户的活动 Blender 含更新的未保存编辑，先保全并明确哪份是本次基准。不要只因文件叫 `work/character.blend` 就认定它最新。读取、保存、导出的工具路线遵循项目 Blender skill。

## 新绑骨与局部修复

新建 Charakuru 角色在头身合装确认后，导出头＋身体及衣装，头发留待返回。核实 Tripo 当前选择的是 VRM 骨架预设，再取得带骨 FBX。原流程只取返回骨配置，用于素体拟合和权重转移，继续使用已采用材质网格。

权重转移、手指权重和手臂／双腿姿势调整是不同阶段。烘焙静止姿势前，检查肩、腋、袖衬、袖尖、腰封、靴筒和手指的骨影响。特别检查下垂袖尖是否误受大腿／小腿驱动。保存烘焙前的几何基准，正确后再进行必要的静止姿势调整。

已有模型只修局部时，先辨别是原形、权重、骨位置、局部坐标轴、动画重定向还是物理导致。将现有有效部分作为基准，避免重新走整套生成／绑骨。

## 已烘焙错误的形状恢复

本轮发现 Tripo 原袖型正确，转移权重后，深色袖尖受小腿影响，白衬尖受大腿影响；随后手臂和腿的姿势调整把错误写进了静止网格。

如果保存的原形与当前网格拓扑、顶点顺序、区域对应均已验证，可以仅回收受损区域的顶点坐标。转换采用世界坐标，示意公式为

```python
world_position = source.matrix_world @ source.data.vertices[index].co
target.data.vertices[index].co = target.matrix_world.inverted() @ world_position
```

这段适用于已确认的基础网格坐标和对象变换。若原形或目标经过修改器、姿态、形态键求值，先明确所取的是基础形状还是求值形状。顶点数相同不足以证明索引对应。边界处需检查肩腋与躯干接缝，恢复区域须排除已确认的手、腰封和鞋。

静止几何恢复后，重新贴合现有袖摆骨链，并核对蒙皮绑定关系。用单骨小角度测试验证骨动确实带动目标布面。不要以骨名存在或权重总和归一判定物理有效。

## 宽袖、内衬和碰撞

- 袖根跟随对应肩／上臂／前臂，腋下与躯干平滑过渡，远端逐步交给袖摆骨链。
- 外袖与内衬使用一致的空间影响范围，结合结构处理折角和袖口，避免两层独立甩开。
- 依据布料跨度设置现有链的根、末端与权重覆盖。连接在骨上的皮肤、手指不能混入袖摆物理。
- VRM 1.0 链的最后关节用于确定末端位置。检查实际变形骨后是否还有有效末端，避免末段布料不受驱动。
- 根据实际胸、腰、臂、腿表面布置必要碰撞体，并确认目标链引用了正确碰撞组。用有碰撞引用／无碰撞引用的同帧对照验证，物理 ON／OFF 仅能证明摆动。
- 检查 center 是否抵消了需要的惯性。把头设为发链 center、腰设为袍摆 center 可能削弱父骨运动引起的摆动，须以运行时响应决定。
- 弹簧骨碰撞约束关节，蒙皮布面在关节之间仍可能穿插。需要观察完整袖面及内衬，不能用骨端未进入碰撞体代替布面验收。

如果改善剩余穿插需要新增骨链、重做拓扑或改用其它模拟方案，先展示当前误差与拟改范围，再决定是否扩大修复。苻渊已用四条袖链改善，但没有证明所有动作无穿插。

## 手指和袍内靴筒

手指横向折叠时，先比较原掌面、手骨／指骨局部轴、目标动画的弯曲方向和 Humanoid 对应。仅移动腕点不能修复局部轴错误。校正后检查五指关节中心落在对应网格内、五指仍受动画驱动，默认走路多帧没有异指相交。静止时从正面与背面检查手腕穿过正确袖口。

袍内黑色筒体露出时，隔离检查究竟是皮肤、腿筒、鞋口还是破损衣面。按遮挡关系调整已确定的内部结构和权重，保留可见鞋面与踝口。不要把整条腿删除或缩小鞋来掩盖问题。走路时要从前、斜前、侧、背面检查袍缝与开口。

## 最小充分验证

| 检查 | 方法 | 可以证明的范围 |
|---|---|---|
| 静止形状 | 原形与修复件同相机、同尺度，量肩线、两侧外袖尖和白衬折角 | 已指定点／区域的静止误差 |
| 骨与权重 | 单骨小角度测试，观察目标顶点响应 | 骨链确实驱动该区域 |
| 屈肘 | 双侧分别或同时屈曲 65°，观察肩腋、腕口、内外袖 | 本姿势下拉伸与穿插 |
| 行走 | 同一默认动作，多帧、多角度，含启动与稳定段 | 该动作和采样范围内表现 |
| 惯性 | 手臂停住后再取 0.2 秒，分别记录袖根、手腕、袖尖 | 固定部位稳定且布料继续运动 |
| 导出一致 | 保存 Blend 后生成实际 VRM／目标引擎资产，核对哈希及运行图 | 交付件与实测件一致 |

按当前修改风险选用这些检查，已经通过且输入未变的区域无需重跑。毫米数据要标明坐标系、区域和采样条件，碰撞计数注明是顶点、帧还是三角面相交对。用实际可见画面辅助判断，不能只交数值。

本对话第 44 版的有限验证示例——默认走路 121 帧、8 角度未检出上段靴筒穿到袍面前；5 帧手指检查无异指相交。稳定行走仍有袖布穿入腋下附近约 42 毫米、下袍约 39 毫米。第 52 帧斜前视角还可从袍缝看到约 8.3 毫米靴筒边线。这些是残余问题，不是通用允许值。[测量记录](../../../../assets/generated-character-art/fuyuan-tripo-p2-tpose/charakuru-sleeves/outfit-motion-qa.json)

## 输出与续作

可编辑 Blend 保存骨、权重、材质、物理和必要纹理，FBX用于几何／骨架检查，VRM保存对应运行时设置。FBX不是 VRM 弹簧骨与 MToon 的完整配置载体。正式 VRM 的作者与使用条件沿用用户提供的信息。

Charakuru 使用 `scripts/update-model.mjs` 的 `phase: "springs"`、`includesHair: true` 和本次实际 Blend／FBX 路径登记。应用的当前 prepare-review／rig complete 入口生成并登记预览 VRM。通过当前请求会话继续，核对正本内 `sourceBlend`、`updatedModel`、`reviewVRM` 与本地实文件对应，打开实际动作确认界面。
